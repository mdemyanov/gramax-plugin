## 2. Таблицы раздела «Валидация» (SKILL.md:542–725)

Преамбула (551–555): типовые ошибки рендеринга проверять ПЕРЕД публикацией; конструкции
роняют рендерер (HTTP 500 / «ошибка отображения»); баланс парных тегов при этом остаётся
идеальным — обычная проверка баланса их не ловит; список собран из реальных инцидентов.

### ERROR — подтверждённые киллеры рендера (SKILL.md:557–568)

| Дефект | Симптом | Правильно |
|---|---|---|
| `<th>` в таблицах | 500 на всех разделах с таблицами | `<td>` + `header="row"` у `<table>` |
| Инлайновый `<note …>текст</note>` в 1 строку | не рендерится | блочный формат с пустыми строками |
| Файл не валидный UTF-8 | 500 либо мусорный хвост на странице | обрезать дописанный хвост |
| Несколько `![](…)` в одной строке | картинки не рендерятся | каждое изображение на своей строке |
| Несбалансированные парные теги | «съеденный» кусок страницы | закрыть все парные теги |
| Многострочный `<colgroup>` (каждый `<col/>` на своей строке) | 500 на всей странице | схлопнуть в одну строку |
| XML-тег внутри HTML-комментария | 500 на всей странице | переписать комментарий текстом |
| Обрывок тега после закрытого тега (хвост вида `splay="List"/>`) | 500 на всей странице | оставить один корректный тег, хвост удалить |

### WARN — стиль и YAML, «рендер не роняют» (SKILL.md:607–615)

| Дефект | Симптом | Правильно |
|---|---|---|
| `title:` с `: ` в frontmatter без кавычек | страница пустая (ломается YAML) | закавычить |
| H1 (`# …`) в теле | дубль заголовка | только `##` и ниже |
| Property во frontmatter не из `.doc-root.yaml` | ошибка | только объявленные properties |
| `<note>` внутри `<td>` | ширины колонок плывут | инлайн: `**Заголовок.** текст` |
| `<note>` внутри `<note>` | вложенные заметки схлопываются | развернуть во внешнюю заметку |

Сноска (SKILL.md:617–622): два последних правила понижены из ERROR в WARN 04.09.2026.
Замер по порталу: 42 вхождения на 19 страницах `<каталог-продукта>` — все отдают HTTP 200,
admonition нормально рендерится внутри `<td>`. Как причину 500 правило не подтвердилось;
осталось как стилевое.

### «НЕ ошибки» — проверено на 441 странице `<каталог-продукта>`, не трогать (SKILL.md:624–629)

- `<colgroup>` / `<col>` в таблицах — используются рабочими страницами (легальна
  **только однострочная форма**; многострочная — ERROR);
- эмодзи в `##`-заголовках — 50 рабочих страниц рендерятся нормально;
- скобки в значениях XML-атрибутов (`title="…(…)…"`);
- много-абзацные ячейки (пустые строки между абзацами внутри `<td>`).

### Культура мисдиагнозов (SKILL.md:631–716)

- Исторически эмодзи и `<colgroup>` вычищали вручную «чтобы починить парсер» —
  мисдиагнозы: реальной причиной 500 всё время был `<th>` (631–632).
- Пять подряд «фиксов» страниц `su/trebovaniya-vstrechi` и
  `support-domen-baza-znaniy/trebovaniya-k-domenu` прошли мимо причины именно потому,
  что навык снимал с `<colgroup>` подозрение целиком; сам тег безвреден — ломает только
  многострочная форма (634–638).
- Три инструмента (640–647): `scan-portal.py` — оракул («спрашивает у портала HTTP-код
  каждой страницы», «100 % — это и есть ответ портала»); `validate-gramax.py` — линтер
  (гипотеза; ERROR откалиброван по оракулу, WARN — стиль); `gramax-cli check` — healthcheck
  ссылок/ассетов. Порядок: сначала линтер (до пуша), потом оракул (после пуша).
- `gramax-cli check` НЕ эквивалент портала: 04.09.2026 на версиях 1.0.51 и 1.0.52
  страницу с многострочным `<colgroup>` (портал давал 500) обе версии пропустили (666–671).
- Правило заведения дефекта (694–695): нашёл новый дефект — сначала подтверди оракулом
  (500 до правки, 200 после), и только потом заводи ERROR-правило; не подтвердил — место
  в WARN.
- «Фикс без оракула — не фикс, а гипотеза. Два неподтверждённых фикса подряд — стоп»
  (706–707). Хронология потерь (709–716): 11 дней страницы в 500, три холостых коммита;
  причина (многострочный `<colgroup>`) найдена 04.09 за один прогон линтера.
- Локализация падения (697–704): оракул называет страницу, линтер — конструкцию; если
  линтер молчит — бинарный поиск в песочнице (папка с `.doc-root.yaml` + страница, резы
  пополам; пуш в общий репозиторий для диагностики не нужен).

## 3. Четыре детектора, которых нет в локальном порту (в апстриме — все ERROR)

**1. Многострочный `<colgroup>`.** Апстрим: построчный матч открывающего тега, занимающего
строку целиком (`validate-gramax.py:154-156`), ERROR «Схлопните в одну строку»; в коде
комментарий — «подтверждённый киллер (04.09.2026, `support-domen-vstrechi/trebovaniya-k-domenu`
отдавал 500)». Однострочная форма легальна. Локально: `gramax-render-rules.json:10`
безусловно allowlist-ит `colgroup`/`col` — форма не различается.

**2. XML-тег внутри HTML-комментария.** Апстрим — два прохода: однострочный комментарий
(164–167) и многострочные через `re.finditer` с `re.S` и вычислением строки (169–177);
общий паттерн тега `<[a-zA-Z][\w-]*…>`, ERROR «Перепишите комментарий текстом».
Исключение: `<!--[if mso]-->` внутри блока сырого `<html>` легален — такие блоки
маскируются `html_mask` (42–63).

**3. Обрывок тега (текстовая форма хвоста).** Апстрим: из строки вырезаются корректные
`<…>` и инлайн-код; если в остатке есть `/>` — ERROR (158–162). Формальный признак
(SKILL.md:577–579): после вырезания остаётся `/>`; проверено на 441 странице — ложных
срабатываний нет. Семантика (570–576): это не опечатка автора, а след сбоя сохранения в
редакторе — хвост исходного тега, обрезанный с начала; рядом бывает обрезанный `title:` во
frontmatter («оба поля пишутся одной недописанной транзакцией»).

**4. Байтовая форма того же дефекта = невалидный UTF-8.** Апстрим читает файл байтами и
декодирует; на `UnicodeDecodeError` — fatal-ERROR со строкой 0 и сообщением с байтом и
позицией (66–81). Семантика: редактор при обрыве сохранения дописывает в конец файла
фрагмент его же хвоста, обрезанный посреди двухбайтового символа. Долевая статистика
(SKILL.md:598–600): из четырёх случаев три давали HTTP 500, четвёртый — видимый мусор в
конце страницы. Фатальная ошибка исключает дальнейший разбор файла, но обход каталога
продолжается. Локально: `validate_render.py:69` читает `read_text(encoding="utf-8")` без
обработки — на таком файле порт падает с необработанным исключением и прекращает обход
(поведение апстрима до v1.2.0, см. CHANGELOG:43-44).

Сопутствующее расхождение severity (вне четвёрки): локальный контекстный проход даёт
ERROR для note-in-cell и note-in-note (`validate_render.py:104-110`, маркер FR-105..107),
апстрим v2.0.0 — WARN для обоих (`validate-gramax.py:109-120`); ERROR остался только для
инлайнового `<note>` в одну строку. `LICENSE.upstream.md:31-33` описывает контекстные
правила как «алгоритмы, не данные», это severity-расхождение не фиксируя.

## 4. Оракул `scan-portal.py` (185 строк)

- Назначение (docstring): спрашивает у портала реальный HTTP-код каждой страницы каталога;
  линтер и `gramax-cli check` дают гипотезы, портал — единственный источник истины;
  655 страниц опрашиваются за пару минут.
- База: `DEFAULT_BASE` — константа с внутренним хостом портала в их коде (строка 30;
  литерал хоста не публикуется — ADR-0014), переопределяется `--base`.
- Токен (34–51): env `GRAMAX_API_TOKEN` (URL-декодируется) либо ближайший вверх по дереву
  `.mcp.json` (`mcpServers.gramax.env.GRAMAX_API_TOKEN`); нет токена — exit 2.
- Отбор страниц (54–80): страница = `.md`, чьи первые байты начинаются с `---`
  (frontmatter) — так отсекаются сниппеты, README и мусорные CLAUDE.md; обход пропускает
  `.git`, `.gramax`, `node_modules`, `.claude`, `.storage`, `.obsidian`; slug = путь без
  `.md`, суффикс `/_index` срезается.
- Запрос (83–93): GET
  `{base}/api/catalogs/{catalog}/articles/{urlencoded-slug}/html`, `Authorization: Bearer`,
  timeout 60 с; сетевая ошибка возвращается строкой `ERR <ИмяИсключения>`.
- Параллелизм: `ThreadPoolExecutor`, `--jobs` по умолчанию 8; retry (104–106, 143–150):
  `--retry N`, `--retry-wait СЕК` (дефолт 120) — перепроверяются только страницы со
  статусом ≥500; повод: «портал переиндексируется после пуша».
- Отчёт (152–174): распределение кодов; секция «ПАДАЮТ» (≥500) с советом прогнать линтер;
  секция 404 («нет на портале»; «404 сразу после пуша — обычно переиндексация»); секция
  сетевых ошибок; `--json` сохраняет slug→код.
- Выходы: 0 — падений нет; 1 — есть страницы с 5xx; 2 — ошибка запуска. Скорость:
  каталог 582 страниц ≈ минута в 8 потоков (SKILL.md:664).

## 5. Протокол калибровки (`validate-gramax.py`, заголовок 13–19)

Заголовок: каждое ERROR-правило подтверждено оракулом — реальным ответом портала.
Последняя сверка 04.09.2026: каталог `ecosystem/<каталог-продукта>`, 655 страниц, 3 отдавали
HTTP 500. «Правило, не подтверждённое оракулом, живёт в WARN, а не в ERROR: ложный ERROR
дороже пропуска, потому что обесценивает весь гейт».

Шаги (SKILL.md:673–695 + CHANGELOG):

1. **Замер:** прогнать линтер и оракул по одному каталогу, сопоставить помеченные ERROR
   страницы с реально падающими (5xx). До калибровки: помечено 23, падало 3 — точность
   13 %; после — помечено 3, падало 3 — 100 % (SKILL.md:677-683, CHANGELOG:23-24).
2. **Разбор расхождений до источника.** Три источника ложных ERROR того замера:
   `<note>` в `<td>` — правило не подтвердилось вовсе, понижено в WARN; `<th>` и
   XML-в-комментарии внутри вставленных блоков `<html>…</html>` — Gramax пропускает такие
   блоки как есть (внутри легальны `<thead><tr><th>` и `<!--[if mso]-->`), блоки исключены
   из разбора маской `html_mask`; инлайн-код в проверке баланса — страница, описывающая
   тег словами в бэктиках, давала фантомный дисбаланс 9/7 при реальном 7/7.
3. **Новый дефект:** подтвердить оракулом (500 до правки, 200 после) → заводить
   ERROR-правило; не подтвердил — WARN.
4. **Эксплуатационная пара:** линтер до пуша (exit 1 = пуш не начинать), оракул после
   пуша с `--retry`. Линтер после итогов печатает: «ERROR — это гипотеза о падении
   рендера. Подтвердите её оракулом» (264–265).

## 6. Окно переиндексации портала

- Измеренный факт апстрима (другой инстанс портала — внутренний; хост не публикуется,
  ADR-0014): задержка
  переиндексации после `git push` — 5–10 минут; починенная страница держала 500 ещё 10
  запросов подряд, потом отдала 200 без действий с нашей стороны (SKILL.md:718-725,
  scan-portal.py:24-25, CHANGELOG:14-15,55). «500 сразу после пуша — не диагноз».
- Для gram.ax (облако) замер напрямую не переносится: страница
  `deploy/doc-portal/content-updates` (проверена 2026-11-21) говорит «изменения попадают
  на портал автоматически — по расписанию или сразу после push по webhook»; окна,
  задержки и cache TTL не документированы. Факт о задержке именно gram.ax по имеющимся
  источникам не установлен (выкачка RES-007 ошибок не даёт, но задержку не измеряла).

## 7. Состояние локального порта (для сопоставления)

- Контекстный проход `validate_render.py:96-123`: note-in-cell ERROR (104–107),
  note-in-note ERROR (109–110), инлайновый `<note>` ERROR (101–103); маркер FR-105..107.
- Контракт `gramax-render-rules.json`: `killerTags: [th]`; `balanceTags: [note, table,
  tr, td, th, tabs, tab, color, highlight]`; `allowlistedTags: [colgroup, col]`
  (безусловно, без различения формы); `schemaVersion: 1`.
- Задокументированные отличия порта (`LICENSE.upstream.md:11-35`): двойное маскирование
  кода fenced+inline (FR-110); severity-модель ERROR/WARN; exit-контракт 0/1/2;
  демаркация с W034; allowlist FR-115…118 (включая `<colgroup>`/`<col>` — у апстрима
  легальна только однострочная форма); ownership баланса; контекстные правила в коде;
  номер строки для unbalanced вместо апстримного L0.
- Не задокументированные наблюдаемые расхождения с апстримом v2.0.0: (1) severity
  note-in-cell/note-in-note ERROR против WARN; (2) отсутствие `html_mask` для сырых
  `<html>`-блоков; (3) отсутствие всех четырёх детекторов из §3; (4) чтение файла без
  защиты от невалидного UTF-8.
