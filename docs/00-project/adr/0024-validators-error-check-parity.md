# ADR-0024: Паритет офлайн-валидаторов с модулем «Проверка на ошибки» — коды находок, строгость, контракт-паритет W034

**Status:** Accepted (ратифицировано PM 2026-11-18)
**Date:** 2026-11-18
**Plugin:** gramax / marketplace

## Context

RES-007 (§2) зафиксировал: модуль приложения «Проверка на ошибки» проверяет шесть категорий
(статьи, ссылки, элементы, диаграммы, шапки, иконки); вердикт по офлайн-валидаторам плагина —
«частично»: цели диаграммных тегов покрывает только `<drawio>` (W031), иконок `.icons/` нет
вовсе. Попутно требование вскрыло дефект согласованности: W034 репортит канонические теги
собственного контракта `gramax-tags.json` (`<view>`, `<mermaid>`, `<snippet>`, `<openapi>`,
`<video>`, `<icon>` — факт 7) и слеп к дефисным именам вроде `plant-uml` (факт 8). Проба SA
2026-11-18 уточнила: слепая зона матчера двойная — невидима и голая self-closing-форма без
атрибутов; форма `<fancy-widget-x/>` из AC-068 невидима по обеим причинам. Требование
[Паритет офлайн-валидаторов](../../30-requirements/2026-11-18-validators-error-check-parity-requirement.md)
(FR-151…FR-157) оставило SA вопросы 1, 3, 6 и решение об ADR-достойности; исполнительская
расшифровка — [дизайн-документ](../../40-architecture/2026-11-18-validators-parity-design.md).

Предшественники: ADR-0012 (контракт валидации: JSON single source, Решение 2 — градуировка
по природе дефекта), ADR-0019 (демаркация W034 по контракту, BR-004 «одна находка»),
ADR-0020 (рекурсивные catalog root), ADR-0006 (semver).

---

## Решение 1 — коды находок: W031 наследуется, W035 новый, W034 сохраняется (вопрос 3)

Диаграммные цели `mermaid`/`plant-uml`/`bpmn` наследуют **W031** — один код на класс дефекта
«файл диаграммы не найден»; сообщение дополняется именем тега (аддитивно, grep по коду и слову
«диаграмм» стабилен). Иконки получают новый код **W035** — нового класса дефекта нет чем
наследовать. W034 остаётся кодом неподдерживаемой разметки (теперь строго по контрактам).

**Почему не отдельные коды на каждый тег (W036/W037/…):** потребители грепают коды в CI —
дробление одного класса дефекта умножает их шаблоны без информационного выигрыша; сегодняшний
прецедент W031 не различает цели drawio по файлу. Паттерн группы `diagrams` в `_ERROR_GROUPS`
(`W031|диаграмм`) классифицирует новые находки без правки.

## Решение 2 — строгость: warning по умолчанию, `--strict` эскалирует (вопрос 6, NFR-066, BR-014)

Все новые находки (расширенный W031, новый W035, расширения W034) — **warning**;
существующий `--strict` — единственный переключатель эскалации (новых флагов нет, наследие
ADR-0012 Mitigations). Закреплено здесь, как требует NFR-066.

**Почему не error-по-природе (образец Решения 2 ADR-0012):** критерий ADR-0012 для error —
«однозначный дефект прод-класса» (плейсхолдер-утечка, битая навигационная ссылка). Битая цель
диаграммы/иконки — деградация одного блока страницы, класс уже градуирован соседями W030
(изображение) и W031 (drawio) как warning; error для `bpmn` при warning для `drawio` расщепил
бы один класс дефекта на два уровня. Уровни модуля приложения для этих категорий RES-007 не
раскрывает — N/A, паритет по строгости не заявляется, градуировка своя.

## Решение 3 — источник диаграммных тегов: ключ `diagramTags` в gramax-tags.json (FR-151, NFR-068, BR-012)

Новый ключ `diagramTags: ["drawio", "mermaid", "plant-uml", "bpmn"]`; `plant-uml`/`bpmn`
добавляются в `selfClosingTags`; `schemaVersion` 1 → 2 (аддитивно). Парсер
`md_link_parser.py` параметризуется списком из контракта (`target_type` = имя тега),
`check_diagrams` проверяет членство; fallback при повреждённом контракте — `["drawio"]` по
прецеденту seed `{"drawio"}` у `known_tags`. Новый диаграммный тег = две строки JSON, ноль
правок кода (BR-012); контракт и код — одним коммитом, запись `Contract:` в CHANGELOG
(NFR-068, наследие FR-041).

## Решение 4 — W034: known-набор из двух контрактов, дефис и self-closing в матче (FR-156/FR-157)

`known_tags` в `validate()` вычисляется как объединение `{"drawio"} ∪ diagramTags ∪
selfClosingTags ∪ pairedTags ∪ killerTags ∪ allowlistedTags` — канонический по контракту
плагина тег не репортится (BR-011), демаркация обновляется правкой JSON. Матчер
`_UNSUPPORTED_HTML_RE` получает дефис в имени (`[a-z][a-z0-9-]*`) и опциональный `/` перед
`>` — обе правки обязательны для AC-068 (проба SA: голый `/>` без атрибутов невидим текущему
паттерну). Истинные позитивы сохранены; автоссылки и закрывающие теги невидимы как прежде.
Паритет — с контрактом плагина, не с полным реестром движка (RES-008: `fragment`, `cmd`,
`kbd` и др. поддержаны движком, но вне контракта) — их добавление writer-parity потоком
обновляет демаркацию автоматически.

## Решение 5 — lucide-реестр не поставляется (вопрос 1, FR-153 граница)

Полная офлайн-валидация lucide-кодов требует реестра иконок в поставке — отклонено: состав
lucide-иконок движка не подтверждён ни одним источником (RES-007/RES-008 его не фиксируют),
реестр был бы неверифицируем и давал ложную уверенность; объём и синхронизация на каждый
релиз — стоимость без доказанной пользы. До доказательства — форма префикса (`lucide-` →
библиотека, иначе кастомный код против `.icons/`). Критерий повторного открытия:
исследовательская задача по пину движка (метод RES-008) со списком имён и версией.

## Решение 6 — таксономия: иконки в группу `images` расширением паттерна

Находки W035 классифицируются существующей группой `images` (`incorrects-paths`) — паттерн
группы дополняется `W035|иконк`. Новая группа `icons` не вводится: каноническое имя
апстрим-группы CatalogErrorGroups не известно (комментарий в коде лишь фиксирует её
отсутствие в нашем отображении) — не выдумывается. Расщепление — после второго прохода
исследования `catalog/error-check` (вопрос 5 требования).

## Решение 7 — версия плагина Minor и разрешение на marketplace.json

Разрешаю (прецедент ADR-0012 Решение 7, ADR-0020 Решение 7) правку
`.claude-plugin/marketplace.json`: `metadata.version` → `"4.7.0"` (текущая 4.6.0) и текстовую
(не структурную) правку `description` записи `gramax` на усмотрение Tech-writer. `name`,
`owner`, состав `plugins`, `source` неприкосновенны. **Minor:** аддитивные проверки +
сужение W034 (нестрогая правка, ADR-0012 Решение 1) + расширение W034/W031 на генуинные
дефекты (прецедент ADR-0020 Решение 7: генуинные находки, известных потребителей нет — G1);
`plugin.json` — синхронно, без отдельного ADR. При коллизии номера с параллельными
ADR-0022/0023 финальную версию согласует PM на ратификации.

## Consequences

**Положительные:** битые цели трёх диаграммных тегов и отсутствующие `.icons/`-иконки
ловятся до публикации (FR-151…FR-155); ложные W034 на канонические теги исчезают, включая
живые на `docs/` (AC-071, симуляция: ноль новых находок); демаркация W034 становится
контрактной с двух сторон (теги + рендер-правила); один код на класс дефекта — grep-стабильно.

**Отрицательные / trade-offs:** W034 видит две ранее невидимые формы (дефисные неизвестные
теги, голые self-closing `/>` вроде `<br/>`) — новые warning, exit без `--strict` не меняется;
`--strict`-потребители краснеют на генуинно битых новых целях; schemaVersion 2 и второй
читатель у `gramax-tags.json` — цена контракта (повреждение — явный error, ADR-0012 паттерн);
слепая зона «тег с `path` без `/>`» унаследована от drawio и документирована, не устранена.

**Mitigations:** warning по умолчанию (Решение 2); `Contract:`-запись в CHANGELOG тем же
коммитом; suite-регресс AC-063 (drawio) и AC-071 (догфудинг `docs/`).

## Alternatives Considered

- Отдельные коды находок на каждый диаграммный тег — отклонено: дробление класса дефекта,
  умножение grep-шаблонов потребителей (Решение 1).
- Error-по-природе для битых целей — отклонено: расщепление одного класса (битый файл-ресурс)
  на два уровня, противоречие соседям W030/W031 (Решение 2).
- Литерал диаграммных тегов в коде парсера — отклонено: второй источник правды, BR-012/NFR-068
  требуют контракта (Решение 3).
- Реестр lucide-иконок в поставке — отклонено до доказательства состава (Решение 5).
- Новая группа таксономии `icons` — отклонено: имя апстрим-группы не подтверждено (Решение 6).
- Отдельный ADR не нужен (решить в дизайне) — отклонено: меняется публичный контракт вывода
  (новый код W035, сужение/расширение W034, schemaVersion 2) и градуировка строгости, которую
  NFR-066 явно относит к ADR.
