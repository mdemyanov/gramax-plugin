## Решение 1 — Периметр плагина не меняется (D9, `gramax-o0q.37`)

**Решение:** состав плагина остаётся — семь навыков (`writer`, `comments-read`, `comments-write`,
`mermaid`, `plantuml`, `drawio`, `export`) и агент `review-agent`. Состав закреплён стабами: строка
состава в `CLAUDE.md` — `tests/gramax/gate-composition/ac-146-root-texts.sh:30-41`; существование
`skills/drawio/SKILL.md` — `tests/gramax/plugin-contract/ac-001-routing-contract.sh:17`.

**Основание.** Нулевое использование — локальный факт, не утверждение о публичных потребителях:
выборка RES-002 — около 30 локальных репозиториев (RES-002 `:21`), в ней «drawio не используется
нигде» (RES-002 `:215-216`) и «`review-agent` — ни одного следа использования» (RES-002 `:217`).
Удаление поверхности breaking для публичных потребителей: по ADR-0006 удаление skill — Major, а
релиз волны — Minor 4.11.0 (D4). `drawio` вшит в контракт, а не стоит рядом: его упоминают 18 файлов
плагина вне CHANGELOG (`git grep -l -i drawio -- plugins/gramax
':!plugins/gramax/CHANGELOG.md' | wc -l`) — `plugin.json`, `gramax-tags.json`,
`scripts/validate_structure.py`, навыки `mermaid`, `plantuml`, `export`, `writer` — и 27 файлов
стабов и сюитов вне архива (`git grep -l -F drawio -- 'tests/gramax/*.sh' 'tests/gramax/*.md'
'tests/gramax/*.txt' ':!tests/gramax/archive' | wc -l`).

**Триггер пересмотра:** зафиксированный случай использования или запрос публичного потребителя
(issue репозитория, запись research) либо недоступность внешнего плагина, на который делегирует
навык `drawio`.

## Решение 2 — G8 и G9 снимаются (D9, `gramax-o0q.37`)

**Решение:** диагностика установки (G8) и пиннинг версии (G9) снимаются с повестки плагина — не
откладываются. Ни той, ни другой поверхности в плагине нет: `git grep -l -i -E 'diagnos|диагностик'
-- plugins/gramax ':!plugins/gramax/CHANGELOG.md'` даёт 3 файла — всё о диагностике UTF-8 и YAML
валидаторов; `git grep -l -i -E 'pinn|pinning|пинн' -- plugins/gramax .claude-plugin
':!plugins/gramax/CHANGELOG.md'` даёт 1 файл — имя иконки `map-pinned`.

**G8 — «enabled ≠ installed».** Основание: два независимых инцидента в одном кластере
потребителей, причина — область установки плагина в менеджере потребителя, а лекарство потребители
уже приняли у себя — правилом «проверять замером, а не чтением конфига» (RES-002 `:139-151`).
Диагностика внутри плагина не может сработать в том состоянии, которое должна описать: если
скиллы плагина в сессии не резолвятся, ему нечего исполнять. Доступное плагину место — текст,
читаемый вне сессии; раздел «Установка» `plugins/gramax/README.md` им остаётся.

**Триггер возврата G8:** повторный зафиксированный случай после 2026-11-24 (issue публичного
репозитория или запись research).

**G9 — фиксация версии.** Основание: уверенность разведки средняя, свидетельство — один
шаблон-потребитель с собственным закреплённым checkout (RES-002 `:153-159`).
Следствие, названное G9 («дрейф поведения между прогонами»), на стороне плагина уже закрыто:
лестница ADR-0006 и grep-уемые записи `Contract:` в `plugins/gramax/CHANGELOG.md` (ADR-0012,
Решение 3). Закрепление версии — политика установки потребителя, не функция плагина.

**Триггер возврата G9:** запрос потребителя на рецепт закрепления версии либо зафиксированный
случай расхождения поведения после Major-релиза.

## Решение 3 — G11 закрывается рецептом: `validate_comments.py` в цикле коммита (D9, `gramax-o0q.37`)

**Решение:** рецепт документарный, код и шаблон хука не меняются. Контракт рецепта:

1. **Дом — `plugins/gramax/skills/comments-write/SKILL.md`**, новый подраздел после «Валидация
   после каждой операции». Причина: дефект G11 — ручные правки вне операции навыка (24 ошибки
   валидатора после ручного триажа, RES-002 `:173-179`), а навык уже несёт проверку одного файла
   (`skills/comments-write/SKILL.md:281-293`); проверка каталога рядом с ней не разъезжается на два
   документа. README — дом обнаружимости шаблона хука (ADR-0012, Решение 4), поэтому туда — одна
   строка-указатель, не копия рецепта.
2. **Команда по каталогу** — текст для навыка дословно:

   ```text
   ### В каталоге и в цикле коммита

   Проверка после операции смотрит один файл; ручные правки вне этой операции она не видит.
   Чтобы они проверялись, добавьте валидатор в pre-commit хук или CI своего репозитория — по
   каталогу:

   uv run ${CLAUDE_PLUGIN_ROOT}/scripts/validate_comments.py content

   `content` — папка с `.doc-root.yaml`. ERROR даёт exit 1 и блокирует коммит; предупреждения
   печатаются, exit не меняют. Шаблон хука плагина (`scripts/pre-commit.sh`, см. README плагина →
   «Валидация каталога») запускает структурный валидатор и рендер-линтер; добавьте в скопированный
   хук строку после них:

   uv run "${CLAUDE_PLUGIN_ROOT}/scripts/validate_comments.py" "$CONTENT_DIR"

   Хук работает в сессии с активным плагином; вне её задайте `CLAUDE_PLUGIN_ROOT`.
   ```

3. **Строка-указатель для README** — после предложения о хуке (`plugins/gramax/README.md:143-144`):

   ```text
   Комментарии эти валидаторы не проверяют: команда по каталогу и способ включения в хук — в
   `skills/comments-write/SKILL.md`, раздел «В каталоге и в цикле коммита».
   ```

4. **Стаб уровня unit** пиннит оба текста: команду и строку хука в `SKILL.md`, строку-указатель в
   README. Сюита по прецеденту стабов текстов плагина (например,
   `tests/gramax/plugin-contract/ac-140-readme-version-docstring.sh`) —
   `tests/gramax/plugin-contract/`; окончательное место — за QA-author.

**Замеры контракта** (`uv run plugins/gramax/scripts/validate_comments.py <каталог>`):

- по `docs/` этого репозитория (форма гейта, `scripts/check-gramax.sh:125`): rc=0, 0 находок;
- на синтетических каталогах: ERROR «yaml missing key for md id» → rc=1; несколько позиций одного
  ID → INFO-строка, rc=0; предупреждение по `dateTime` → rc=0; несуществующий путь → rc=2;
- в хуке scratch-репозитория (три вызова валидаторов на каталоге `content`): коммит с дефектом
  отклонён (rc=1, коммит не создан), после исправления создан (rc=0); без `CLAUDE_PLUGIN_ROOT`
  хук коммит отклоняет.

**Границы.** Рецепт ловит класс ERROR. Повторные позиции одного ID — штатная конструкция движка
(FR-210): INFO-строка, коммит не блокирует; «дубли якорей» из G11 рецепт не судит. `--strict`
в хук не входит. Собственный гейт репозитория не меняется: ADR-0027 Решение 4 держит
`validate_comments.py` в `--full`.

## Решение 4 — Три отложенные возможности снимаются (D10, `gramax-o0q.30`)

**Решение:** ни одна из трёх не начата, кандидатов на миграцию нет — снимаются с записью условия
возврата. Замер по `docs/`: `uv run plugins/gramax/scripts/validate_structure.py docs` → rc=0,
0 находок (нет ни плоской нотации, ни пропуска V4/V5).

| Возможность | Состояние | Условие возврата |
|---|---|---|
| overlay-`properties` с вложенными корнями | Вне периметра по диспозиции, Тема B (`docs/40-architecture/2026-08-11-writer-rules-disposition.md:61-72`, `:136`); позиция опубликована (`plugins/gramax/CHANGELOG.md:591`, `skills/writer/references/doc-root-schema.md:176-202`) | Сигнал усиливается до ≥2–3 независимых потребителей — отдельный ADR (порог — из диспозиции) |
| CLI `--migrate-frontmatter` | Не реализован; вне дерева волны-4 упоминается один раз — `plugins/gramax/CHANGELOG.md:871` («Не вошло (отложено)») | Конкретный кандидат миграции: названный каталог-потребитель с плоской нотацией frontmatter |
| Проверки V4/V5 для `type: select` | Пропуск с предупреждением: `scripts/validate_structure.py:246-277`, `:892-895`; синтаксис объявлен экспериментальным (`skills/writer/references/doc-root-schema.md:278-280`) | `type: select` перестаёт быть экспериментальным в документации движка на пине либо потребитель просит проверку |

**Уточнение по вложенным корням.** Снята формальная поддержка как first-class механизм — контракт
конфликта property и приоритета второго `.doc-root.yaml`. Рекурсивное обнаружение и проверка
каждого корня отдельно остались с ADR-0020. Число ADR в диспозиции («ориентировочно 0014») не
резервируется: номер занят.

**V3 не затронут.** Предупреждение V3 (плоская нотация) в валидаторе остаётся
(`scripts/validate_structure.py:476-484`) — снятие CLI его не касается.

## Поправка к ADR-0014 (часть «Механизм») — третий remote доставки (D7, `gramax-o0q.8`)

**Цитаты** (`0014-dual-publication-targets.md:51-52`, `:61-62`): «Два независимых git-таргета
публикации с разными ролями. Редактирование существует только на одном из них.»; «**Механизм (уже
выполнен).** Второй git remote `internal`, публикация обновлений — ручной `git push internal main`.»

**Новая редакция:** «Три независимых git-таргета доставки с разными ролями: `origin` — источник
правды и канал distribution, `internal` — read-only витрина, `gitsd` — вторая read-only копия того
же содержимого (потребители копии неизвестны, D7). Редактирование существует только на одном из
них. **Механизм.** Публикация обновлений — три именованных ручных пуша в фиксированном порядке:
`git push origin main`, затем `git push internal main`, затем `git push gitsd main`; каждый —
fast-forward, без force. Ни `internal`, ни `gitsd` не становятся upstream ветки `main` и не
назначаются push-default: обычный `git push`/`git pull` их не задевает.»

**Порядок в ритуале релиза.** После зелёных `--fast` и `--full` (D5) — `origin`, `internal`,
`gitsd`. После каждого пуша сверка: `git ls-remote <remote> refs/heads/main` совпадает с
`git rev-parse main`. Имя хоста третьего remote в файлы репозитория не пишется (раздел о
маскировании ниже).

**Замеры 2026-11-24.** `git remote` → `gitsd`, `internal`, `origin`; `git rev-parse --abbrev-ref
main@{upstream}` → `origin/main`; `remote.pushDefault`, `branch.main.pushRemote` и
`remote.<name>.push` не заданы. Копия стояла на 4.5.0 при 4.10.0: `git merge-base --is-ancestor
fba407a db24aec` → rc 0, `git rev-list --count fba407a..db24aec` → 99 (версия `plugin.json` на
`fba407a` — 4.5.0, на `db24aec` — 4.10.0). Обновление исполнено fast-forward `fba407a..db24aec`;
`git ls-remote <remote> refs/heads/main` для всех трёх remote → `db24aeca`.

## Поправка к ADR-0014 (часть «Маскирование хоста») — приватность (D8, `gramax-o0q.36`)

**Цитата** (`0014-dual-publication-targets.md:97-99`): «**Маскирование хоста.** Имя внутреннего
GitLab-хоста не попадает в файлы `content/`, `docs/`, `README.md` и любые другие публичные файлы
этого репозитория — по прецеденту `docs/onboarding-nauta.md`.» Второе предложение раздела — о
пути внутреннего репозитория («не секрет и не маскируется») — остаётся в силе (поправка PM при
ратификации 2026-11-24).

**Новая редакция:** «**Маскирование.** Имя внутреннего GitLab-хоста, имена приватных
репозиториев-потребителей и сторонних организаций и слаг каталога проб не попадают в файлы
`docs/`, `README.md` и любые другие публичные файлы этого репозитория — по прецеденту
`docs/onboarding-nauta.md:59` (`<внутренний-хост>`); классификация файлов и токены маскировки — в
диспозиции приватности волны-4. Не маскируются путь репозитория-витрины (второе предложение
раздела) и путь репозитория-источника nauta в базисе доставки — оба названы инструментами этого
репозитория. История git не переписывается: корпоративный адрес автора в метаданных коммитов и
внутренний хост в сообщении коммита `6de79a8` приняты как есть; новые коммиты подписываются

- Закрепить в ac-003 не коммит, а содержимое — идентификаторы blob-ов двух замаскированных файлов,
  известные до коммита: пин и маскирование легли бы одним коммитом. Отклонено: расширяет правку
  стаба и библиотеки под цепочку QA-author и Dev, не добавляя гарантии к пословному доказательству.
- Не ставить маркер «Опоры» в два файла и назвать для них исключение в критерии маркера. Отклонено:
  постоянные «неопределим: 2» в каждом прогоне гейта.
- Исключение для двух файлов (не маскировать их). Отклонено D8: оставляет приватные имена на HEAD.

**Риск.** Перенесённый пин может скрыть правку за пределами двух допущенных видов на отрезке
между пинами. Смягчение — пословное доказательство, которое само проверяется на приёмке BA.

## Запись — путь публикации (D6, `gramax-o0q.2`)

Публикация в стороннем маркетплейке — issue его владельцу с предложением одной объединённой записи
`gramax` на базе этого плагина; текст подтверждает владелец репозитория до подачи, подача — от его
аккаунта. Контракты репозитория (`marketplace.json`, `plugin.json`, гейты) не меняются; публиковать
оба плагина под одним именем нельзя — пересечение триггеров.

## Допущения

Поведение внешних платформ, не измеренное здесь; ни одно решение на нём не стоит одно:

- Claude Code и `CLAUDE_PLUGIN_ROOT` вне активной сессии плагина — не измерялось; измерен только
  отказ шаблона без переменной (`plugins/gramax/scripts/pre-commit.sh:25-29`, scratch-замер).
- Что Claude Code открывает плагину о резолве его скиллов (G8) — не измерялось; решение опирается на
  выборку RES-002 и на то, что нерезолвящийся скилл не исполняется.
- Как клиент потребителя выбирает версию из маркетплейса (G9) — формулировка RES-002, уверенность
  средняя; повторно не измерялось.
- Сохранение формы настроек движка в живом UI для каталога с `code` длиннее 4 символов — не
  исполнено: вывод о нечувствительности формы к значению получен чтением кода на пине.
- Поддержка `type: select` движком — не измерялось; снятие опирается на собственную оценку плагина
  («экспериментальный»).
- Потребители копии `gitsd` неизвестны (D7).

## Consequences

- **Положительные:** каждое решение владельца имеет именованный узел; устаревшие следы разведки
  (G8, G9, три возможности, `Proposed`) закрыты решением с условием возврата, а не молчанием.
- **Совместимость:** ADR-0006 — релиз остаётся Minor, навыки не добавляются и не удаляются;
  ADR-0012 — строгости проверок не меняются; ADR-0014 — третий remote в том же read-only рисунке;
  ADR-0016 и ADR-0017 — поправлены записью, тела не тронуты; ADR-0020, ADR-0021 — без изменений;
  ADR-0026, ADR-0027 — контракты валидаторов и состав гейта не меняются.
- **Trade-offs:** `drawio` и `review-agent` остаются без подтверждения практикой; хук потребителя
  работает только при заданном `CLAUDE_PLUGIN_ROOT`; страж `ac-003` после переноса короче на один
  отрезок истории.
- **NFR-мэппинг** (требование BA волны-4, вне индекса на момент письма): NFR-089 — Решения 3 и 4 не
  трогают код и гейт, поправки — записи; NFR-090 — в разделах о доставке и приватности нет
  внутренних имён; NFR-091 — девять карточек имеют ровно один узел — этот ADR.

## Alternatives Considered

- Удалить `drawio` и `review-agent` как неиспользуемые — отклонено: Major по ADR-0006, 27 файлов
  стабов, локальный характер факта (Решение 1).
- Закрыть G11 третьим вызовом в шаблоне `scripts/pre-commit.sh` — отклонено: D9 назначил рецепт
  документарным; правка шаблона меняет поведение будущих копий молча (Решение 3).
- Дом рецепта — README плагина — отклонён в пользу навыка: навык уже несёт проверку файла; README
  получил строку-указатель (Решение 3).
- Ввести `Proposed` в словарь — отклонено: синоним вне надзора прибора дрейфа (Решение 5).
- Укоротить `code` — отклонено: нулевой выигрыш и правка идентичности корня (поправка к ADR-0017,
  Решение 5).
- Пин стража `ac-003` на коммите релиза волны-4 — отклонено: коммит не может нести хеш коммита с
  самим собой, а пин после релиза краснил бы `--full` всей волны.
- Поправить старые ADR на месте — отклонено: стирает след пересмотра (BR-001 требования ретракции).
