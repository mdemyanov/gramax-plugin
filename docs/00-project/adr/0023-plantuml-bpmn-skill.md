# ADR-0023: Навык plantuml — PlantUML/BPMN-авторство как новый публичный скилл: плейсмент, релизная поверхность, граница рендера

**Status:** Accepted
**Date:** 2026-11-18
**Plugin:** gramax / marketplace

## Context

[RES-007](../../10-domain/research/2026-11-18-enterprise-server-skill-gap.md) фиксирует пробел:
страница `article/editor/diagrams` документирует PlantUML, Salt («Макеты интерфейса») и BPMN как
полноправные типы диаграмм, но из пяти навыков плагина 4.6.0 покрыт только mermaid (file-based,
ADR-0010) и drawio (заглушка-делегатор, ADR-0008/0009). Требование
[Авторство PlantUML/BPMN-диаграмм](../../30-requirements/2026-11-18-plantuml-bpmn-requirement.md)
(FR-141…FR-148) оставляет плейсмент открытым вопросом Q-1: новый навык / расширение `gramax:mermaid`
/ справочник writer; Q-2…Q-5 — inline-политика, semver, атрибуты тегов, Salt.

Ground truth движка на пине `48592b36` (blobless-клон; метод — [RES-008](../../10-domain/research/2026-11-18-writer-docs-divergence-audit.md),
аудит параллельного потока): тег `plant-uml` зарегистрирован, атрибуты `path, title, width, height,
float, scale` (общая схема с mermaid, `getters/markdocModel.ts`); рендер PlantUML — только серверный
(`POST {DIAGRAM_RENDERER_SERVICE_URL}/convert/plantuml`); **тега `bpmn` в движке на пине нет** —
0 совпадений по дереву, отсутствует в реестре тегов и enum `DiagramType`, при том что docs его
документируют (расхождение класса `<gallery>` из RES-008 §5: docs опережают пин).

Требование явно разводит эту фичу с прецедентом ADR-0008: удалённый drawio-pipeline требовал
локальной конвертации и внешних бинарников; `.puml`/`.bpmn` — финальные текстовые артефакты,
рендерит движок, инвариант BR-008 запрещает любые скрипты и конвертации. Смена набора публичных
скиллов и правка `marketplace.json` — красная линия AGENTS.md (только через ADR); прецеденты —
ADR-0008/0009 (удаление), ADR-0022 (добавление export).

## Decision

### Решение 1 — Q-1: отдельный публичный навык `plugins/gramax/skills/plantuml/`, BPMN внутри него

PlantUML- (включая Salt) и BPMN-авторство — один новый навык `gramax:plantuml`, не расширение
`gramax:mermaid` и не справочник writer. Отдельного `gramax:bpmn` не создаётся: один JTBD-класс
(текстовые диаграммные исходники + тег-ссылка), пересекающиеся триггеры, малый форматный объём
BPMN — второй навык удваивал бы публичную поверхность без выигрыша маршрутизации; bpmn-ключи
входят в description plantuml. Обоснование против альтернатив: (a) расширение mermaid ломало бы
его узкий контракт «Только для Mermaid DSL» (FR-146, BR-011, routing-требование 2026-05-11) и
раздувало SKILL.md против NFR-062; (b) справочник writer не имеет триггера — «нарисуй plantuml»
не активирует writer, обнаружимость теряется. Дефолт неявного запроса («нарисуй диаграмму») —
**mermaid, без изменений**: владелец generic-триггеров и fallback-диалога остаётся `gramax:mermaid`
(дополняет ADR-0009 Решение 1, не supersede — диалог расширяется до четырёх опций: mermaid /
plantuml / bpmn / drawio). Границы с `gramax:mermaid` и `gramax:drawio` — взаимные анти-триггеры в
description; точные тексты — в design-документе.

### Решение 2 — Q-3: additive minor, синхронный bump, номер по арбитражу PM

Новый скилл — additive minor по ADR-0006 (ничего не удаляется; правки существующих навыков —
только триггерные формулировки, что BR-011 допускает). `plugins/gramax/.claude-plugin/plugin.json`
(`version`) и `.claude-plugin/marketplace.json` (`metadata.version`, описание entry) — синхронно,
одним коммитом; настоящий ADR — разрешение на правку публичного файла. Исполнитель — Tech-writer в
release-flow. Номер не резервируется: ADR-0022 заявил 4.7.0 для export с оговоркой о параллельных
волнах 2026-11-18 — общий минор при одном релизе или развод по порядку мержа (прецедент ADR-0018),
арбитр PM.

### Решение 3 — Q-4/Q-5: контракт тегов по движку; `<bpmn>` и Salt — verify-before-include; рендер — только движок

`<plant-uml>`: атрибуты `path, title, width, height, float, scale` — по схеме движка на пине;
канонический вывод навыка — минимальный `<plant-uml path="…"/>`, дефолтные размеры не изобретаются
(для mermaid дефолт шёл из `blocks.md`, для plant-uml writer-основания нет). `<bpmn>`: только `path`
по docs; в движке на пине тег отсутствует — навык авторит по документированной форме, публичные
обещания формулируются с оговоркой «рендер на проверенном окне движка не подтверждён», до релиза —
runtime-probe в живом окружении; при неудаче — эскалация PM (оговорка vs дескоп FR-143), локальный
рендер/конвертация не строится ни в каком исходе (BR-008/BR-009). Salt остаётся в scope авторства
тем же контуром (`@startsalt` в `.puml`, штатный тег); весь PlantUML-рендер серверный и требует
рендер-сервис движка (`DIAGRAM_RENDERER_SERVICE_URL`; без него — ошибка движка) — оговорка
окружения входит в навык; поддержка Salt конкретным рендер-сервисом из этого репозитория не
измерима, закрывается тем же probe.

### Решение 4 — Q-2: file-based канон с рождения

Навык канонизирует file-based форму (`.puml`/`.bpmn`-файл + тег-ссылка), единый стандарт с
mermaid/ADR-0010: одна конвенция именования (FR-147), защита от перезаписи (FR-148), идемпотентность.
Inline-блоки ```plant-uml, документированные docs как текущая форма, при чтении `target_page`
распознаются: уведомление + предложение точечной миграции по явному подтверждению (опции блока
`{title, scale, float}` переносятся в одноимённые атрибуты тега — соответствие схеме движка);
молчаливая перезапись запрещена (BR-010). Batch-миграция — вне scope, отдельная задача по
прецеденту mermaid-adopting (FR-054—FR-060). Применяет прецедент ADR-0010, не меняет его.

## Consequences

**Положительные:** шесть → семь компетенций с чистыми триггерными границами; пробел RES-007
«Статья → Диаграммы» закрывается текстовым навыком без скриптов (урок ADR-0008 соответствует, а
не нарушается); additive minor; fallback-диалог покрывает все четыре движка docs-страницы.

**Отрицательные / trade-offs:** правится публичный `marketplace.json` (рассинхрон ловит
manifest-coherence); навык несёт оговорку про окружение рендера и verify-статус `<bpmn>` — обещание
слабее, чем у mermaid; седьмой навык удлиняет описание entry.

**Mitigations:** verify-before-include + релизный probe (Решение 3); точные пин-тексты триггеров в
design-документе совместимы с AC-059 (в `mermaid/SKILL.md` запрещены литералы `@startuml`/`.bpmn`);
регистрация статей (требование, design, этот ADR) в `_index.md` — центрально выполняет PM.

## Alternatives Considered

- **Расширить `gramax:mermaid` до «текстовых диаграмм»** (Q-1b) — отклонено: ломает узкий
  триггерный контракт mermaid (FR-146/BR-011), возвращает проблему ложных триггеров routing-требования,
  растит SKILL.md против NFR-062.
- **Только справочник в writer** (Q-1c) — отклонено: нет триггера на «нарисуй plantuml», прямые
  диаграммные запросы не обнаруживаются.
- **Отдельный навык `gramax:bpmn`** — отклонено: удваивает поверхность без выигрыша маршрутизации
  (один JTBD-класс, пересекающиеся триггеры).
- **Inline как легитимная форма авторства** (Q-2ii) — отклонено: вторая форма хранения параллельно
  file-based нарушала бы единая-конвенция-инвариант FR-147 и размывала бы прецедент ADR-0010.
- **Дескоп BPMN до появления тега в движке** — отклонён: авторство корректно относительно docs,
  рендер — ответственность движка (BR-009); verify-before-include честнее молчаливого исключения.
- **Batch-миграция inline-блоков сейчас** — отклонена: вне scope требования; прецедент — отдельная
  задача (mermaid-adoption).
