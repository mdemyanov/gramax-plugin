## Решение 1 — чтение в парсере: один путь чтения, одна маска (`gramax-4jf.14`)

`lib/md_link_parser.py` читает страницы через `lib/read_page.py` и отдаёт ошибки чтения наружу: новый
`scan_md_resources(root, diagram_tags=…, *, exclude=None) -> (list[MdResource], list[MdPageError])`;
`parse_md_resources` сохраняет сигнатуру и тип результата. Собственная копия `_mask_code` в парсере
(`:43-60`) удаляется — маска одна, `lib/md_code_mask.py`. В `validate_structure.py` удаляются
`_parse_resources` (`:331-371`), `_collect_links` (`:625-663`) и `_resolve_link_target`
(`:607-622`): ресурсные проверки получают ресурсы от тонкого адаптера — предикат исключений и
превращение `MdPageError` в `E036`, дубли гасит `_dedupe_utf8_findings`. **Почему:** публичный парсер
на файле с битым UTF-8 падает исключением (`parse_md_resources(<каталог>)` → `UnicodeDecodeError`;
контроль без битого файла → 2 ресурса), а валидатор обходит его собственной обёрткой — второй
читатель и вторая маска (`grep -c 'def _mask_code'` по трём файлам → 1, 1, 1). После правки файл с
битым UTF-8 даёт один `MdPageError`, ни одного ресурса, обход продолжается; ac-133 остаётся зелёным.

## Решение 2 — маска многострочного code-span: вторая фаза (`gramax-o0q.22`, пункт б)

`_mask_code` (`lib/md_code_mask.py:34-56`) становится двухфазной. Фаза 1 — нынешнее выражение, без
изменений; фаза 2 идёт по его остатку, замена сохраняет переводы строк; оба выражения дословно — в
блоке целевых значений ниже. Фаза 2 спаривает лишь бэктики, оставшиеся одинокими на своей строке, в
пределах блока — пустая строка обрывает; числовых пределов нет. **Почему:** code-span, разорванный
переносом строки, сегодня не маскируется и даёт ложный ERROR (фикстура с `<note>…</note>` в таком
спане → `FAIL`, `ERROR L6`, rc=1). Однопроходный вариант отклонён замером: на `docs/` базы он меняет
спаривание
и добавляет 8 находок, включая 2 ERROR рендера. Двухфазный меняет 0 находок на обоих корпусах
(`docs/`: 0/0 и 0 ERROR/130 WARN до и после; корпус сравнения: 96 ERROR/539 WARNING и 5 ERROR/151
WARN до и после). Примитив общий — фаза действует и в валидаторе, и в парсере комментариев.

## Решение 3 — детектор диаграммного тега без самозакрытия (`gramax-o0q.21`)

`_diagram_tag_re` (`lib/md_link_parser.py:24-30`). Было `<({names})\s[^>]*path="([^"]+)"[^>]*/>`,
стало `<({names})(?:\s[^>]*?)?\s+path="([^"]+)"[^>]*>`. Парная форма
(`<plant-uml path="…">…</plant-uml>`) и форма без закрывающего `>` дают ту же находку W031, что
самозакрытая; атрибут, чьё имя оканчивается на `path`, целью не считается. **Факт движка:** парная
форма — законная грамматика (`tag.pegjs:19-36`), атрибуты читаются из открывающего тега, ресурс
`path` регистрируется (`markdocModel.ts:27`) и проверка на ошибки его судит (`Healthcheck.ts:238-252`):
слепое пятно было расхождением с движком, не паритетом. **Замер:** на фикстуре с битой целью — W031 = 1
у самозакрытой формы, 0 у парной, 0 у незакрытой; в корпусах парной формы с `path` нет (68 тегов, все
самозакрытые), старое и новое выражение дают 68 и 68 одинаковых совпадений. Уровень warning
(ADR-0024 Решение 2).

## Решение 4 — резолвер ссылки: файл, каталог, `_index.md` (`gramax-o0q.25`)

Единственный резолвер — в `lib/link_resolver.py`:
`resolve_link_target(source_dir, target, *, index_optional=False) -> Path | None`. Литерал `is_file()`
→ `target + ".md"` `is_file()` → `литерал/_index.md` `is_file()` → при `index_optional` литерал
`is_dir()` → `None`. Каталог без `_index.md` без флага даёт ERROR с формулировкой
`битая ссылка (broken link) на "{raw}" — каталог без _index.md (раздела в дереве нет): {resolved}`;
с флагом `optionalCategoryIndex: true` — резолв без находки; при одноимённых файле и каталоге
побеждает файл; `#якорь` ссылки на раздел проверяется по `_index.md`. `resolve_no_ext` (`:80-106`)
удаляется. **Факты движка:** папка без `_index.md` без флага не раздел (`FileStructure.ts:528-531`);
папка — не файл (`linkCreator.ts:156-162`); проверка на ошибки судит цель без расширения по
`_index.md` (`Healthcheck.ts:192-201`, `app/config/const.ts:32-33`). **Замер:** сегодня ссылка на
каталог без индекса даёт 0 находок, а при одноимённых `section.md` и `section/` статья остаётся
«сиротой»; целевой резолвер меняет 0 вердиктов на 1478 ссылках обоих корпусов. Структурное правило
подпапки не меняется — две находки судят разные объекты.

## Решение 5 — утечка абсолютных путей: правило E037 (`gramax-o0q.27`)

Ручная проверка (диспозиция 2026-08-11, `:103` по `f551d87`: «остаётся ручной проверкой») заменена
правилом `validate_structure.py`: код `E037`, уровень `error`, по сырой строке статьи без маски кода,
одна находка на строку; в сообщение попадают номер строки и форма, но не сам путь. **Основание —
замер:** ручная форма пропустила две реальные строки собственного корпуса (`docs/lessons-learned.md:440`
и `docs/30-requirements/2026-11-17-docs-layout-inversion.md:138` по `f551d87`, обе внутри code-span) и
10 строк в 3 файлах корпуса сравнения; маскированные формы находкой не становятся (17 синтетических
случаев — все как ожидается). Уровень — детерминированный признак класса приватности, прецедент
ADR-0012 Решение 2 (`:73` по `f551d87`). Правка кода входит после чистки D8.

## Решение 6 — правило H1: факт движка и именованный замер, код не меняется (`gramax-o0q.29`)

**Факт движка (чтение):** `title` берётся из frontmatter; первый H1 извлекается в `title`, только
если у статьи нет `title` (`parseContent.ts:49-54`, `extractHeader.ts:4-31`); иначе H1 тела рендерится
элементом `h2` (`ArticleContentHeader.tsx:5`, `getComponents.tsx:31`) — на странице оба заголовка,
без дедупликации. По этому чтению правило (`validate_render.py:202-205`, WARN) — true positive, а шум
есть свойство корпуса: 130 из 131 файла `docs/` базы несут H1
(`python3 -B plugins/gramax/scripts/validate_render.py docs | grep -c 'H1'` → 130; с
`--errors-only` → 0); в корпусе сравнения H1 несут 55 из 766. **Решение координатора:** правило не
меняется по одному чтению исходника. Назван недостающий замер (шаг D12): живой рендер двух страниц —
`h1-equals-title.md` и `h1-absent.md` — со счётом `h1` и `h2`, несущих текст `title`. Если на странице
с H1 такой заголовок один лишний — правило остаётся, а конвенция корпуса «H1 == title» становится
решением владельца вне волны; если их поровну — правило калибруется с изъятием формы «H1 равен title»
отдельным изменением после записи замера.

## Решение 7 — контракты gen_comment_id.py и slugify.py (`gramax-o0q.33`)

Контракты закреплены дословно в дизайне §3.7: сигнатуры, инварианты (ID из 5 знаков
`[A-Za-z0-9]`, уникальный против ключей файла; slug — транслит кириллицы, нижний регистр, дефисы;
пустой ввод slugify — rc=2) и крайние случаи. Одна правка: две границы `--check` в `gen_comment_id.py`,
дающие сегодня traceback с rc=1 (каталог — `IsADirectoryError`, файл с битым UTF-8 —
`UnicodeDecodeError`), переводятся чтением через `read_page` в именованный отказ в stderr с rc=2:
`not a file: {yaml_path}` и `{yaml_path}: файл не является валидным UTF-8 (байт 0xNN на позиции P из S)`.
**Замер:** 2000 запусков генератора — 2000 различных ID, все пятизначные.

## Решение 8 — миграторы: обход дерева не объединять (`gramax-o0q.35`)

Исход «не объединять»: семь обходов `rglob("*.md")` (карточка называла пять) остаются с разными
фильтрами; поимённое основание каждого — дизайн §3.8 (владелец правил границ у структурного
валидатора, самодостаточный stdlib-инструмент `migrate_mermaid.py`, замороженный диагност
`migrate_nav_codespans.py` с побайтовыми копиями по прецеденту RES-005). Дрейфа, давшего ложную
находку, нет. Условие возврата — восьмая копия либо такой дрейф. Ожидаемое поведение двух непокрытых
случаев записано и измерено: N legacy-блоков в файле мигрируются все (3 блока → 3 файла, DSL
побайтово); перечисление без маркера остаётся SUBJECT (ADR-0016 Решение 3, точечный проход FR-235).

## Решение 9 — временный протокол ADR-0016 Решение 2 снят (пункт 9; `gramax-o0q.40`)

Протокол явного `.md` снят: его условие конца исполнено. **Замер:** доставленный nauta 2.27.0 делает
инференс — `PYTHONDONTWRITEBYTECODE=1 python3 -B scripts/validate-content.py <scratch>` → C9 печатает
только `missing`, `[b](b)` проходит; инференс пришёл коммитом `38fe3e6` (2026-08-31),
`scripts/validate-content.py:512-544`. Контракт после снятия — FR-080 как написан: канон для новых и
правимых ссылок — без расширения; существующие ссылки с `.md` валидны и миграции не требуют
(`git grep -c -E '\]\([^)]+\.md\)' -- docs | wc -l` → 108 файлов; 548 из 567 ссылок на снимке).
Массовой перелинковки в волне нет.

## Решение 10 — реестр тегов: двенадцать имён движка входят (пункт 10; `gramax-o0q.42`)

Правило членства (решение координатора): тег входит в `gramax-tags.json`, когда на пине он есть в
реестре движка (`getTagElementRenderModels.ts`), доступен автору статейной разметки по записи реестра
и схеме и не является legacy-формой, которую редактор переписывает при сохранении. Документация
вендора условием не является: W034 — утверждение о рендере и следует реестру движка. Входят `alert`,
`block-field`, `block-property` (в `pairedTags`) и `db-diagram`, `db-table`, `include`, `term`,
`module`, `issue`, `when`, `who`, `see` (в `selfClosingTags`); `db-diagram` — также в `diagramTags`.
Не входят `br` и `snippet-link` (переписываются при сохранении: `transformer.ts:206-209`,
`brFormatter.ts:6`), `formula` (внутреннее представление `$…$`) и девять внутренних ключей
компонента. **Замер:** вне известного набора плагина лежат 24 ключа реестра; на фикстуре со всеми
ними W034 выдаётся на 25 именах (с фиктивным тегом), по правилу ложный он у двенадцати. Последствия:
W034 снят на двенадцати именах; `check_tags` балансирует три парных тега (несбалансированная пара —
ERROR `unpaired <тег>`); `db-diagram` с `path` даёт W031; `schemaVersion` остаётся `3`.

## Решение 11 — `--strict` валидатора комментариев эскалирует каждое предупреждение (пункт 11)

`validate_comments.py::main()` выходит с кодом 1, когда есть ошибка либо под `--strict` есть
предупреждение; уровень `info` не эскалируется. **Замер:** справка обещает «Warnings → errors.»
(`:167`), а `--strict` на фикстуре с плохим `dateTime` даёт rc=0 — эскалировались лишь дубликат
ответа и отсутствие ключа `answers`. Ни одна нога стабов волны-3 не закрепляет нынешнее поведение:
`ac-139-reply-user-id.sh:39` судит запуск без `--strict`, единственная нога с `--strict` —
`ac-129-multiposition-id.sh:43-48` на фикстуре без предупреждений. Код выхода на обоих корпусах не
меняется.

## Поправка к ADR-0019 (часть Решение 5)

Примитив остаётся общим; уточняется его предмет: кроме fenced- и однострочного inline-кода маскируется
inline-код, разорванный переносом строки внутри абзаца. Слова Решения 5 «тело функции не меняется»
описывали экстракцию 4.4.0 и более не описывают примитив. Действует Решение 2.

## Поправка к ADR-0024 (часть Решение 3 и Consequences)

Матчер Решения 3 более не требует `/>`. Следствие Consequences «слепая зона "тег с `path` без `/>`"
унаследована от drawio и документирована, не устранена» (`:127` по `f551d87`) снято. Формулировка про
`<br/>` в том же абзаце стоит на другом основании: `<br>` — legacy-форма, которую редактор
переписывает (`brFormatter.ts:6`; RES-007, `:324` по `f551d87`), а не тег, которого движок не читает.
Действует Решение 3.

## Поправка к ADR-0024 (часть Решение 4)

Граница паритета «W034 следует контракту плагина, не полному реестру движка» уточняется: реестр
движка на пине — источник пополнения контракта. Тег из реестра, доступный автору и не переписываемый
редактором, входит в `gramax-tags.json`; «документирован writer» остаётся достаточным, но не
необходимым условием. BR-028 без изменений: тег, известный контракту, не репортится. Действует
Решение 10.

## Поправка к ADR-0026 (часть Решение 6)

Круг читателей расширяется: ресурсный парсер читает через `read_page` и отдаёт ошибки чтения; одну
находку `E036` на файл по-прежнему держит дедуп валидатора. Решение 8 того же ADR получает вторую
фазу маски. Действуют Решения 1 и 2.

## Поправка по ревью без автора — раунд r1 (2026-11-25)

Независимое ревью диффа плагина (субъект — карточка эпика, запись `review-r1`) вернуло одну блокирующую и
шесть консультативных находок. Здесь — поправки к решениям этого ADR, меняющие целевые значения или их
прочтение; остальное закрыто стабами и подписями кода.

- **Решение 1 (область «одной маски»).** Одна маска — на двух контурах: парсер ресурсов и валидаторы.
  Копия `_mask_code` в `migrate_nav_codespans.py` — записанное исключение (Решение 2; ADR-0029 Решение 3 —
  замороженный ручной диагност), а не вторая маска контура. Подпись копии в самом файле устарела: источником
  назывался `validate_structure.py::_mask_code` — определения с таким именем там больше нет, а единственная
  маска `lib/md_code_mask.py` получила вторую фазу, так что «побайтовая копия» перестала быть верной.
  Копия подписана как редакция однофазного алгоритма по прецеденту RES-005; стаб `ac-165` закрепляет ровно
  два определения в `plugins/gramax/scripts` и отсутствие устаревшего указателя.
- **Решение 2 (граница блока второй фазы).** Граница — пустая строка — решение этого ADR, а не правило
  CommonMark: смежные блоки без пустой строки между ними (пункты плотного списка, строки таблицы, абзац и
  следующий за ним заголовок) вторая фаза может сцепить, и одинокий бэктик соседнего блока погасит находку
  построчного правила. На корпусе репозитория таких областей 3 из 136, ни одна не скрывает тег-киллер,
  ссылку или плейсхолдер. Формулировка комментария кода «как в CommonMark» снята; уточнение границы до
  блоков CommonMark — именованный хвост (`gramax-o0q.48`).
- **Решение 5 (правило E037).** Ревью показало две слепые зоны регулярного выражения: класс сегмента имени
  пропускал домашний каталог с не-латинским именем (`/Users/<имя кириллицей>/…` и то же с буквой диска), а
  взгляд назад отсекал форму WSL `/mnt/<буква>/Users/<имя>/…`; буква диска в сообщении была пришита (`C:` для
  любого диска). Целевое значение ниже заменено: класс сегмента — `\w` (любые буквы и цифры Юникода);
  добавлена альтернатива формы WSL; буква диска и буква монтирования в сообщении — фактические. Имя и путь в
  сообщение по-прежнему не попадают. Значения формы `{form}`: `/Users/<имя>/…`, `/home/<имя>/…`,
  `X:\Users\<имя>\…` (X — фактическая буква диска), `/mnt/<буква>/Users/<имя>/…` (фактическая буква).
  **Послезамер 2026-11-25:** `docs/` — 0 E037 до и после; корпус сравнения — 10 E037 до и после (все
  формы `/Users/<имя>/…`; не-латинских имён и формы WSL в корпусе нет), 106 ERROR и 539 WARNING до и
  после — иных смен вердиктов нет. Стаб `ac-181` закрепляет восемь грязных строк и чистые двойники.
  Смешанные разделители дисковой формы (`X:\Users/<имя>/…`) не ловятся и вынесены хвостом
  (`gramax-o0q.49`). Уточнение в тот же день: послезамер взят до того, как запись тест-дизайна
  процитировала полные фиктивные пути фикстур; на полном прогоне расширенное правило поймало эту
  строку собственной датированной записи (1 E037 на `docs/` — ноги догфудинга покраснели), пути в
  записи замаскированы, `docs/` — 0 E037. Правило тем самым показано и на собственном корпусе.

## Строки Contract: для CHANGELOG

Каждая строка блока — один абзац `plugins/gramax/CHANGELOG.md` под заголовком 4.11.0, дословно:
```text
Contract: `md_link_parser.py` — диаграммный тег с `path`, записанный парным (`<plant-uml path="…">…</plant-uml>`) или без закрывающего `>`, даёт ту же находку W031, что самозакрытая форма `/>`: детектор `diagramTags` больше не требует самозакрывающего слэша (ADR-0028 Решение 3; движок читает атрибуты из открывающего тега и проверяет цель — `markdocModel.ts:27`, `Healthcheck.ts:238-252` на пине 48592b36). Contract: `lib/md_link_parser.py` — новый `scan_md_resources(root, diagram_tags=…, *, exclude=None)` читает страницы через `lib/read_page.py` и возвращает `(resources, errors)`: файл с битым UTF-8 даёт `MdPageError`, а не исключение. `parse_md_resources` сохраняет сигнатуру и тип результата. Собственная копия маски кода в парсере удалена — маска одна, `lib/md_code_mask.py` (ADR-0028 Решение 1).
Contract: `lib/md_code_mask.py` — code-span, разорванный переносом строки внутри одного абзаца, маскируется наравне с однострочным (вторая фаза маски, ADR-0028 Решение 2): иллюстрация синтаксиса в таком спане не даёт ложных ERROR и WARN в `validate_structure.py`, `validate_render.py`, `validate_comments.py`, `parse_comments.py`. Contract: `validate_structure.py` — новое правило E037 (error): абсолютный локальный путь контрибьютора (`/Users/<имя>/…`, `/home/<имя>/…`, `X:\Users\<имя>\…`, WSL `/mnt/<буква>/Users/<имя>/…`; имя — любые буквы и цифры, включая не-латиницу) в тексте статьи, включая код; сообщение называет строку и форму с фактической буквой диска, но не сам путь (ADR-0028 Решение 5 с поправкой от 2026-11-25; FR-072, FR-073).
Contract: `gramax-tags.json` — в реестр входят двенадцать имён тегов движка (ADR-0028 Решение 10): `pairedTags` + `alert`, `block-field`, `block-property`; `selfClosingTags` + `db-diagram`, `db-table`, `include`, `term`, `module`, `issue`, `when`, `who`, `see`; `diagramTags` + `db-diagram`. ## Consequences
```

- **Положительные:** закрыты два слепых пятна (тег без самозакрытия; каталог без `_index.md`);
  сняты ложные сигналы (W034 на двенадцати именах движка, ERROR внутри многострочного спана);
  чтение, маска и резолв — по одному; утечка личного пути ловится правилом, а не ревью.
- **Совместимость:** коды выхода сохраняют форму 0/1/2. Смена вердиктов на двух корпусах — 0 (1478
  ссылок; дизайн §2). Новые классы ERROR: ссылка на каталог без `_index.md` без флага,
  несбалансированные `alert`, `block-field`, `block-property`, `E037`. Решение 5 включается после
  чистки D8.
- **Trade-offs:** `path` тегов `db-table` и `include` и схема YAML `db-diagram` не проверяются
  (условие возврата названо); `snippet` остаётся в реестре по FR-172 как исключение из правила
  членства.
- **Остановленная ветвь Решения 9:** текущий официальный текст вендора предписывает ссылки с `.md`
  (`gramax-article-syntax.md:91`, `:332`), тогда как FR-080 опирается на то, что редактор срезает
  `.md` при пересохранении. Что редактор пина пишет при сохранении, не измерено; замер отнесён к шагу
  D12. До него канон новых ссылок — FR-080.
- **NFR-мэппинг:** BR-004 — Решения 1 и 5; BR-025…BR-027 — целевые значения дословно и опора
  каждого уровня на факт или замер; NFR-001 — Решения 2, 4, 11 (0 смен вердикта); NFR-084 — таблица
  переводов в дизайне §5; FR-196 и BR-021…BR-024 — Решение 6 (вердикт не меняется, замер назван);
  FR-072 и FR-073 — Решение 5; BR-029 и BR-030 — каждый исход назван с замером.
- **Superseded в части (тела старых ADR не редактируются):** ADR-0016 — Решения 1 и 2; ADR-0019 —
  Решение 5; ADR-0024 — Решение 3, Решение 4 и следствие Consequences о слепой зоне; ADR-0026 —
  Решение 6 (круг читателей).

## Alternatives Considered

- Оставить слепое пятно тега как «наследованное» — отклонено: факт движка показывает расхождение.
- Однопроходная маска с многострочным спаном — отклонена замером (+8 находок на `docs/`).
- Предел числа строк для спана — отклонён: не различает перенос команды и пару одиночных бэктиков.
- Ратифицировать ручную проверку путей — отклонено замером (2 и 10 пропущенных строк).
- `E037` уровнем warning — отклонено: детерминированный признак класса приватности (ADR-0012).
- Подавить или понизить правило H1 либо менять его по чтению исходника — отклонено: нужно измерение.
- Объединить обходы дерева — отклонено: у каждой из семи копий названо основание, цена правки
  живых файлов, среди них двух миграторов, выше выигрыша.
- Сохранить временный протокол ссылок — отклонено: условие конца исполнено 2026-08-31.
- Массовая перелинковка на форму FR-080 — вне волны: FR-080 её не требует.
- Держать теги движка вне реестра за неописанностью — отклонено: W034 — утверждение о рендере.
- Эскалировать предупреждения в местах их выдачи — отклонено: два механизма у одного флага.
- Закрепить traceback `--check` как поведение — отклонено: именованный отказ вместо аварии.
