# Дерево решений генезиса: хвосты 4.7.0 → 4.8.0

**Опоры:** `docs/30-requirements/2026-11-18-writer-sync-470-requirement.md`,
`plugins/gramax/README.md`

## Цель

Разобрать хвосты волны 4.7.0: отложенные открытые вопросы writer-sync как следующий цикл
writer 4.8.0; runtime-проба `<bpmn>`/Salt в живом окружении до публичных обещаний рендера;
косметика README (статусная строка suite plantuml-bpmn, список навыков до заявленных семи).

## Дерево решений

- **D1** Один эпик или отдельные задачи? → **решение:** один эпик «хвосты 4.7.0 → 4.8.0» с
  тремя потоками: П1 — writer-хвост 4.8.0 полным контуром (BA → SA → QA-author → dev →
  QA-runner → BA-acceptance) по всем шести открытым вопросам
  [writer-sync 4.7.0](../../30-requirements/2026-11-18-writer-sync-470-requirement.md) плюс
  исключениям RES-007 §3; П2 — runtime-проба `<bpmn>`/Salt отложенным листом с триггером
  «первое GES-окно», исполнители — агент и владелец; П3 — README-косметика немедленным
  one-shot. **почему:** три предмета одной волны-источника с единым релизным носителем;
  проба внешне заблокирована (GES-окно) и не должна тормозить контентный поток.
- **D2** Что делать с публичным обещанием рендера BPMN/Salt до вердикта пробы? →
  **решение:** честная статусная пометка — «рендер BPMN/Salt заявлен движком;
  runtime-проверка в живом окружении ожидается»; после пробы — подтвердить или снять
  обещание отдельным коммитом. **почему:** публичное обещание без runtime-проверки —
  репутационный риск; пометка сохраняет честность, не блокируя релиз и не выкидывая
  функциональность.
- **D3** Форма статусной строки suite plantuml-bpmn? → **решение:** строка
  «Suite: `tests/gramax/plantuml-bpmn` — 12/12» плюс статус рендера из D2 в
  `plugins/gramax/README.md` § Skill `plantuml`; корневой README дополнить bullets
  `/gramax:plantuml` и `/gramax:export` — список становится 7/7, как заявлял релиз 4.7.0.
  **почему:** строка запрошена владельцем; список 5 из 7 — расхождение релиз-ноты с
  фактом, найденное фантом-проверкой при открытии эпика.
- **D4** Релизный носитель writer-хвоста? → **решение:** релиз 4.8.0 по ритуалу — пара
  версий `plugin.json` + `marketplace.json` и CHANGELOG на main (прецедент 4.7.0); П2 не
  блокирует релиз. **почему:** writer-хвост — контентная поставка навыка (SKILL +
  references); вердикт пробы меняет только статусную строку и уходит отдельным коммитом.
