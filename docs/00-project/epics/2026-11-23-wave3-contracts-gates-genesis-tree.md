# Дерево решений генезиса: волна-3 — калибровка контрактов валидаторов и гейтов, релиз 4.10.0

**Опоры:** `docs/30-requirements/2026-11-23-wave3-validators-contracts-gates-requirement.md`,
`docs/00-project/adr/0026-validator-contracts-engine-pin.md`,
`docs/00-project/adr/0027-full-gate-composition.md`

## Цель

Выпустить 4.10.0 с закрытым эпиком `gramax-4jf` (12 подтверждённых дефектов плагина) и с
исправимыми в репозитории хвостами гейта и гигиены из эпика `gramax-o0q`. Волна идёт поверх
закрытой волны-2 калибровки (ACCEPT 9/9, коммит 563f005; релиз 4.9.0 — 43435c7) и наследует
её решения, кроме одного — политики живой ноги, которая пересматривается здесь (D5).

## Дерево решений

- **D1** Маршрут и класс Stage 0? → **решение:** ONE-SHOT — режим назван владельцем после
  напечатанного UNCLEAR (в запросе нет ни одного литерала класса: 0 совпадений и в полном
  тексте, и в абзаце цели); периметр волны измерен классом «прибор»: perimeter 536 файлов /
  anchors 341 файла, тир full. Расхождения названы: `plugins/` вне таблицы классов;
  `openspec/` в дереве нет; стор задач — beads (`.beads`, `bd`), `bin/store.sh` отсутствует
  (OPS-002). **почему:** постоянная инструкция владельца «режим называет владелец»;
  раунд UQ-1 от 2026-11-23; прецедент — деревья волн 1–2 в том же доме.
- **D2** Цель волны? → **решение:** релиз 4.10.0 — эпик `gramax-4jf` целиком плюс хвосты
  гейта и гигиены; остальные хвосты приоритизированы и записаны, но исполняются по своим
  триггерам. **почему:** запрос владельца «актуализируй локальный беклог и спланируй
  следующую волну» при цели «все хвосты и проблемы приоритизированы, согласованы со мной
  и решены».
- **D3** Состав волны? → **решение:** `gramax-4jf` (12 задач: SA-гейт, проверка, девять
  правок) плюс из `gramax-o0q`: политика живой ноги, сюиты вне гейта, собакаедство
  валидаторов, базис nauta 2.27.0, мёртвый overlay-тулинг, устаревшие корневые тексты и
  README сюит, 3 предупреждения W034 на `docs/`, хвосты записи волны-1, коллизия
  AC-061/AC-062. Вне волны: документарная волна (маркер «Опоры», статусы Draft,
  предупреждения TPL-69), поведение плагина вне `gramax-4jf`, решения владельца, внешние
  зависимости. **почему:** рекомендация PM принята владельцем (вариант «4jf + гейты и
  гигиена»).
- **D4** Приоритеты остальных хвостов? → **решение:** как предложено PM — P1: политика
  живой ноги и путь публикации; P2: сессия замеров, GES-окно, сюиты вне гейта,
  собакаедство, базис, копия на внутреннем канале доставки; P3: 34 пункта; P4: отложенное владельцем и принятые
  ограничения. **почему:** согласовано владельцем в том же раунде.
- **D5** Политика живой ноги `--full`? → **решение:** живой прогон прибора выносится из
  `--full` в именованный отдельный шаг: `--full` зелёный в стационарном состоянии, сессия
  замеров на портале — отдельный шаг релизного ритуала (токен и публикация проб — акты
  владельца). Этим решением поправляется D8 волны-2, где стационарно красная живая нога
  была названа поведением прибора. Офлайн-рычаг при тёплом кэше фиксируется в runbook и
  README сюиты. **почему:** замер 2026-11-23 на 43435c7 — `fixtures=21 match=0
  divergence=21` (пробы убраны с портала), то есть `--full` красный по умолчанию, а
  приёмка эпика требует зелёного `--full`; выбор владельца из трёх вариантов.
- **D6** Режим исполнения и пуш? → **решение:** автономно до push включительно: SA →
  QA-author → Dev → QA-runner → приёмка → версия 4.10.0 → push в origin и internal при
  зелёных гейтах. Санкция на пуш дана владельцем в раунде и действует на эту волну.
  **почему:** выбор владельца «До push включительно».
- **D7** Судьба неисполняемого в репозитории? → **решение:** листы с триггерами — сессия
  замеров (токен и санкция владельца), GES-окно (владелец и агент); решения владельца —
  путь публикации после закрытия `gramax-4jf`, копия на внутреннем канале доставки, приватность в публичном
  репозитории, корневой CHANGELOG; оракул-прибор и модуль доступа к порталу остаются
  отложенными решением от 2026-11-21. **почему:** для них нужны внешние окна или ответ
  владельца; гейт `--full` после D5 они не блокируют.
- **D8** TDD-цепочка для контрактов? → **решение:** SA фиксирует целевые значения
  контрактов в ADR дословно, но JSON и код не правит — правки делает Dev под заглушками
  QA-author, которые рождаются красными; задачи без контрактной неоднозначности (повторный
  ID комментария, блочная XML-форма, UTF-8, `user.id`, устаревшие тексты) получают
  заглушки параллельно с SA. **почему:** красные линии AGENTS.md — нет Dev без SA для
  нетривиальных правок, нет передачи тестов в QA-runner до заглушек QA-author.
