# Паритет офлайн-валидаторов с модулем «Проверка на ошибки» — цели диаграммных тегов, иконки `.icons/`, контракт-паритет W034

**Опоры:** `docs/30-requirements/2026-11-18-validators-error-check-parity-requirement.md`,
`docs/00-project/adr/0024-validators-error-check-parity.md`,
`plugins/gramax/scripts/validate_structure.py`, `plugins/gramax/gramax-tags.json`

## Контекст

Реализация требования [Паритет офлайн-валидаторов плагина с модулем проверки ошибок
приложения](../30-requirements/2026-11-18-validators-error-check-parity-requirement.md)
(FR-151…FR-157, NFR-065…NFR-069, BR-028, BR-012…BR-014, AC-152…AC-163). Решения закреплены в
[ADR-0024](../00-project/adr/0024-validators-error-check-parity.md); этот документ несёт то,
что ADR намеренно не несёт: компоненты, точные правки кода, контракт с QA-author, миграцию.

Дельта доказуема по двум категориям модуля «Проверка на ошибки» (RES-007 §2): диаграммы
(цель проверяется только у `<drawio>` — W031) и иконки (проверки нет вовсе). Попутный дефект
согласованности: W034 «неподдерживаемая разметка» срабатывает на канонические теги собственного
контракта `gramax-tags.json` и слеп к дефисным именам. Предшественники: ADR-0012 (контракт
валидации, JSON как единственный источник), ADR-0019 (демаркация W034 по контракту
`gramax-render-rules.json`), ADR-0020 (рекурсивное обнаружение catalog root, границы ownership).

**Пробы SA 2026-11-18** (фикстура в `/tmp`, вызов `uv run plugins/gramax/scripts/validate_structure.py`,
HEAD на 2026-11-18) — подтверждают факты 4, 7, 8 требования и уточняют факт 8:

1. Фикстура с битыми целями всех четырёх диаграммных тегов + `<icon>` + `<view>` +
   `<fancy-widget-x/>` дала: ровно одну W031 (drawio), четыре ложные W034
   (`<view>`, `<mermaid>`, `<bpmn>`, `<icon>`), ноль находок по `<plant-uml>` и
   `<fancy-widget-x/>`. Exit 0.
2. **Уточнение факта 8 (существенно для AC-159):** слепая зона текущего матчера
   `_UNSUPPORTED_HTML_RE` (`validate_structure.py:744`) двойная. Кроме дефиса в имени
   (`[a-z][a-z0-9]*` не матчит `plant-uml`), невидим и голый self-closing-форма WITHOUT
   атрибутов: `` <br/> `` — после имени идёт `/`, ветка `(?:\s[^>]*)?` требует whitespace,
   `>` не наступает. Форма `<fancy-widget-x/>` из AC-159 невидима по ОБЕИМ причинам —
   одного добавления дефиса в charset недостаточно, нужен также опциональный `/` перед `>`
   (см. «FR-156/FR-157»).
3. Симуляция постфиксного W034 на живом `docs/` (тот же `_mask_code`, known-набор из двух
   контрактов + `legacy`, новый паттерн): **ноль новых находок**; четыре существующих
   предупреждения (`<home>` ×2, `<raw>`, `<file>` — проза без маскирования) остаются как есть.
   Догфудинг-эффект AC-162 положительный, побочных покраснений нет.

## План изменений по FR

Все пути — относительно корня репозитория. Правки кода исполняет Dev (TDD по stub'ам
QA-author); SA не правит код. Номера строк — POINTER на HEAD 2026-11-18.

### FR-151/FR-152 — цели диаграммных тегов (`mermaid`, `plant-uml`, `bpmn`)

**`plugins/gramax/scripts/lib/md_link_parser.py`:**

- `_DRAWIO_RE` (`:16`) заменяется обобщённым матчером, собираемым из списка тегов:

  ```python
  def _diagram_tag_re(diagram_tags: tuple[str, ...]) -> re.Pattern[str]:
      names = "|".join(re.escape(t) for t in diagram_tags)
      return re.compile(rf"<({names})\s[^>]*path=\"([^\"]+)\"[^>]*/>")
  ```

- `parse_md_resources(root, diagram_tags=("drawio",))` — новый keyword-параметр; блок
  «Drawio tags» (`:84-88`) заменяется проходом по матчеру: цель резолвится относительно
  `md.parent`, `in_scope` — против `root.resolve()` (дословно текущая семантика ветки drawio),
  `MdResource.target_type` = **имя тега** (`"drawio" | "mermaid" | "plant-uml" | "bpmn"`),
  докстринг `:26` обновляется. Дефолтный кортеж `("drawio",)` — деградационный fallback для
  standalone-вызова без контракта, по прецеденту seed `{"drawio"}` у `known_tags`
  (`validate_structure.py:645`): повреждённый контракт уже дал error через
  `load_json_contract`, молчаливый ноль диаграммных проверок не добавляется.

**`plugins/gramax/scripts/validate_structure.py`:**

- `validate()` (`:625`): после чтения `tags_contract` —
  `diagram_tags = tuple((tags_contract or {}).get("diagramTags", ["drawio"]))`; значение
  прокидывается в `_validate_catalog_root` → `_parse_resources` (`:271`) →
  `parse_md_resources`.
- `check_diagrams` (`:719-735`): фильтр `res.target_type != "drawio"` заменяется членством
  `res.target_type not in diagram_set`; сообщение дополняется именем тега (единый формат для
  всех четырёх, включая drawio — суффикс аддитивен, grep по коду W031 и слову «диаграмм»
  сохраняется, AC-153/AC-154):

  ```text
  W031: файл диаграммы не найден (тег <bpmn>): "./missing.bpmn" → /abs/path/missing.bpmn
  ```

- Границы наследуются без нового кода: путь резолвится относительно статьи; цель вне catalog
  root — `in_scope=False`, находки нет (FR-047/FR-120); каждый вложенный root (ADR-0020)
  валидирует свои диаграммы сам — `check_diagrams` уже вызывается из
  `_validate_catalog_root` per-root.

**Демаркация W034 (FR-152, NFR-067) — структурная, по образцу `:738-742`:** все четыре
диаграммных тега после NFR-068 лежат в `selfClosingTags` → входят в `known_tags` (см.
FR-156) → W034 по ним молчит; битая цель даёт ровно одну находку W031 (AC-160). Известная
унаследованная слепая зона (паритет семантики drawio, оговорён FR-151 «в той же семантике»):
тег с `path`, записанный БЕЗ self-closing слэша, не матчится парсером (нет W031) и не
репортится W034 (known) — ноль находок. У текущей проверки drawio та же слепая зона сегодня;
расширение охвата — отдельный вопрос, не этого требования.

### FR-153/FR-154/FR-155 — собственные иконки `.icons/`

**`plugins/gramax/scripts/validate_structure.py`** — новая проверка `check_icons(root,
issues, nested)`, вызывается из `_validate_catalog_root` рядом с `check_images`:

- Сбор вхождений по маскированному тексту (`_mask_code`, тот же примитив, что у W034):

  ```python
  _ICON_RE = re.compile(r"<icon\s[^>]*code=\"([^\"]+)\"[^>]*/>")
  ```

- Код `X` без префикса `lucide-` резолвится против **своего** catalog root:
  `expected = root / ".icons" / f"{X}.svg"` (RES-007 §3: `.icons/<code>.svg` рядом с
  `.doc-root.yaml`; ADR-0020 даёт каждому root своё поддерево — статья вложенного каталога
  проверяется против `.icons/` своего root, не внешнего).
- Файл отсутствует — одна warning-находка на вхождение (по образцу W030/W031 — на точку
  использования, не на файл; BR-004 запрещает дубли между проверками, не сворачивает
  несколько использований одного файла):

  ```text
  W035: файл иконки не найден: код "my-custom-icon" → ожидается .icons/my-custom-icon.svg
  ```

- FR-154: периметр — только `<icon code="..."/>` в статьях (`_collect_md_files`);
  `properties.icon` (frontmatter, `.doc-root.yaml`) не трогается — открытый вопрос 2
  требования за PM.
- FR-155: пустой сбор кодов (нет кастомных иконок) → ноль обращений к файловой системе,
  ноль находок — отсутствие папки `.icons/` само по себе не проверяется.
- `lucide-`-код (`<icon code="lucide-zap"/>`) против `.icons/` не резолвится — только форма
  префикса (BR-013, Решение 5 ADR-0024). Пограничный случай для QA: код `xlucide-zap`
  префиксом не является → кастомный → резолв против `.icons/xlucide-zap.svg`.

### FR-156/FR-157 — паритет W034 с контрактом тегов

**`validate_structure.py`, конструкция `known_tags` (`:645-651`)** — расширяется вторым
контрактом (сегодня — только `gramax-render-rules.json`):

```python
known_tags = {"drawio"} | set(diagram_tags)                       # seed + diagramTags
if tags_contract is not None:
    known_tags |= set(tags_contract.get("selfClosingTags", []))   # FR-156
    known_tags |= set(tags_contract.get("pairedTags", []))        # FR-156
if render_contract is not None:
    known_tags |= {killerTags} | set(allowlistedTags)             # существующее (ADR-0019 Решение 3)
```

Деградация при повреждённом контракте структурно та же, что сегодня: `(contract or {})`
даёт пустые списки, `known_tags` сходится к `{"drawio"} ∪ killer ∪ allowlist` — error о
контракте уже выдан `load_json_contract` (ADR-0012 Consequences).

**Матчер (`:744`)** — две правки (обе обязательны, см. пробу 2 Контекста):

```python
_UNSUPPORTED_HTML_RE = re.compile(r"<(?!/)([a-z][a-z0-9-]*)(?:\s[^>]*)?/?>", re.IGNORECASE)
```

- `[a-z][a-z0-9-]*` — дефис в имени (FR-157): `<plant-uml>` видим, но исключён known-набором
  (контракт); `<fancy-widget-x>` — находка.
- `/?` перед `>` — голая self-closing-форма без атрибутов (нужно для AC-159: `<fancy-widget-x/>`).
  Побочное расширение: `` <br/> `` -подобные самозакрытия становятся видимы (ранее — слепая
  зона) — это генуинно неподдерживаемая разметка, warning-уровень; см. «Миграция».
- Истинные позитивы сохранены: автоссылки вида `<https://…>` не матчатся (`:` после имени не
  проходит ни одну ветку — поведение то же), закрывающие `</tag>` отсечены `(?!/)`,
  camelCase-имена матчатся как сегодня (`re.IGNORECASE`), lookup в known-наборе — через
  `.lower()` как сегодня.

**Граница паритета (явная):** W034 теперь строго следует контракту плагина, не полному
реестру движка. Теги, которые движок поддерживает, но контракт не декларирует (`fragment`,
`fragment-link`, `cmd`, `kbd`, `alfa`, `beta`, `img-h`, `img-v` — RES-008), продолжат получать
W034 до тех пор, пока параллельный writer-parity поток не добавит их в `gramax-tags.json` —
после чего демаркация обновится автоматически (структурное свойство: known-набор вычисляется
из контракта). Это соответствует BR-028: канонический **по контракту плагина** тег не
репортится; расхождение контракта с движком — отдельная задача контракта, не валидатора.

### Контракт `gramax-tags.json` (NFR-068, BR-012)

Одним коммитом с кодом:

```json
{
  "schemaVersion": 2,
  "pairedTags": ["note", "tabs", "tab", "html", "comment", "color", "highlight"],
  "selfClosingTags": ["view", "snippet", "openapi", "mermaid", "video", "icon", "image",
                      "drawio", "plant-uml", "bpmn"],
  "diagramTags": ["drawio", "mermaid", "plant-uml", "bpmn"]
}
```

- `plant-uml`, `bpmn` — новые строки `selfClosingTags` (FR-156 применительно к ним);
- `diagramTags` — новый ключ, единственный источник списка тегов с file-based целью;
  новый диаграммный тег = строка здесь + строка в `selfClosingTags`, ноль правок кода
  (BR-012);
- `schemaVersion` 1 → 2 — аддитивное расширение; запись `Contract:` в
  `plugins/gramax/CHANGELOG.md` тем же коммитом (наследие FR-041/NFR-003 ADR-0012).

## Миграция (изменение поведения W031/W034 для существующих потребителей)

1. **W034 сужается** (канонические теги контракта больше не репортятся): вывод может только
   уменьшиться, exit-коды — только улучшиться. Живые ложные находки факта 7 требования на
   `docs/` исчезают (AC-162; симуляция: ноль новых, четыре старых предупреждения остаются).
2. **W034 расширяется на две ранее невидимые формы** (неизвестные дефисные теги; голые
   self-closing `/>` без атрибутов, как `` <br/> ``): новые warning-находки возможны на
   существующих каталогах. Уровень warning — exit без `--strict` не меняется. Симуляция на
   `docs/`: ноль новых находок.
3. **W031 расширяется** на три семейства тегов: новые warning на битых целях `mermaid` /
   `plant-uml` / `bpmn`; под `--strict` ранее зелёные каталоги с генуинно битыми целями
   краснеют — прецедент классификации ADR-0020 Решение 7 (генуйинные дефекты, известных
   потребителей у валидатора нет — ADR-0012 G1).
4. **W035 новый**: warning-находки на отсутствующих `.icons/<code>.svg`; exit-эффект
   симметричен W031.
5. Запись `Contract:` в CHANGELOG (schemaVersion 2) обязательна тем же коммитом; hook-шаблон
   `pre-commit.sh` не меняется (один вызов, поведение аддитивно).

**Edge cases для покрытия (по пробам SA):** голый self-closing `` <br/> `` теперь W034
(расширение, не регрессия); имя с хвостовым дефисом `<b->` матчится как имя `b-`;
автоссылка `<https://…>` невидима (сохранено); закрывающий `</plant-uml>` не репортится;
код `xlucide-zap` — кастомный (префикс не в начале); вложенный doc-root со своим
`.icons/` — иконка резолвится против своего root (ADR-0020); диаграммный тег с `path` без
`/>` — ноль находок (унаследованная слепая зона, паритет drawio — документирована, не дефект
этого изменения).

## Открытые вопросы

1. **Lucide-реестр** (вопрос 1 требования): критерий повторного открытия — исследовательская
   задача по пину движка (метод RES-008: blobless-клон, чтение `package.json`/сборки) с
   списком lucide-имён и их версией; до него любая поставка реестра неверифицируема.
2. **`properties.icon` и `logo`/`logo_dark` формы `icon:<код>`** (вопросы 2/4): за PM;
   положительный ответ расширяет `check_icons` на свойства — архитектура готова (резолв тот
   же), потребуется только новый источник вхождений.
3. **Категория «шапки»** (вопрос 5): второй проход по `catalog/error-check`; офлайн-проверки
   не вводятся до состава правил (красная линия «no invented metrics»).
4. **Коллизия Minor-версии** с параллельными ADR-0022/0023 (зарезервированы): финальный номер
   4.x согласует PM на ратификации; Решение 7 ADR-0024 называет 4.7.0 от текущей 4.6.0.
