# writer 4.7.0 — массовая синхронизация с движком 48592b36: решения Q1–Q6, план правок по кластерам, контракт тегов

## Контекст

Реализация требования [writer 4.7.0 — массовая синхронизация скилла с окном движка
48592b36](../30-requirements/2026-11-18-writer-sync-470-requirement.md) (FR-161…FR-182,
NFR-070…NFR-073, BR-015…BR-018, AC-073…AC-096). Факт-база —
[RES-007](../10-domain/research/2026-11-18-enterprise-server-skill-gap.md) (карта покрытия) и
[RES-008](../10-domain/research/2026-11-18-writer-docs-divergence-audit.md) (пять вердиктов по
исходнику движка, `путь:строка`). Приоритет источников — BR-015: вердикт RES-008 выше docs
gram.ax, docs выше текущего текста writer.

Открытый вопрос 1 требования поручал SA точечный engine-проб по doc-root-ключам, не покрытым
RES-008. Проб исполнен при подготовке этого дизайна: blobless-клон
`github.com/Gram-ax/gramax` в `/tmp/gramax-engine-audit` (вне дерева проекта), checkout на пин
`48592b36` — тот же пин, что RES-006/RES-008; метод — чтение кода, без запуска. Все `путь:строка`
ниже относительны к корню движка на этом пине. Попутно проб закрыл двигателем же два смежных
пункта брифа: видео-атрибуты (вопрос 4) и состав справочника тестов (FR-163) — engine-составляющие
выделены пометками источника. Дизайн отвечает на шесть открытых вопросов требования, раскладывает
FR-161…FR-182 по файлам навыка, задаёт диф контракта тегов (NFR-072) и тест-хуки для QA-author.

Границы с параллельными требованиями сегодняшнего среза — как в requirement: офлайн-проверки новых
поверхностей — зона [паритета валидаторов](2026-11-18-validators-parity-design.md) (там FR-156
считает known-набор W034 из контрактов — см. [«Контракт тегов»](#контракт-тегов-nfr-072));
PlantUML/BPMN и inline-диаграммы writer не переизлагает.

## Q1 — engine-проб doc-root-ключей (открытый вопрос 1)

Факт 18 требования (`doc-root-schema.md` в аудит RES-008 не входил) закрыт прямым чтением. Формат
каждого вердикта: что читает движок, где доказано, что делает writer 4.6.0. Общий механизм чтения:
`.doc-root.yaml` грузится как YAML напрямую в тип `CatalogProps` без переименования ключей —
`core/logic/FileStructue/FileStructure.ts:708-711` (`yaml.load` → `CatalogProps`); ключ вне типа —
молча проигнорированный ключ. Имена файлов: `.doc-root.yaml` (также `.doc-root.yml`,
`doc-root.yaml`, `doc-root.yml` — `app/config/const.ts:18-27`; в справочник не добавляем —
канон уже зафиксирован, факт указан для полноты).

**(а) Enum `syntax`.** Движок: ровно три значения — `XML`, `Legacy`, `GitHub Flavored Markdown`
(`core/extensions/markdown/core/edit/logic/Formatter/Formatters/typeFormats/model/Syntax.ts:1-6`).
Селектор настроек каталога предлагает `Object.values(Syntax)` — те же три
(`core/extensions/catalog/actions/propsEditor/hooks/useFormSelectValues.ts:29-35`); неизвестное
значение в форматтере молча падает в Legacy-форматтер (`…/typeFormats/getFormatterType.ts:41`,
`?? LegacyFormatter`). Вердикт: таблица docs соответствует движку; значение `Markdown` из
writer 4.6.0 в движке не существует — каталог с ним фактически работает как `Legacy`. Правка:
enum в `references/doc-root-schema.md` заменяется на три значения движка с пометкой «значение
`Markdown` writer 4.6.0 — не значение движка, трактуется как `Legacy`» (не молча — NFR-071:
существующие каталоги продолжают работать). Попутно: шаг Workflow SKILL.md «Прочитай `syntax`
(XML или Markdown)» и заголовок blocks.md «Markdown-формат (для `syntax: Markdown`)» перецеляются
на enum движка (адмонitions `:::` — форма для `Legacy`/`GitHub Flavored Markdown`).

**(б) `filterProperty` vs `filterProperties`.** Движок читает `filterProperty?: PropertyID` —
одиночный идентификатор (`core/logic/FileStructue/Catalog/CatalogProps.ts:17`); ключа
`filterProperties` в модели нет вообще — единственные совпадения по дереву движка — ключи
локализации, не конфигурации. Редактор настроек пишет и читает тоже одиночный
(`core/extensions/catalog/actions/propsEditor/model/CatalogEditProps.ts:14`,
`…/logic/getCatalogEditProps.ts:16`). Значение матчится по правилу `id ?? name` свойства
(`core/extensions/git/core/ScopedCatalogs/events/ScopedCatalogsResolver.ts:49`). Вердикт: расхождение
решено в пользу движка — writer документирует `filterProperty` (одиночный id) как действующий ключ;
форма `filterProperties` (список имён), которой writer 4.6.0 учил, движком не читается — в
справочнике она сохраняется одной строкой как legacy-форма writer с пометкой «движком на пине не
читается; миграция — заменить на `filterProperty`». Следствие для собственного репозитория:
`docs/.doc-root.yaml:27` использует непрочитываемую форму — эскалация PM (открытый вопрос 1 этого
дизайна), правка не входит в срез writer.

**(в) Нотация свойств: `id` против `name`.** Модель свойства — `{id?, name, type, style, icon?,
options?, values?}` (`core/extensions/properties/models/index.ts:13-21`): `id` опционален, `name`
обязателен. Вся свёртка идёт по правилу `id ?? name` — и в каталоге, и во frontmatter статей
(`core/extensions/properties/logic/catalogProperty.ts:13` и `:54-57`). Значение статьи во
frontmatter — объект `PropertyValue {id, value?}` (`models/index.ts:24-25`); родная сериализация
редактора пишет `{id, value: […]}` — `core/extensions/properties/logic/changeProperty.ts:26-30`.
Вердикт: обе нотации читаются (фолбэк), канон сериализации — `id`. Правка: справочник
`Property`-определения получает поле `id` (опционально; без него идентификатором работает `name`);
frontmatter-нотация для нового контента — `- id: <id>` + `value: [...]` (объектная форма writer
сохраняется как валидная — NFR-071, меняется ключ привязки с `name` на `id` с пометкой «name-
нотация читается фолбэком»). Типы — по enum движка `Flag`, `Enum`, `Many`, `Text`, `Numeric`,
`Date` (`models/index.ts:43-53`; служебный `BlockMd` не подходит для статей —
`isPropertySuitableForArticle`, `:55-62`); типа `String` в движке нет — текущая строка справочника
`Enum | String` переписывается по движку с пометкой расхождения; опция
`options.docportalVisible: true` — engine-верифицирована (`models/index.ts:9-11`). Ограничение
«свойство нельзя переименовать» (docs) включается с пометкой источника docs — в прочитанном коде
запрета не искали, противоречия нет.

**(г) Палитра `style`.** Enum движка — ровно 20 значений:
`red`, `blue`, `black`, `green`, `purple`, `teal`, `blue-pink`, `red-green`, `pink-blue`,
`orange-red`, `red-orange`, `blue-green`, `blue-purple`, `purple-blue`, `dark-orange`,
`pink-purple`, `orange-green`, `green-orange`, `bright-orange`, `purple-orange`
(`core/components/HomePage/Cards/model/Style.ts:1-22`). Пикер настроек предлагает все 20
(`SPECTRUM`, `core/components/Atoms/ColorTilePicker.tsx:7-28`); бейджи свойств и карточка каталога
используют тот же enum (`PropertyStylePicker.tsx:29`, CSS-переменная
`--color-property-bg-${style}`). Вердикт: «20 значений docs» = enum движка, состав совпадает.
Пересечение с текущими 11 значениями writer — 5 (`green`, `blue`, `blue-green`, `purple`,
`dark-orange`); остальные 6 (`gray`, `light-green`, `light-blue`, `light-purple`, `orange`,
`light-pink`) в enum не входят — движок их не валидирует и не падает, но CSS-переменная не
найдётся и бейдж рендерится без цвета. Правка: каноническая палитра справочника — 20 значений
enum; бывшие 11 перечисляются отдельной строкой legacy с пометкой «6 значений вне enum движка —
не использовать в новом контенте» (замена не молчаливая — NFR-071: существующие каталоги
рендерятся, деградация только цвета).

**(д) Формы логотипов.** Ключи `logo` и `logo_dark` — engine-верифицированы
(`CatalogProps.ts:38-39`). Разбор значения: префикс `icon:` — код Lucide-иконки с опциональным
вторым сегментом `icon:<код>:<цвет>`; префикс `emoji:` — символ эмодзи
(`core/extensions/catalog/logo/catalogLogoIcon.ts:4-24`). Вердикт: обе формы docs соответствуют
движку; в справочник входят с уточнением про опциональный суффикс цвета у `icon:` — деталь,
которой в docs нет, но она в коде.

**Попутные вердикты проба по смежным ключам кластера B** (закрывают FR-174 без «ждать вердикта»):
`versions?: string[]` (`CatalogProps.ts:16`), `relatedLinks?: TitledLink[]` (`:23`; форма записи —
`{url, title, icon?, target?}`, `core/extensions/navigation/NavigationLinks.ts:63-71`),
`lfs?: {auto?: boolean, exclude?: string[]}` (`:21`;
`core/logic/GitLfs/logic/autoLfsAttachments.ts:21-24`), `hidden?: boolean` (`:25`), хранилище
представлений `<каталог>/.gramax/views` (`core/extensions/catalog/views/logic/CatalogViewProvider.ts:26`).
Все шесть ключей FR-174 документируются как engine-верифицированные — пометка «расхождение» не
нужна; FR-175 остаётся только про палитру/`filterProperty`/источники значений (см. выше).

## Q2 — парные изображения (открытый вопрос 2)

**Решение: включить.** Обоснование: (1) источник сильнейшего класса — прямое чтение движка на пине,
того же класса, что вердикты RES-008: регистрация тегов `img-h`/`img-v` в реестре контентных тегов
(`core/extensions/markdown/core/render/logic/getRenderElements/getTagElementRenderModels.ts:59-60`),
схема с атрибутами `imageFirst`/`imageSecond` (String) — `core/extensions/markdown/elements/imgs/model/imgs.ts:5-19`,
рендер-компонент `Images` (`core/extensions/markdown/elements/md/render/getComponents/getMdComponents.tsx:22`);
(2) закрывает реальную потребность (пара скриншотов рядом/столбцом) без изобретения; (3) цена —
одна строка справочника с примером и один тег в контракте. BR-016 здесь не работает — он про
элементы, которых в движке нет; `img-h`/`img-v` — противоположный случай: есть в движке, нет ни в
writer, ни в docs. Обязательная оговорка (engine-факт): в HTML-фолбэк-карте рендера компонент
помечен unsupported (`getMdHTMLComponents.tsx:25`) — надёжнее всего элемент рендерится в основном
веб-рендере; строка справочника несёт эту пометку. NFR-072: оба тега входят в
`selfClosingTags` контракта одним изменением с правками writer.

## Q3 — политика правки шаблонов (открытый вопрос 3)

**Решение: правка файлов `.gramax/templates/<id>.md` разрешена, но только как отдельная, явно
запрошенная пользователем операция — никогда как побочный эффект правки одной статьи.** Engine-
основание: `TemplateProvider` при правке шаблона обходит всех потребителей (`item.props.template === id`)
и перезаписывает их тела пустотой — `core/extensions/templates/logic/TemplateProvider.ts:50-71`;
сама операция «сделать шаблоном» вытирает тело статьи-источника и пишет `template: <id>` во
frontmatter (`:36-46`). Т.е. файл шаблона — единственная точка хранения общего текста, и его правка
мгновенно меняет все статьи-потребители: операция легитимна, но её радиус обязан быть проговорен в
запросе. Три правила для SKILL.md (дополняют FR-181, не заменяют):

1. Тело статьи-потребителя (frontmatter `template:`) пусто by design — НЕ «восстанавливать» его
   копированием текста шаблона: это создаст форк сборки, который следующая правка шаблона сотрёт.
2. Статья-потребитель редактируется только во frontmatter-блоках `properties` (FR-181) и
   именованных полях `fields` (пишутся редактором — `TemplateProvider.ts:72-110`); агент поля
   `fields` сам не сочиняет.
3. Файл шаблона правится целиком осознанно: изменились все потребители разом; в commit-message
   потребителя указывать templateId.

BR-018 расширяется формулировкой «содержимое `.gramax/templates/`» → «файлы шаблонов правятся
только по явному запросу; тела статей-потребителей не трогаются» — само правило зоны «не трогать»
для автоматических правок сохраняется.

## Q4 — видео: embed-форма и `cover` (открытый вопрос 4)

**Решение: документировать embed-форму — но как правило рендра, не как расширение списка
хостингов.** Engine-факт: рендер видео с внешним URL, содержащим подстроку `embed`, отдаётся в
iframe без преобразования (`core/extensions/markdown/elements/video/render/components/RenderVideo.tsx:163-166`);
список известных хостингов (семь: `youtube.com`, `youtu.be`, `drive.google.com`, `mega.nz`,
`rutube.ru`, `dropbox.com`, `instagram.com`) — это гейт пути вставки/вставки из MS Office, не
рендера (`core/extensions/markdown/elements/video/logic/isVideoSupported.ts:1-12`, потребитель —
`…/copyMsO/transfomerMsO.ts:196`). Формулировка для `references/blocks.md` (реклама расплывчатой
docs-формулы снята, правило стало машинно-точным): «внешняя ссылка, содержащая подстроку `embed`,
рендерится как iframe как есть — рабочий способ для хостингов вне списка семи; редакторская
вставка и вставка из MS Office ограничены списком семи».

Атрибуты: `title` и `scale` — engine-верифицированы (`…/video/render/model/video.ts:12-16`,
`…/logic/getVideoAttrs.ts:3-9`). Атрибут `cover` — в движке на пине отсутствует (поиск по
video-элементу движка — 0 совпадений), при том что FR-168 внёс его по docs. По BR-015 движок
выше docs: `cover` документируется негативной пометкой по образцу AC-079 — «атрибут обложки,
названный в docs, в движке на пине `48592b36` не найден — не использовать в новом контенте»
(слово в тексте есть, AC-082 матчится, факт остаётся engine-истинным).

## Q5 — массовая миграция фрагментов (открытый вопрос 5)

**Решение: teach-legacy-only; рецепт превентивной массовой миграции в скилл не входит, отдельный
инструмент не создаётся.** Обоснование: (1) движок сам мигрирует фрагмент из `.gramax/snippets/`
в `.gramax/fragments/` при первой правке (RES-008 §1, `FragmentProvider.ts:129-144`) — превентивная
миграция не даёт рендерного выигрыша; (2) NFR-071 — синхронизация аддитивна: `<snippet>` остаётся
валидным тегом (алиас в реестре, `getTagElementRenderModels.ts:65-66`), каталоги потребителей
продолжают работать; (3) массовая перезапись чужих корпусов — churn и риск побочных правок без
запроса пользователя — тот же класс, что отклонённая обязательная миграция `.md`-ссылок
(FR-173/BR-017, прецедент RES-008 §2). Скилл учит: новый контент — `<fragment id="…"/>` +
`.gramax/fragments/` + `<fragment-link id>текст</fragment-link>`; встретив `<snippet>`/`snippets/`
— оставить как есть (движок читает; при первой правке файла мигрирует сам), принудительно
переносить не нужно. Если у потребителя возникнет запрос на массовую миграцию — это отдельная
задача будущего цикла по сигналу (прецедент порога «сигнал ≥2–3 случая» из вложенных
`.doc-root.yaml`), не рецепт в навыке.

## Q6 — хвост кандидата 4.8.0 (открытый вопрос 6)

Именованное «что сознательно не вошло» (источник — Out of scope требования + находки этого проба):


1. Frontmatter-поля статьи: `description`, `hidden` (поле статьи — не ключ doc-root, вошедший во
   FR-174), `expanded` (`_index.md`), `orderAsc`, служебные `welcome`/`external`/`shouldBeCreated`.
2. Типографские детали и «чего нет в синтаксисе»: тире `--`, перенос `\` в конце строки,

6. `<gallery>`/`Gantt` — остаются под BR-016 до engine-окна, подтверждающего их появление.

## Решение по ADR

**ADR-0025 не пишется.** Основания: (1) прецедент — синхронизации writer 4.2.0 и 4.6.0 (включая
исправления по окну движка) прошли без отдельных ADR; (2) правка машиночитаемого контракта тегов —
эволюция внутри действующего контракта ADR-0012 (JSON single source): аддитивное расширение списков
без смены схемы (`schemaVersion` остаётся 2), оформляется записью `Contract:` в CHANGELOG — тот же
механизм, что зафиксирован NFR-004 дизайна от 2026-08-13; (3) semver-категория релиза — зона
ADR-0006, ожидаемо Minor, решение PM при выпуске (NFR-071 требования); (4) единственная
ретрокоррекция — `filterProperty` — это исполнение BR-015 (приоритет источников) над документацией,
а не новое стоящее архитектурное решение; её операционное следствие (миграция собственного
`docs/.doc-root.yaml`) — задача PM, не ADR. Публичная поверхность плагина не меняется (скилл
существующий, новые файлы — внутри него).

## Порядок правок

1. `references/quizzes.md` — новый файл (нет зависимостей).
2. `references/blocks.md` — наибольший диф, независим от остальных.
3. `references/doc-root-schema.md` — ключи, палитра, property, файловые следы, мультиязычность.
4. `references/structure.md` — шаги `aliases` (малый диф).
5. `SKILL.md` — последним: навигационные строки (Frontmatter-таблица, Дашборды, Изображения,
   Видео, Фрагменты, Ссылки, UI-токены), Guardrails, staging, Resources (+ строка
   `references/quizzes.md`). Причина: ссылки навигации не должны повиснуть ни на одном комите;
   SKILL.md — единственный файл, куда параллельный Dev-поток добавляет одну строку кросс-ссылки в

## Контракт с QA-author

**AC (полный список требования):** AC-073…AC-096. Уровни по пирамиде: AC-073…AC-095 — integration
(bash-наборы по дереву `plugins/gramax/skills/writer/` + `gramax-tags.json`, таксономия ADR-0011,
прецедент `tests/gramax/*`); AC-096 — e2e композит (`bash scripts/check.sh --fast`, код возврата).
Автотестов вне репо-дерева нет; фреймворк выбирает QA-author.

Архитектурный контекст: все проверки — офлайн, файловая система; тестируемая поверхность — пять
md-файлов навыка, один JSON-контракт; сетевых вызовов и auth нет.

**Группы:**

- AC-073, AC-074 — frontmatter-ключи (grep по SKILL.md/references).
- AC-075, AC-076 — справочник тестов: файл существует, маркеры `questionAnswer`/`showIf`/
  `countOfCorrectAnswers`; полнота перечня типов — по редким `ranking`/`matrix`.
- AC-077…AC-087 — кластер A: новые элементы, переписанный `<view>` (маркеры: `orderby`, `Kanban`,
  «скрыт»), XML+скобочные токены, `scale`+«реальный размер», видео (`dropbox`/`mega`/`cover`),
  OpenAPI, «блок кода»+`highlight.js`, `{#`, фрагменты (`<fragment id=`, `fragment-link`,
  `legacy`, «фрагмент» в SKILL.md), ссылки («без .md» + «обе формы»).
- AC-088…AC-094 — кластер B: `logo_dark`/`relatedLinks`/`versions`/`hidden`/`filterProperty`,
  `GitHub Flavored Markdown` + двухцветные, `.gramax/views`, `lfs`+`.gitattributes`,
  «мультиязыч»+«непереведён», `docportalVisible`+`Flag`+`Numeric`, `.icons/`.
- AC-095 — guardrails: `template:`, `.gramax/templates`, `.gramax/inbox`, `.gramax/mr` в SKILL.md.
- AC-096 — композитный.

**Edge cases / границы (обязательны к учёту):**

- **AC-079 — байтовый негативный контроль.** Грепы `! grep -rq '<gallery' …` и
  `! grep -rq 'display="Gantt"' …` не знают markdown: литеральные формы не должны встречаться
  нигде в дереве writer, В ТОМ ЧИСЛЕ в код-спанах и код-блоках. Формулировки избегания — без
  литеральной формы: «тег галереи» (без угловой скобки), «значение Gantt» (без
  `display="`-префикса). Это же касается примеров: негативная проза — без воспроизведения формы.
- **AC-082 (`cover`)** — позитивный grep: негативная пометка Q4 слово содержит, тест зелёный;
  но тест не различает позитивное и негативное употребление — ревьюер проверяет смысл вручную.
- **AC-087** — regex-альтернативы: формулировка Dev обязана содержать дословно одну из фраз
  «обе формы» / «тоже резолв» / «резолвятся обе»; целевая фраза дизайна — «обе формы резолвятся».
- **AC-088** — regex `filterProperty([^i]|$)`: плуральная форма не матчится (в
  «filterProperties» после «filterPropert» идёт «i»), так что справочник может упоминать обе формы;
  сингулярная обязана присутствовать.
- **AC-081** — дословная фраза «реальный размер» (не «фактический»).
- **AC-078** — «скрыт» в любой форме (регистронезависимо) в blocks.md.
- **markdown-`scale`** — engine-факт (аннотация применяет только `width`/`height`) означает: если
  Dev случайно задокументирует `{scale=…}` как рабочий, ни один AC это не поймает — предусмотреть
  ревью-пункт (процессная проверка), не новый гейт.
- **Параллельный Dev-поток** добавляет одну строку в «Ресурсы» SKILL.md — тесты не должны
  зависеть от порядка/состава списка ресурсов.
- **AC-075 (`showIf`)** и `mode`/`shuffleQuestions` — docs-поверхность GES: тест проверяет наличие
  строк в справочнике, не engine-семантику (её в OSS-дереве нет — Q-проб).

## Открытые вопросы

1. **Миграция собственного `docs/.doc-root.yaml:27`** с непрочитываемой движком формы
   `filterProperties` на `filterProperty` — решение и коммит PM (вне среза writer; движок форму
   игнорирует, поведение портала не меняется, но фильтр боковой панели не работает как задумано).
2. **6 вне-enum значений палитры** (`gray`, `light-green`, `light-blue`, `light-purple`,
   `orange`, `light-pink`) — считать ли deprecation-кандидатами 4.8.0: решение при следующем окне
   движка (появится ли валидация значений).
3. **`cover`, `showIf`, `mode`/`shuffleQuestions`, 9 расширенных типов вопросов** — docs-only
   утверждения о поверхности GES; верифицировать при первом окне, где GES-часть доступна исходно
   (или запросом вендору).
4. **Незадокументированные теги проба** (`block-property`, `block-field`, `when`, `who`, `see`) —
   кандидаты аудита 4.8.0 (Q6).
