## Контекст

Решение владельца D8 (`docs/00-project/epics/2026-11-24-wave4-tails-genesis-tree.md`,
узел D8): «чистить дерево, историю не трогать» — обезличить имена приватных
репозиториев и организаций и слаг в записи волны-1; «регрессионные фикстуры не
трогаются». Аудит `docs/00-project/security/audit-2026-08-13-link-form-wave.md`
(раздел «Вне периметра волны») нашёл этот класс и разделил его: в ADR, research и
требованиях имена стоят в содержательном тексте; тестовые файлы «воспроизводят
дефект как учебный пример/regression guard».

Этот документ — предписание проходу, а не сам проход: классификация каждого
затронутого файла, конвенция маскирования и команды проверки. Проход исполняет
позднейший этап, коммиттер один — PM. Три правила письма:

| Правило | Смысл |
|---|---|
| ничего не пишется | имена, метки хостов, слаг и личный путь не попадают в файлы репозитория — ни сюда, ни в отчёты; в командах стоят места подстановки в угловых скобках, их значения исполнителю передаёт координатор в брифе |
| одна база | все числа измерены на `f551d87` приведёнными командами; в рабочем дереве номера строк после блока `**Опоры:**` сдвинуты (+2 в журнале уроков, +4 в двух сторожимых файлах), поэтому где исполнителю нужно что-то найти, дана команда, а не номер |
| закрытый набор | у каждого файла ровно один класс, у каждого класса ровно одна правка; четыре класса брифа дополнены по решениям PM классами «личный абсолютный путь» и «внутренний хост»; класс брифа «описание случая» записан как «утечка (описание случая, правится на месте с пометкой)» |

Отправная точка — команда брифа, `git grep -l -E '<приватный паттерн>' -- .`: на
`f551d87` она даёт 23 файла, 126 строк и 162 вхождения. Это не периметр прохода —
его задаёт раздел «Правило вывода набора».

## Правило вывода набора

Ручной список имён — неверный инструмент: урок 2026-08-13 в `docs/lessons-learned.md`
фиксирует, что такой список «систематически неполон». Набор выводится из дерева до
прохода семью шагами (нумерация — как в комментариях команды):

1. Корни — сегменты пути, за которыми в дереве стоит стем паттерна координатора,
   кроме собственного пространства проекта (ADR-0014). На `f551d87`: 4 сегмента,
   минус собственное пространство — 3 корня.
2. Листа́ — в путевых токенах вида «корень/…» все сегменты после корня до первого
   сегмента внутри репозитория (закрытый словарь, расширение файла, суффикс
   `:строка`); элементы фигурных списков разворачиваются; каталог плагина — шум.
3. Базовый набор — стемы без концевой косой черты плюс листа́, длинные первыми:
   27 имён = 10 стемов + 17 листьев.
4. Якорь — имя считается именем, только если слева нет буквы, цифры, `_` и `-`.
5. Замыкание — голые имена в скобочном перечислении, где уже стоят не меньше двух
   выведенных имён; сегменты путей этого репозитория именами не считаются. Даёт 7
   имён — все в перечислении «12 репозиториев» файла
   `docs/30-requirements/2026-08-13-doc-root-discovery-contract.md` (строки 84–87
   на `f551d87`); счётчик в тексте остаётся.
6. Итоговый набор — базовый, замыкание и имена по явному решению PM (поле
   `EXTRA`): 1 имя, вложенный каталог документации внутри репозитория потребителя,
   3 вхождения в 3 файлах. Итог — 35 имён.
7. Перепись на базовом дереве: файл → строки и итог.

```bash
set -uo pipefail
BASE='<базовый коммит до прохода>'
PAT='<приватный паттерн координатора>'      # альтернативы через |, как в брифе
# путь этого репозитория в GitLab — не секрет (ADR-0014)
OWN='<собственное пространство проекта>'
EXTRA='<имена по явному решению координатора>'  # через |; пустая строка, если решений не было
# сегменты ВНУТРИ репозитория (не имя) и форма сегмента-файла
export VOCAB='scripts|content|docs|tests|plugins|references|skills'
export VOCAB="$VOCAB"'|\.claude|\.claude-plugin|\.githooks|\.github|bin|lib|src'
export EXT='\.[A-Za-z0-9][A-Za-z0-9]?[A-Za-z0-9]?[A-Za-z0-9]?[A-Za-z0-9]?$'
# (1) корни: сегменты, за которыми в дереве стоит стем; собственное пространство исключено
ROOTS="$(git grep -h -o -E "[A-Za-z0-9_.-]+/($PAT)" "$BASE" -- . | sed 's#/.*##' | sort -u \
  | grep -v -x "$OWN" | paste -sd'|' -)"
# (2) листа́: сегменты после корня до первого «внутрирепозиторного» (словарь, расширение,
#     суффикс `:строка`); элементы фигурных списков разворачиваются; каталог плагина — шум
LEAVES="$(git grep -h -o -E \
    "(^|[^A-Za-z0-9_./-])($ROOTS)(/[A-Za-z0-9_.-]+|/[{][^}]*[}])*" \
  "$BASE" -- . | awk -F/ '{
      sub(/^[^A-Za-z]/, "", $1); stop = 0
      for (i = 2; i <= NF && !stop; i++) {
        gsub(/[{}]/, " ", $i); k = split($i, E, ",")
        for (j = 1; j <= k; j++) {
          e = E[j]; gsub(/^[ \t]+|[ \t]+$/, "", e)
          if (e ~ "^(" ENVIRON["VOCAB"] ")$" || e ~ ENVIRON["EXT"] || e ~ /:/) {
            stop = 1; break
          }
          if (e != "" && e != "gramax") print e
        }
      }
    }' | sort -u)"
# (3) базовый набор: стемы без концевой косой черты + листа́, длинные первыми
NAMES="$(printf '%s\n%s\n' "$(printf '%s\n' "$PAT" | tr '|' '\n' | sed 's#/$##')" "$LEAVES" \
  | grep -v '^$' | sort -u | awk '{ print length "\t" $0 }' | sort -rn | cut -f2 \
  | paste -sd'|' -)"
# (4) якорь: слева от имени нет буквы, цифры, _ и -
BASENAMES="$NAMES"
ANCHORED="(^|[^A-Za-z0-9_-])($NAMES)"
# (5) замыкание: голые имена в скобочном перечислении, где уже стоят >= 2 выведенных имени;
#     сегменты путей этого репозитория именами не считаются
SEGS="$(mktemp)"; git ls-tree -r --name-only "$BASE" | tr '/' '\n' | sort -u > "$SEGS"
CLOSE="$(git grep -l -E "$ANCHORED" "$BASE" -- . | sed "s/^$BASE://" | while IFS= read -r f; do
    git show "$BASE:$f"
  done | awk -v RS= -v names="$BASENAMES" '{
      n = split($0, P, /[()]/)
      for (i = 2; i <= n; i += 2) {
        known = 0; m = 0
        while (match(P[i], /`[A-Za-z0-9][A-Za-z0-9_-]*`/)) {
          t = substr(P[i], RSTART + 1, RLENGTH - 2)
          P[i] = substr(P[i], RSTART + RLENGTH)
          if (t ~ ("(^|[^A-Za-z0-9_-])(" names ")($|[^A-Za-z0-9_])")) known++; else C[++m] = t
        }
        if (known >= 2) for (j = 1; j <= m; j++) print C[j]
      }
    }' | sort -u | grep -v -x -F -f "$SEGS" | grep -v '\.' || true)"
rm -f "$SEGS"
# (6) итоговый набор: базовый + замыкание + имена по явному решению координатора
NAMES="$(printf '%s\n%s\n%s\n' "$BASENAMES" "$CLOSE" "$EXTRA" | grep -v '^$' | sort -u \
  | awk '{ print length "\t" $0 }' | sort -rn | cut -f2 | paste -sd'|' -)"
ANCHORED="(^|[^A-Za-z0-9_-])($NAMES)"
[ -n "${NAMES_OUT:-}" ] && printf '%s' "$NAMES" > "$NAMES_OUT"
# (7) перепись на базовом дереве: файл -> строки; итог — файлы, строки, вхождения, имена
git grep -c -E "$ANCHORED" "$BASE" -- . | sed "s/^$BASE://" | sort -t: -k2 -rn
echo "files=$(git grep -l -E "$ANCHORED" "$BASE" -- . | wc -l | tr -d ' ') \
lines=$(git grep -c -E "$ANCHORED" "$BASE" -- . | awk -F: '{ s += $NF } END { print s }') \
occ=$(git grep -o -E "$ANCHORED" "$BASE" -- . | wc -l | tr -d ' ') \
names=$(printf '%s\n' "$NAMES" | tr '|' '\n' | grep -c .)"
```

Результат на `f551d87`: `files=33 lines=192 occ=309 names=35`. Шаги 1–3 дают те же
27 имён, что и независимый Python-пересчёт на копии дерева. Границы правила:

- Стемы ни разу не совпали с обычным словом. Единственное постороннее совпадение
  команды брифа — `docs/30-requirements/2026-08-11-mermaid-file-based-adoption.md:55`,
  где стем №10 — хвост другого имени репозитория; то имя выведено шагом 2 и
  маскируется. В `scripts/_drift_check.py:348` стем №5 — само имя репозитория.
- Вариантов регистра нет: `git grep -i` с паттерном брифа даёт те же 23 файла и
  162 вхождения.
- Ни один путь в дереве не содержит имени: `git ls-tree -r --name-only f551d87`
  (868 путей) с якорем набора даёт 0 совпадений — переименовывать нечего.
- Локальные корни, кроме стема №10, — два обычных слова (13 и 4 строки), не имена;
  не маскируются (решение PM).
- Правило не достаёт голые имена того же класса вне скобочных перечислений; их
  число не измерено: N/A — механического правила нет. Известно одно: строка `:95`
  файла `docs/30-requirements/2026-08-11-writer-consumer-rules.md` — цитата из
  чужого файла называет того, кто добавил overlay (команда или продуктовая линия,
  не репозиторий); ни стемы брифа, ни аудит не устанавливают это слово как имя
  приватного репозитория или организации, поэтому оно оставлено.

## Реестр токенов

Одна сущность — один токен во всех файлах. Токен — кириллический, в угловых
скобках, всегда в код-спане: так он отличим от настоящего имени и не читается
рендерером как тег. Роли взяты из таблицы потребителя
(`docs/10-domain/research/2026-08-11-plugin-consumers-gaps.md`, строки 27–32 на
`f551d87`). Стем №k — k-я альтернатива паттерна координатора слева направо; числа
вхождений и файлов — отпечаток для сверки перед правкой. Новые имена получают
буквы по алфавиту внутри своей роли; буквы замыкания и `EXTRA` продолжают
нумерацию базового набора, поэтому добавление имени в шаг 5 не переименовывает
уже назначенные токены.

## Конвенция маскирования

Что и как заменяется:

| Форма в тексте | Замена |
|---|---|
| имя в код-спане | токен в том же код-спане |
| имя внутри пути | только сегмент имени; стем №10 → `<локальный-корень>` с сохранением косой черты; прочие сегменты и прочие локальные корни остаются |
| файл, названный по репозиторию | токен внутри имени файла |
| фигурный список | каждый элемент набора по отдельности; элементы вне набора остаются |
| имя в прозе вне код-спана | токен в код-спане |
| имя внутри идентификатора (ключ auto-memory) | часть-имя; суффикс остаётся |
| метка хоста; личный путь | `<внутренний-хост>`; `/Users/<имя>/…` |
| комментарий, докстринг, текст справки, описание фикстуры, на который никто не ассертит | маскируется как проза |
| исполняемый литерал: значение по умолчанию, регулярка, вход фикстуры под ассертом | класс «сторож» с названным стабом; в дереве таких литералов набора нет |

Чего правка не делает:

1. Не меняет числа строк: правка построчная, переперенос запрещён. Основание — 158
   ссылок вида `файл:строка` из других отслеживаемых файлов в затронутые файлы (9 в
   диспозицию, 16 в требование под сторожем, 4 в журнал); в симуляции 54 строки
   пересекают 100 символов, 17 — 120 — принятая цена. Новых строк TPL-69 не возникает.
2. Не оставляет пометку в исторических записях — приёмках, at-design, dev-notes,
   research: они маскируются на месте. Пометка не удаляет имя, и цель D8 не
   достигается; пометка внутри принятой записи — вторая правка сверх санкции D8, а в
   двух сторожимых файлах она сломала бы доказательство «кроме имён ничего не
   менялось». Провенанс несут этот документ и коммиты A и X; журнал уроков —
   единственное исключение.
3. Не подменяет слаг плейсхолдером: слаг записи волны-1 — имя
   каталога-потребителя и получает тот же токен, что в документах августа (одна
   сущность — один токен); `{catalog}` из FR-204 описывает поле конфига, а не имя.
4. Ничего не переименовывает — ни файл, ни каталог фикстуры, ни стаб: имя ни одного
   отслеживаемого пути набора не содержит, а история не переписывается. Имена,

## Два файла под байт-сторожем `ac-003`

Сторож `tests/gramax/cross-catalog-retraction/ac-003-disposition-and-source-untouched.sh`
(строка `:39`) сравнивает диспозицию и требование-первоисточник побайтово с пином
`BASELINE_COMMIT` из `tests/gramax/cross-catalog-retraction/lib/baseline-commit.sh`
(строка `:30`); сюита — шаг `--full` (`scripts/check-gramax.sh:338`). На `f551d87`
оба файла побайтово равны своим версиям на действующем пине:
`git diff --quiet <старый пин> f551d87 -- <два файла>` даёт код возврата 0.

| Сторона | Дословно |
|---|---|
| D8 | «обезличить имена приватных репозиториев и организаций в 23 файлах» |
| FR-097 (`docs/30-requirements/2026-08-13-cross-catalog-retraction.md`), Решение 1 ADR-0017 | «ретракция обязана быть внесена БЕЗ правки тела, статуса и frontmatter диспозиции … и требования-первоисточника … их текст не редактируется задним числом»; правка диспозиции на месте отклонена |

Решение PM: байт-сторож уступает D8 явным и проверяемым перемещением, а не
исключением. После старого пина сторож допускает ровно два вида правки этих
файлов: (1) приватные имена заменены токенами ролей; (2) блок `**Опоры:**` в шапке
— строка-маркер, продолжения из код-спанов путей с запятыми и пробелами, пустая
строка за ними (FR-242). Блок пишет не этот проход: он уже стоит, и проход оставляет
его как есть. Поправка к Решению 1 ADR-0017 записывается в ADR-0030.

| Коммит | Что несёт |
|---|---|
| X | маскирование двух файлов, пин без изменений |
| Y | `BASELINE_COMMIT=<X>` в `lib/baseline-commit.sh` с пометкой в заголовке библиотеки; сразу за X |

Полный гейт на дереве X не запускается: pre-commit зовёт только
`scripts/check.sh --fast` (`.githooks/pre-commit:106`), а `ac-003` живёт в `--full`.
Пин не может указывать на релиз — коммит не содержит хеша самого себя. Пин двигает
PM в коммите Y — не Dev и не проход; после X эти два файла до перемещения пина не
трогает никто. Доказательство сдаётся с отчётом; ожидаемая таблица замен — 20 строк
и 30 вхождений (4 и 6 в диспозиции, 16 и 24 в требовании).

```bash
        seen[number] = tokens
        if (not names or len(names) != len(tokens)
                or NAMES.sub("§", before) != TOK.sub("§", after)):
            fail.append(f"{path}:{number}: изменена иначе, чем «имя -> токен»")
    if seen != want:
        fail.append(f"{path}: таблица замен не совпадает с ожидаемой")
    print(f"{path}: строк заменено {len(seen)}, "
          f"вхождений {sum(len(v) for v in seen.values())}")
for line in fail:
    print("FAIL:", line)
raise SystemExit(1 if fail else 0)
PY
```

Команда проверена на копии дерева с симулированным проходом. Положительный исход:
код возврата 0, «строк заменено 4, вхождений 6» и «строк заменено 16, вхождений 24».
Семь отрицательных исходов, каждый даёт код возврата 1 и строку `FAIL`:

| Случай | Что внесено | Что поймано |
|---|---|---|
| N1 | лишнее слово в замаскированной строке | «изменена иначе, чем „имя -> токен“» |
| N2 | имя заменено токеном другой роли | «таблица замен не совпадает с ожидаемой» |
| N3 | добавлена строка вне блока «Опоры» | «строк вне блока „Опоры“ 177 -> 178» |
| N4 | токен внесён в неизменённую строку | N1 и N2 вместе |
| N5 | строка удалена | «строк вне блока „Опоры“ 372 -> 371» |
| N6 | второй блок «Опоры» | «блоков „Опоры“ 2, ожидался 1» и сдвиг строк |
| N7 | имя заменено токеном вне реестра | N1 и N2 вместе |

## Бриф исполнителю прохода

**Архитектура:** этот файл. **Требование:** FR-255 (вне индекса на момент письма).
**Фаза:** после коммита прохода маркера FR-242, до включения находки FR-231.

**Порядок:** вывод набора и сверка отпечатков → маскирование 25 файлов вне
сторожа → два сторожимых файла → коммиты X и Y PM → пометка PM в журнале → проверки → issue по
payload координатором. `**Опоры:**` в чужих файлах не пишется и не правится;

**Чего не делать:** не переименовывать файлы; не перепереносить строки; не
дополнять замаскированные строки пояснениями; не трогать классы «сторож» и «вне
доступа»; не записывать имена и паттерны в файлы репозитория, отчёты и сообщения
коммитов.

## Контракт с QA-author

**Архитектурный контекст:** правки только текстовые — 27 файлов, исполняемого
пути нет; код плагина меняется одним комментарием; `lib/baseline-commit.sh` —
одной строкой пина (коммит Y, владелец PM).

| Что проверяется | Уровень | Основание |
|---|---|---|
| команда проверки имён, личных путей и хостов; доказательство по двум файлам | unit | статические чтения git-объектов и рабочего дерева |
| `bash scripts/check.sh --fast`, `bash scripts/check.sh --full` | integration | весь корпус `docs/` и 17 сюит вместе |

**Граничные случаи:**

- Пустой набор имён не должен сходить за чистоту: контроль «внутри остатка 8 из 8»
  обязателен так же, как «вне остатка 0».
- Имя, заменённое токеном другой роли, проходит нормализацию и ловится только
  таблицей замен доказательства.
- Блок «Опоры» вне шапки, второй блок или отсутствующая пустая строка за блоком —
  отказ доказательства.
- Строка, где имя стоит в прозе вне код-спана, после правки получает код-спан;
  нормализация «имя → токен» её не описывает — в сторожимых файлах таких строк нет.
  Ссылки вида `файл:строка` верны, только если число строк файла не изменилось.
