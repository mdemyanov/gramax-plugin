# writer 4.8.0 — хвост writer-sync: служебная синтаксика, негативный перечень, HTML-компонент, frontmatter-поля

## Контекст

Реализация потока П1 эпика [«хвосты 4.7.0 → 4.8.0»](../00-project/epics/2026-11-18-tails-480-genesis-tree.md)
(решения D1/D4) по требованию [writer 4.8.0 — хвосты волны
4.7.0](../30-requirements/2026-11-18-writer-tail-480-requirement.md): FR-183…FR-186,
BR-019/BR-020, AC-097…AC-103, NFR-074…NFR-076. Прецедент раскладки и конвенций —
[дизайн writer-sync 4.7.0](2026-11-18-writer-sync-design.md); его решения Q1–Q5 закрыты
реализацией 4.7.0 и здесь не переоткрываются — таблица разбора требования зафиксировала их
фактами 1–5, этот дизайн работает только с новым объёмом: Q6 (служебная синтаксика и «чего
нет»), исключения среза 4.7.0 (HTML-компонент изнутри, frontmatter-поля) и кодификация
BR-019/BR-020.

Релизный носитель — 4.8.0 (D4): пара версий `plugin.json` + `marketplace.json` и CHANGELOG на
main. Engine-зависимые пункты (развёртки таблиц) стоят в очереди engine-пробы потока П2;
требование не планирует пробу (D1) — все новые утверждения writer несут docs-пометку
«(docs-пометка, RES-007 §3)» / «§3/§4» и не выдаются за engine-вердикты (NFR-075, прецедент —
раздел «Блок кода» blocks.md).

Текущее состояние дерева (grep 2026-11-18): формы Q6 (`--`, `\$`, `\[note]`, `<!--`),
маркеры «чего нет», `data-theme`/`data:`, поля `orderAsc`/`expanded`/`shouldBeCreated` в
SKILL.md — ноль совпадений; строка «Спецсимволы» blocks.md:512-515 уже несёт две формы того
же класса (`5\.1`, перенос `\`) — учитывается раскладкой ниже.

## Раскладка по файлам навыка

### Решение о размещении (открытый вопрос 2 требования)

**Один сводный раздел, не распределение по существующим разделам.** Основания: (1) JTBD
требования — автор ищет ответ о служебной синтаксике в одном месте, «не собирая по кусочкам
из вендорских страниц»; распределение по «Стилизации», «Комментариям» и «Спецсимволам»
воспроизводит именно этот разбор; (2) все формы класса — символьный уровень исходника, а не
блоки: ни один существующий раздел блоков им не хозяин; (3) раздел «Спецсимволы» уже
существует как де-факто сводный носитель класса — дизайн легализует это, расширяя и
перенося его на место рядом с «Блок кода» (место по умолчанию из FR-183). Сворачивание
«Спецсимволы» в новый раздел убирает второй носитель того же класса (одно место истины);
существующие два пункта (`5\.1`, перенос `\`) переезжают дословно.

### FR-183 — раздел «Служебная синтаксика»

Состав — шесть форм; каждая новая строка несёт пометку `(docs-пометка, RES-007 §3)`, два
переехавших пункта «Спецсимволов» сохраняют свой текст (writer-практика, не новое
утверждение):

| Форма | Как пишется | Эффект |
|---|---|---|
| Тире в тексте | `--` | Два дефиса подряд рендерятся тире |
| Перенос внутри абзаца | `\` в конце строки | Разрыв строки без нового абзаца |
| Экранирование `$` | `\$` | Показать знак доллара, не открыв формулу (`$…$` — делимитер, см. «Формулы») |
| Экранирование скобочного литерала | `\[note]` | Показать скобки, не вызвав эффект синтаксиса |
| HTML-комментарий | `<!-- … -->` | Виден только в исходнике, при рендере не показывается |
| Экранирование точки в нумерации | `5\.1` | Строка не становится списком (перенос из «Спецсимволы») |

Целевой пример (один ограждённый блок, NFR-075):

```markdown
Цена -- 100 \$ за лицензию, актуальная версия 5\.1.
Длинная строка абзаца\
переносится без нового абзаца.
```

**Дизамбигуация HTML-комментариев** — обязательный пункт FR-183, двусторонняя: в «Служебной
синтаксике» — предложение «HTML-комментарий — не ревью-комментарий: `<comment id="…">` и
`[comment:id]` видны ревьюерам в интерфейсе, раздел „Комментарии“»; в разделе «Комментарии» —
встречная строка «HTML-комментарии — служебная синтаксика, не ревью: видны только в
исходнике» со ссылкой на новый раздел.

### FR-184 — раздел «Чего нет в синтаксисе»

**Граница перечня (открытый вопрос 3 требования): ровно четыре формы из docs, без
самостоятельных дополнений.** Docs фиксируют перечень сам (RES-007 §3), NFR-076 запрещает
объявлять отсутствующим то, что может рендериться; всё, что SA мог бы добавить от себя, —
гипотеза без вердикта, а не знание. Перечень:

| Форма | Как выглядит в других диалектах | Статус |
|---|---|---|
| Setext-заголовки | подпись `===` под строкой заголовка | нет в синтаксисе |
| Сноски | маркер сноски в квадратных скобках с крышкой | нет в синтаксисе |
| Выделение двойным `==` | `==текст==` | нет в синтаксисе |
| Авто-ссылки | голый URL в тексте | нет в синтаксисе |

Вводная формулировка раздела — «Форм, которых в синтаксисе Gramax нет — не использовать и не
изобретать, из других диалектов не переносить (docs-пометка, RES-007 §3)». Замыкающий абзац
разводит классы отсутствия — формулировки БЕЗ литеральных ключей развёрток (см. AC-102 ниже):

> Перечень — ровно четыре формы. Всё прочее, чего в справочнике нет, — двух классов:
> не задокументировано (может войти после engine-вердикта) или заявлено docs без вердикта —
> такие пункты стоят в очереди engine-пробы (BR-020) и в справочник не входят; первый случай
> — развёртки таблиц. Класс «ждёт вердикта» негативным перечнем не поглощается: «нет в
> синтаксисе» и «не документируем до вердикта» — разные утверждения.

### FR-185 — раздел «HTML»: условия компонента

Существующий раздел — голый пример; после него добавляется список условий, каждая строка с
пометкой `(docs-пометка, RES-007 §3)`:

- рендер в изолированном фрейме — стили и скрипты компонента не действуют на страницу статьи;
- допускаются только встроенные `<script>` и `<style>` — внешние файлы не подключаются;
- картинки — только `data:`-URI: внешние и файловые пути не резолвятся;
- тёмная тема компонента — селектор `html[data-theme="dark"]`.

Целевое дополнение примера (ограждённый блок):

```html
<html>
<style>
  html[data-theme="dark"] .card { background: #1e1e1e; }
</style>
<div class="card">Произвольный HTML</div>
</html>
```

### FR-186 — frontmatter-поля в SKILL.md

Единственный FR с правкой SKILL.md (NFR-074). Четыре правки:

1. Таблица «Дополнительные ключи frontmatter статьи» — две строки: `description` («текст для
   поиска и превью статьи; без ключа берётся начало текста статьи»; не путать с `description`
   каталога в `.doc-root.yaml`), `hidden` («скрыть статью»; не путать с `hidden` каталога).
   Пометка `(docs-пометка, RES-007 §3/§4)`.
2. После yaml-шаблона `_index.md` — новая компактная таблица «Дополнительные ключи
   `_index.md`»: `expanded` (свернуть раздел в навигации; не атрибут `<cut expanded>` —
   дизамбигуация факта 9) и `orderAsc` (`false` — сортировка статей раздела по убыванию).
3. После таблицы ключей статьи — строка-абзац служебных ключей: «Служебные ключи frontmatter
   `welcome`, `external`, `shouldBeCreated` пишет движок — агенту не писать (docs-пометка,
   RES-007 §4)».
4. Навигационная строка «Полный справочник блоков (…)» (SKILL.md:346) — сопроводительная
   правка перечисления: добавляются «служебная синтаксика» и «чего нет в синтаксисе». Нового
   раздела в SKILL.md это не создаёт; поле `description` фронтматтера SKILL.md не растёт —
   триггер выбора навыка не меняется (NFR-074).

### BR-019/BR-020 — кодирование без правок текста

**BR-019:** политика шаблонов уже действует в Guardrails (факт 3: `SKILL.md:408-414`,
формулировки «явно запрошенная операция», «тело… пусто by design»). Текстовой правки срез не
требует; знание кодифицируется regression-guard'ом AC-101 — ассерт зелёный уже сейчас и
защищает формулировку от деградации в будущих правках.

**BR-020:** правило живёт в требовании; дизайн кодирует его первое применение двумя
механизмами: (а) граница негативного перечня FR-184 — развёртки таблиц относятся к классу
«ждёт engine-вердикта» и в writer не входят; (б) негативный контроль AC-102 — литеральные
ключи развёрток запрещены в дереве writer байтово. Включение после вердикта — тем же
изменением, что и вердикт (поток П2, триггер — первое GES-окно).

## Контракт тегов (NFR-072 прецедент — без дифа)

**`gramax-tags.json` не меняется.** Построчное обоснование:

| FR | Что вводит | Почему не тег контракта |
|---|---|---|
| FR-183 | `--`, `\`-перенос, `\$`, `\[note]`, `<!-- … -->` | Символьный уровень и стандартная markdown/HTML-форма: ни одна форма не является контентным тегом движка; контракт (`pairedTags`/`selfClosingTags`, ADR-0012) зеркалит реестр тегов, а не пунктуацию |
| FR-184 | ничего | Перечень по построению ничего не добавляет — его содержание «эти формы не существуют» |
| FR-185 | `<script>`/`<style>`/`data:`-URI внутри `<html>` | Внешний тег `<html>` уже в `pairedTags`; внутренности изолированного фрейма — обычный HTML, не Gramax-разметка; внесение их в контракт расширило бы known-набор W034 на весь каталог, а не на тело компонента |
| FR-186 | ключи frontmatter | Контракт тегов тегов не охватывает frontmatter вовсе |

Следствия: `schemaVersion` остаётся 2; окно координации NFR-072 (один релиз с правкой
контракта) не наступает — дифа нет; W034 не затронут (known-набор не меняется, новых тегов
под амнистию FR-156 не поступает); секция `Contract:` в CHANGELOG 4.8.0 не нужна — записи
`Contract:` фиксируют изменения контрактов, их нет (прецедент 4.7.0 обязателен к записи был
именно из-за дифа тегов). Инвариант требования «если SA документирует новый тег — контракт
обновляется тем же изменением» не срабатывает: новых тегов дизайн не документирует.

## Решение по ADR

**ADR не пишется.** Граница прецедента: writer-sync 4.7.0 — тот же класс артефакта
(аддитивная контентная синхронизация навыка внутри действующих контрактов) — прошёл без
собственного ADR; линия ADR-0012/ADR-0024 требует ADR при правке машиночитаемых контрактов
или валидаторов (ADR-0024 появился из-за переноса вычисления known-набора W034 в контракт) —
здесь ни контракт, ни валидатор, ни публичная поверхность плагина не меняются: скилл
существующий, файлов-структурных решений нет, `marketplace.json` не трогается. Semver-категория
(ожидаемо Minor, прецеденты 4.2.0/4.6.0/4.7.0) — зона ADR-0006, решение PM при выпуске.

таксономия suite; ADR-0006 — публичная поверхность не меняется, ожидание Minor.

## Контракт с QA-author

**AC (полный список требования):** AC-097…AC-103. Уровни: AC-097…AC-102 — integration
(bash-наборы по дереву `plugins/gramax/skills/writer/`, таксономия ADR-0011, прецедент
`tests/gramax/writer-sync-470`: один AC — один скрипт `ac-NNN-*.sh`, `lib/assert.sh`,
README с таблицей стартовых цветов); AC-103 — e2e композит (`bash scripts/check.sh --fast`,
код возврата). Фреймворк выбирает QA-author. Тестируемая поверхность — два md-файла навыка;
офлайн, без сети и auth.

**Design-derived ассерты** (сверх формул AC, каждый с пометкой источника — раскладка этого
дизайна): ac-097 — заголовок «Служебная синтаксика» и свернутый «Спецсимволы» (заголовок
отсутствует); ac-098 — замыкающий абзац классов отсутствия (маркер «ждёт»/«очередь» рядом с
«развёртками таблиц»); ac-099 — маркер «изолиров» (фрейм); ac-100 — `welcome`/`external` и
дословное «агенту не писать».

**Edge cases / границы:**

- **AC-102 — байтовый негативный контроль** (прецедент AC-079): грепы не знают markdown —
  литеральные ключи развёрток запрещены везде в дереве writer, включая код-спаны и блоки.
  Формулировки FR-184 обязаны говорить «развёртки таблиц» без литеральных ключей; этот
  дизайн называет литералы только в docs/, вне дерева writer.
- **AC-098 (`===`)** — позитивный grep негативного употребления (прецедент AC-082 `cover`):
  тест не различает «документируем отсутствие» от «используем»; смысл проверяет ревьюер,
  пример — только в ограждённом блоке.
- **AC-099 (`data:`)** — подстрока: Dev обязан употребить `data:`-форму минимум однажды;
  ревью-пункт — `data-theme` встречается именно в селекторе тёмной темы, не в прозе о данных.
- **AC-100 (`expanded`)** — цель SKILL.md, не blocks.md (там `expanded` — атрибут `<cut>`,
  останется); дизамбигуация — ревью-пункт, грепом не дёшево.
- **AC-101** — зелёный warden: слабое место — формулировка «явно запрошен» может деградировать
  при будущем редактировании Guardrails; ассерт защищает дословную фразу.
- **AC-103** — цвет внешний: изоляция suite'а до регистрации в `--full` — по брифу, как
  writer-sync-470.

## Допущения

1. Единственный источник новых утверждений — формулировки RES-007 §3/§4 (docs gram.ax);
   engine-проба для FR-183–FR-186 не проводится (D1) — все строки несут docs-пометку,
   снятие пометок и пересмотр перечня — при engine-пробе потока П2.
2. Docs не различают тип тире (короткое/длинное) и дефолт `expanded` — недокументированное
   источником не домысливается, строки справочника не конкретизируют лишнего.
3. Semver-категория 4.8.0 (ожидаемо Minor) — решение PM при выпуске; дизайн категорию не
   фиксирует.
