# Навык export — guidance-скилл экспорта DOCX/PDF: плейсмент, структура, границы, рецепты

**Опоры:** `docs/30-requirements/2026-11-18-export-skill-requirement.md`,
`docs/00-project/adr/0022-export-skill-placement.md`,
`plugins/gramax/skills/export/SKILL.md`

## Контекст

Реализация требования [Навык export — экспорт DOCX/PDF: шаблоны, CI/CD и статический
портал](../30-requirements/2026-11-18-export-skill-requirement) (FR-131…FR-139, NFR-055…NFR-058,
AC-041…AC-050). Факт-база — [RES-007](../10-domain/research/2026-11-18-enterprise-server-skill-gap):
§2 фиксирует вердикт «не покрыт» для зон `collaboration/export-docx-pdf/*`, `deploy/export-ci-cd`,
`deploy/doc-portal/export-templates`, `deploy/doc-portal/install/static-site-generator`; §3 несёт
scope-заметки — выгрузка статьи/раздела/каталога в DOCX и PDF; шаблон PDF — CSS-файл с классами
(`.page`, `.title-page`, колонтитулы); шаблон DOCX — `.docx`/`.dotx`, авторство в Word; загрузка
шаблонов на портал в `assets/pdf`/`assets/word`; `npx gramax-cli export -f docx|pdf` как стадия
`.gitlab-ci.yml` с переменной `EXPORT_FILE_PATH`; установка портала статическим сайтом через
`gramax-cli`.

Функциональность экспорта живёт в продукте (UI приложения и портала, `gramax-cli`, CI-раннер).
Навык её не дублирует — его роль та же, что у `writer` для синтаксиса: guidance. Плейсмент меняет
публичную поверхность плагина (новый скилл = additive minor по ADR-0006, правка публичного
`marketplace.json`-договора) — это зафиксировано в [ADR-0022](../00-project/adr/0022-export-skill-placement).
Настоящий документ несёт то, что ADR намеренно не несёт: план файлов, контракт триггеров, границу
исполнения, маппинг FR/NFR и тест-хуки для QA-author.

Каркас SKILL.md (порядок секций, по прецеденту sibling-навыков — FR-132):

1. frontmatter `name: export` + `description` (контракт ниже);
2. H1 и абзац роли (guidance-навык: инструктирует и готовит артефакты, не исполняет);

5. «Шаблоны экспорта» — ядро FR-133/FR-134 (PDF: CSS-файл с классами `.page`, `.title-page`,

7. «Терминология» — глоссарий `writer` (каталог, статья, раздел, `.doc-root.yaml`), собственных

8. «References» — список справочников.

## Контракт триггеров (description)

FR-131 требует в `description` слов «экспорт», «DOCX», «PDF», «шаблон экспорта», «CI/CD»,
«статический портал» в стиле writer («Используй когда пользователь…»). Целевой текст для Dev
(финальная редакция — Dev, формулировки AC-041…AC-049 обязаны матчиться):

```yaml
name: export
description: "Экспорт документации Gramax в DOCX/PDF и сборка статического портала. Используй когда пользователь просит: «выгрузи/экспортируй статью, раздел или каталог в DOCX/PDF», «сделай шаблон экспорта», «настрой оформление PDF или DOCX», «поставь экспорт в CI/CD», «собери каталог статическим порталом». Навык инструктирует и готовит артефакты: CSS-шаблон PDF (классы .page, .title-page, колонтитулы), шаблон DOCX (.docx/.dotx, авторство в Word), размещение шаблонов на портале (assets/pdf, assets/word), команду npx gramax-cli export -f docx|pdf, стадию .gitlab-ci.yml с EXPORT_FILE_PATH. Граница исполнения: запуск требует Node.js и gramax-cli в окружении пользователя или CI-раннера — навык экспорт не исполняет. Не для правки контента статей → gramax:writer; не для диаграмм → gramax:mermaid / gramax:drawio."
```

Свойства контракта:

- **Позитивные триггеры** — шесть слов FR-131 присутствуют; формулировки запросов пользователя
  («выгрузи…», «поставь экспорт в CI/CD», «собери статический портал») повторяют User Journey
  требования.
- **Негативная демаркация** — «Не для правки контента статей → gramax:writer» по паттерну
  mermaid/drawio: скиллы плагина перекрёстно ссылаются друг на друга в description, внешний
  роутер Claude Code выбирает по триггерам.
- **Граница в самом description** (Решение 3 ADR-0022): потребитель навыка читает оговорку
  «навык экспорт не исполняет» до первой генерации — ожидания не строятся на исполнении (BR-006).
- Description writer не расширяется экспортными триггерами (Q-1): шесть слов FR-131 в description
  writer ломали бы его контракт — ложные срабатывания на CI/портал-запросы, где writer бессилен.

## Граница исполнения (навык vs окружение)

NFR-055/BR-006: секция «Граница исполнения» — обязательная часть каркаса, не молчаливое допущение.
Исполнение экспорта требует Node.js и `gramax-cli` в окружении (локально или в CI-раннере) —
навыком не гарантируется. Матрица для Dev (каждая строка обязана быть проговорена в SKILL.md):

| Действие | Навык (агент в сессии) | Окружение (пользователь / CI-раннер) |
|---|---|---|
| Авторство CSS-шаблона PDF | да — пишет файл по требованиям пользователя (Write tool) | — |
| Авторство шаблона DOCX | нет — бинарный Word-формат; навык даёт инструкцию (`.docx`/`.dotx`, авторство в Word) | пользователь в Word |
| Локальный CLI-экспорт | нет — готовит команду к исполнению | `npx gramax-cli export -f docx\|pdf` |
| CI-стадия | да — готовит текст стадии как копируемый блок | раннер с Node.js исполняет |
| Загрузка шаблонов на портал | нет — инструкция placement (`assets/pdf`, `assets/word`) | пользователь/админ портала |
| Статический портал | нет — рецепт генерации + указатель на docs | пользователь; установка и деплой портала — вне навыка |
| UI-экспорт (приложение/портал) | нет — описывает путь пользователя, не имитирует действия | пользователь в UI |

Прецедент паттерна «навык готовит — внешний инструмент исполняет» — делегация в `drawio`
(two-step workflow); export обобщает тот же паттерн на окружение пользователя. Канонические
формулировки для Dev (AC-049 матчится именно на них): «навык экспорт не исполняет», «граница
исполнения», «запуск требует Node.js и gramax-cli в окружении».

## Факт-гигиена

Политика для деталей, которых RES-007 не раскрывает (открытый вопрос 4 требования) —
**verify-before-include**, продолжение BR-007/NFR-056:

1. **Правило включения.** Класс CSS, флаг CLI, путь, переменная попадает в текст навыка как факт
   ⟺ (a) раскрыта в RES-007 §3, либо (b) верифицирована на момент реализации с записью источника
   рядом с фактом. Команды верификации: `npx gramax-cli --help` и `npx gramax-cli export --help`
   (локально, Node.js 18+ — то самое окружение, которого навык не гарантирует, но которое доступно
   Dev-машине); апстрим-страницы gram.ax по путям RES-007 §1.
2. **Fallback-форма.** Деталь, не верифицированная на момент реализации (например, в окружении Dev
   нет Node.js или сети), остаётся в тексте **указателем** на источник (путь апстрим-страницы), а
   не фактом. Это не дефект приёмки: AC-041…AC-049 проверяют только RES-007-факты. Расширение
   после верификации — контентная правка навыка, без изменения архитектуры и версий (patch).
3. **Известные нераскрытые детали** на момент дизайна: полный список CSS-классов PDF-шаблона;
   флаги скоупа CLI-экспорта (статья/раздел/каталог); локальная раскладка шаблонов внутри каталога;
   точная подкоманда статической генерации портала; применимость портальных шаблонов
   (`assets/pdf`, `assets/word`) к экспорту из приложения. Все пять — кандидаты верификации п.1,
   до того — указатели.
4. **Почему не document-as-pointer как основная политика.** Указатель-без-верификации оставил бы
   навык заведомо тоньше доступной проверки: команды `--help` воспроизводимы локально и дёшевы, а
   антифабрикационная норма дома требует «значение с командой измерения либо пустое поле».
   Указатель — состояние неверифицированного факта, не альтернативный канал для постоянных
   неверифицированных деталей.

## Sample-шаблоны и валидатор

**Sample-файлы НЕ поставляются** (открытый вопрос 3 требования — решён отрицательно):

- CSS-скелет как файл `references/` либо был бы тривиально пуст (три документированных имени
  классов), либо изобретал бы свойства/классы сверх RES-007 — прямое нарушение BR-007. Файл в
  навыке копируют дословно — это де-факто контракт сильнее guidance; неверифицированный контракт
  в публичном плагине хуже его отсутствия.
- `.dotx` — бинарный формат Word; по фактам RES-007 авторство шаблона DOCX и есть «авторство в
  Word». Агент не может авторить `.dotx`; поставляемый бинарник — непроверяемый код-ревью объект
  в публичном payload.
- Инструкция (как строить шаблон по документированным классам + указатель на полный список) —
  ровно та форма, которую требование объявляет in-scope («как инструкция, не как готовые образцы»).

**Скрипт-валидатор НЕ пишется** (открытый вопрос 5 — решён отрицательно): предмет проверки
(«обязательные классы CSS-шаблона») не раскрыт RES-007 — валидатор на изобретённом обязательном
наборе нарушает BR-007; цель валидации (`assets/pdf`/`assets/word` на портале) лежит вне дерева,
который сканируют валидаторы плагина (ADR-0012). Триггер пересмотра — верификация полного списка
классов по политике §«Факт-гигиена»: тогда WARN-линтер присутствия документированных классов
становится возможным как отдельная задача (прецедент `validate_render.py`, ADR-0019).

## Релизная поверхность

## Контракт с QA-author

**Suite:** `tests/gramax/export-skill/` (таксономия ADR-0011). **Уровни:** unit неприменим — в
навыке нет исполняемого кода; AC-041…AC-049 — integration (проверки артефактов: файлы,
frontmatter, контент-грейпы); AC-050 — e2e (композитный гейт). Фреймворк выбирает QA-author.

**Хуки по AC:**

| AC | Предмет | Хук |
|---|---|---|
| AC-041 | существование + frontmatter | `test -f $S`; грейпы `^name: export`, слов «экспорт/docx/pdf» в frontmatter |
| AC-042…AC-044 | факты шаблонов | грейпы `.page`, `title-page`, колонтитул/header/footer, `dotx`, `word`, `assets/pdf`, `assets/word` |
| AC-045…AC-048 | рецепты | грейпы `gramax-cli export`, `-f docx\|pdf`, `gitlab-ci`, `EXPORT_FILE_PATH`, статическ/static + `gramax-cli`, приложени/раздел/каталог |
| AC-049 | граница | грейпы `node` + альтернации «не исполняет\|не запускает\|инструктир\|границ» |
| AC-050 | композит | `bash scripts/check.sh --fast` по коду возврата |

**Edge cases / boundary conditions:**

- Экранирование литерала `-f docx|pdf` в regex AC-045 — пайп в альтернативе; тест обязан
  матчить и ветку `-f pdf` (запасная форма требования).
- AC-049 хрупок на синонимах: Dev использует канонические формулировки §«Граница исполнения»
  («навык экспорт не исполняет», «граница исполнения») — грейп матчит их, а не произвольную
  парафразу.
- Негативный кейс триггеров: description export не содержит авторинг-триггеров writer
  («создаёт/редактирует статьи») — иначе ложный маршрутинг; симметрично, description writer не
  содержит экспортных слов.
- Структурный кейс FR-132: оба `references/`-файла существуют и зарегистрированы в SKILL.md
  (секция References).
- Кросс-ссылка: `gramax:export` присутствует в writer SKILL.md (раздел «Ресурсы»), ровно одна
  строка, description writer не изменён.
- Релизная поверхность: согласованность версий `plugin.json`/`marketplace.json`/CHANGELOG —
  существующий suite `tests/gramax/plugin-contract/` (ac-006 manifest-coherence); проверить
  покрытие или дополнить.
- NFR-056 (отсутствие изобретений) грепом не проверяется — процессная ревью-проверка по
  источникам, отмеченным в тексте навыка.
