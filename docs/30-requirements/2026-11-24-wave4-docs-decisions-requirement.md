## Функциональные требования

### A. Документарная гигиена (AC — наблюдаемое состояние дерева)

- **FR-242 (маркер «Опоры», gramax-o0q.14):** проход по корпусу `docs/`, после которого каждая
  статья с «Тип контента» из словаря несёт в шапке маркер «Опоры» с конкретными tracked-файлами
  либо объявленный отказ — других форм гейт не знает (факт 5). Правило классов: источники
  декларируют статьи, у которых они есть; статья без осмысленных источников (append-only журнал
  уроков, информационные записи) использует форму отказа с названной причиной; `_index.md` вне
  выборки гейта. Вход волны, ещё не закоммиченный, именуется в теле с пометкой «вне индекса на
  момент письма», строку маркера дополняет PM коммитом входов (урок 2026-11-21). Проход входящих
  ссылок не создаёт и судьбу FR-090 сам не решает — она снята записью D11 (см. FR-249).
- **FR-243 (конвенция статусов, gramax-o0q.15):** переход статуса требования — по событию, не
  по памяти: Draft с момента посадки статьи; Accepted — по записи at-acceptance с вердиктом pass
  (событие — коммит записи приёмки); Done — по релизной записи в `plugins/gramax/CHANGELOG.md`
  и версии `plugin.json` (событие — релизный коммит). Исполняет PM в коммиттерском окне (D15 —
  единственный коммиттер этапа); написание статуса единообразно по корпусу и совпадает со
  словарём «Статус»; Proposed конвенция не требует — требование попадает в дерево только при
  открытой волне, начального Draft достаточно. Словарь «Статус» ожидается без изменений
  (исход — ADR-0030); конвенция фиксируется указателем в ADR-0030 или уроком журнала.
- **FR-244 (TPL-69, gramax-o0q.16):** семь склеенных абзацев переформатированы без изменения
  смысла (факт 9; переформатирование ADR-0020 санкционировано D3); смысл правит не исполнитель —
  перенос строк только. Исполняет tech-writer этой же волны, после прохода — повторный замер.
- **FR-245 (RES-007, gramax-o0q.18):** research несёт обратную markdown-ссылку на требование
  export (форма FR-089: предшественник получает ссылку на реализацию), строки :280 и :285
  приведены к факту приземления навыка (коммит 1409740) с указанием даты; проверка семантики
  роутинга триггеров export исполняется либо завершается вердиктом «не проверено» с причиной —
  карточка разрешает второй исход.
- **FR-246 (асимметрия плейсхолдеров, gramax-o0q.20):** документация плагина описывает обе
  стороны строгости по ADR-0012:223-224: плагин — error, контур nauta — C7 warning

## Нефункциональные требования

- **NFR-089 (гейт не краснеет от волны):** документарный проход оставляет быстрый гейт зелёным

  существующих сюит и фикстур сохраняется (наследник NFR-084 волны-3).
- **NFR-090 (приватность новых текстов):** новые и правленые статьи волны не несут внутренних
  имён хостов, приватных репозиториев и организаций, токенов и персональных контактов; маскировка
  — по конвенции disposition и прецеденту `docs/onboarding-nauta.md`.
- **NFR-091 (одно решение — одна запись):** каждое решение владельца волны имеет ровно одну
  именованную точку записи в дереве (ADR-0030, карточка, запись приёмки), находимую grep'ом;
  решение, живущее только в сообщении коммита или в чате, приёмку не проходит (урок факта 17).

## User Journey

1. Dev/tech-writer проводит проход «Опоры» и переформатирование → `--fast` зелёный без
   предупреждений; PM коммитит входы волны и дополняет строки маркеров.
2. PM в релизном окне выставляет статусы по конвенции → шапки требований говорят правду о
   реализации; реестр диапазонов получает строку волны.
3. SA регистрирует ADR-0028/0029/0030 → каждое решение владельца читается в именованном узле;
   disposition и дайджест встают в свои дома.
4. Координатор подаёт внешние issues после подтверждения владельцем → карточки несут ссылки.

Альтернативный путь: часть проверок недоступна из репозитория (GES-окно, триггеры export) —
вердикт «не проверено» с причиной, записанный в именованном узле, проходит приёмку.

## Бизнес-правила

- **BR-031 (опоры — провенанс, не истина):** маркер «Опоры» утверждает «якоря уже в
  tracked-дереве», а не «статья верна» (ADR-076 Д3); ссылаться можно только конкретными
  tracked-путями, каталоги и несуществующие пути не резолвятся; вход волны вне индекса
  именуется в теле с пометкой, строку маркера дополняет PM коммитом входов (уроки журнала
  2026-11-21).
- **BR-032 (поправки старых ADR — только в ADR-0030):** строка-поправка к ADR-0006, ADR-0012,
  ADR-0014, ADR-0016 или ADR-0017 живёт внутри ADR-0030 и поимённо называет поправляемый узел;
  сами старые ADR не редактируются; решение без записи в именованном узле исполнением не
  считается (BR-031, NFR-091).

## Инварианты и Safeguards

**Содержательные:**

- Все числа фактов — замеры 2026-11-24 на f551d87 с командами в источнике; замеры бида карточек
  датированы тем же днём на db24aec и процитированы как есть.
- Гейт не ослабляется: проход «Опоры» добавляет декларации, а не отключает проверки (NFR-089);
  смысл переформатированных текстов не меняется (D3).
- История git не переписывается; регрессионные фикстуры и `tests/gramax/archive/` неприкосновенны
  (D8); вердикты «не проверено» принимаются только с причиной (D12).
- Диапазоны FR-242…FR-261, AC-189…AC-213, NFR-089…NFR-091, BR-031…BR-032 закреплены за этой
  статьёй; в остальных статьях идентификаторы волны только цитируются.

**Sensitive content:** приватный шаблон, имена хостов и токены в статью не выписываются —
наблюдаемое — счётчик нуля после прохода (FR-255); маскировка по прецеденту
`docs/onboarding-nauta.md`; литералов персональных данных статья не создаёт.

**Жизненный цикл:** конвенция статусов и правило маркера пересматриваются при смене формы гейта
или словаря (через ADR); записи решений владельца не редактируются задним числом — новая
редакция живёт новой строкой-поправкой в ADR-0030. Owner — сопровождающий репозитория (PM).
