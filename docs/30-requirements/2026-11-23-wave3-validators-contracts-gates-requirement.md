# Волна-3 — релиз 4.10.0: калибровка контрактов валидаторов, гейтов и хвостов гигиены

**Контур И:** файл целиком уезжает в стор (Фаза 3) — собственной capability у него нет.

## Уезжает в стор (Фаза 3)

Все разделы ниже уезжают в стор в Фазе 3 целиком; контракты задач живут в этом файле и в
ADR-0026/ADR-0027, пара дрейфа с openspec/ не объявляется. В скоупе навыка волна новых умений не
добавляет — она калибрует контракты валидаторов по факту движка и чинит гейты репозитория.

## Источники и статус решений

Требование — поток волны-3 по [дереву решений генезиса: волна-3](../00-project/epics/2026-11-23-wave3-contracts-gates-genesis-tree.md)
(далее — дерево волны-3). Решения D1–D8 приняты владельцем 2026-11-23 и не переобсуждаются; решения
волн 1–2 наследуются, кроме одного — политика живой ноги пересмотрена D5 (поправляет D8 волны-2).
Доказательная база — эпики `gramax-4jf` (12 дефектов) и `gramax-o0q` (44 хвоста, 9 в волне) в store
beads (`bd show <id>`), замеры 2026-11-23 на HEAD 43435c7. Нумерация за волной-2 (FR-187…FR-207,
AC-104…AC-128): волна занимает FR-208…FR-221, AC-129…AC-151, NFR-084…085, BR-025…027. Механику
несёт SA: контракты — ADR-0026 (gramax-4jf.1), живая нога — ADR-0027 (пишутся параллельно).

## Scope

### In scope

- Контракты валидаторов: пересмотр по движку с дословной фиксацией целевых значений в ADR-0026 и
  вердикт по properties (FR-208, FR-209).
- Девять правок валидаторов и навыков по подтверждённым дефектам (FR-210…FR-218).
- Гейт: политика живой ноги (D5) и подключение сюит с собакаедством (FR-219, FR-220).
- Тексты, записи и реестр идентификаторов (FR-221).

### Out of scope (явные non-goals)

- Усиления из gramax-skills (оракул портала, контур публикации, самодостаточный рецепт drawio) и
  заявка в ИИ-офис — вне скоупа `gramax-4jf`, отдельное решение владельца о пути публикации (D7).
- Документарная волна: маркер «Опоры» по корпусу docs/, статусы Draft у 12 реализованных требований,
  6 предупреждений TPL-69 — вне волны (D3).
- Решения владельца (gitsd-копия, приватность публичного репозитория, корневой CHANGELOG), сессия
  замеров на портале и GES-окно — по своим триггерам, внешние окна (D7).
- Форма пустых answers не меняется: обе формы штатны (факт 9); скобочная legacy-форма комментария
  сохраняется — миграция потребителей не входит в волну.

## Функциональные требования

### A. Контракты валидаторов (D8, ADR-0026)

- **FR-208 (ADR контрактов):** SA-задача gramax-4jf.1 выпускает ADR-0026 с дословными целевыми
  значениями пяти контрактов по движку 48592b36: language вне обязательных полей
  `.doc-root.yaml`; table/tr/td в `gramax-tags.json` с подъёмом schemaVersion (прецеденты ADR-0012,
  ADR-0024); судьба W035/BR-013 по голым kebab-кодам Lucide; правило «подпапка без `_index.md`»
  с учётом флага optionalCategoryIndex; severity для properties по вердикту FR-209. JSON и код SA
  не правит — правки исполняет Dev под красными заглушками (D8, BR-025); механика (реестр Lucide,
  модель строгости) — ADR-0026.
- **FR-209 (вердикт properties):** проверка gramax-4jf.2 завершается записанным вердиктом о видимом
  эффекте properties у `_index.md` (фильтры `<view>`, карточка раздела или отсутствие эффекта) со
  ссылкой на место в движке; severity правила валидатора, формулировка в writer и число ERROR на
  products-legacy приводятся к вердикту.

### B. Правки валидаторов и навыков (эпик `gramax-4jf`)

- **FR-210 (мультипозиционный ID):** повторный ID комментария в md перестаёт быть ошибкой — несколько
  позиций разметки у одного ID штатны (факт 2); validate_comments не выдаёт «duplicate comment id»,
  операция delete в comments-write описана как снятие всех позиций ID, comments-read говорит о
  нескольких позициях.
- **FR-211 (XML-форма блочного комментария):** parse_comments.py, validate_comments.py и навыки
  comments-read/comments-write распознают обе блочные формы — XML (самозакрывающийся открывающий
  `<comment id="ID"/>`, текст, закрывающий `</comment>`) и скобочную legacy; навыки называют
  XML-форму каноном для syntax: XML; парность той же формы учитывает и validate_structure.py.
- **FR-212 (битый UTF-8 без падения):** файл с оборванным многобайтовым символом даёт именованный
  ERROR с путём и позицией байта — без traceback и без обрыва обхода; обязательна для
  validate_render.py и validate_structure.py, проверяется то же для parse_comments.py и
  validate_comments.py; механика апстрима (read_page, MIT-порт по ADR-0019) берётся как есть.
- **FR-213 (language необязателен):** `.doc-root.yaml` без language не даёт «missing field:
  language»; присутствующее поле проверяется по типу как прежде; README плагина,
  `gramax-catalog-rules.json` и справочник doc-root-schema говорят одно (правка по ADR-0026).
- **FR-214 (теги таблицы):** table/tr/td входят в известные теги валидатора через `gramax-tags.json`
  (schemaVersion поднят), W034 на XML-таблицах уходит; баланс этих тегов не дублируется — одна
  находка на дефект, от validate_render (BR-027); строка Contract: в CHANGELOG.
- **FR-215 (иконки Lucide):** W035 перестаёт срабатывать на встроенных кодах Lucide (голый
  kebab-case — факт 5); пользовательская иконка без файла `.icons/<код>.svg` по-прежнему находится;
  writer и валидатор согласованы о форме кода (механика — ADR-0026).
- **FR-216 (маска сырого HTML и плейсхолдеры docs/):** содержимое блоков `<html>…</html>` маскируется
  от построчных проверок и баланса (общий примитив рядом с lib/md_code_mask.py, механика html_mask) —
  теги внутри не дают W034/W035 и не входят в проверки validate_render; `<html>` внутри кода маску
  не переключает. Тот же контур снимает 3 W034-плейсхолдера на docs/ (gramax-o0q.12: формулировка
  или code-span).
- **FR-217 (optionalCategoryIndex):** правило «подпапка без `_index.md`» читает флаг каталога:
  с optionalCategoryIndex: true ошибки нет; без флага ERROR остаётся с верной формулировкой —
  раздел не появится в дереве, статьи поднимутся на уровень выше; флаг описан в справочнике
  `.doc-root.yaml`, формулировка writer исправлена («статьи внутри недоступны» — неверно).
- **FR-218 (user.id в ответах):** шаблон ответа comments-write несёт id, равный mail, под user;
  validate_comments предупреждает об ответе без user.id; формы с пустыми answers (обе, факт 9)
  не меняются и проходят.
- **FR-219 (политика живой ноги, D5):** живой прогон прибора выводится из `--full` в именованный
  отдельный шаг релизного ритуала: `--full` зелёный в стационарном состоянии — без опубликованных
  проб и без сети; шаг замера отказывается поимённо с рычагом офлайна (UV_OFFLINE=1 — в runbook и
  README сюиты), когда сеть или цель недоступны; D8 волны-2 перефиксировано в эпике. Хост шага —
  ADR-0027.
- **FR-220 (гейт и сюиты):** (а) cross-catalog-retraction и docs-migration получают явный статус —
  подключение к `--full` (шаг в check-gramax.sh и строка заголовка) либо перенос в
  tests/gramax/archive/ с записью; (б) validate_structure.py и validate_comments.py входят в
  `--full` с порогом 0 ERROR на docs/ (после правок группы B); оставшиеся предупреждения закрыты
  или приняты с записью; (в) мёртвый overlay-тулинг — apply-overlay.sh и четыре хелпера
  (`_init_helpers.py`, `_resolve_agents.py`, `_apply_profile.py`, `_apply_yaml_patch.py`)
  со ссылками на docs/overlays/ и несуществующий scripts/init.sh — удалён с записью в
  sunset-registry либо переключен на templates/overlays/ со смоком.
- **FR-221 (тексты, записи, реестр идентификаторов):** (а) README плагина называет актуальную
  версию, докстринг validate_render согласован с `gramax-render-rules.json` (th — WARN с 4.9.0),
  проверка версии в сюите краснеет при расхождении; (б) CLAUDE.md и корневой README соответствуют
  дереву (состав навыков, ref nauta, описание `--full`, блок предусловий ADR-0008/RES-001); (в)
  README сюит и заголовок check-gramax.sh перечисляют фактический состав; (г) CHANGELOG получает
  запись калибровки волны-1, маркер «Опоры» — в шапке той записи; (д) коллизия AC-061/AC-062
  устранена перенумерацией диапазона validators-parity, заведён реестр владения FR/AC/NFR/BR.

## Нефункциональные требования

- **NFR-084 (сила сюит сохраняется):** адаптация фикстур переводит ассерты на новую семантику и не
  ослабляет их: негативы, границы и rc-контракты продолжают проверять факт; удаление или
  обезвреживание ассерта вместо перевода — дефект адаптации (преемник NFR-083 волны-2); гейты не
  ослабляются (NFR-079 волны-1).
- **NFR-085 (стационарная детерминированность гейта):** `--full` в стационарном состоянии не требует
  сети, опубликованных проб и токена; сетевые и внешние шаги живут только в именованном шаге замеров
  и отказываются поимённо (D5); «зелёного без прогона» нет ни в одном пути волны.

## User Journey

1. Сопровождающий правит контракты по ADR-0026 под красными заглушками → прогон на products-legacy
   даёт 0 ложных ERROR/W034/W035 и ни одного traceback → строка Contract: в CHANGELOG, версия 4.10.0.
2. Релизный ритуал: `--full` зелёный на чистом дереве → именованный шаг замера на портале → уборка проб.
3. Потребитель получает согласованную тройку «правило — README — навык» по каждому контракту.
4. Автор сюиты берёт свободный AC-номер из реестра владения — коллизий больше нет.

Альтернативный путь: сеть или цель недоступны → именованный отказ шага замера с рычагом офлайна
(FR-219), гейт остаётся зелёным.

## Бизнес-правила

- **BR-025 (контракт через ADR):** целевые значения опубликованных контрактов валидаторов меняются
  только решением, зафиксированным дословно в ADR (волна — ADR-0026); JSON и код правит Dev под
  красными заглушками QA-author — правка кода без дословной записи в ADR приёмку не проходит (D8).
- **BR-026 (вердикт по факту):** severity правила меняется только по факту движка (файл:строка на
  пине 48592b36) или замера корпуса с указанием источника; ни одного изменения «по впечатлению»
  (наследник BR-021 волны-1 в контуре офлайн-валидаторов).
- **BR-027 (один дефект — одна находка):** баланс парных тегов ведёт один валидатор;
  validate_structure не дублирует баланс validate_render — один дефект даёт одну находку
  (расширение семантики AC-160 на теги таблицы).

## Инварианты и Safeguards

**Содержательные:**

- Вердикты и контракты меняются только по факту движка/корпуса с источником (BR-026) и через
  дословную запись в ADR-0026 (BR-025); числа фактов (999, 90, 43, 16, 21/21) — замеры 2026-11-23.
- Обе формы пустых answers и скобочная legacy-форма сохраняют силу; обратная несовместимость
  фиксируется строками Contract: и подъёмом версии (D6).
- Сюиты сохраняют силу при адаптации (NFR-084); гейты не ослабляются; `--fast` живой ноги не
  касается (наследие NFR-078 волны-1).
- Диапазон AC-152…AC-163 закреплён за перенумерованным validators-parity (AC-150); пуш — D6,
  решения D7 — вне волны.

**Sensitive content:** N/A по PII — персональных данных правки не создают; user.id в шаблоне
ответа — служебное поле движка (значение равно mail), литеральных адресов в репозиторий нет;
токен и хост портала — вне волны (режимы NFR-081 волны-1).

**Жизненный цикл:** ревизия контрактов — при смене пина движка или следующем сравнении с
gramax-skills; реестра — при открытии нового диапазона. Owner — сопровождающий репозитория (PM).
