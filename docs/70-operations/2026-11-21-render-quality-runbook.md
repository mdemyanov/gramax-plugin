# Runbook: прибор рендер-проб Playwright — прогрев, цель рендера, пробы и калибровка validate_render

**Опоры:** `docs/40-architecture/2026-11-21-playwright-render-quality-design.md`,
`docs/30-requirements/2026-11-21-playwright-render-quality-requirement.md`,
`docs/60-implementation/acceptance/2026-11-21-playwright-render-quality-at-acceptance.md`,
`tests/gramax/render-quality/README.md`, `scripts/render-quality/render-target.example.json`,
`scripts/render-quality/warm.sh`, `scripts/render-quality/probe.sh`

Прибор рендер-проб (`scripts/render-quality/`) меряет факт рендера портала-цели по
фикстурам и служит оракулом для калибровки локального валидатора `validate_render.py`.
Документ для сопровождающего репо: он знает git и гейты, но не внутренности прибора.
Драйвер инструментария — `uv` (корневого `package.json` в репо нет; Playwright входит
питон-биндингом без npm-поверхности — ADR-0025).

## Когда этот runbook

Точка входа — именованные отказы прибора. Гейт `scripts/check-gramax.sh --full` на шаге 18
(`==> render-quality`) вызывает `bash tests/gramax/render-quality/run.sh`; живой прогон
прибора на неготовом окружении завершается баннером `REFUSAL <КОД>: <подсказка>` с rc=2.

| Симптом в выводе `--full` | Что случилось | Раздел |
|---|---|---|
| `REFUSAL RENDER_TARGET_UNSET` | цель рендера не сконфигурирована (нет конфига и env-полей) | [Настройка цели](#настройка-цели-рендера) |
| `REFUSAL RENDER_TARGET_INVALID` | конфиг есть, но дефектный — подсказка называет поле | [Настройка цели](#настройка-цели-рендера), [Диагностика](#диагностика-отказов) |
| `REFUSAL PLAYWRIGHT_UNAVAILABLE` | `import playwright` не проходит при tier-1/2 в скоупе — типично запуск прибора мимо `probe.sh` | [Прогрев](#прогрев-окружения) |
| `REFUSAL PLAYWRIGHT_NO_BROWSER` | playwright есть, chromium не установлен | [Прогрев](#прогрев-окружения) |

Другие поводы: запушить фикстуры на цель ([Пуш фикстур](#пуш-фикстур-на-цель)), прогнать
замер калибровки FR-196 — закрытие AC-115/116 ([Протокол замера](#калибровочный-протокол-fr-196)),
перезапустить гейт после переиндексации ([Пробы и вердикты](#пробы-и-вердикты)).

Не этот runbook: rc=1 — это вердикт прогона (есть расхождения), а не отказ окружения;
читай отчёт `results/report.md`. В `--fast` прибора нет никогда — `--fast` прибор не касается.

## Прогрев окружения

```bash
bash scripts/render-quality/warm.sh
```

Скрипт делает ровно три шага и идемпотентен — повторный запуск ничего не ломает и
сходится к зелёному `check-env`:

1. Кэш uv для `playwright==<пин>` — пин читается одной строкой из `probe.sh`
   (`PLAYWRIGHT_PIN`), единственный дом пина.
2. `playwright install chromium` — браузер ставится в штатный пользовательский кэш
   playwright, вне репо (vendoring запрещён).
3. `probe.sh --check-env` — проверка лестницей: цель → импорт playwright → запуск браузера.

Проверяемый исход: последняя строка `check-env: OK (цель, импорт playwright, запуск
chromium)`, rc=0.

Нюансы:

- Шаги 1–2 требуют сети; их падение — `FAIL: warm …` на stderr, rc=2. Повтори после
  проверки сети.
- `check-env` требует сконфигурированной цели: проверка цели идёт до любого обращения к
  playwright. На машине без цели `warm.sh` завершится rc=2 с `REFUSAL RENDER_TARGET_UNSET`
  — это значит «окружение прогрето, цель не задана»; переходи к настройке цели.
- Обёртка uv в `probe.sh` (прецедент ADR-159) распознаёт офлайн-промах кэша uv по
  суженной сигнатуре и добавляет к stderr рычаг `bash scripts/render-quality/warm.sh`;
  rc передаётся насквозь. Сигнатура не совпала — вывод нетронут.

## Настройка цели рендера

```bash
cp scripts/render-quality/render-target.example.json scripts/render-quality/render-target.local.json
```

Файл цели — вне git (строка `.gitignore:30`). Проверяемый исход:

```bash
git check-ignore -v scripts/render-quality/render-target.local.json
# .gitignore:30:scripts/render-quality/render-target.local.json	scripts/render-quality/render-target.local.json
```

Затем заполни поля. Откуда значение:

| Поле | Откуда значение | Контракт прибора |
|---|---|---|
| `baseUrl` | хост портала цели — данные владельца цели | непустая строка; схема http(s). Прибор хост не изобретает |
| `catalog` | слаг выделенного каталога проб на портале, например `render-probes` (каталог создаёт владелец цели) | непустая строка |
| `apiArticleUrlTemplate` | дефолт из примера `{base}/api/catalogs/{catalog}/articles/{slug}/html` — проверенная форма апстрим-оракула (RES-009 §4) | менять, только если API портала отличается; подстановки `{base}`, `{catalog}`, `{slug}` |
| `pageUrlTemplate` | **живая форма** `{base}/{catalog}/{slug}` — данные владельца цели (волна-2, D3); `{slug}` — последний сегмент пути (лист), отдельного сегмента страницы у живой формы портала нет; прибор форму не выдумывает | обязателен, когда `tiers` содержит `tier1`/`tier2`; обязан содержать `{slug}` |
| `token` | токен цели: `null` в конфиге и `GRAMAX_API_TOKEN` в env (предпочтительно) — либо строка в конфиге | никогда не коммитится (NFR-081); в коде, отчётах и логах его нет |
| `tiers` | `["tier0", "tier1", "tier2"]` из примера | опционально; допустимы ровно эти три значения |
| `viewport` | `{ "width": 1280, "height": 720 }` | публичные данные; фиксирует скриншоты между прогонами |

### env-переопределения и старшинство

| Переменная | Замещает поле |
|---|---|
| `GRAMAX_RENDER_BASE_URL` | `baseUrl` |
| `GRAMAX_RENDER_CATALOG` | `catalog` |
| `GRAMAX_API_TOKEN` | `token` (имя переменной — ровно апстримное, RES-009 §4) |

Старшинство: env-поля ложатся поверх полей дефолтного файла
`render-target.local.json`. Если файла нет — env единственный источник, и тогда нужны
обе переменные `GRAMAX_RENDER_BASE_URL` и `GRAMAX_RENDER_CATALOG` (без каталога валидация
даст `RENDER_TARGET_INVALID` по полю `catalog`). Нюанс: при явном `--config <путь>` env
не применяется — файл единственный источник (это шов для тестов).

### Гигиена хоста (FR-195, AC-114)

Единственный коммитимый файл прибора с литералом `https://` — `render-target.example.json`,
и там хост-заполнитель `.invalid` (RFC 2606). Реальный хост живёт только в gitignore-конфиге
и env; stdout прибора зеркалит отчёт и называет цель целиком — вставка прогона в
коммитируемый документ запрещена. Проверяемый исход после конфигурации реального хоста:

```bash
git grep -n "<литерал реального хоста>"
# пусто — обязано быть пустым по всему отслеживаемому дереву
```

Проверяемый исход настройки:

```bash
bash scripts/render-quality/probe.sh --check-env
# check-env: OK (цель, импорт playwright, запуск chromium)
```

## Пробы и вердикты

```bash
bash scripts/render-quality/probe.sh; echo "rc=$?"
```

Дефолтные пути: фикстуры `tests/gramax/render-quality/fixtures/`, отчёт
`tests/gramax/render-quality/results/report.md` (каталог gitignored, `.gitignore:31`),
stdout зеркалит отчёт. Скриншоты — `tests/gramax/render-quality/results/screenshots/<слаг>.png`.

Флаги (сверены с `probe.py`):

| Флаг | Дефолт | Назначение |
|---|---|---|
| `--config <путь>` | `scripts/render-quality/render-target.local.json` | шов для тестов; env при нём не применяется |
| `--fixtures <каталог>` | `tests/gramax/render-quality/fixtures/` | набор фикстур; каталог обязан существовать |
| `--report <путь>` | `…/results/report.md` | путь отчёта; скриншоты кладутся рядом, в `<каталог отчёта>/screenshots/` |
| `--check-env` | выкл | только лестница цель → playwright → браузер; без тиров и отчёта |
| `--retry N` | 2 | ретраи только по ≥500 (итого N+1 попытка) |
| `--retry-wait SEC` | 5 | пауза между ретраями; операционный параметр, не окно |
| `--jobs N` | 8 | параллелизм tier-0 |

rc-семантика: `0` — расхождений нет; `1` — есть расхождения (отчёт написан); `2` —
именованный отказ окружения (баннер `REFUSAL <КОД>: <подсказка>`, отчёт не пишется).
Гейт краснеет на любом rc≠0.

Факт-состояния tier-0 и операционный смысл:

| Состояние | Что значит | Действие |
|---|---|---|
| `OK 2xx` | страница отдала 2xx | факт рендера; вердикт сверяется с ожиданием фикстуры |
| `STABLE_5XX` | 5xx пережил bounded ретрай | нота «кандидат на переиндексацию». 500 сразу после пуша — не диагноз; перезапусти прогон после переиндексации |
| `NOT_FOUND 404` | страницы на цели нет | обычно фикстура не запушена или переиндексация; проверь пуш (раздел «Пуш фикстур») |
| `HTTP_4XX` | прочие 4xx | 401/403 — нота про токен: проверь `GRAMAX_API_TOKEN`/поле `token` |
| `NETWORK_ERR` | цель не достигнута | нота про доступ к внутреннему хосту: сеть, VPN, имя хоста |

Матч факта с ожиданием: ожидание лежит рядом с фикстурой в `<слаг>.expect.json`
(`"tier0": "ok" | "kill" | "either"`). `NOT_FOUND`, `HTTP_4XX`, `NETWORK_ERR` —
расхождение всегда: это не факт рендера, а недоступность страницы, судить нечего.
tier-1 (DOM-ассерты по человекочитаемой странице) судится только при `OK 2xx` и когда
ожидание несёт `"tier1": "pass"` (или `"fail"`) с непустым `asserts`; `"tier1": "any"`
или пустой `asserts` — строка `any (не судится)`, тишины нет;
tier-2 (скриншоты) — артефакт вне агрегата вердикта: `tier2: missing` — примечание,
не красность.

Окно переиндексации: измеренные 5–10 минут принадлежат другому инстансу
(внутренний инстанс апстрима — хост не публикуется, ADR-0014; RES-009 §6); для gram.ax
окно **не установлено** и числом не
кодируется (NFR-080) — ретрай даёт состоянию имя, а не выжидает окно, констант сна в
приборе нет. Гейт вправе честно краснеть сразу после пуша; перезапуск после
переиндексации — операционная норма (риск R3 дизайна).

Контекст сюиты: `bash tests/gramax/render-quality/run.sh` — 12 офлайн-стабов плюс живой
прогон прибора с дефолтными путями; rc агрегата — вход шага 18 `--full`. На непрогретой
машине живой прогон даёт именованный отказ → сюита красная → `--full` красный
(D8: отказ, а не «зелёный без прогона»).

## Пуш фикстур на цель

Стандартная git-рутина сопровождающего, без автоматизации (D4: sync/push-навыки не
строятся никогда). Инварианты рутины:

- Каталог-приёмник — выделенный каталог проб на портале, слаг из поля `catalog` конфига
  (например `render-probes`); смешивать его с контентом реальной документации нельзя.
- Слаг страницы = имя файла фикстуры без `.md` (плоский нейминг, FR-187).
- Пушатся все 21 `.md`-фикстуры из `tests/gramax/render-quality/fixtures/`, включая
  `invalid-utf8.md` как есть: файл намеренно не является валидным UTF-8 (обрыв посреди
  двухбайтового символа — семантика апстрима); копируется байтово, без правок и
  перекодировок.
- Файлы `.expect.json` на цель не пушатся — это данные прибора (ожидания), прибор читает
  их из репо, а не с цели.
- До пуша `NOT_FOUND` — ожидаемое состояние, а не дефект (Решение 4): дрейф «фикстура в
  репо, страницы на цели нет» прибор называет нотой, не молчит.

Четыре A/B-твина (`colgroup-multiline-ok`, `xml-in-html-comment-ok`, `tag-fragment-tail-ok`,
`invalid-utf8-ok`) — сторона «после» для строгого подтверждения детекторов (FR-198): твин
различается с дефект-сиблингом ровно одной конструкцией. На цели они должны существовать
до A/B-замера.

Проверяемый исход: до пуша живой прогон называет `NOT_FOUND` по ещё не существующим
страницам; после пуша и переиндексации `NOT_FOUND` уходит, факты сходятся с ожиданиями
(`summary: fixtures=21 match=21 divergence=0`, rc=0 — если цели и ожидания согласованы).

## Калибровочный протокол FR-196

Назначение: сопоставить вердикты локального валидатора `validate_render.py` с фактом
рендера на цели и менять вердикты только по замеру (BR-021…BR-024). Предусловия:
прогрев и цель зелёные по `--check-env`, фикстуры запушены и переиндексированы —
два прогона прибора подряд дают стабильные факты.

1. **Прогон прибора** — `bash scripts/render-quality/probe.sh; echo "rc=$?"`; отчёт
   `tests/gramax/render-quality/results/report.md` несёт tier-0 факт по каждой фикстуре.
2. **Прогон валидатора по тем же фикстурам, исключая байтовую**:

   ```bash
   find tests/gramax/render-quality/fixtures -name '*.md' ! -name 'invalid-utf8.md' -print0 \
     | xargs -0 uv run plugins/gramax/scripts/validate_render.py
   ```

   Исключение обязательное: локальный порт валидатора падает на невалидном UTF-8
   необработанным исключением и прекращает обход (факт 4 RES-009; FR-198, D7). Твин
   `invalid-utf8-ok.md` — обычный валидный файл, в прогоне остаётся. rc валидатора:
   `0` — ERROR нет; `1` — есть ERROR (на дефект-фикстурах это ожидаемый замер, не авария);
   `2` — ошибка использования.
3. **Сопоставление**: помеченные валидатором ERROR против факта tier-0; точность
   помеченных считается из отчёта (апстрим-прецедент: 13 % → 100 %).
4. **Разбор расхождений до источника** — обязательный шаг протокола; перечень источников
   входит в запись замера.
5. **Решения по классам**, каждое обусловлено фактом:
   - severity-понижение `note-in-cell`/`note-in-note` (FR-197) — только если те же
     фикстуры отдали HTTP 200;
   - заведение нового ERROR-детектора из четырёх (`colgroup-multiline`,
     `xml-in-html-comment`, `tag-fragment-tail`, `invalid-utf8`, FR-198) — только по
     собственному «500 до правки, 200 после» (BR-024); A/B-твины — сторона «после»
     этого замера;
   - неподтверждённое — место в WARN либо правило не заводится вовсе (BR-023).
6. **Культура мисдиагнозов** (BR-021…BR-024, журнал уроков): «фикс без оракула — не
   фикс, а гипотеза» (BR-021); два неподтверждённых изменения подряд — стоп, работа с
   вердиктами останавливается до разбора расхождений до источника (BR-022);
   неподтверждённое правило живёт в WARN, не в ERROR (BR-023).
7. **Запись замера**: `docs/60-implementation/acceptance/2026-MM-DD-render-calibration-<slug>.md`
   (frontmatter `Тип контента: [Тест-отчёт]`; `**Опоры:**` на требование, дизайн,
   `gramax-render-rules.json`, `validate_render.py`). Тело — таблица замера из девяти
   полей записи: Правило/детектор (id); Класс изменения; Набор фикстур (имена + `tableRow`);
   `validate_render` до правки (перечень ERROR файл:строка); tier-0 факт (HTTP-вердикты
   из отчёта прибора); «500 до правки, 200 после» (да/нет + ссылки на два отчёта);
   Расхождения и их источники; Решение; Прогоны (rc валидатора, rc прибора, дата).
8. **Совместная посадка**: правка кода `validate_render.py` (+ правка
   `gramax-render-rules.json`, если детектор контрактный) и запись замера — **одним
   коммитом**; запись без правки или правка без записи приёмку не проходит (AC-115/116).
   Правка плагина несёт запись в `plugins/gramax/CHANGELOG.md` тем же коммитом;
   индексную строку в `acceptance/_index.md` заводит PM.
9. **Закрытие и перегреп**: после записи вердиктируемы AC-115/116 и живая буква
   AC-108/109; перегреп AC-114 — `git grep -n "<литерал реального хоста>"` пуст,
   включая новые записи приёмки.

## Диагностика отказов

Порядок отказов фиксирован: цель → импорт playwright → запуск браузера; первый промах —
отказ, последующие проверки не выполняются. Проверка цели не требует playwright, поэтому
`RENDER_TARGET_*` диагностируется на любой машине с uv.

| Код | rc | Условие | Рычаг |
|---|---|---|---|
| `RENDER_TARGET_UNSET` | 2 | ни `--config`/дефолтного файла, ни env-полей цели | создай `render-target.local.json` по образцу `render-target.example.json` или задай `GRAMAX_RENDER_BASE_URL`; прогрев: `bash scripts/render-quality/warm.sh` |
| `RENDER_TARGET_INVALID` | 2 | конфиг есть, но дефектный: нечитаем/не-JSON, нет `baseUrl`/`catalog`, схема не http(s), неизвестный tier, нет `{slug}` в `pageUrlTemplate` при tier-1/2, пустой `catalog` в env-only-режиме | подсказка называет поле: «почини поле `<имя>` в `<путь конфига>`; формат — render-target.example.json» |
| `PLAYWRIGHT_UNAVAILABLE` | 2 | tier-1/2 в скоупе, `import playwright` не проходит | запускай прибор через `bash scripts/render-quality/probe.sh` (uv добавляет `--with playwright==<пин>`); прогрев: `bash scripts/render-quality/warm.sh` |
| `PLAYWRIGHT_NO_BROWSER` | 2 | playwright импортируется, запуск chromium не удался | прогрей браузер: `bash scripts/render-quality/warm.sh` (исполняет `playwright install chromium`); тот же код детерминированно даёт `PLAYWRIGHT_BROWSERS_PATH`, указывающий на пустой каталог |
| офлайн-промах кэша uv | насквозь | stderr совпал с сигнатурой «found in the cache» и «disabled» | обёртка `probe.sh` добавляет рычаг `bash scripts/render-quality/warm.sh`; сигнатура не совпала — вывод и rc нетронуты (fail-open) |

rc=1 отказом не является: это расхождения факта с ожиданиями — читай отчёт
