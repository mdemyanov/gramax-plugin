## Покрытие AC

Каждый AC-120…AC-128 получает именованный стаб либо именованное N/A с владельцем
(тишины-скипа нет ни по одному AC). Уровень — интеграционные bash-скрипты по дом-паттерну
сюиты; все стабы офлайн: сеть, живая цель и браузер стабам недоступны — они проверяют
разрешение конфига, именованные отказы, данные expect.json и th-семантику по локальным
файлам и дублям.

## Верификация красного состояния (замер 2026-11-21)

Каждый стаб запущен в момент посадки; краснота — по именованной причине из шапки стаба,
не по дефекту стаба (замеры носителей сделаны до посадки: `th-in-table.md` → `ERROR L8/L9`
и `rc=1`; дубль с несбалансированным `<th>` → киллер без балансовой строки; `config.resolve`
живой формы → разрешается; `/page/` в публичных файлах — только в примере схемы):

| Стаб | rc | Вывод (последняя строка, сокращено) |
|---|---|---|
| `ac-120` | 1 | `[FAIL] ac-120: записи повторного замера th нет — …render-calibration-th.md отсутствует; судьба th-вердикта без записанного основания (AC-120, FR-199, BR-021)` |
| `ac-121` | 1 | `[FAIL] ac-121: 7 assertion(s) failed` — среди них: `SEVERITY=<absent>`, `th-in-table` rc=1 с `ERROR L8/L9` (2 строки), дубль с несбалансированным `<th>` — «баланс подавлен безусловно», `HTTP 500` присутствует |
| `ac-123` | 1 | `[FAIL] ac-123: 8 assertion(s) failed; недостающие элементы цикла понижения (FR-202): запись-замера CHANGELOG th-in-table.expect.json ac-013-фикстура ac-001 ac-007 ac-011 ac-012` |
| `ac-126` | 0 | `[PASS] ac-126: живая форма {base}/{catalog}/{slug} разрешается, отказ по pageUrlTemplate именован и раньше playwright, конфиг вне git` (зелёный варден — см. «Отклонения») |
| `ac-127` | 1 | `[FAIL] ac-127: 4 assertion(s) failed` + дамп факта: `unbalanced.TIER1=any`, `images.TIER1=any`, `ASSERTS_ACTUAL=[]` (контролы и ноги tier0=kill — зелёные) |
| `ac-128` | 1 | `[FAIL] ac-128: 3 assertion(s) failed` — пример не на живой форме, живой формы в runbook нет, дополнения нет |

Негативная проверка маркеров ac-123 (гард от перевёрнутых маркеров): пост-состояние
цикла симулировано sed-преобразованиями таблицы Решения 4 во временных копиях — все пять
маркерных ног (ac-001, ac-007, ac-011, ac-012, ac-013-фикстура) насыщаемы → PASS; до
исполнения цикла те же ноги красные. При посадке найден и устранён дефект сопоставления:
`grep 'images.TIER1=pass'` ложно совпадал со строкой контроля `ctrl-images.TIER1=pass`
(точка = регэксп-джокер) — паттерны заякорены `^имя\.`, `SEVERITY` ужесточён до точного
значения `^SEVERITY=warn$` (защита от ложного прохода на `warning`).

Синтаксическая гигиена: `bash -n` на всех шести стабах — чисто; ассоциативные массивы bash
не используются (системный bash 3.2 — дом-прецедент портативности); стабы не требуют ни
uv-кэша, ни playwright-браузера: валидатор и `config.py`/`probe.py` — чисто stdlib,
playwright импортируется лениво и стабами не достигается.

## Что должен сделать Dev, чтобы стабы позеленели (контракт вызова)

Один цикл понижения (FR-202, порядок — D4 волны-2):

1. **Носители вердикта** (факт 3): `plugins/gramax/gramax-render-rules.json` — записи
   `killerTags` тега `th` атрибут `"severity": "warn"` (membership сохраняется —
   W034-подавление `validate_structure` не трогается); `plugins/gramax/scripts/
   validate_render.py` — severity-aware киллерный проход: `severity=warn` → `W()`,
   дефолт (атрибута нет) → `E()` как сегодня; поглощение th-баланса — только для
   ERROR-киллера (warn баланс не подавляет). rc-контракт 0/1/2 не меняется.
   → зеленит `ac-121` (ноги A–D).
2. **Запись замера**: `docs/60-implementation/acceptance/2026-11-21-render-calibration-th.md`
   (форма девяти полей runbook; tier-0 факт — из отчёта прибора живой цели; оба носителя
   названы; индексную строку в `acceptance/_index.md` заводит PM). → зеленит ногу (1)
   `ac-123` и `ac-120`.
3. **Адаптация сюит** по полному перечню NFR-083 (таблица выше / Решение 4 дизайна).
   → зеленит `ac-123` (ноги 3–8) и `ac-127`: в `tests/gramax/render-quality/fixtures/`
   меняются три файла ожиданий — `th-in-table.expect.json` (`tier0: "ok"`), 
   `unbalanced-pair-tags.expect.json` и `multiple-images.expect.json` (tier1-ассерты
   данными, точно как в таблице Решения 3: имена `tail-paragraph`/`img-count`, селекторы
   и счётчики — стаб ассертит их дословно; расхождение селектора с живым фактом
   разбирается по протоколу FR-196 записью, молчаливая правка селектора = красный
   `ac-127` и дефект процесса).
4. **CHANGELOG**: пункт в `plugins/gramax/CHANGELOG.md` тем же коммитом; маркерная форма
   — строка, называющая th и понижение/warn (например «`th` понижен ERROR → WARN…»).
   → зеленит ногу (2) `ac-123`. Синхрон README §validate_render и SKILL.md writer —
   за тем же циклом (перечень Решения 4), маркерами не ловится.
5. **Документарное закрытие** (D4): at-acceptance дополнение волны-2 по пути
   `docs/60-implementation/acceptance/2026-11-21-render-quality-wave2-at-acceptance.md`
   (путь зафиксирован этим at-design; судьба th + факты пробных страниц + заключения
   tier-1); пример схемы `render-target.example.json` → `"{base}/{catalog}/{slug}"`
   (`.invalid` сохраняется); runbook — живая форма в таблице настройки цели, без `/page/`;
   README сюиты — синхронно. → зеленит `ac-128`.

`run.sh` менять не нужно — агрегатор берёт `ac-*.sh` циклом по glob; таблицу инвентаря
стабов README сюиты пополняет Dev на шаге закрытия (AC-128в). Целевое состояние: 6 новых
стабов зелёные, `bash tests/gramax/render-quality/run.sh` → rc=0 на прогретой машине с
запушенными пробными страницами; далее qa-runner — независимый прогон, BA-acceptance —
AC-120…AC-123 по записи замера, AC-124/125 — по протоколу сессии, AC-122 — сверкой ветки.

## Отклонения и именованные решения этой задачи

- **`ac-126` зелёный при посадке** — не «прибитый к стене» зелёный: это варден
  контрактного решения волны-2 «схема конфига не расширяется, `config.py` не меняется»
  (Решение 1 дизайна), чей предмет уже в дереве и подтверждён замером этой задачи
  (живая форма разрешается; отказ по полю `pageUrlTemplate`; `tier0`-only — поле
  опционально). Форсировать красный на работающем контракте — подгон под красную
  букву брифа против BR-021; прецедент волны-1 — зелёные с рождения `ac-104`/`ac-118`
  (его at-design, «Отклонения»). Красный `ac-126` после посадки = регрессия приёма
  живой формы или игнор-строки — триаж, не плановая краснота.
- **Отступление от «Контракта с QA-author» дизайна** («новых стаб-файлов волна не
  требует»): бриф этой задачи прямо требует стабы на каждый тестируемый AC волны-2
  вместо владельческих N/A. Исполнено буквально: замерные/процедурные AC получили
  именованные владельцы (N/A-строки таблицы), механически проверяемые — стабы. Противоречия
  с дизайном по существу нет: дизайн называет владельцев, эта задача делает их
  проверяемыми до цикла.
- **Маркеры ac-123 — пост-состояние из таблицы Решения 4, не догадки.** Если адаптация
  Dev исполнена по существу, но словится иначе (например, `warn`-ассерт переписан другой
  конструкцией, а нога маскирования ac-007 сохранена), правится маркерная нога стаба с
  обоснованием в описании изменений — дом-прецедент «поправь фикстуру и стаб
  с обоснованием» (волна-1, «Отклонения»). Маркеры проверяют полноту цикла, но не
  заменяют NFR-083 целиком: «не ослаблено» в полном объёме верифицирует композит
  qa-runner по зелёному `run.sh` render-linter.
- **Шов исполнения прибора в ac-126 — прямой вызов `probe.py` питоном**, а не `probe.sh`:
  баннер `REFUSAL` печатает сам `probe.py`, а прямой вызов гарантирует офлайн
  (обёртка `uv run --with playwright` на холодном кэше ходила бы в сеть — бриф запрещает
  сети в стабах). Отказ конфига по лестнице раньше playwright — поэтому вызов детерминирован
  на любой машине с python3. Остальные стабы сети не касаются вовсе.
- **Путь at-acceptance дополнения зафиксирован at-design** (`…wave2-at-acceptance.md`) —
  по аналогии с волной-1 (`…playwright-render-quality-at-acceptance.md`); Dev использует
  именно его, иначе `ac-128` остаётся красным.
- **Дубли ног между стабами — осознанные**: запись замера ассертится и `ac-120` (существование
  и содержимое), и `ac-123` (полнота цикла) — это разные AC с разным предметом (основание
  вердикта vs одновременность артефактов), 1:1 «AC → стаб по ID» важнее дедупликации ног.
