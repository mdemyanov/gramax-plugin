**Роль:** QA-author (тест-дизайн до реализации Dev — этот документ и стабы-сюита
предшествуют коду прибора, не следуют за ним; TDD-цепочка qa-author → dev → qa-runner).

**Требование:** [Прибор рендер-проб Playwright и калибровка validate_render](../../30-requirements/2026-11-21-playwright-render-quality-requirement.md) (AC-104…AC-119, FR-187…FR-198, NFR-077…NFR-082, BR-021…BR-024)
**Дизайн:** [2026-11-21-playwright-render-quality-design](../../40-architecture/2026-11-21-playwright-render-quality-design.md) — источник контракта стабов (раздел «Контракт с QA-author (красные стабы)»), швов `--config`/`--fixtures`/`--report`/`--check-env`, формата фикстур и отчёта; не пере-дизайнивается этим документом

## Фикстуры ↔ ERROR-таблица (AC-104, RES-009 §2)

| Файл | `tableRow` | Строка таблицы апстрима | Ожидание `tier0` |
|---|---|---|---|
| `th-in-table.md` | `ERROR-1` | `<th>` в таблицах (симптом: 500 на разделах с таблицами) | `kill` |
| `note-inline.md` | `ERROR-2` | инлайновый `<note>…</note>` в одну строку | `kill` |
| `invalid-utf8.md` | `ERROR-3` | файл не валидный UTF-8 (500 либо мусорный хвост — оба исхода подтверждены) | `either` |

| `colgroup-multiline.md` | `ERROR-6` | многострочный `<colgroup>` (каждый `<col/>` на своей строке) | `kill` |
| `xml-in-html-comment.md` | `ERROR-7` | XML-тег внутри HTML-комментария | `kill` |
| `tag-fragment-tail.md` | `ERROR-8` | обрывок тега с хвостом вида `splay="List"/>` | `kill` |
| `note-in-cell.md` / `note-in-note.md` | `WARN-note-in-cell` / `WARN-note-in-note` | спорные severity (апстрим-замер 04.09.2026: 42 вхождения на 19 страницах — все HTTP 200) | `ok` |
| `control-*.md` (7 файлов) | `control` | легальные формы соответствующих конструкций («НЕ ошибки» и нормальные формы) | `ok` |

Каждая дефект-фикстура несёт ровно одну дефектную конструкцию (FR-187); фикстуры — данные
прибора (реальные теговые конструкции внутри `.md`), не статьи каталога. `invalid-utf8.md` —
байтовая фикстура: не декодируется как UTF-8 (хвост обрезан посреди двухбайтового символа,
семантика RES-009 §3.4); из прогона валидатора `validate_render.py` по протоколу FR-196
**исключается** (локальный порт падает необработанным исключением — факт 4 RES-009; защита
чтения без детектора в эпик не входит, FR-198/D7). Контингенция R1 дизайна для коммита:
строка `.gitattributes` `tests/gramax/render-quality/fixtures/invalid-utf8.md -text` —
решение на коммитёре (Dev/PM).

## Что должен сделать Dev, чтобы сюита позеленела (контракт вызова)

1. **Каркас** `scripts/render-quality/` по Решению 5 дизайна: `probe.sh`, `warm.sh`,
   `probe.py`, `config.py`, `tier0_http.py`, `tier1_dom.py`, `tier2_shots.py`, `report.py`,
   `render-target.example.json`; gitignore-строки тем же коммитом (Решение 1).
2. **Швы, которые вызывают стабы:** `--config <путь>` (дефолт
   `render-target.local.json`, env-поля поверх файла), `--fixtures <каталог>`,
   `--report <путь>` (каталог отчёта = каталог результатов;
   `screenshots/<slug>.png` рядом с отчётом), `--check-env` (цель → импорт playwright →
   браузер, без тиров), `--retry N`/`--retry-wait SEC`/`--jobs N` (Решение 6).
3. **Формы вывода, которые грепают стабы:** баннер `REFUSAL <КОД>: <подсказка>`
   (коды `RENDER_TARGET_UNSET`/`RENDER_TARGET_INVALID`/`PLAYWRIGHT_UNAVAILABLE`/
   `PLAYWRIGHT_NO_BROWSER`, rc=2, подсказка зовёт `bash scripts/render-quality/warm.sh`);
   факт-состояния `OK 2xx` / `STABLE_5XX` / `NOT_FOUND 404` / `HTTP_4XX` / `NETWORK_ERR`;
   ноты «кандидат на переиндексацию…», «решён ретраем», «404 сразу после пуша…»;
   строки `tier1: pass (N asserts)` / `tier1: fail (assert <имя>)` / `tier2: skip (tier0 …)`;
   `summary: fixtures=N match=M divergence=D`; `verdict: PASS|FAIL`; `<slug>: match|divergence`.
4. **Мини-формат ассертов tier-1:** `{"name", "selector", "count"}` из `expect.json`
   (дизайн, Решение 5).
5. **Регистрация шага 18** в `--full`-блоке `scripts/check-gramax.sh` — только после
   зелёного прогона qa-runner (AC-113; позеленяет `ac-113`, `ac-118` остаётся зелёным).
6. Прогрев (`warm.sh`) и пуш фикстур в выделенный каталог цели — операционная рутина
   README сюиты; стабы офлайн и цели не требуют.

Изменять фикстуры/ожидания ради позеленения нельзя — расхождение живого замера с
`expect.json` разбирается по протоколу FR-196 (антифабрикация R2: селекторы tier-1 —
гипотезы до живого замера, подтверждение — записью замера Решения 8).

## Отклонения и именованные решения этой задачи

- **`ac-104` и `ac-118` зелёные при посадке** — не «прибитые к стене» зелёные: `ac-104` —
  варден данных, посаженных этой же задачей (дизайн прямо предписывает «зелёный после»
  посадки фикстур qa-author), `ac-118` — варден изоляции, зелёный с рождения («красный —
  триаж»). Остальные 10 — красные по именованной причине. Это соответствует букве
  контракта стабов дизайна, а строки брифа «каждый стаб красный сейчас» читаются как
  «каждый стаб, чей предмет — поведение прибора».
- **`run.sh` создан этой задачей** (не перечислен в брифе среди артефактов): состав раннера
  фиксирован Решением 7 дизайна (офлайн-стабы + живой прогон), шаг 18 гейта зовёт именно
  `run.sh` — без него контракт регистрации Dev не исполним. Сюитная территория (`tests/`),
  поверхность Dev (`scripts/render-quality/`) не создавалась.
- **Шов «каталог скриншотов» конкретизирован:** дизайн фиксирует дом-раскладку
  `results/report.md` + `results/screenshots/<slug>.png`; для стабов с временным `--report`
  стабы контрактуют каталог скриншотов как каталог отчёта. Если Dev выберет иной шов
  (отдельный `--results`), правится шапка `ac-111`/`ac-108`/`ac-112`/`ac-117`, а не
  ассерты — несоответствие молча не игнорировать (дом-прецедент «поправь фикстуру и стаб
  с обоснованием»).
- **Портативность bash:** ассоциативные массивы не используются — системный bash 3.2
  (macOS) ломается на `declare -A` под `set -u` (найдено при самопроверке `ac-104`,
  переписано на пары «имя|строка»; та же причина, что в дом-прецеденте plain-loop
  агрегаторов).

## Гигиена

- В файлах сюиты нет литералов реального хоста: стаб-портал — `127.0.0.1` только,
  заполнитель цели — RFC 2606 `.invalid`; секретов нет (NFR-081).
- Сюита не зарегистрирована ни в одном гейте; `--fast` не затронут. Запись at-design
  зарегистрирована строкой в `docs/60-implementation/acceptance/_index.md` (текст буллета =
  H1 дословно): каталожный C1 этого раздела делает незарегистрированную статью error'ом
  `--fast`, а дом-прецедент (коммит `1d3b17e` — протокол writer-tail-480 + его индексная
  строка одним изменением) сажает регистрацию вместе с записью. Отступление от строки брифа
  «`_index.md` не править» — осознанное, во исполнение критерия «`--fast` зелёный с файлами
  задачи»; остальные индексы (требования, дизайна, сюит) не правились.
- Размеры: стабы 60–130 строк, модульная форма (NFR-082); `docs/`-запись — этот документ.

## Передача Dev

Dev (`/nauta:dev`) получает: этот документ + `tests/gramax/render-quality/` (12 стабов:
10 красных по имени «входа прибора нет», 2 зелёных-вардена; `run.sh` rc=1; README с
