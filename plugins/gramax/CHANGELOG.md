# Changelog

## 4.11.0 — 2026-11-25

Калибровка контрактов валидаторов и резолвера ссылок по движку `48592b36` (ADR-0028: факты
движка — чтение исходника на пине). Закрыты два слепых пятна — диаграммный тег без
самозакрытия и ссылка на каталог без `_index.md`; сняты ложные сигналы — W034 на двенадцати
именах тегов движка и ERROR внутри многострочного code-span; ручная проверка утечки
абсолютных путей стала правилом валидатора `E037`. Гейт репозитория получает шаг
`shellcheck-changed` в `--fast` и 18-ю живую сюиту в `--full` (ADR-0029; блок
«Инструменты репозитория» ниже). Периметр плагина не меняется (ADR-0030): семь навыков и
агент `review-agent`. Semver — Minor (ADR-0006): навыки не добавлялись и не удалялись,
`mcpServers` не менялись; ужесточаются отдельные проверки валидаторов. Тексты навыков
`writer`, `comments-write` и README дополнены по решениям этой волны.

### Changed

- **Валидатор `validate_structure` и резолвер ссылок — контракты по ADR-0028** (решения 1–5):
  закрыты два слепых пятна — диаграммный тег с `path`, записанный парным
  (`<plant-uml path="…">…</plant-uml>`) или без закрывающего `>`, даёт ту же находку W031
  (файл диаграммы не найден), что самозакрытая форма `/>`; ссылка на каталог без `_index.md`
  без флага `optionalCategoryIndex: true` даёт ERROR битой ссылки (прежде — тишина). При
  одноимённых файле и каталоге (`section.md` и `section/`) побеждает файл. Новое правило
  `E037` (error) — абсолютный локальный путь контрибьютора в тексте статьи, включая код.
  Code-span, разорванный переносом строки внутри абзаца, маскируется наравне с однострочным;
  у парсера и валидатора остаются один путь чтения страниц и одна маска кода. Механика — в
  строках `Contract:` ниже; реестр тегов, `--strict` и `--check` — там же.

Contract: `md_link_parser.py` — диаграммный тег с `path`, записанный парным (`<plant-uml path="…">…</plant-uml>`) или без закрывающего `>`, даёт ту же находку W031, что самозакрытая форма `/>`: детектор `diagramTags` больше не требует самозакрывающего слэша (ADR-0028 Решение 3; движок читает атрибуты из открывающего тега и проверяет цель — `markdocModel.ts:27`, `Healthcheck.ts:238-252` на пине 48592b36). Атрибут, чьё имя оканчивается на `path` (`data-path=`), целью не считается.

Contract: `lib/link_resolver.py`, `validate_structure.py` — один резолвер `resolve_link_target`: литеральный файл → `цель.md` → `цель/_index.md` → каталог только при `optionalCategoryIndex: true`. Ссылка на каталог без `_index.md` без флага даёт ERROR «битая ссылка (broken link) на "…" — каталог без _index.md (раздела в дереве нет): …» (ранее — тишина); при одноимённых файле и каталоге побеждает файл (ранее — каталог, и статья оставалась «сиротой»); `#якорь` ссылки на раздел проверяется по `_index.md`. `resolve_no_ext` удалён (ADR-0028 Решение 4, поправка к ADR-0016 Решение 1).

Contract: `lib/md_link_parser.py` — новый `scan_md_resources(root, diagram_tags=…, *, exclude=None)` читает страницы через `lib/read_page.py` и возвращает `(resources, errors)`: файл с битым UTF-8 даёт `MdPageError`, а не исключение. `parse_md_resources` сохраняет сигнатуру и тип результата. Собственная копия маски кода в парсере удалена — маска одна, `lib/md_code_mask.py` (ADR-0028 Решение 1).

Contract: `lib/md_code_mask.py` — code-span, разорванный переносом строки внутри одного абзаца, маскируется наравне с однострочным (вторая фаза маски, ADR-0028 Решение 2): иллюстрация синтаксиса в таком спане не даёт ложных ERROR и WARN в `validate_structure.py`, `validate_render.py`, `validate_comments.py`, `parse_comments.py`. Однострочные спаны маскируются как прежде; бэктики разных абзацев маской не соединяются.

Contract: `validate_structure.py` — новое правило E037 (error): абсолютный локальный путь контрибьютора (`/Users/<имя>/…`, `/home/<имя>/…`, `X:\Users\<имя>\…`, WSL `/mnt/<буква>/Users/<имя>/…`; имя — любые буквы и цифры, включая не-латиницу) в тексте статьи, включая код; сообщение называет строку и форму с фактической буквой диска, но не сам путь (ADR-0028 Решение 5 с поправкой от 2026-11-25; FR-072, FR-073).

Contract: `gramax-tags.json` — в реестр входят двенадцать имён тегов движка (ADR-0028 Решение 10): `pairedTags` + `alert`, `block-field`, `block-property`; `selfClosingTags` + `db-diagram`, `db-table`, `include`, `term`, `module`, `issue`, `when`, `who`, `see`; `diagramTags` + `db-diagram`. W034 на них не выдаётся; `db-diagram` с `path` проверяется как файловая цель диаграммы (W031); несбалансированные `alert`, `block-field`, `block-property` дают ERROR `unpaired <тег>`. `schemaVersion` остаётся 3 — ключи не менялись, списки расширены.

Contract: `validate_comments.py` — `--strict` эскалирует каждое предупреждение в код выхода 1 (ранее эскалировались только дубликат ответа и отсутствие ключа `answers`): `dateTime not ISO 8601 UTC` и «у ответа нет user.id» под `--strict` дают rc=1 с прежней меткой `WARNING`; уровень `info` не эскалируется (ADR-0028 Решение 11).

Contract: `gen_comment_id.py` — `--check <путь>`: каталог или файл с битым UTF-8 дают именованный отказ в stderr с кодом 2 вместо traceback с кодом 1 (ADR-0028 Решение 7).

- **Навык `writer`** (FR-247, FR-248): цитата вида `путь:строка` обязана явно называть
  режим — `RECORD` («на HEAD=… было верно»: факт истории, ревалидации не требует) или
  `POINTER` («сейчас верно»: требует периодической ревалидации); формулировка в настоящем
  времени без пометки читается как `POINTER`. Форма `:::` (markdown-admonitions) помечена
  legacy: редактор переписывает её при сохранении — в новом контенте использовать `<note>`
  синтаксиса XML; та же оговорка стоит в `references/blocks.md`. В
  `references/doc-root-schema.md` уточнены вложенные корни: каждый найденный `.doc-root.yaml`
  проверяется как отдельный catalog root, статья судится по схеме ближайшего корня;
  поведение `writer` для вложенных корней по-прежнему не специфицировано. Статус ADR до
  ратификации в репозитории плагина несёт значение `Draft`; `Proposed` в enum `Статус` не
  вводится.

- **README плагина и `references/staging.md`** (FR-246, FR-256, FR-257): названы обе
  стороны строгости плейсхолдеров — она задана неодинаково намеренно (ADR-0012, Решение 2):
  плагин выдаёт error без условия, контур nauta проверяет плейсхолдеры только
  предупреждением; то же предложение добавлено в `references/staging.md` навыка `writer`.
  Строка-указатель на рецепт запуска `validate_comments.py` по каталогу (сам рецепт живёт в
  навыке `comments-write`). Строка статуса `plantuml`: окно живых проверок закрыто
  документарно 2026-11-24, runtime-проверка рендера BPMN/Salt не выполнялась, оговорка о
  рендере `<bpmn>` сохраняется. Раздел «Валидация каталога» дополнен правилами этой версии:
  `E037`, резолв ссылки на каталог, `--strict` валидатора комментариев.

- **Навык `comments-write`** (FR-256): новый подраздел «В каталоге и в цикле коммита» —
  проверка после операции смотрит один файл, ручные правки вне этой операции она не видит;
  рецепт называет команду `validate_comments.py` по каталогу и строку для скопированного
  pre-commit хука. Код и шаблон хука `scripts/pre-commit.sh` не менялись.

- **`scripts/migrate_nav_codespans.py`**: правлены только комментарии — временный протокол
  ADR-0016 Решение 2 снят (ADR-0028 Решение 9); подпись копии маски кода приведена к факту: копия —
  редакция однофазного алгоритма по прецеденту RES-005, записанное исключение из «одной маски»
  (ADR-0028 Решение 2, поправка от 2026-11-25), вторую фазу не получает; поведение не меняется.

- **Снято с повестки плагина** (ADR-0030, решения 2 и 4; не отложено):
  - диагностика установки — внутри плагина она не может сработать в состоянии, которое
    должна описать: нерезолвящийся навык не исполняется;

  - overlay-`properties` с вложенными корнями — снята формальная поддержка как отдельный

    заменена решением ADR-0030);
  - проверки V4/V5 для `type: select` — синтаксис остаётся экспериментальным, пропуск с
    предупреждением остаётся; предупреждение V3 (плоская нотация) не затронуто.

- **Замер до/после** (ADR-0028): резолвер ссылок, вторая фаза маски и `--strict` меняют 0
  вердиктов на `docs/` этого репозитория и корпусе сравнения (1478 ссылок); код выхода

  `docs/` — 0 ERROR / 0 WARNING; корпус сравнения — +10 ERROR, все десять — `E037`,
  предупреждения без изменений; то же после расширения правила на не-латинские имена и
  форму WSL (поправка от 2026-11-25).

### Breaking change

Semver — Minor: навыки не добавлялись и не удалялись, `mcpServers` не менялись. Что
потребитель может заметить иначе по сравнению с 4.10.0:

- **Абсолютный локальный путь в статье** (`/Users/<имя>/…`, `/home/<имя>/…`,
  `X:\Users\<имя>\…`, WSL `/mnt/<буква>/Users/<имя>/…`; имя — любые буквы и цифры, включая
  не-латиницу) — новый ERROR `E037` у `validate_structure.py`: одна находка на строку,
  включая путь внутри кода; прежде валидатор такой путь не замечал. Сообщение называет
  строку и форму с фактической буквой диска, но не сам путь; путь с маской вместо имени
  (`/Users/<имя>/…`, `/Users/...`) находкой не считается.
- **Ссылка на каталог без `_index.md`** без флага `optionalCategoryIndex: true` — ERROR
  битой ссылки «каталог без _index.md (раздела в дереве нет)»; прежде находки не было. С
  флагом находки нет. Проверка самой подпапки без `_index.md` остаётся отдельной находкой.
- **Одноимённые файл и каталог** (`section.md` и `section/`): ссылка без расширения
  `[Название](section)` ведёт в файл; прежде резолв шёл в каталог, и статья оставалась
  «сиротой».
- **Диаграммный тег с `path` без самозакрытия**: парная форма
  `<plant-uml path="…">…</plant-uml>` и форма без закрывающего `>` дают то же
  предупреждение W031, что форма `/>`, когда файла диаграммы нет; прежде такие формы
  детектор не видел.
- **Теги движка** — `alert`, `block-field`, `block-property`, `db-diagram`, `db-table`,
  `include`, `term`, `module`, `issue`, `when`, `who`, `see` — больше не дают W034
  (неподдерживаемая разметка); незакрытый `alert`, `block-field` или `block-property` даёт
  ERROR `unpaired <тег>`; `<db-diagram path="…">` проверяется как файловая цель диаграммы
  (W031). `schemaVersion` реестра остаётся 3.
- **Code-span, разорванный переносом строки**: маскируется наравне с однострочным — ложные
  ERROR и WARN на иллюстрации синтаксиса в таком спане уходят у `validate_structure.py`,
  `validate_render.py`, `validate_comments.py`, `parse_comments.py`.
- **`validate_comments.py --strict`**: каждое предупреждение даёт код выхода 1 — прежде
  эскалировались только дубликат ответа и отсутствие ключа `answers`; метки находок
  остаются прежними (`WARNING`). Уровень `info` не эскалируется; без флага поведение не
  меняется.
- **`gen_comment_id.py --check <путь>`**: каталог или файл с битым UTF-8 дают именованный
  отказ в stderr с кодом выхода 2 вместо traceback с кодом 1.

### Инструменты репозитория

В поставку плагина не входит; относится к сопровождению репозитория (ADR-0029).

- **Шаг `shellcheck-changed` в `--fast`** (`scripts/check-gramax.sh`): shellcheck по
  изменённым и новым `.sh` (кроме `tests/gramax/archive/`) — тест-скрипт с находкой ловится
  на пути от QA-author к Dev, а не только в полном прогоне. Исключения `-e` действуют
  только для `.sh` файлов базиса доставки, остальные файлы проверяются без них; на чистом
  дереве шаг shellcheck не вызывает.
- **Живая сюита `tests/gramax/docs-layout-invariants/` — 18-я в `--full`** (сразу после
  `nauta-integration`): пять инвариантов раскладки документации, выделены копированием из
  архивной сюиты `tests/gramax/archive/docs-migration/`; архив не менялся.
- **Шаг `submodule status` снят**: сабмодулей в дереве нет (`git submodule status` — 0
  строк, `.gitmodules` нет).
- **Два инструмента не усыновлены**, гейт остаётся n/a по обоим: `check-backlog-closure.py`
  судил бы несохранённое состояние (стор задач локальный и исключён из git);
  `check-breaking-change-section.py` не доставляется и гейтом не вызывается — блок
  «Breaking change» этого журнала остаётся ручной проверкой.
- **Отчётный режим `migrate_nav_codespans.py`** в `--full` не входит и снят с планов; скрипт
  остаётся ручным диагностом.
- **Сессия замеров исполнена** (2026-11-24; шаг замера ритуала ADR-0027 — в 4.10.0 он был
  не исполнен). Прибор рендер-проб с включённым tier-1: `fixtures=23 match=23 divergence=0`,
  rc=0 — 23 страницы: 21 фикстура и две страницы замера H1. Заголовки с текстом `title`
  (FR-232): страница «title + равный ему H1» показывает два таких элемента (`h1`=1 —
  титульный заголовок, `h2`=1 — H1 тела), та же страница без H1 — один (`h1`=1, `h2`=0).
  Дублирование подтверждено: правило `# H1` в теле у `validate_render.py` остаётся без
  изменений, конвенция корпуса «H1 == title» — решение владельца вне волны.
  Четыре ассерта tier-1, которые судит прибор, прошли; семь ассертов, ни разу до этого не
  исполнявшихся, исполнены — все семь разошлись с ожиданием: портал не отдаёт `data-testid`
  на элементах контента (4 ассерта), ожидаемое число противоречит тексту самой фикстуры (2),
  рендерер добавляет пустую строку заголовка каждой таблице (1). Вердикты в этой волне не
  менялись (решение владельца D12 «только замеры сейчас», дерево решений волны-4);
  калибровка — именованный хвост следующей волны. Дрейф-гипотезы (multiple-images,
  unbalanced-pair-tags, tag-fragment-tail, xml-in-html-comment): HTTP 200 третий замер
  подряд, вердикты валидатора без изменений (BR-021…BR-024). Пробы после замера убраны.
  Окно переиндексации цели: пробы появляются на портале через 10–11 минут после публикации
  и исчезают примерно через 6 минут после уборки.

## 4.10.0 — 2026-11-23

Калибровка контрактов валидаторов по движку `48592b36` (ADR-0026): сигнал валидатора —
реальный дефект каталога, а не шум. Контур комментариев распознаёт обе формы блочного
комментария — XML (её пишет визуальный редактор) и скобочную legacy. Гейт репозитория
`--full` больше не зависит от сети, опубликованных проб и токена (ADR-0027; блок
«Инструменты репозитория» ниже). Semver — Minor (ADR-0006, ADR-0026 Решение 7): навыки не
добавлялись и не удалялись, `mcpServers` не менялись; ужесточения — только на генуинные
дефекты по факту движка.

### Changed

- **Валидатор `validate_structure` — калибровка по контракту движка** (ADR-0026, решения
  1–6): каталог без `language` в `.doc-root.yaml` проходит; XML-таблицы (`table`/`tr`/`td`)
  и встроенные коды иконок Lucide перестали давать ложные W034/W035; `properties` в
  `_index.md` подпапки разрешён; флаг `optionalCategoryIndex: true` снимает требование
  `_index.md` у подпапок (без флага ERROR остаётся с новым текстом — «раздела в дереве нет,
  статьи подняты выше»); файл с битым UTF-8 даёт одну именованную находку `E036`, обход
  каталога продолжается; содержимое блоков `<html>…</html>` не судится как разметка
  страницы. Механика — в строках `Contract:` ниже.

- **Валидатор `validate_render`**: файл с битым UTF-8 даёт одну ошибку
  (`ERROR L0: Файл не является валидным UTF-8 (байт 0xNN на позиции P из S)`), остальные
  файлы каталога проверяются; содержимое блоков `<html>…</html>` маскируется от построчных
  проверок и баланса тегов. Баланс `table`/`tr`/`td` по-прежнему ведёт только этот
  валидатор — структурный его не дублирует (BR-027).

- **Контур комментариев — `validate_comments.py`, `parse_comments.py`** (FR-210, FR-211,
  FR-212, FR-218): повторный ID комментария в md перестал быть ошибкой — несколько позиций
  у одного ID штатны, валидатор показывает их информационной строкой, rc и `--strict` не
  меняются; блочный комментарий распознаётся в XML-форме `<comment id="ID"/> … </comment>`
  рядом со скобочной legacy; примеры тегов в code-span и fenced-блоках не считаются
  разметкой; ответ без `user.id` даёт предупреждение; файл с битым UTF-8 — находка `E036` у
  валидатора, у читателя — предупреждение на stderr и пропуск файла (rc=0).

- **Навыки `comments-read`, `comments-write`**: блочный комментарий описан в двух формах —
  XML-форма `<comment id="ID"/> … </comment>` названа каноном для `syntax: XML`, скобочная
  `[comment:ID] … [/comment]` — legacy (обе читаются); несколько позиций у одного ID —
  штатная конструкция, `--delete` снимает все позиции; шаблон ответа несёт у автора `id`,
  равный `mail`.

- **Навык `writer`**: `language` в `.doc-root.yaml` необязателен; флаг

### Breaking change

Semver — Minor: навыки не удалялись, `mcpServers` не менялись. Что потребитель может
заметить иначе по сравнению с 4.9.0:

- **Каталог без `language`** в `.doc-root.yaml` перестаёт давать код выхода 1 по находке
  «missing field: language»; присутствующее поле неверного типа по-прежнему даёт ERROR.
- **`properties` в `_index.md` подпапки** больше не ERROR (на корпусе сравнения — 43
  ложных). Взамен к индексу подпапки применяются проверки свойств по схеме каталога (V3–V5:
  необъявленное свойство, значение вне enum, плоская нотация) — во внешних каталогах могут
  появиться истинные находки. `_index.md` корня остаётся вне проверки.
- **Повторный ID комментария в md** — не ошибка: «duplicate comment id» уходит, вместо него
  информационная строка с номерами строк; rc и `--strict` не меняются.
- **Коды иконок**: встроенные коды Lucide (голый kebab-case — `check`, `zap`) больше не дают
  W035; код с префиксом `lucide-` без файла в `.icons/` даёт W035 с подсказкой убрать
  префикс. Навык `writer` пишет коды без префикса.
- **XML-таблицы**: `table`/`tr`/`td` больше не дают W034, под `--strict` таблицы перестают
  краснеть; незакрытый тег таблицы по-прежнему даёт одну находку — ERROR баланса от
  `validate_render.py`.
- **Файл с битым UTF-8**: вместо traceback и обрыва обхода — именованная находка (`E036` у
  структурного валидатора и валидатора комментариев, `ERROR L0` у рендер-линтера);
  остальные файлы каталога проверяются, код выхода 1.
- **Два ужесточения** (ADR-0026 Решение 8): самозакрывающий открывающий
  `<comment id="…"/>` без парного `</comment>` — ERROR `unpaired <comment>` у структурного
  валидатора (прежде — тишина); тег с переносом строки между `<comment` и `id=` — ERROR
  «тег разорван» у валидатора комментариев (прежде считался позицией комментария).
- **Подпапка без `_index.md`**: с флагом `optionalCategoryIndex: true` ошибки нет; без
  флага ERROR остаётся, текст сообщения новый — «раздела в дереве нет, статьи подняты
  выше».
- **JSON-контракты напрямую**: `gramax-tags.json` — `schemaVersion` 3,
  `gramax-catalog-rules.json` — `schemaVersion` 2; потребитель собственного валидатора
  обязан ожидать новые версии.

### Migration notes (с v4.1.x)

1. Замени собственную regex-таблицу Gramax-тегов чтением контракта — синхронизация с новым
   релизом плагина перестаёт требовать ручной правки на твоей стороне:
   ```bash
   jq -r '.pairedTags, .selfClosingTags' "${CLAUDE_PLUGIN_ROOT}/gramax-tags.json"
   ```
2. Если у тебя нет pre-commit-гейта для Gramax-каталога — скопируй готовый шаблон вместо того,
   чтобы писать свой валидатор с нуля:
   ```bash
   cp "${CLAUDE_PLUGIN_ROOT}/scripts/pre-commit.sh" .githooks/pre-commit
   chmod +x .githooks/pre-commit
   git config core.hooksPath .githooks
   ```
3. Мигрируй устаревший inline-mermaid в своём каталоге — сначала отчёт, затем правка:
   ```bash
   uv run "${CLAUDE_PLUGIN_ROOT}/scripts/migrate_mermaid.py" content
   uv run "${CLAUDE_PLUGIN_ROOT}/scripts/migrate_mermaid.py" content --fix --yes
   ```
4. Если твой собственный content-валидатор ограничивает проверяемые файлы суффиксом `.md` —
   расширь allowlist на `.mermaid`, иначе file-based диаграммы для него невидимы. Одного
   расширения allowlist недостаточно для проверки содержимого — предикат «валидный
   `.mermaid`-файл» см. `skills/mermaid/references/jurisdiction-and-validation.md`:
   ```python
   ALLOWED_SUFFIXES = {".md", ".mermaid"}
   ```
5. `_index.md` в корне каталога больше не ошибка валидатора плагина — и одновременно Gramax
   его не отображает: содержимое не попадает ни в титульную страницу, ни в список статей
   корня. Если в корневом `_index.md` лежит дашборд или контент, рассчитанный на читателя, —
   он остаётся видимым только в git-репозитории, не в интерфейсе Gramax; при необходимости
   перенеси такой контент в `_index.md` подраздела верхнего уровня, где Gramax его отображает.

## 4.0.0 — 2026-05-12

Breaking change. Mermaid skill переведён с inline-workflow на file-based: DSL теперь хранится в отдельном `.mermaid`-файле рядом со статьёй, а в md вставляется тег-ссылка `<mermaid path="…"/>`. Соответствует реальному формату Gramax, задокументированному в `blocks.md`.

### Breaking change

- `gramax:mermaid` больше не вставляет DSL inline в md-файл (`<mermaid>…</mermaid>` или ` ```mermaid … ``` `). Inline-подход несовместим с Gramax-рендером.
- Skill теперь создаёт два артефакта: `.mermaid`-файл (DSL) и тег-ссылку в md.
- Пользователи, строившие workflow на inline-вставке, должны адаптироваться к новому workflow (см. Migration notes ниже).

### Added

- **File-based workflow:** skill создаёт `.mermaid`-файл в той же директории, что и `target_page`, через Write tool. DSL содержит только чистый Mermaid (без обёрток).
- **Naming convention:** `<page-slug>-<diagram-slug>.mermaid`. Специальный кейс `_index.md` → `page-slug` берётся из родительской директории.
- **Коллизия имён:** при повторном вызове с уже существующим `.mermaid`-файлом skill читает первые 5 строк, информирует пользователя и предлагает три опции: перезаписать / выбрать другое имя / отменить. Без явного «перезаписать» — файл не трогается (NFR-001: идемпотентность).
- **Backward-compat предупреждение:** при обнаружении inline-блока `<mermaid>…</mermaid>` или fenced block ` ```mermaid … ``` ` в `target_page` — skill выводит предупреждение «устаревший формат» и предлагает миграцию. Не мигрирует молча.
- **Кириллица в slug:** при кириллической теме диаграммы skill предлагает семантический перевод на английский (не механическую транслитерацию).

### Changed

- `skills/mermaid/SKILL.md` — полная переработка: file-based workflow, naming convention, backward-compat, обновлённый fallback-диалог (mermaid-опция: «файл `.mermaid` рядом со статьёй, тег-ссылка в md»), расширенный checklist (добавлен пункт «файл не содержит Gramax-разметки»).
- `skills/mermaid/references/syntax-rules.md` — секция «Особенности Gramax» обновлена: file-based формат тега `<mermaid path="…"/>` вместо описания inline-блоков как основного формата.
- `.claude-plugin/plugin.json` — version `4.0.0`.
- `.claude-plugin/marketplace.json` — metadata.version `4.0.0`; descriptions обновлены.

5. При неявном запросе («нарисуй диаграмму» без указания движка) `gramax:mermaid` задаст уточняющий вопрос. Для детерминированного выбора — указывай движок явно в запросе. Подробнее — в `plugins/gramax/skills/mermaid/SKILL.md` (секция «Fallback при ambiguous-request»).

### ADR
- ADR-0009 (новый) — обоснование удаления `claude-mermaid`, добавления `gramax:drawio`, keyword-стратегия description, процедура `git submodule deinit`. Документ: `content/00-project/adr/0009-drawio-stub-and-claude-mermaid-removal.md`.
- ADR-0008 остаётся Active — ADR-0009 дополняет его, не отменяет.

### Backward compatibility

- Имя skill'а `gramax:mermaid` не изменилось — явные запросы с «mermaid» в тексте работают без изменений.
- Inline-генерация mermaid DSL работает идентично v2.0.0.
- Skills `writer`, `comments-read`, `comments-write` и agent `review-agent` не затронуты.
- **Known limitation:** при неявном запросе («нарисуй диаграмму» без движка) Claude может активировать `gramax:drawio` вместо `gramax:mermaid`. Полный детерминизм — только при явном engine-keyword в запросе (см. ADR-0009, Решение 6).
