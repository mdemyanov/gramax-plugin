# Блоки Gramax — полный справочник

## Примечания (Notes / Admonitions)

### XML-формат (для `syntax: XML`)

```markdown
<note type="tip" title="Заголовок" collapsed="false">

Содержимое заметки.

</note>
```

| Параметр | Значения | Обязательный |
|----------|----------|--------------|
| `type` | `tip`, `info`, `hotfixes`, `quote`, `lab`, `note`, `warning`, `danger` | да |
| `title` | строка | нет |
| `collapsed` | `true`, `false` | нет |

**Правило:** пустые строки после `<note>` и перед `</note>` обязательны.

### Markdown-формат (`syntax: Legacy` / `GitHub Flavored Markdown`)

Форма `:::` — для синтаксиса `Legacy` и `GitHub Flavored Markdown`. Значение
`Markdown`, перечислявшееся здесь writer 4.6.0, значением движка не является —
оно трактуется как `Legacy` (см. `doc-root-schema.md` → ключ `syntax`).

```markdown
:::info

Информационный блок.

:::

:::tip Заголовок

Подсказка с заголовком.

:::
```

## Скрытые фрагменты и привязки к свойствам

### `<cut>` — инлайн-скрытый фрагмент

```markdown
Текст до <cut text="Подробнее" expanded="true">скрытое содержимое</cut> текст после.
```

| Атрибут | Значения | Назначение |
|---------|----------|------------|
| `text` | строка | Надпись сворачивающего фрагмента |
| `expanded` | `true`, `false` | Развёрнут по умолчанию |

Инлайн-форма рендерится спойлером; блочная форма — legacy: редактор переписывает
её при сохранении (docs-пометка, RES-007 §4) — в новом контенте использовать
инлайн-форму. Engine: `cut.ts:6-21`.

### `<property/>` — привязка к свойству каталога

```markdown
<property id="Тип контента" value="ADR"/>
```

Привязка вкладок/контента к свойству каталога, в том числе механизм подстановки
версии (назначение — docs, RES-007 §3; синтаксис — engine: `propertyTag.ts:3-8`).
Атрибуты: `id` (свойство каталога), `value` (значение).

### `<inline-property/>` — значение свойства в тексте

```markdown
Текущий статус: <inline-property bind="Статус"/>.
```

Атрибут `bind` — свойство каталога; его значение подставляется в текст статьи
(engine: `inlineProperty.ts:5-11`).

## Дашборды через `<view>`

Динамический список статей с фильтрами, сортировкой и группировкой. Используется
в `_index.md`.

### Синтаксис

```markdown
<view defs="Статус=Historical&Superseded, hierarchy=child-to-current" orderby="Статус" select="Статус, Тип контента" display="Table"/>
```

Пример скрывает статьи со `Статус` = `Historical` или `Superseded`, ограничивает
выборку потомками текущего раздела, сортирует по `Статус`, показывает колонки
`Статус` и `Тип контента` в табличном представлении.

### Атрибуты

| Атрибут | Формат значения | Семантика |
|---------|-----------------|-----------|
| `defs` | `свойство=v1&v2, свойство2=…` | Фильтр сокрытия: перечисленные значения исключают статьи из выборки — статьи с ними скрыты. `none` — остаются только статьи, у которых свойство есть; `yes` — только статьи без свойства. Системная запись `hierarchy=child-to-current` ограничивает выборку потомками текущего раздела |
| `orderby` | `свойство=v1&v2` или голое имя свойства | Сортировка результата |
| `groupby` | имя свойства | Группировка результата (опц.) |
| `select` | перечень свойств | Показываемые колонки свойств |
| `display` | `List`, `Table`, `Kanban`; дефолт `List` | Представление. Значение Gantt, называемое docs gram.ax, в движке на пине отсутствует — не указывать (BR-016) |

Внутри property-записи `&` перечисляет значения; между записями `,`. `hierarchy` —
не атрибут тега, а запись системного свойства внутри `defs`.

Семантика `none` / `yes`:

```markdown
<view defs="Тип контента=none"/>
```
— только статьи, у которых свойство `Тип контента` есть;

```markdown
<view defs="Тип контента=yes"/>
```
— только статьи, у которых свойства нет.

**Примечание (NFR-071):** прежняя формулировка writer 4.6.0 называла `defs`
«фильтром отбора», а `none` толковала как «и статьи без значения» — она была
обратной реальному поведению движка и заменена по вердикту 3 RES-008
(`ViewFilter.ts:90-114,259-290`); старый пример с ней удалён.

### Когда использовать

- ✅ Корневой `_index.md` каталога — дашборды всех статей
- ✅ `_index.md` крупного раздела (>20 статей) — для группировки
- ❌ Малые разделы (<10 статей) — избыточно, проще ручная таблица

### Связь со схемой

Свойства в `defs=`, `orderby=`, `select=` должны совпадать с property из
`.doc-root.yaml` — по `id`, а без него по `name` (правило `id ?? name`; точное
совпадение значения). См. `references/doc-root-schema.md`.

## Фрагменты (Fragments)

Канон движка (вердикт 1 RES-008): фрагмент — markdown-файл без frontmatter в
`.gramax/fragments/`; вставка — `<fragment id="…"/>`:

```markdown
<fragment id="common-warning"/>
```

Ссылка на фрагмент с собственным текстом — `<fragment-link id>текст</fragment-link>`:

```markdown
<fragment-link id="common-warning">Перед установкой сделайте бэкап.</fragment-link>
```

Пути и теги — engine: реестр `getTagElementRenderModels.ts:65-72`, схемы
`fragment.ts:5-30`, `fragmentLink.ts:4-15`, каталог `const.ts:6,10-11`.

**Legacy (NFR-071):** форма `<snippet id="…"/>` и каталог `.gramax/snippets/`
валидны — движок читает их как алиасы того же элемента; при первой правке
фрагмента движок сам мигрирует файл в `fragments/` (`FragmentProvider.ts:27-31,
129-144`). Превентивная массовая миграция не нужна — рендерного выигрыша нет,
принудительно переносить не требуется.

```markdown
<snippet id="common-warning"/>
```

## Видео

```markdown
<video path="https://youtube.com/watch?v=..."/>
```

Хостинги пути вставки (гейт редакторской вставки и вставки из MS Office —
engine: `isVideoSupported.ts:1-12`): `youtube.com`, `youtu.be`, `drive.google.com`,
`mega.nz`, `rutube.ru`, `dropbox.com`, `instagram.com`; плюс прямые файлы
`mp4` / `webm` / `ogg`.

Атрибуты `title` и `scale` — engine-верифицированы (`video.ts:12-16`,
`getVideoAttrs.ts:3-9`):

```markdown

```

**Embed-правило рендера** (engine: `RenderVideo.tsx:163-166`): внешний URL,
содержащий подстроку `embed`, рендерится как iframe как есть — рабочий способ для
хостингов вне списка семи; редакторская вставка и вставка из MS Office остаются
ограничены списком семи.

**Негативная пометка (Q4, BR-015):** атрибут обложки cover, названный в docs
gram.ax, в движке на пине `48592b36` не найден — не использовать в новом контенте.

## Изображения

### Markdown

```markdown
![](./screenshot.png){width=800 height=450}
```

Аннотация `{…}` после картинки применяется к `width` и `height`
(engine: `imgSizePlugin.ts:24-25`); для `scale` используйте XML-форму.

### XML (с кадрированием/аннотациями)

```markdown
<image src="./image.png" crop="..." objects="..." width="800" height="450" float="center"/>
```

**Не редактируй** числовые параметры `crop` и `objects` вручную — генерируются редактором.

### Семантика размеров (вердикт 5 RES-008)

- `width` / `height` — реальный размер файла в пикселях (px): резервирует место
  до загрузки; отображение ограничено шириной колонки. Это НЕ «размер отображения»
  (engine: `ImageRenderer.tsx:168-193`, `getAdjustedSize.ts:9-17`).
- `scale` — ширина на странице: значение в `px` — абсолютная ширина (не больше
  ширины колонки); число — проценты ширины колонки (`getScale.ts:1-3`).
  Атрибут XML-формы `<image scale="…"/>`:

```markdown
<image src="./image.png" scale="400px"/>
<image src="./image.png" scale="50"/>
```

- Без `scale` ширина = `min(width, ширина колонки)` с сохранением пропорций.

### Парные изображения (`img-h` / `img-v`)

Две картинки рядом (`img-h`) или столбиком (`img-v`); атрибуты `imageFirst`,
`imageSecond` (engine: реестр `getTagElementRenderModels.ts:55-56`, схема
`imgs.ts:5-19`):

```markdown
<img-h imageFirst="./before.png" imageSecond="./after.png"/>
```

Engine-пометка: в HTML-фолбэк-карте рендера компонент помечен unsupported
(`getMdHTMLComponents.tsx:25`) — надёжнее всего элемент рендерится в основном
веб-рендере.

Тег галереи (галерейный блок с каруселью/плиткой) в движке на пине отсутствует —
не документируется и не используется (BR-016).

## Draw.io

```xml
<drawio path="./filename.svg" width="WIDTHpx" height="HEIGHTpx"/>
```

Файл `.svg` хранится рядом со статьёй, создаётся через `gramax:drawio`.

Устаревший формат (до v4.1.0): `[drawio:./filename.svg:Описание:WIDTHpx:HEIGHTpx]` — в новых документах не использовать.

Устаревший формат (в старых каталогах): `[START Name.drawio](<./START Name.drawio>)` — **не использовать для новых документов**. Конвертация и детали → `drawio.md`.

## UI-токены

**XML-формы — канон для `syntax: XML`** (engine: `cmd.ts:3-10`, `kbd.ts:3-8`,
`alfaBeta.ts:3-9`; реестр `getTagElementRenderModels.ts:104-112`):

```markdown
<cmd text="Сохранить" icon="plus" color="blue"/>
<kbd text="Ctrl+S"/>
<alfa/>
<beta/>
```

| Тег | Атрибуты | Результат |
|-----|----------|-----------|
| `<cmd>` | `text`, `icon`, `color` | Кнопка/команда (атрибут `color` — новое знание, RES-008 вердикт 4) |
| `<kbd>` | `text` | Сочетание клавиш |
| `<alfa>` | — | Альфа-бейдж |
| `<beta>` | — | Бета-бейдж |

**Скобочные формы — валидны** (вход препарсера движка, `MdParser.ts:251-263`;
позиционные аргументы маппятся на атрибуты по порядку — `MdParser.ts:315-324`):

| Токен | Пример | Результат |
|-------|--------|-----------|
| `[cmd:Label]` | `[cmd:Сохранить]` | Кнопка/команда |
| `[cmd:Label:Icon]` | `[cmd:Добавить:plus]` | Кнопка с иконкой |
| `[kbd:Keys]` | `[kbd:Ctrl+S]` | Сочетание клавиш |
| `[alfa]` | `[alfa]` | Альфа-бейдж |
| `[beta]` | `[beta]` | Бета-бейдж |

Парность токена цвета: `[color:#FF5733]текст[/color]`.

Legacy HTML-форма `<kbd>текст</kbd>` читается движком (`MdParser.ts:79,245-249`) —
в новом контенте использовать XML- или скобочную форму.

## Формулы

Inline:
```markdown
Формула $E = mc^2$ в тексте.
```

Block:
```markdown
$$
\int_0^\infty e^{-x^2} dx = \frac{\sqrt{\pi}}{2}
$$
```

Legacy (если встречается — сохраняй как есть):
```markdown
{%formula content="E = mc^2" /%}
```

**`${…}` — не формула.** Подстановки (плейсхолдер секрета, shell-переменная в примере команды)
движком математикой не считаются: `$…$` не может открыться или закрыться на `${…}` —
`${PROJECT_NAME}` или `export PATH=${PATH}:/opt/bin` в тексте и код-блоках безопасны.

**Плейсхолдеры ключей и паролей** (элемент «секреты», движок 2026-jul→sep): `${key.field}`,
где поле — `login` | `password` | `token` | `url`, например `${gitlab.token}`. В тексте это
отображается как плейсхолдер, а не литерал `${…}`; в формулы не превращается никогда.
