# Операции со структурой Gramax-каталога

## Превращение страницы в раздел

Когда к листовой странице добавляется вложенная статья — страница становится разделом (директорией).

**До:**
```
parent-folder/
├── _index.md
└── my-article.md              # листовая страница
```

**После:**
```
parent-folder/
├── _index.md
└── my-article/                # теперь папка
    ├── _index.md              # содержимое бывшей my-article.md
    ├── _index.comments.yaml   # комментарии (если были)
    └── nested-article.md      # вложенная статья
```

Операции при трансформации:

| Было | Стало |
|------|-------|
| `my-article.md` | `my-article/_index.md` |
| `my-article.comments.yaml` | `my-article/_index.comments.yaml` |
| Вложения рядом с `my-article.md` | Переместить в `my-article/` |

**Важно:** обнови все ссылки на эту страницу — путь меняется с `./my-article` на `./my-article/_index`.

## Добавить статью в существующий раздел

Раздел — папка с `_index.md`. Просто создай новый `.md` файл:

```
existing-section/
├── _index.md
├── existing-article.md
└── new-article.md          # ← создать
```

## Добавить вложенную статью

Если нужный подраздел уже существует:

```
existing-section/
├── _index.md
└── sub-section/
    ├── _index.md
    └── new-nested.md       # ← создать
```

## Добавить новый раздел

Создай папку с `_index.md`:

```
parent/
├── _index.md
└── new-section/            # ← папка
    └── _index.md           # ← файл
```

## Переместить статью

1. Перемести `.md` файл
2. Перемести `.comments.yaml` (если есть)
3. Перемести вложения, используемые статьёй (изображения, SVG, PDF, YAML)
4. Обнови все ссылки на эту статью
5. Добавь старый путь в `aliases` во frontmatter статьи — список старых путей
   без `.md` относительно корня контента. Перенос через UI движок записывает его
   сам (engine: `aliasAutowrite.ts:31-44`); при ручном переименовании/переносе
   агент добавляет его сам:

```yaml
---
order: 3
title: "Название"
aliases:
  - old-section/old-name
---
```

## Переместить раздел

1. Перемести всю папку целиком
2. Обнови ссылки на все страницы внутри раздела
3. Для каждой статьи с изменившимся публичным путём добавь старый путь в её
   `aliases` (см. «Переместить статью», шаг 5) — иначе внешние ссылки на раздел
   перестанут резолвиться

## Удалить статью

1. Удали `.md` файл
2. Удали `.comments.yaml` (если есть)
3. Удали вложения, которые больше не используются
4. Убери ссылки на эту статью

## Удалить раздел

1. Удали папку целиком (включая `_index.md`, все статьи, вложения)
2. Убери ссылки на страницы этого раздела

## Правила `_index.md`

### Корень каталога — `_index.md` разрешён, не обязателен, но не отображается

**Корень каталога (где `.doc-root.yaml`) может содержать `_index.md`, но Gramax его не
показывает.** Файл не запрещён — валидатор не считает его ошибкой, — однако движок
каталога исключает `_index.md` из списка статей любой папки, включая корень, и для
корневой категории не выполняет шаг чтения индекс-файла, который выполняется для
подпапок: содержимое не появляется в интерфейсе ни как титульная страница, ни как раздел.
Навигация корня строится целиком из `.doc-root.yaml`. Кладите `_index.md` в корень, только
если этого требует внешний инструмент вашего проекта (например, собственный
content-валидатор) — не как способ показать читателю дашборд: этот текст останется видимым
только в git-репозитории.

Статьи размещаются как:
- `leaf.md` — листовая статья
- `section/` — директория со своей `_index.md` и дочерними

**Пример:**
```
catalog/
├── .doc-root.yaml
├── simple-page.md
└── main-section/
    ├── _index.md
    ├── child-1.md
    └── child-2.md
```

```
catalog/
├── .doc-root.yaml
├── _index.md           ← не запрещён, но Gramax его не отображает
├── child-1.md
└── child-2.md
```

### Подпапки — `_index.md` обязателен (исключение: `optionalCategoryIndex`)

В **любой** подпапке каталога (содержащей `.md` файлы или вложенные папки) `_index.md` обязателен. Без `_index.md` папка не становится разделом: раздела в дереве нет, статьи поднимаются на уровень выше. Флаг `optionalCategoryIndex: true` в `.doc-root.yaml` снимает требование — такая папка становится разделом, список детей движок собирает сам (движок подставляет его и без индекс-файла).

**Сценарии:**

| Тип подпапки | Шаблон `_index.md` |
|--------------|--------------------|
| Коллекция однотипных статей (`adr/`, `runbooks/`) | `order` + `title` + описание + таблица файлов |
| Статья с подстатьями (`api-reference/`) | `order` + `title` + контент-как-у-обычной-статьи |
| Узел иерархии без своего контента | `order` + `title` + `<view>` для генерации списка |

`properties:` в `_index.md` подпапки разрешены: движок читает свойства раздела как свойства статьи (`Category` наследует `Article`), и фильтр каталога судит раздел по его собственным свойствам, если в фильтре не выжил ни один ребёнок. Валидатор применяет к индексу подпапки те же проверки свойств, что и к статьям (объявленность, enum, нотация).

### Сравнение: корень vs подпапка

| | `_index.md` в корне | `_index.md` в подпапке |
|-|---|---|
| Обязателен? | Разрешён, не обязателен | Обязателен (исключение: `optionalCategoryIndex: true`) |
| Отображается Gramax? | **Нет** — исключён из чтения корневой категории движком | Да — становится титулом раздела |
| `properties:` | Может содержать, но движок файл не читает — свойства ни на что не влияют (ADR-0015); валидатор вне проверок | Разрешены: фильтр судит раздел по собственным свойствам; проверяются по схеме каталога |
| Назначение | Нет Gramax-функции; допустим, если требуется внешним инструментом проекта (например, nauta) | Титул раздела + навигация |

## XML-блоки, засчитываемые как структура

Наравне с заголовком и таблицей, следующие Gramax-теги считаются структурным элементом статьи
— опора для сторонних эвристик (валидаторы потребителей, метрики объёма вроде используемой в
BA-процессе ADR-018), чтобы не переизобретать собственный детектор:

`<note>`, `<tabs>`, `<view>`, `<snippet>`, `<mermaid>`, `<drawio>`, `<image>`, `<openapi>`

Полный синтаксис каждого блока — `references/blocks.md`; этот список декларирует только то,
что считается структурой, не дублирует справочник синтаксиса.

## Примеры структур

### Каталог с одной статьёй-разделом

```
my-catalog/
├── .doc-root.yaml
└── opisanie-processa/
    ├── _index.md
    ├── politika-1.md
    └── politika-2.md
```

### Каталог с несколькими статьями и вложенностью

```
my-catalog/
├── .doc-root.yaml
├── new-article.md                    ← листовая
├── rabochie-instrumenty/             ← статья с дочерними
│   ├── _index.md
│   ├── tool-1.md                     ← дочерняя листовая
│   └── nested-section/               ← вложенная с дочерними
│       ├── _index.md
│       ├── page-1.md
│       └── page-2.md
└── katalog-roley/
    └── _index.md
```
