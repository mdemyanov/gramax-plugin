# `.doc-root.yaml` — справочник схемы

Конфигурация каталога Gramax. Лежит в корне. Рядом с `.doc-root.yaml` может лежать
`_index.md` — он разрешён, но Gramax его не отображает (ADR-0015; см.
`references/structure.md` → «Правила `_index.md`»).

## Корневые ключи

| Ключ | Тип | Обязательное | Назначение |
|------|-----|--------------|------------|
| `title` | string | да | Заголовок каталога в Gramax UI |
| `description` | string | да | Описание для каталог-листа |
| `language` | string | да | Основной язык (`ru` / `en`) |
| `syntax` | enum | да | `XML` (активирует `<note>`, `<tabs>`, `<view>`) или `Markdown` |
| `code` | string | нет | Короткое отображаемое имя каталога в UI (≤4 символа по форме настроек; резолвером ссылок не используется) |
| `style` | string | нет | Цвет заголовка каталога. Палитра — та же, что для property-level `style:` (см. ниже). |
| `supportedLanguages` | array | нет | Список поддерживаемых языков; `[]` = без ограничений |
| `properties` | array | нет | Определения property для frontmatter (см. ниже) |
| `filterProperties` | array | нет | Имена property для боковой панели фильтров: `[Тип контента, Фаза]` |
| `editors` | array | нет | Email'ы с правами публикации |

## Property-определение

```yaml
properties:
  - name: <имя property>
    type: <Enum | String>
    style: <цвет бейджа>
    icon: <Lucide-иконка>
    values:
      - <значение 1>
      - <значение 2>
```

| Поле | Обязательное | Назначение |
|------|--------------|------------|
| `name` | да | Имя property; используется в frontmatter статей в `- name: <X>` |
| `type` | да | `Enum` для select из `values:`; `String` для свободного текста |
| `style` | нет | Цвет бейджа в frontmatter и sidebar |
| `icon` | нет | Lucide-иконка рядом с бейджем |
| `values` | для `Enum` | Массив строк — допустимые значения |

## Палитра `style:`

Применяется к двум уровням: к корневому ключу `style:` (цвет заголовка каталога) и к property-level `style:` (цвет бейджа property). Список валидных значений общий.

Подтверждённые валидные значения:

`gray`, `green`, `light-green`, `blue`, `light-blue`, `blue-green`, `purple`, `light-purple`, `orange`, `dark-orange`, `light-pink`

**Рекомендуемая семантика:**

- **categorical** (что это) — `green`, `light-blue`, `purple`
- **lifecycle** (где в цикле) — `light-green`, `dark-orange`
- **priority / attention** — `orange`, `dark-orange`, `light-pink`
- **metadata** (id, технические поля) — `gray`

## Иконки

Любая иконка из набора Lucide (`https://lucide.dev/icons`). Часто используемые:

`hash`, `layers`, `package`, `box`, `folder`, `user`, `users`, `zap`, `briefcase`, `link`, `repeat`, `play`, `target`, `circle-check`, `alert-triangle`, `git-branch`, `file-text`, `check-circle`, `user-check`

## `code` — декоративное имя каталога, не идентификатор для ссылок

Поле `code` (см. таблицу выше) — короткое отображаемое имя каталога, ограниченное вендорской
формой настроек каталога 4 символами. Это декоративный элемент карточки каталога в UI Gramax:
резолвер ссылок нигде его не читает и не использует как идентификатор каталога-цели.

Прежде этот раздел показывал двухшаговый рецепт cross-каталожной ссылки, построенный на
`code:` (каталог-источник объявляет значение → каталог-получатель ссылается через inline code
`` `CODE/путь.md` ``), как перспективный синтаксис. Проверка на реальном резолвере опровергла
рецепт: путь без `../`-префикса структурно не может покинуть каталог статьи-источника — какое
бы значение ни стояло первым сегментом, ссылка остаётся внутри своего каталога. Рецепт не
резолвился бы ни при каком внешнем сетапе.

Рабочей замены рецепту здесь не публикуется. Практическая рекомендация для cross-каталожной
ссылки не изменилась: inline code, не markdown-ссылка — см. `SKILL.md` → «## Ссылки». Дальнейшая
правка этого раздела — только по результатам нового исполняемого теста на живом сетапе, не по
чтению кода или предположению.

## Вложенные `.doc-root.yaml` и overlay-расширение `properties`

**Вложенные `.doc-root.yaml`-каталоги** (подпапка внутри уже описанного каталога, несущая
собственный `.doc-root.yaml` со своим набором `properties`) — вне периметра плагина. Поведение
`writer` и `validate_structure.py` для этого сценария (конфликт property, приоритет второго
`.doc-root.yaml`) не специфицировано и не гарантировано. Единственный известный случай — один
сторонний каталог-потребитель со вложенным `.doc-root.yaml` — недостаточный сигнал (BR-001),
чтобы фиксировать поведение как контракт плагина: сигнал по одному случаю недостаточен для
нетривиальной поверхности. Потребитель, использующий вложенные `.doc-root.yaml`, управляет
этим сценарием сам — решение зафиксировано явно, не молчанием; при усилении сигнала (≥2–3
независимых случая) — кандидат отдельного ADR.

**Overlay-расширение `properties`** сверх набора, заданного владельцем каталога, технически не
запрещено (YAML не проверяется полной схемой), но не валидируется плагином. Необязывающая
рекомендованная конвенция провенанса — комментарий рядом с добавленным property:

```yaml
properties:
  - name: Сценарий
    type: Enum
    values: [...]
    # добавлено overlay'ем <имя-оверлея>
```

Как и вложенные каталоги — формальная поддержка overlay как first-class механизм здесь не
решена (тот же недостаточный сигнал одного случая); усилится сигнал — кандидат того же
будущего ADR.

## Content type ADR — `Статус`

Рекомендация по property `Статус` для статей с `Тип контента: ADR`:

- **Новые каталоги** — enum `Статус` включает `Proposed` наравне с уже принятыми значениями
  (`Accepted`, `Superseded`, `Historical`, ...), 1:1 с телом ADR
  (`Proposed | Accepted | Superseded by ADR-MMMM`), без слоя трансляции.
- **Существующие каталоги**, где enum разошёлся сильнее одного значения (пример — сторонний
  каталог-потребитель, где тело `Accepted`/frontmatter `Approved`, тело `Proposed`/frontmatter
  `Review`) — обязательная явная таблица соответствия (`Тело ADR` / `Frontmatter`) в реестре
  ADR каталога.
- **Источник истины.** Тело статьи (`**Статус:**` или аналог) — источник истины; `Статус` во
  frontmatter — проекция, обновляется тем же изменением, что и тело. Расхождение носителей
  (тело говорит одно, frontmatter — другое) — дефект.

**Известное расхождение этого репозитория:** `content/.doc-root.yaml` сегодня не включает
`Proposed` в enum `Статус` — приведение в соответствие вынесено в отдельный follow-up
(SA/PM), не решается точечной правкой документации `writer`.

## Полный пример

```yaml
title: My Knowledge Base
description: Documentation catalog
language: ru
syntax: XML
style: blue
supportedLanguages: []

properties:
  - name: Тип контента
    type: Enum
    style: green
    icon: file-text
    values:
      - Требование
      - Архитектура
      - ADR

  - name: Статус
    type: Enum
    style: dark-orange
    icon: check-circle
    values:
      - Draft
      - Approved
      - Superseded

filterProperties: [Тип контента]
editors:
  - user@example.com
```

## Антипаттерны

### `required:` на property

Не используется на практике. Gramax не делает с ним ничего полезного — пропускать.

### `type: select` с `values: [{name: X}]`

Экспериментальный синтаксис, не рекомендуется. Использовать `type: Enum` со строковым массивом `values:`.
