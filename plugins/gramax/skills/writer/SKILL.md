# Gramax Writer

Создание, редактирование и структурирование документации в формате Gramax (markdown + XML-расширения для визуального редактора).

## Core Principles

### 1. Сохраняй существующий формат

Если в репо уже есть контент — сохраняй структуру, нейминг, форматирование. Не переформатируй таблицы, не меняй синтаксис блоков.

### 2. Следуй syntax из `.doc-root.yaml`

Если указано `syntax: XML` — используй XML-теги (`<note>`, `<tabs>`, `<snippet/>`). Проверяй `.doc-root.yaml` перед редактированием.

### 3. Храни вложения рядом со страницей

Изображения, SVG, PDF, YAML, Mermaid-файлы — в той же папке, что и страница, которая их использует.

### 4. Не ломай макросы форматированием

Автоформатирование может сломать блоки Gramax. Сохраняй пустые строки вокруг `<note>`, `<tabs>`. Не трогай самозакрывающиеся теги и XML-форматы таблиц/изображений из визуального редактора.

### 5. `writer` — authoritative источник Gramax-соглашений

Локальный скилл потребителя, специфичный для одного каталога/проекта, — легитимен; локальный скилл, переизлагающий общее правило `writer` и объявляющий себя приоритетным «при расхождении», — сигнал устаревания/неполноты `writer` (обнаружение — `references/authoritative-source.md`), не постоянная архитектура.

## Workflow

### При первой операции

1. Найди `.doc-root.yaml` в корне каталога
2. Прочитай `syntax` (XML, Legacy или GitHub Flavored Markdown) и `language`
3. Применяй соответствующее форматирование во всех последующих операциях

### При создании/редактировании

1. Определи целевую папку
2. Сформируй имя файла по правилам нейминга (см. ниже)
3. Создай frontmatter (`order`, `title`)
4. Добавь контент с блоками в правильном syntax

## Структура каталога

```
.
├── .doc-root.yaml             # конфигурация каталога — только в корне
├── simple-page.md             # листовая статья
├── parent-article/            # статья с дочерними — ДИРЕКТОРИЯ
│   ├── _index.md              # титульная страница этой статьи
│   ├── child-page.md
│   ├── image.png              # вложения рядом со страницей
│   └── nested-article/        # вложенная статья с дочерними
│       ├── _index.md
│       └── grandchild.md
└── another-article/
    └── _index.md
```

**Ключевые правила:**
- Папка = статья с дочерними. `_index.md` внутри = титульная страница этой статьи.
- Листовая статья = просто `article.md` (без папки).
- **Корень каталога (где `.doc-root.yaml`) может содержать `_index.md`, но Gramax его не
  показывает.** Файл не запрещён — валидатор не считает его ошибкой, — однако движок
  каталога исключает `_index.md` из списка статей любой папки, включая корень, и для
  корневой категории не выполняет шаг чтения индекс-файла, который выполняется для
  подпапок: содержимое не появляется в интерфейсе ни как титульная страница, ни как
  раздел. Навигация корня строится целиком из `.doc-root.yaml`. Кладите `_index.md` в
  корень, только если этого требует внешний инструмент вашего проекта (например,
  собственный content-валидатор) — не как способ показать читателю дашборд: этот текст
  останется видимым только в git-репозитории.
- **Каждая подпапка с `.md`-файлами или вложенными папками ОБЯЗАНА содержать `_index.md`.** Без него Gramax не строит навигацию — папка не видна в дереве, статьи внутри недоступны.

Минимальный шаблон `_index.md` для подпапки-коллекции:

```markdown
---
order: <число>
title: <Название раздела>
---

<Одно-два предложения, что здесь хранится.>

| Файл | Описание |
|------|----------|
| [Название](файл.md) | Краткое описание |
```

**Пример:**
```
catalog/
├── .doc-root.yaml
├── _index.md           ← не запрещён, но Gramax его не отображает
└── child-1.md
```

```
catalog/
├── .doc-root.yaml
├── simple-page.md
└── main-section/
    ├── _index.md
    └── child-1.md
```

Операции со структурой (добавить/переместить/удалить/превратить страницу в раздел) → `references/structure.md`.

## Frontmatter

Каждый `.md` **обязан** начинаться с frontmatter. Формат отличается для статей и `_index.md`.

### Статья (любой `.md`, кроме `_index.md`)

```yaml
---
order: 1
title: "Заголовок статьи"
properties:
  - id: <id property из .doc-root.yaml>   # без id у property — name
    value: [<значение из enum>]
---
```

- `order` — числовой порядок в навигации (целые или десятичные для вставки)
- `title` — заголовок на языке страницы; в кавычках если содержит `:` или начинается с цифры
- `properties` — **опционально**, список объектов `{id, value: [...]}`. Привязка —
  по `id` property (канон сериализации редактора); name-нотация (`- name: <X>`)
  читается движком фолбэком — существующие каталоги продолжают работать.
  `value:` всегда массив (поддерживает мульти-select).

### Дополнительные ключи frontmatter статьи

| Ключ | Назначение |
|------|------------|
| `searchPhrases` | Список поисковых фраз: подъём статьи в поиске по тексту; регистр не важен, срабатывание по части слова (RES-007 §2) |
| `aliases` | Список старых путей (без `.md`, от корня контента) после переноса/переименования статьи; UI-перенос записывает его сам, ручной — агент добавляет сам (см. `references/structure.md`) |
| `quiz` | Режим (тест/опрос) и поведение вопроса-блока статьи → `references/quizzes.md` |
| `template` | `<id>` шаблона: тело статьи хранится в `.gramax/templates/<id>.md`, файл статьи тела не содержит — см. Guardrails |
| `description` | Текст для поиска и превью статьи; без ключа берётся начало текста статьи (не путать с `description` каталога в `.doc-root.yaml`; docs-пометка, RES-007 §3/§4) |
| `hidden` | Скрыть статью (не путать с `hidden` каталога; docs-пометка, RES-007 §3/§4) |

Служебные ключи frontmatter `welcome`, `external`, `shouldBeCreated` пишет движок —
агенту не писать (docs-пометка, RES-007 §4).

### `_index.md` (любая папка, включая корень — Gramax его там не отображает, см. выше)

```yaml
---
order: 1
title: Название раздела
---
```

`_index.md` **не должен содержать** блок `properties:` — раздел не имеет собственных property, они определяются на статьях. Для фильтров по разделу — `<view>` блоки в теле (см. ниже).

**Дополнительные ключи `_index.md`** (docs-пометка, RES-007 §3/§4):

| Ключ | Назначение |
|------|------------|
| `expanded` | Свернуть раздел в навигации; ключ `_index.md`, не атрибут `<cut expanded>` (тот управляет свёрнутым фрагментом в теле статьи) |
| `orderAsc` | `false` — сортировка статей раздела по убыванию |

### Антипаттерн: плоская нотация (LEGACY)

```yaml
properties:
  - Тип контента: ADR
  - Фаза: PoC
```

Встречается в старых каталогах. Gramax парсит, но рендерит непредсказуемо при несовпадении регистра ключей. **Не использовать в новом контенте.** При работе с legacy — мигрировать пакетно.

## `.doc-root.yaml` — кратко

Конфигурация каталога. Лежит в корне.

```yaml
title: My catalog
description: Описание каталога
language: ru
syntax: XML

properties:
  - id: content-type
    name: Тип контента
    type: Enum
    style: green
    icon: file-text
    values: [Требование, ADR, Архитектура]

filterProperty: content-type
```

**Ключевое:**
- `properties` — список **объектов** с `id/name/type/style/icon/values`. Привязка во
  frontmatter статей — по `id` (без него по `name`).
- `style:` — цвет бейджа property. Палитра — 20 значений enum движка (включая
  двухцветные; 6 цветов writer 4.6.0 вне enum — см. `references/doc-root-schema.md`).
- `icon:` — любая иконка из Lucide (`https://lucide.dev/icons`) или собственный код из `.icons/`.
- `filterProperty` — один property (его `id`, а без него `name`) для боковой панели
  фильтров. Форма `filterProperties` (список), которую учил writer 4.6.0, движком
  не читается — миграция: заменить на `filterProperty`.

Полный справочник (все ключи, палитра, антипаттерны) → `references/doc-root-schema.md`.

## Нейминг файлов и папок

Правила:
1. Транслитерация кириллицы в латиницу
2. Пробелы и спецсимволы → дефис `-`
3. Только lowercase
4. Удалить кавычки, скобки, точки (кроме расширения)
5. Множественные дефисы схлопнуть в один

Примеры:
| Заголовок | Имя файла |
|-----------|-----------|
| Быстрый старт | `bystryy-start.md` |
| Установка и настройка | `ustanovka-i-nastroyka.md` |
| Раздел «Документы» | `razdel-dokumenty/` |
| Что нового? | `chto-novogo.md` |

**Утилита:**
```bash
uv run ${CLAUDE_PLUGIN_ROOT}/scripts/slugify.py "Быстрый старт"           # → bystryy-start
uv run ${CLAUDE_PLUGIN_ROOT}/scripts/slugify.py --filename "Что нового?"  # → chto-novogo.md
```

Полная таблица транслитерации → `references/blocks.md`.

## Ссылки

- Внутренние (без `.md`): `[Название](./другой-документ)` или `[Название](./../app/_index)`
- На раздел: `[Название](./features/_index)`
- На вложения (с расширением): `./diagram.png`, `./file.pdf`
- Якоря заголовков: `## Установка {#ustanovka}`, ссылка из текста — `[Установка](#ustanovka)` (подробнее → `references/blocks.md` → «Якоря заголовков»)
- Кросс-каталожные: `` `other-catalog/path/to/file.md` `` — inline code, не markdown-ссылка

**Оговорка о форме с `.md` (RES-008 вердикт 2):** обе формы резолвятся движком и
офлайн-валидатором. Канон для новых ссылок — форма без .md (родная форма сериализации
редактора для XML/Legacy-каталогов); форма с .md — валидный, но не канонический вид.
Миграция существующих .md-ссылок не обязательна.

**Cross-каталожные ссылки:** только inline code, не markdown-ссылка. Обычная ссылка без
`../`-префикса не покидает каталог статьи-источника — резолвится только то, что физически лежит
внутри текущего `.doc-root.yaml`-каталога:

❌ `[Документ](other-catalog/path/to/file.md)` — не резолвится
✅ `` `other-catalog/path/to/file.md` `` — работает (читается как путь, не как ссылка)

Ловушка чужих валидаторов: код-спан `` `[X](Y)` `` (обратные кавычки) внешне похож на
markdown-ссылку `[X](Y)` — regex-чекер потребителя может дать ложное срабатывание даже на
корректном ❌-примере выше.

**Антипаттерн — повтор имени doc-root-каталога:** путь, начинающийся с имени каталога, где лежит
`.doc-root.yaml` (в этом репозитории — `docs`), внутри текста markdown-ссылки не резолвится
ни при каких условиях — не альтернативный синтаксис, а невалидная форма (FR-081):

❌ `[Название](docs/section/doc.md)` — не резолвится: движок не ожидает имя doc-root-каталога
внутри пути ссылки; реальный файл резолвится только БЕЗ этого префикса
✅ `[Название](section/doc.md)` или `[Название](./section/doc)` — путь относительно каталога
документа-источника, без повтора имени doc-root-каталога

**Ссылка на файл без расширения:** цель без суффикса, не резолвящаяся в статью, но существующая
как файл, рендерится ссылкой на скачивание — движок отличает существующий файл от статьи
(gh#675, окно движка jul→sep 2026):

✅ `[Лицензия](LICENSE)` или `[Сборка](./Dockerfile)` — файл-ссылка на скачивание

## Изображения

Markdown:
```markdown
![](./screenshot.png){width=800 height=450}
```

XML (с кадрированием/аннотациями — НЕ редактировать `crop`/`objects` вручную):
```markdown
<image src="./image.png" crop="..." objects="..." width="800" height="450" float="center"/>
```

Семантика размеров (вердикт 5 RES-008): `width`/`height` — реальный размер файла в
px (резерв места до загрузки, ограничение шириной колонки); ширина на странице —
отдельный атрибут `scale` XML-формы (`scale="400px"` — абсолютная, `scale="50"` —
проценты ширины колонки; в markdown-аннотации `{…}` `scale` не применяется).
Парные картинки рядом/столбиком — `<img-h>`/`<img-v>`. Подробнее → `references/blocks.md` → «Изображения».

Вложения хранятся в той же папке, что и страница.

## Diagrams (Draw.io)

В Gramax диаграммы Draw.io хранятся как **SVG-файлы с встроенными drawio-данными**.

Синтаксис вставки:
```markdown
<drawio path="./filename.svg" width="WIDTHpx" height="HEIGHTpx"/>
```

Примеры:
```markdown
<drawio path="./architecture.svg" width="971px" height="311px"/>
<drawio path="./overview.svg" width="211px" height="101px"/>
```

**Drawio через внешний плагин** (двухшаговый workflow):

1. Установи prerequisites и внешний плагин `Agents365-ai/drawio-skill` (см. `references/drawio.md`).
2. Вызови внешний skill — Claude автоматически подберёт его по триггеру (drawio, схема, диаграмма).
3. Drawio-skill создаёт файл в CWD или по явно указанному пользователем пути — пользователь сам выбирает расположение.
4. Вставь тег в md вручную: `<drawio path="./file.svg" width="800px" height="600px"/>` — единый синтаксис для Markdown и XML (с v4.1.0; `.doc-root.yaml syntax` на формат тега больше не влияет).

Полные детали, prerequisites и troubleshooting → `references/drawio.md`.

## Краткий справочник блоков

| Блок | Синтаксис | Назначение |
|------|-----------|------------|
| Заметка | `<note type="tip">...</note>` | Callout (tip/info/warning/danger/...) |
| Табы | `<tabs><tab name="A">...</tab></tabs>` | Переключаемые вкладки |
| `<view>` | См. ниже | Динамический список: сокрытие, сортировка, колонки |
| Фрагмент | `<fragment id="name"/>` | Вставка из `.gramax/fragments/`; ссылка — `<fragment-link id>текст</fragment-link>` (legacy-алиас — `<snippet/>`) |
| Вопрос | `<question type="one">...` | Вопрос-блок и тесты статьи (`quiz`) → `references/quizzes.md` |
| Скрытый фрагмент | `<cut text="Подробнее">...</cut>` | Инлайн-спойлер |
| OpenAPI | `<openapi src="./api.yaml"/>` | Спецификация API |
| Mermaid | `<mermaid path="./diagram.mermaid" width="800px" height="450px"/>` | Диаграмма Mermaid |
| Видео | `<video path="URL"/>` | Встроенное видео: mp4/webm/ogg, YouTube (watch/youtu.be/shorts/live, таймкод `?t=`, плейлист `list=`), Rutube, Google Drive, Instagram, Dropbox, mega.nz; атрибуты `title`, `scale`; URL с подстрокой `embed` — iframe как есть |
| Иконка | `<icon code="lucide-name"/>` | Lucide-иконка или собственный код из `.icons/` |
| HTML | `<html>...</html>` | Сырой HTML |

### Дашборды через `<view>`

Используется в `_index.md` для списков статей с фильтрацией и группировкой:

```markdown
<view defs="Статус=Historical&Superseded, hierarchy=child-to-current" orderby="Статус" display="Table"/>
```

- `defs` — фильтр сокрытия: перечисленные значения исключают статьи из выборки
  (статьи с ними скрыты); `none` — остаются только статьи, у которых свойство
  есть; `yes` — только статьи без свойства; иерархическая выборка — записью
  `hierarchy=child-to-current` внутри `defs` (не атрибутом тега).
- `orderby` — сортировка (`свойство=v1&v2` или голое имя); `select` — показываемые
  колонки свойств; `groupby` — группировка (опц.).
- `display` — `List`, `Table` или `Kanban`; дефолт `List`.

**Когда использовать:** в корневом `_index.md` каталога (дашборд всех статей) или в крупных разделах (>20 статей). Малые разделы (<10 статей) — избыточно.

Подробности и примеры → `references/blocks.md`.

**UI-токены:** XML-формы `<cmd text="…" icon="…" color="…"/>`, `<kbd text="…"/>`,
`<alfa/>`, `<beta/>` (канон для `syntax: XML`) и скобочные `[cmd:Label]`,
`[kbd:Ctrl+S]`, `[alfa]`, `[beta]` — обе формы валидны → `references/blocks.md`.

Полный справочник блоков (все типы note, markdown-admonitions `:::info`, таблицы в 3 синтаксисах, стилизация `<color>`/`<highlight>`, формулы, служебная синтаксика, перечень «чего нет в синтаксисе», блочные комментарии) → `references/blocks.md`.

## Типовые ошибки рендеринга

Контент-линтер `validate_render.py` ловит конструкции, которые роняют рендерер Gramax (HTTP 500)
или ломают вёрстку. Киллеры — ERROR (блокируют), стиль — WARN (advisory). Правила ниже
согласованы с линтером 1:1 (BR-003) — расхождение документации и кода закрывается правкой одной
из сторон, никогда молчанием.

### ERROR — киллеры рендера

- `<th>` — не поддерживается Gramax → HTTP 500. Замените на `<td>`, шапку задаёт `header="row"` у `<table>`.
- Инлайновый `<note>…</note>` в одну строку — нужен блочный формат: `<note …>` ⏎ пустая ⏎ текст ⏎ пустая ⏎ `</note>`.
- `<note>` внутри ячейки `<td>`/`<th>` — вынесите в инлайн: `**Заголовок.** текст`.
- `<note>` вложенный в `<note>` — разверните во внешнюю заметку (`**Заголовок:**` + содержимое).
- Несколько `![](…)` в одной строке — каждое изображение на отдельной строке.
- Несбалансированные парные теги: `note`, `table`, `tr`, `td`, `th`, `tabs`, `tab`, `color`, `highlight` — открыто/закрыто должны сходиться.

### WARN — стиль, не краш

- `# H1` в теле — заголовок страницы берётся из frontmatter `title`; используйте `##` и ниже.
- frontmatter `title:` со значением, содержащим `: `, без кавычек — ломает YAML, страница пустая. Закавычьте.

### Не ошибки (allowlist)

- `<colgroup>` / `<col>` — валидные теги таблиц.
- Эмодзи в заголовках `##` и ниже.
- Скобки и спецсимволы внутри XML-атрибутов (например `title="(важно)"`).
- Многоабзацная ячейка `<td>` (пустые строки между абзацами).

### Как проверить

```bash
uv run ${CLAUDE_PLUGIN_ROOT}/scripts/validate_render.py <path-to-catalog>
```

Exit: 0 — ERROR нет (WARN допустимы), 1 — есть хотя бы один ERROR, 2 — некорректный вызов.
Pre-commit-хук плагина уже прогоняет оба валидатора — структурный (`validate_structure.py`) и
контент-линтер (`validate_render.py`, с `--errors-only`), — киллер рендера блокирует коммит
до публикации.

## Staging — pre-publish checklist

Перед подготовкой к загрузке в Gramax:

1. Удалить служебные файлы: `.DS_Store`, `Thumbs.db`, `CLAUDE.md`
2. **НЕ удалять** `.gramax/` (содержит фрагменты/сниппеты, представления, шаблоны) и `.doc-root.yaml`
3. **НЕ трогать** служебные папки `.gramax/inbox/` (личные заметки) и `.gramax/mr/` (состояние ревью) — см. Guardrails
4. Конвертировать все `.drawio` → `.svg`
5. Проверить frontmatter у всех страниц, отсутствие плейсхолдеров `{{ИМЯ}}`, статей-сирот и битых markdown-ссылок

Автоматическая проверка:
```bash
uv run ${CLAUDE_PLUGIN_ROOT}/scripts/validate_structure.py <path-to-catalog>
uv run ${CLAUDE_PLUGIN_ROOT}/scripts/validate_structure.py <path> --fix --yes   # удалить мусор
```

Полный чеклист → `references/staging.md`.

## Guardrails

- Не удаляй/переименовывай `.gramax/` (фрагменты/сниппеты, представления, шаблоны)
- **Шаблоны:** никогда не правь тело статьи, во frontmatter которой есть `template: <id>` —
  текст такой статьи хранится в `.gramax/templates/<id>.md`, файл статьи собственного
  текста не содержит. Правка статьи-потребителя допустима только во frontmatter-блоке
  `properties` (и именованных полях `fields`, которые пишет редактор). Файл шаблона
  `.gramax/templates/<id>.md` правится только как отдельная явно запрошенная операция —
  он меняет всех статьи-потребители разом; тело статьи-потребителя пусто by design —
  не «восстанавливай» его копированием текста шаблона
- **Служебные папки:** не создавай, не редактируй и не удаляй `.gramax/inbox/`
  (личные заметки пользователей) и `.gramax/mr/` (состояние ревью и согласований)
- **Git LFS:** не трогай `.gitattributes` и файлы-указатели LFS (см. ключ `lfs` в
  `references/doc-root-schema.md`)
- При переименовании страниц — обнови все ссылки и добавь старый путь в `aliases`
- Валидируй парные теги (`<note>`, `<tabs>`, `<tab>`, `<html>`, `<comment>`, `<color>`, `<highlight>`)
- Сохраняй пустые строки внутри `<note>`, `<tabs>`
- Не редактируй числовые параметры `crop`/`objects` в XML-изображениях вручную
- Не копируй в статью абсолютные локальные пути контрибьютора (`/Users/<имя>/...`, `C:\Users\<имя>\...`) — риск двойной: утечка идентификационных данных контрибьютора и битая ссылка при рендеринге у другого читателя

## Ресурсы

- `references/blocks.md` — полный справочник XML-блоков и токенов
- `references/quizzes.md` — вопрос-блоки `<question>`/`<questionAnswer>` и frontmatter `quiz`
- `references/drawio.md` — конвертация `.drawio` → SVG, алгоритм, отладка
- `references/structure.md` — операции со структурой (добавить/переместить/превратить страницу в раздел)
- `references/staging.md` — pre-publish checklist
- `references/doc-root-schema.md` — полный справочник `.doc-root.yaml`
- `references/authoritative-source.md` — легитимный vs нелегитимный локальный скилл-дубль, grep-конвенция обнаружения
- `gramax:export` — экспорт DOCX/PDF, шаблоны экспорта, CI/CD, статический портал (guidance)

## Production-паттерны

Рекомендуемая структура каталога: id-нотация frontmatter (`properties: [- id/value: [...]]`), `style:` + `icon:` на каждом property, `<view>`-дашборды в `_index.md`. Подробности: `references/doc-root-schema.md` и `references/structure.md`.
