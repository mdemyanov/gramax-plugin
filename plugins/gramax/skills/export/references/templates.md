# Шаблоны экспорта: PDF (CSS) и DOCX (Word)

Развёрнутая инструкция по авторству шаблонов экспорта и их размещению. Ядро — в `SKILL.md`;
здесь — полные списки, пути, правила. Граница исполнения: CSS-шаблон агент пишет сам
(Write tool), шаблон DOCX — бинарный Word-формат, агент его не авторит и даёт инструкцию
пользователю.

**Источники (verify-before-include).** Факты ниже — RES-007 §3 либо страницы gram.ax,
выкачанные 2026-11-18 (путь указан у каждой группы фактов), либо `npx gramax-cli --help` /
`npx gramax-cli export --help` / `npx gramax-cli build --help` (gramax-cli 1.0.54,
Node v24.21.0, 2026-11-18). Sample-шаблоны файлами не поставляются (решение SA — открытые
вопросы 3/5 требования): CSS-скелет изобрёл бы свойства сверх документированных, `.dotx` —
бинарный формат, непроверяемый в публичном payload.

## PDF — шаблон как CSS-файл

Источник: `collaboration/export-docx-pdf/add-custom-template/pdf` (gram.ax, 2026-11-18);
базовые факты также RES-007 §3.

Шаблон PDF — CSS-файл, задающий внешний вид PDF: шрифты, поля, колонтитулы, правила печати.

### Документированные классы

| Зона | Классы |
|---|---|
| Все страницы (базовый) | `.page` |
| Титульная страница | `.title-page` (плюс базовый `.page`) |
| Титульная — контейнеры колонтитулов | `.title-page-top`, `.title-page-bottom` |
| Титульная — ячейки колонтитулов | `.title-page-top-left`, `.title-page-top-right`, `.title-page-bottom-left`, `.title-page-bottom-right` |
| Титульная — заголовок | `h1.title-page-header` — название каталога/раздела |
| Остальные страницы — контейнеры колонтитулов | `.page-top`, `.page-bottom` |
| Остальные страницы — ячейки колонтитулов | `.page-top-left`, `.page-top-right`, `.page-bottom-left`, `.page-bottom-right` |
| Основное содержимое | `.page-content` |
| Страница оглавления | `.toc-page` (структура обычной страницы + этот класс) |

### CSS-переменные

- `--title` — заголовок экспортируемой статьи/раздела (название каталога); типовое
  применение — `content: var(--title)` в колонтитуле.
- `--pdf-min-scale` — минимальный допустимый коэффициент масштабирования изображений и
  диаграмм; если для размещения на странице нужен меньший масштаб, ресурс делится на
  несколько страниц.
- `--pdf-split-scale` — масштаб частей разрезанного ресурса; если не задана, берётся
  значение `--pdf-min-scale`.

### Селекторы элементов контента

`p` — обычный текст; `h1` — заголовок статьи; `h2`, `h3`, `h4` — подзаголовки; `a` —
ссылка; `strong` — жирный; `em` — курсив; `span.inline-code > code` — инлайн-код;
`div.admonition.admonition-{type}` — примечания (заголовок `.admonition-heading > div >
title`, контент `.admonition-content > .paragraph`); `table` — таблица (ячейки шапки
`td.cell-header-row`, `td.cell-header-col`, любая ячейка шапки несёт `.cell-header`);
`pre` — блок кода; `button` — кнопка; `div.tabs` — вкладки; `img` — изображения.

### Подключение к экспорту

Единый флаг `-t` (`--template`) команды `gramax-cli export`: путь к CSS-файлу или имя
шаблона из воркспейса каталога (источник: `npx gramax-cli export --help`, 1.0.54;
`deploy/export-ci-cd`). Пример: `npx gramax-cli export -f pdf --pdf-title --pdf-toc
--pdf-number -t ./template.css`.

### Загрузка шаблона в приложение

Источник: `collaboration/export-docx-pdf/add-custom-template/pdf`, шаг 2 (2026-11-18).

- Путь: `[папка пространства]/.workspace/assets/pdf/`.
- Папки `.workspace`, `assets`, `pdf` при отсутствии создаются вручную.
- Шаблоны загружаются отдельно для каждого пространства; после загрузки пользователи
  выбирают шаблон при экспорте в интерфейсе.
- Чтобы шаблон был доступен читателям портала, файл передаётся администратору портала
  (портальные пути — раздел «Placement» ниже).

## DOCX — шаблон `.docx`/`.dotx` в Word

Источник: `collaboration/export-docx-pdf/add-custom-template/docx` (gram.ax, 2026-11-18);
формат и «авторство в Word» также RES-007 §3.

Шаблон — файл `.docx` или `.dotx`, редактируется в Microsoft Word. На странице docs есть
готовый пример-образец для скачивания (указатель: та же страница, «Начните с готового
примера»); навык бинарный образец не поставляет.

### Обязательные элементы

1. **Плейсхолдер контента** — `{{gramax_content}}` в месте документа, куда вставляется
   текст статьи из Gramax.
2. **Стили списков** — создаются и настраиваются в Word («Многоуровневый список →
   Определить новый стиль списка»): `OrderedList` — нумерованные, `BulletList` —
   маркированные, `TaskList` — задачи. Экспорт контента со списками без этих стилей
   завершается ошибкой.

### Поля Word, обновляемые при экспорте

Стандартные поля Word (Вставка → Экспресс-блоки → Поле) Gramax заполняет автоматически:
`Title` — заголовок статьи/раздела; `CreateDate` — момент экспорта. При первом открытии
созданного документа Word запросит разрешение на обновление полей.

### Библиотека стилей

Правило: стиль с точно таким названием есть в шаблоне — элемент форматируется по нему;
стиля нет — элемент вставляется обычным текстом (`Normal`). Настраивать нужно только те
стили, которые действительно используются.

| Группа | Стили |
|---|---|
| Стандартные Word | `Normal`, `Heading1`–`Heading9`, `Hyperlink`, `Strong`, `Emphasis`, `ListParagraph` |
| Пользовательские Gramax — подзаголовки | `H2`, `H3`, `H4` |
| — заголовки примечаний | `Info Title`, `Danger Title`, `Hotfixes Title`, `Lab Title`, `Note Title`, `Quote Title`, `Tip Title` |
| — подписи и прочие | `Table Title`, `Picture Title`, `Video Title`, `Tabs Title`, `Horizontal Line`, `Picture`, `Code` (инлайн-код), `Fence` (блок кода), `Formula`, `Formula Inline`, `Kbd`, `Button` |
| Табличные стили Gramax | `Note Table`, `Lab Table`, `Tip Table`, `Info Table`, `Danger Table`, `Quote Table` (примечания в Word представлены таблицами), `Tabs` (плоская таблица), `Table` (поддерживается перенос настроек «Строка заголовка»/«Столбец заголовка»), `Fence Table` (блок кода) |

### Загрузка шаблона в приложение

Как у PDF, ветка `word`: путь `[папка пространства]/.workspace/assets/word/`; папки
`.workspace`, `assets`, `word` создаются вручную при отсутствии; шаблоны — отдельно для
каждого пространства; выбор при экспорте в интерфейсе; для читателей портала файл
передаётся администратору портала.

## Placement шаблонов на портале (различие веток pdf/word)

Источник: `deploy/doc-portal/export-templates` (gram.ax, 2026-11-18); префикс
`assets/pdf` / `assets/word` также RES-007 §3. Читатели портала выгружают статьи в PDF и
DOCX в собственных шаблонах; готовый шаблон добавляет на портал администратор.

| Установка портала | PDF | DOCX |
|---|---|---|
| Docker («портал для чтения») | `[ROOT_PATH]/.workspace/assets/pdf/` | `[ROOT_PATH]/.workspace/assets/word/` |
| Helm | постоянное хранилище портала; в контейнере папка `/app/data` | та же папка `/app/data` |
| Статический сайт | флаг сборки `--pdf-templates` (`gramax-cli build --pdf-templates [путь]`) | флаг сборки `--docx-templates` (`gramax-cli build --docx-templates [путь]`) |

- `ROOT_PATH` — папка из одноимённой переменной `docportal-docker-compose.yaml`; если не
  задана — папка `gramax` рядом с compose-файлом.
- Папки `.workspace`, `assets`, `pdf`/`word` при отсутствии создаются вручную.
- Ветки различаются по формату: `pdf` — для CSS-шаблонов, `word` — для `.docx`/`.dotx`;
  скрещивать нельзя — каждая ветка читается экспортом своего формата.

### Приложение против портала

Применимость (открытый вопрос 2 требования, теперь раскрыт апстримом): это два разных
адреса размещения, а не один. Шаблон в воркспейсе пространства
(`.workspace/assets/pdf|word`) виден пользователям **приложения** при экспорте в UI;
читателям **портала** шаблон доставляет администратор портала (Docker — `ROOT_PATH`,
Helm — `/app/data`, статический сайт — флаги `--pdf-templates`/`--docx-templates`).
Источники: шаги 2 на страницах `add-custom-template/pdf` и `add-custom-template/docx`,
страница `deploy/doc-portal/export-templates` (2026-11-18).
