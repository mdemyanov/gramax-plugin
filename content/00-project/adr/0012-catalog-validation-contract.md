# ADR-0012: Контракт валидации Gramax-каталога — обнаружимость, машиночитаемость, `_index.md`, догфудинг

**Status:** Accepted
**Date:** 2026-08-11
**Plugin:** gramax / marketplace

## Context

Разведка (`content/10-domain/research/2026-08-11-plugin-consumers-gaps.md`, G1, G2, G7, G13) и
требование `content/30-requirements/2026-08-11-validation-contract.md` (FR-035…FR-049) фиксируют:
плагин поставляет `plugins/gramax/scripts/validate_structure.py`, но ~20 потребителей независимо
переизобрели его как `scripts/validate-content.py` (коды C1–C14) — валидатор упомянут только в
`skills/writer/SKILL.md:293` и `README.md:69`, никто на него не ссылается (G1). Список
поддерживаемых Gramax-тегов задублирован вручную в regex каждого потребителя (G2). Правило
`writer/SKILL.md:63` «нет `_index.md` в корне» нарушено во всех 10 внешних докъ-репозиториях/
шаблонах и в самом этом репозитории (G7); прогон `uv run validate_structure.py content` здесь
красный. Проверено дополнительно (SA, эта задача): `scripts/validate-content.py:198-213`
(`check_indexes`, nauta-валидатор, авторитетный для `check.sh --fast`, зелёный) **требует**
`_index.md` в `content_dir` наравне с подпапками — прямо противоположно
`check_no_index_in_root`. Два валидатора одного каталога противоречат друг другу буквально в коде,
не только в описании. Плейсхолдеры/сироты/битые ссылки (C7/C9/C10) потребители закрывают сами —
плагин их не проверяет (G13).

Предшественники: ADR-0006 (semver-policy, Active), ADR-0011 (прецедент suite в `tests/gramax/`,
прецедент ADR как разрешающий документ для правки `marketplace.json`).

## Решение 1 — `_index.md` в корне каталога: развести семантику (вариант c FR-042)

**Решение:** `check_no_index_in_root` **удаляется** из `validate_structure.py`. `_index.md` в
корне каталога — разрешён и не обязателен (титульная/дашборд-страница, как уже используется в
`content/_index.md` этого репозитория). `check_subfolders_have_index` не меняется: `_index.md` в
подпапке остаётся обязательным (`subdir == root` уже исключён из этой проверки — код готов).

**Почему не «оставить запрет» (a) и не «сделать обязательным» (b):** запрет противоречит 100%
наблюдаемой практике (10 внешних репозиториев + этот репозиторий) и живому C1-эквиваленту nauta,
который уже требует root-index и зелёный — запрет никогда не отражал реальность Gramax. Сделать
`_index.md` в корне *обязательным* тоже не подтверждено: обоснование `check_subfolders_have_index`
(«без него Gramax не строит навигацию, папка не видна в дереве») специфично для вложенных папок —
корень и так перечисляется через `.doc-root.yaml`, репозиторий не даёт свидетельств, что Gramax
не рендерит каталог без корневого `_index.md`. Из двух непроверенных крайностей выбрана та, что не
создаёт нового отказа ни для одного каталога — N/A: нет данных о фактическом поведении Gramax при
отсутствии корневого `_index.md`; разрешение (не требование) — консервативный выбор при отсутствии
измерения.

**Правки:** `writer/SKILL.md:60-97` — убрать пункт «Корень… НЕ должен содержать `_index.md`» и
пример «Неправильно»; заменить на «корень может нести `_index.md` как титульную страницу — не
обязателен, Gramax строит навигацию каталога из `.doc-root.yaml` независимо». Код и документация
правятся в одном коммите (FR-043).

**Классификация:** нестрогая — удаление ERROR-проверки только *ослабляет* исход (ранее падавший
каталог теперь проходит), не может покрасить то, что раньше было зелёным. Non-breaking.

## Решение 2 — строгость C7/C9/C10-эквивалентов (FR-046…FR-048)

| Проверка | FR | Уровень у nauta (C-экв.) | Уровень в плагине | Обоснование |
|---|---|---|---|---|
| Плейсхолдер `{{...}}` | FR-046 | C7 — warning | **error** | `validate_structure.py` — pre-publish gate (staging checklist), не непрерывный lint; утечка плейсхолдера в прод — однозначный дефект (доказанный кейс `tsn-assistant`); AC-012 требует ненулевой exit без `--strict` |
| Статья-сирота | FR-047 | C10 — warning | **warning** | Ложноположительные срабатывания на нерезолвленные cross-каталожные ссылки (граница FR-047, AC-014) — advisory, не блокирующая |
| Битая markdown-ссылка | FR-048 | C9 — error | **error** | Однозначный дефект, симметрично nauta; AC-015 «сообщает об ошибке» |

Существующий переключатель `--strict` (уже покрывает `check_garbage`/`check_no_drawio`) не
трогается: orphan остаётся под ним (warning → error при `--strict`, как сегодня), placeholder и
broken-link — error безусловно, той же природы, что уже безусловные `check_doc_root`/
`check_frontmatter`/`check_tags`. Семантика существующих проверок не меняется (BR-003).

**Почему не «все три — warning по умолчанию» (более осторожный вариант):** отклонено — NFR-001
защищает от покраснения *существующего* CI, а его не существует: G1 подтверждает, что ни один из
~20 потребителей сегодня не вызывает `validate_structure.py`. Активировать error-проверки сейчас
не может сломать то, что никто не запускает; будущее ужесточение *уже включённой* проверки —
другой случай, требующий deprecation-окна по NFR-001/BR-003, этим решением не покрывается.

Асимметрия с nauta (C7 у нас строже) — осознанная, задокументированная здесь и в
`plugins/gramax/skills/writer/references/staging.md`, не молчаливый дрейф.

## Решение 3 — машиночитаемый контракт: два JSON-файла (FR-038, FR-040, BR-002)

- `plugins/gramax/gramax-tags.json` — `schemaVersion`, `pairedTags[]`, `selfClosingTags[]`,
  `legacy[]` (`tag`, `deprecatedSyntax`, `canonicalSyntax`, `removedInVersion` — сюда переезжает
  история drawio-тега).
- `plugins/gramax/gramax-catalog-rules.json` — `schemaVersion`, `docRootRequiredFields`
  (`title`/`language`/`syntax`), `frontmatterRequiredFields` (`order`/`title`), `indexPolicy`
  (`root: optional`, `subfolder: required`), `garbageFiles[]`.

`validate_structure.py` **читает** оба файла вместо хардкода `PAIRED_TAGS`/`SELF_CLOSING`/
`GARBAGE_FILES` — единственный источник (BR-002), FR-039 закрыт структурно: разойтись код и
контракт не могут, один читает другой. Расположение — корень `plugins/gramax/`, не `scripts/`:
это публичный интерфейсный артефакт, не процедурный скрипт (соответствует AC-004:
`find plugins/gramax -iname '*tag*' -iname '*.json'`).

**NFR-003:** `schemaVersion` — отдельный счётчик на файл, не привязан к `plugin.json`. Патч-релиз
плагина может не трогать контракт; привязка к semver плагина заставляла бы потребителя следить за
версией плагина, чтобы узнать про контракт, хотя это два разных вопроса. Каждое изменение
`schemaVersion` — grep-able запись в `CHANGELOG.md`, начинающаяся с `Contract:` (FR-041), в том же
коммите, что и правка JSON (AC-007 сверяет коммиты обоих файлов).

**Отклонено:** флаг `--list-tags`/`--list-rules` без файла-основания — не даёт потребителю
статичного артефакта для offline-diff между релизами и создаёт риск второго источника (сам код
генерации списка), если он не читает тот же JSON. Схема внутри `.doc-root.yaml`-подобного файла —
отклонено: `.doc-root.yaml` — потребительский артефакт per-каталог, не плагинный.

## Решение 4 — обнаружимость валидатора (FR-035…FR-037)

- **README.md**: новый заголовок `## Валидация каталога` — четвёртым `##` (после `## Установка`,
  `## Skills`, перед `## Agents`/`## Scripts`), с одним абзацем + ссылками на
  `validate_structure.py`, `gramax-tags.json`/`gramax-catalog-rules.json`, hook-шаблон.
- **`--help`**: `argparse` `epilog` с явным текстом-указателем, например «Документация: README.md
  → «Валидация каталога», `skills/writer/SKILL.md`. Репозиторий:
  `https://github.com/mdemyanov/gramax-plugin`» (закрывает AC-002 по всем трём альтернативным
  паттернам сразу).
- **Hook-шаблон**: `plugins/gramax/scripts/pre-commit.sh` — копируемый в `.git/hooks/pre-commit`
  или `.githooks/pre-commit` потребителя; вызывает
  `uv run "${CLAUDE_PLUGIN_ROOT}/scripts/validate_structure.py" content`. Форма по аналогии с
  `nsmp-plugin/scripts/install-hooks.sh` + `.githooks/pre-commit`, но адаптирована: там пара
  устанавливает хук *для собственного* репозитория автора, здесь — шаблон *для чужого* репозитория
  потребителя (копирование, не установка внутри плагина). README.md документирует шаг копирования.

**Отклонено:** отдельный `install-hooks.sh` внутри плагина, как у `nsmp-plugin` дословно —
не подходит: `nsmp-plugin`-скрипт настраивает `core.hooksPath` для git-репозитория, в котором сам
лежит; плагин `gramax` живёт в `~/.claude/plugins/cache`, не в репозитории потребителя — установка
не может выполниться «из коробки» без явного copy-шага.

## Решение 5 — точка подключения догфудинга и сосуществование валидаторов (FR-044, FR-045)

**Новый suite** `tests/gramax/catalog-validator/` (плоская структура, прецедент ADR-0011 Решение
5): `run.sh` + `ac-001-dogfood-clean-exit.sh` (AC-010/011: `uv run
plugins/gramax/scripts/validate_structure.py content`, exit=0, на **собственном** `content/`) +
`ac-002…005` — фикстурные позитив/негатив-тесты C7/C9/C10-эквивалентов (AC-012…015) на синтетических
мини-каталогах в `fixtures/` + `ac-006-no-bloat-flag-in-help.sh` (AC-016, граница периметра).
Подключается к `scripts/check.sh --full` восьмым шагом, по прецеденту `plugin-contract`/
`doc-paths`. `scripts/*.py` этого репозитория не создаётся и не правится — только новый bash-suite
и одна новая строка в `check.sh` (bash, не территория nauta).

**Предусловие для зелёного AC-010** (FR-044): `content/.doc-root.yaml` не несёт `language`/
`syntax` — добавить (12 статей уже используют XML-теги `<note>`/`<view>`/`<mermaid>`/`<drawio>` →
`syntax: XML` подтверждено практикой репозитория; `language: ru` — по факту содержимого). Frontmatter
большинства статей (включая все ADR 0001–0011) не несёт `title`/`order` — требуется backfill.
Это content-правка, не архитектурное решение; выполняет Dev/PM как часть FR-044, не в этом ADR.

**Сосуществование `validate-content.py` (nauta) и `validate_structure.py` (плагин) — не конфликт,
разные полномочия:**

| | `scripts/validate-content.py` (nauta) | `plugins/gramax/scripts/validate_structure.py` (плагин) |
|---|---|---|
| Подключение | `check.sh --fast`, каждый коммит | `check.sh --full`, новый suite, релизный гейт |
| Авторитетен для | Соответствия `content/` конвенциям nauta-проекта (шире Gramax) | Публичного контракта плагина: догфудинг + то, что реально видит потребитель |
| Источник правды по C7/C9/C10 severities | Собственный (ADR-014/TPL-37а вне этого репозитория) | Решение 2 этого ADR — сознательно допускает отличие (placeholder строже) |
| Меняется этим ADR? | Нет — территория nauta, не трогаем | Да |

Разные валидаторы намеренно проверяют один каталог с разной строгостью для разных целей — это не
BR-001-нарушение (BR-001 — про документацию правила и код *одного* правила, не про то, что два
независимых инструмента обязаны совпадать построчно).

## Решение 6 — граница периметра плагин / потребитель (FR-049)

**Критерий:** проверка входит в плагин, если ответ на неё **универсален для любого Gramax-каталога**
(не зависит от проекта) — обязательность `_index.md`, парность тегов, битая ссылка, плейсхолдер,
сирота. Проверка остаётся у потребителя, если она **специфична для проекта** — числовой порог
(«сколько строк — уже раздуто»), доменная property-схема сверх стандартных полей `.doc-root.yaml`,
словарь/маппинг терминов (пример: статус ADR `Accepted→Approved` в `mango-cti-rest`) — у таких
проверок нет единственно верного ответа, применимого ко всем каталогам сразу.

Явно вне плагина (FR-049): бюджеты объёма C11–C14, доменные property-схемы, проектные словари.
AC-016 закрепляет границу негативно: `--help` не содержит `bloat`/`budget`/`token-budget`.

**Отклонено:** «плагин предоставляет опциональный budget-модуль с дефолтными порогами» —
отклонено: дефолтный порог для «раздутости» так же произволен для чужого проекта, как и его
отсутствие — не даёт объективного улучшения, добавляет площадь API без универсального ответа.

## Решение 7 — разрешение на правку `marketplace.json` (bump до 4.2.0)

**Разрешение:** этот ADR — разрешающий документ (прецедент ADR-0008 «Решение 7», ADR-0011 Решение
6) на будущую правку `.claude-plugin/marketplace.json`: `metadata.version` → `"4.2.0"` и текст
(не структуру) `description` записи `gramax`, если Tech-writer сочтёт нужным упомянуть новую
возможность (валидация/контракт) — по прецеденту ADR-0006 (1.0.0 → 1.1.0, Minor). `name`, `owner`,
состав `plugins`, `source` — неприкосновенны. Правку выполняет Dev/Tech-writer отдельным коммитом
после реализации, не этим ADR.

**Semver (ADR-0006):** **Minor**. Решения 1–5 — additive (новые файлы контракта, новые
error/warning-проверки, новый раздел README, новый hook-шаблон, новый suite) плюс одно
ослабление существующей error-проверки (Решение 1 — не breaking, см. там). Ничего не подпадает под
критерии Major (переименование плагина, удаление skill, несовместимый `mcpServers`, смена
структуры `marketplace.json`). `plugins/gramax/.claude-plugin/plugin.json`: `4.1.1` → `4.2.0` (не
требует отдельного ADR — не корневой `marketplace.json`).

## Consequences

**Положительные:**
- Плагин перестаёт быть источником дублирования: единый машиночитаемый контракт тегов/правил
  вместо ~20 ручных regex-таблиц (G1/G2 закрыты).
- Репозиторий плагина проходит собственный валидатор — BR-004 исполняется, не декларируется.
- Противоречие `_index.md` разрешено в пользу уже состоявшейся практики — 10 внешних репозиториев
  не получают технического долга.

**Отрицательные / trade-offs:**
- Асимметрия строгости placeholder (плагин error / nauta warning) требует явной документации на
  обеих сторонах, иначе выглядит как рассинхрон.
- `validate_structure.py` берёт на себя чтение двух JSON-файлов при каждом запуске — минимальная,
  но новая зависимость от их валидности; невалидный JSON-контракт должен явно падать, не
  проглатываться молча (Dev: `error`, не `warning`, при повреждённом `gramax-tags.json`/
  `gramax-catalog-rules.json`).
- Backfill `title`/`order`/`language`/`syntax` по всему `content/` — заметный объём мелких правок
  (все 11 существующих ADR как минимум), не покрыт этим ADR.

**Mitigations:**
- `--strict` остаётся единственным переключателем ужесточения — новых флагов не вводится, знакомый
  потребителю интерфейс.
- CHANGELOG-маркер `Contract:` (FR-041) даёт потребителю `grep`-детектируемый способ узнать о
  дрейфе контракта без чтения полного diff.

## Alternatives Considered

- Оставить запрет `_index.md` в корне (Решение 1, вариант a) — отклонено: противоречит 100%
  наблюдаемой практике и живому C1 nauta.
- Обязательный `_index.md` в корне (Решение 1, вариант b) — отклонено: нет свидетельств, что
  Gramax действительно требует его для рендера корня; консервативнее — разрешить, не требовать.
- Все новые проверки — warning по умолчанию (Решение 2) — отклонено: NFR-001 защищает не
  существующий CI (его нет — G1), излишняя осторожность без объекта защиты.
- `--list-tags`/`--list-rules` без файла-контракта (Решение 3) — отклонено: не даёт статичного
  offline-артефакта, риск второго источника правды.
- `install-hooks.sh` один в один с `nsmp-plugin` (Решение 4) — отклонено: плагин не лежит в
  репозитории потребителя, установка `core.hooksPath` не может исполниться на месте.
- Budget-модуль с дефолтными порогами в плагине (Решение 6) — отклонено: произвольный дефолт не
  более обоснован, чем его отсутствие.
