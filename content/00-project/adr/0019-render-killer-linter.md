# ADR-0019: Линтер рендер-киллеров Gramax — отдельный контент-слой, гибридный контракт, демаркация с W034

**Status:** Accepted
**Date:** 2026-08-12
**Plugin:** gramax / marketplace

## Context

Эмпирически подтверждено 2026-08-12: тег `<th>` роняет GES с HTTP 500 (краш локализован
на страницу). Существующий `plugins/gramax/scripts/validate_structure.py` (структурный валидатор,
W030–W034, ADR-0012) видит `<th>` лишь как generic-W034-WARNING «неподдерживаемая разметка»
(`_KNOWN_TAGS = {"drawio"}`) — тот же уровень, что «картинка не найдена»; контекстных киллеров
вида «`<note>` внутри `<td>`», «`<note>` в `<note>`», «инлайновый `<note>`» он не различает и не
ловит. У коллег есть проверенный в проде линейный линтер `validate-gramax.py` (MIT, плагин
`gramax-skills`, автор Всеволод Шадрин) с правилами по реальным инцидентам GES. Требование
[Линтер рендер-киллеров Gramax](../../30-requirements/2026-08-12-render-killer-linter.md)
(FR-104…FR-119, AC-001…AC-021, BR-001…BR-004, NFR-001…NFR-008) — портировать его правила в плагин
с корректным severity (ERROR для киллеров, WARN для стиля) и демаркацией против
`validate_structure.py`, чтобы дефект давал ровно одну находку (BR-004).

Измеренный факт портирования (BA факт 2): немодифицированный исходник коллег на собственном
`content/` даёт **11 ложных ERROR** — его `code_mask` маскирует только fenced-код, не inline;
наш `_mask_code` (validate_structure.py) маскирует оба (факт 3). Реальных `<th>` в `content/`
ноль (все вхождения — в inline-коде статей, включая саму спеку). `check_tags` балансит
`note, tabs, tab, html, comment, color, highlight` (gramax-tags.json), порт добавляет
`table/tr/td/th` — пересечение по `note, tabs, tab, color, highlight` требует ownership-границы
(факт 4). W034 через `_KNOWN_TAGS` расширяется точечно (NFR-007). Прецедент атрибуции —
`plugins/gramax/skills/mermaid/LICENSE.upstream.md`.

Предшественники: ADR-0012 (контракт валидации: JSON как single source of truth, BR-002;
прецедент suite в `tests/gramax/`, прецедент ADR как разрешающего документа на правку
`marketplace.json`), ADR-0006 (semver-политика).

## Решение 1 — отдельный скрипт `plugins/gramax/scripts/validate_render.py` (контент-слой)

**Решение:** порт реализуется **отдельным** скриптом `validate_render.py` в
`plugins/gramax/scripts/`, а не расширением `validate_structure.py`. Оба валидатора живут в одной
директории, один вызывающий контракт (`uv run <скрипт> <каталог|файл>`) и общий примитив
маскирования кода (Решение 5).

**Почему не расширение `validate_structure.py` (альтернатива a):**

| Критерий | `validate_structure.py` | `validate_render.py` (новый) |
|---|---|---|
| Предмет | Структура каталога: `_index`, frontmatter, ссылки, сироты, плейсхолдеры, W030–W034 | Контент страницы: разметка-киллер рендера по эмпирическим инцидентам GES |
| Severity-модель | error/warning, escalation через `--strict` | Киллер = ERROR безусловно (FR-113, BR-001), стиль = WARN; `--strict` отсутствует |
| Происхождение | Собственная разработка плагина | Порт MIT-кода коллег (NFR-006) |
| Exit-контракт | 0/1, 2 при `--fix` без `--yes` | 0/1, 2 при некорректном вызове (NFR-001) |

Три основания для разделения. **(1) Разная семантика severity-оси.** У структурного валидатора
строгость переключается `--strict`; у рендер-линтера severity присуща классу правила (BR-001:
киллер не понижается ниже ERROR, стиль не повышается). Один общий axis `--strict` смешал бы две
несовместимые модели. **(2) Атрибуция порта (NFR-006).** Портируемый код — чужая MIT-логика;
отдельный файл + `LICENSE.upstream.md` рядом (Решение 7) даёт чистую границу provenance по
прецеденту mermaid-скилла, не размывая её внутри файла, где 80% — наш код. **(3) Граница правок
NFR-007.** Изоляция порта означает, что `validate_structure.py` получает только две
санкционированные правки (демаркация W034, Решение 3; дедуп баланса, Решение 6), а не весь порт.

**Последствия:** у потребителя появляется второй вызываемый скрипт — смягчается обновлением
hook-шаблона `pre-commit.sh` (вызывает оба) и README. Совместный примитив `_mask_code`
выносится в `lib/` (Решение 5). Догфудинг-граница независима: структурный и контент-гейт
проверяют разные классы дефектов и не «красят» друг друга.

## Решение 2 — гибрид: `gramax-render-rules.json` (данные) + контекстная логика в коде

**Решение:** новые машиночитаемые данные — файл `plugins/gramax/gramax-render-rules.json`
(корень плагина, рядом с `gramax-tags.json`/`gramax-catalog-rules.json` — публичный
интерфейсный артефакт, ADR-0012 Решение 3), `schemaVersion: 1`, со следующими таблицами:

- `killerTags: [{tag, message}]` — список известных киллеров с per-tag подсказкой по исправлению.
  Стартовый набор: `{tag: "th", message: "замените на <td>; шапку задаёт header=\"row\" у <table>"}`.
  Кандидат в данные, потому что это **эмпирический реестр инцидентов** (BR-001): новый киллер,
  подтверждённый на живом GES, добавляется строкой + CHANGELOG-записью (BA «альтернативный путь»:
  «добавляется в список ERROR-правил»). `message` в данных, а не в коде — закрывает BR-003
  (документация правила и код не могут утверждать разное): текст подсказки grep-абелен и diff-абелен
  в ревью.
- `balanceTags: ["note","table","tr","td","th","tabs","tab","color","highlight"]` — набор
  парных тегов для баланс-чека FR-109. Список, а не алгоритм — данные.
- `allowlistedTags: ["colgroup","col"]` — allowlist «не ошибки» (FR-115) как явный
  регрессионный контракт (BR-002: «не флагается ни ERROR, ни WARN»). Данные — чтобы вынос из
  allowlist был задокументированной правдой в diff, не молчаливой правкой regex.

**Контекстная логика остаётся кодом:** детекция «`<note>` в `<td>`», «`<note>` в `<note>`»,
«инлайновый `<note>` в одну строку» (стековый проход), «несколько `![](` в строке», «H1 в теле»,
«frontmatter `title:` без кавычек», маскирование кода — это алгоритмы (построчный/стековый обход),
не перечисляемые данные. Правил-движок («правила как данные») не вводится: он добавил бы
абстрактный слой без второго потребителя.

**Почему не всё hardcoded в скрипте (альтернатива a):** ADR-0012 Решение 3 / BR-002 — код и
контракт не могут разойтись; реестр киллеров и allowlist — ровно тот класс «списка», ради
которого BR-002 введён. Allowlist-регрессии (FR-115…FR-118) становятся diff-абельным контрактом с
CHANGELOG-маркером `Contract:` (прецедент ADR-0012 NFR-003/FR-041), а не правкой regex внутри кода.

**Почему не полный data-driven (движок правил):** логика вложенности — это код, а не данные;
предложение PM «СПИСОК киллер-тегов и allowlist — кандидат в данные, контекст — код» принято как
гибрид. `validate_render.py` **читает** контракт; отсутствующий/повреждённый
`gramax-render-rules.json` — явный error, не молчаливый fallback (ADR-0012 Consequences). Каждое
изменение `schemaVersion` — запись в CHANGELOG `Contract:` в том же коммите.

**Последствия:** реестр киллеров открыт потребителю для offline-diff между релизами (симметрично
`gramax-tags.json`); BR-002 исполняется структурно; `validate_render.py` получает зависимость от
валидности третьего JSON-файла — та же цена, что уже платит `validate_structure.py` (ADR-0012).

## Решение 3 — демаркация с W034: `<th>` владеет рендер-линтер, `_KNOWN_TAGS` становится контрактным

**Решение:** `<th>` принадлежит `validate_render.py` как ERROR (FR-104, AC-011); W034
(`validate_structure.py`) не должен дополнительно флагать `<th>` как «неподдерживаемая разметка»
(FR-114, AC-012). Механизм — **структурный**, не post-hoc-дедуп: `_KNOWN_TAGS` в
`validate_structure.py` заменяется с литерала `{"drawio"}` на производное от контракта:

```
known = {"drawio"} ∪ renderRules.killerTags ∪ renderRules.allowlistedTags
```

- `<th>` (killer) → W034 молчит (тег во `known`), рендер-линтер даёт ERROR. Итого по гейту —
  ровно одна находка (AC-012, BR-004).
- `<colgroup>`/`<col>` (allowlist, FR-115) → W034 также молчит. Это закрывает «Открытый вопрос 2»
  спеки: BR-002 формулирует allowlist гейтово — «не флагается ни ERROR, ни WARN», поэтому W034-шум
  на валидных тегах таблиц недопустим; в нашем `content/` их нет, но у потребителей есть.
- Будущий новый киллер добавляется строкой в `killerTags` — и W034-демаркация для него
  устанавливается автоматически, без повторной правки `validate_structure.py` (граница W034/рендер
  живёт в одном месте — контракте).

**Почему не дедуп на уровне `check.sh` (альтернатива б):** кросс-инструментальный дедуп вывода —
хрупок (сопоставление строк двух форматов, маскирование exit-кода); BR-004 требует ownership.
**Почему не литерал `{"drawio","th","colgroup","col"}` (альтернатива в):** второй источник правды —
те же факты уже в `gramax-render-rules.json`; при будущем исключении `th` из киллеров (BR-001
опровержение) пришлось бы править оба места. Контрактный `_KNOWN_TAGS` — в духе ADR-0012 BR-002.

**Граница правок NFR-007:** это «демаркация W034», прямо санкционированная. Отсутствие/повреждение
`gramax-render-rules.json` → `validate_structure.py` выдаёт явный error через существующий
`load_json_contract` (не молчит); оба файла поставляются в одной версии плагина — инвариант упаковки.

**Одна находка внутри линтера:** для тега, являющегося и киллером, и балансным (`th`), киллер-находка
поглощает балансную (баланс для тега, уже зафлагованного киллером в файле, подавляется) — без этого
сбалансированный `<th>…</th>` дал бы и killer-ERROR, и баланс-ERROR на один дефект.

**Последствия:** W034 сужается до «genuinely-неподдерживаемой разметки» — теперь строго по реестру;
`validate_structure.py` читает второй контракт (симметрично ADR-0012). AC-012 закрыт структурно.

## Решение 4 — интеграция: `--fast`-шаг на `content/` + suite `tests/gramax/render-linter/` в `--full`

**Решение:** две точки подключения, обе по прецедентам репозитория:

1. **`check.sh --fast`** — новый шаг после «2.5 content»:
   `uv run plugins/gramax/scripts/validate_render.py content` (зеркало шага `validate-content.py`).
   Exit-агрегация по существующему паттерну `FAILED`: ненулевой exit → `FAILED=1`. Для рендер-линтера:
   exit 0 (нет ERROR; WARN допустимы) → зелёный; exit 1 (есть ERROR) → красный; exit 2 (битый вызов) →
   красный (сломанная инвокация — дефект гейта, не тишина). Это делает pre-commit-гейт блокирующим
   по киллерам рендера: FR-119 User Journey 1 («автор чинит до коммита»), AC-019 («команда присутствует
   в шаге, исполняемом гейтом»).
2. **`--full`** — новый suite `tests/gramax/render-linter/` (агрегатор `run.sh` + `ac-001…ac-021.sh`
   + `fixtures/`), подключается шагом по прецеденту `catalog-validator`/`plugin-contract` (ADR-0011
   Решение 5, ADR-0012 Решение 5). Покрывает полный поведенческий контракт AC-001…AC-021, включая
   догфудинг AC-018.

**Почему `--fast`, а не только `--full`:** FR-119 явно требует pre-commit-перехват; `--full` —
релизный гейт вручную/CI, он не защитит автора на коммите. NFR-004 (собственный `--fast` зелёный)
держится: в `content/` нет немасоченных `<th>` (проверено), а WARN (H1 в теле, десятки статей) на
exit не влияет (Решение 8). **Почему не встроено в `validate-content.py`:** это nauta-территория
(`scripts/`, CLAUDE.md) — не редактируется здесь. Соединение идёт bash-шагом в `check.sh` (репозиторный
bash, правки санкционированы ADR-0012 Решение 5) + suite в `tests/gramax/`; новых `.py` в `scripts/`
не появляется — ограничение FR-119 соблюдено.

**Куда сканировать:** `content/` этого репозитория и, в общем случае, каталог потребителя —
позиционный аргумент, как у `validate_structure.py`.

**Рекомендация Dev (не блокирующая):** флаг отображения `--errors-only` для `--fast`-инвокации,
чтобы принятый шум H1-WARN (BA «Открытый вопрос 3», ремедиация вне периметра) не спамил каждый
pre-commit; exit-контракт при этом не меняется.

**Последствия:** `--fast` дорожает на один офлайн-прогон (<1 с на `content/`, NFR-005); количество
шагов `--full` растёт (12 → 13); hook-шаблон `pre-commit.sh` обновляется на два вызова.

## Решение 5 — двойное маскирование кода: извлечение `_mask_code` в `lib/md_code_mask.py`

**Решение:** `_mask_code`, `_FENCE_RE`, `_INLINE_CODE_RE` выносятся из `validate_structure.py` в
общий модуль `plugins/gramax/scripts/lib/md_code_mask.py`; оба валидатора импортируют его.
Порт использует этот общий примитив (маскирует и fenced-, и inline-код) вместо исходного
fenced-only `code_mask` коллег.

**Почему:** FR-110 требует двойной охват; исходник коллег маскирует только fenced-блоки, из-за чего
`<th>`/`<note>` в inline-коде прозы дают **11 ложных ERROR** на собственном `content/` (BA факт 2).
`validate_structure.py::_mask_code` уже решает задачу (факт 3). Общий модуль — единственный источник
правды для примитива, который является критичным анти-ложносрабатывающим механизмом сразу для
баланс-чеков обоих инструментов: копия в два места дрейфовала бы (дух BR-002).

**Почему `lib/`, а не копия в `validate_render.py`:** в `lib/` уже живут `md_link_parser`,
`link_resolver` — извлечение ложится в существующий паттерн, а не заводит третий способ обойти
файлы. Импорт из `validate_structure.py` напрямую отклонён: втянул бы в рендер-линтер ненужные
зависимости (`pyyaml`, link-парсеры), которые импортируются целым модулем.

**Граница правок NFR-007:** правка `validate_structure.py` — механическая, семантически инвариантная
экстракция (тело функции не меняется, импорт-подмена). Это единственный структурный рефакторинг
сверх демаркаций W034/баланса; семантика проверок W030–W034, `check_tags`, сирот, битых ссылок,
плейсхолдеров не меняется.

**Последствия:** AC-007/AC-008 (маскирование fenced+inline) закрыты структурно; диф плагина содержит
добавленный `lib/md_code_mask.py` и два импорт-сайта.

## Решение 6 — баланс-чеки: рендер-линтер владеет набором FR-109, `check_tags` дедуплицируется вычитанием контракта

**Решение:** `validate_render.py` балансит **полный** набор FR-109: `note, table, tr, td, th, tabs,
tab, color, highlight` (требование FR-109/AC-006 — рендер-линтер обязан сообщать баланс
`note`/`tabs`). `validate_structure.py::check_tags` дедуплицируется структурно: его эффективный
набор = `pairedTags − renderRules.balanceTags` = `{html, comment}` (теги, которые `check_tags`
владеет эксклюзивно). Вычисляется данными (чтение `gramax-render-rules.json`), не литералом в коде.

Это закрывает пересечение по `note, tabs, tab, color, highlight` (BA факт 4): unbalanced
`note`/`tabs`/`tab`/`color`/`highlight` выдаётся только рендер-линтером, unbalanced
`html`/`comment` — только `check_tags`, unbalanced `table/tr/td/th` — только рендер-линтером.
Один дефект — одна находка (FR-114, BR-004). Это ровно санкционированное NFR-007 «устранение
дубля баланс-чека».

**`gramax-tags.json` `pairedTags` не меняется:** он документирует словарь парных тегов Gramax
(контракт вокабуляра), а не то, какой инструмент сообщает о дисбалансе. Изменяется только
ownership репорта.

**Почему не «рендер-линтер берёт только `table/tr/td/th`» (BA Открытый вопрос 1, вариант B):**
противоречит FR-109 и AC-006 (рендер-линтер обязан репортить баланс `note`/`tabs`). Принят вариант A
(рендер-линтер владеет полным набором) с дедупликацией `check_tags` по контракту.

**Последствия / компромисс:** standalone `validate_structure.py` перестаёт репортить unbalanced
`note`/`tabs`/`tab`/`color`/`highlight`. Смягчается: (а) ADR-0012 G1 — у `validate_structure.py`
нет известных потребителей (~20 потребителей переизобрели свои валидаторы); (б) README фиксирует
переход ownership баланса в рендер-линтер; (в) hook-шаблон запускает оба; (г) рендер-линтер едет в
том же релизе. Два разных формата баланс-сообщения (у `check_tags` и у рендер-линтера) — осознанная
UX-асимметрия двух независимых инструментов (та же позиция, что ADR-0012 Решение 5).

## Решение 7 — атрибуция MIT: `plugins/gramax/scripts/LICENSE.upstream.md`

**Решение:** рядом со скриптом создаётся `plugins/gramax/scripts/LICENSE.upstream.md` по образцу
`plugins/gramax/skills/mermaid/LICENSE.upstream.md`: upstream-проект (плагин `gramax-skills`,
sandbox-marketplace), автор (Всеволод Шадрин), лицензия MIT, provenance-заметка (в исходнике нет
явного copyright-заголовка — атрибуция выводится из provenance плагина, BA факт 6), **список
изменений относительно upstream** (двойное маскирование fenced+inline; severity-модель ERROR/WARN
по FR-113; exit 0/1/2 по NFR-001; демаркация с W034; allowlist; ownership баланса; отсутствие
`--strict`), полный текст MIT-лицензии, заметка о совместимости (плагин `gramax` — MIT, оба
MIT-совместимы). Дополнительно: короткий copyright-заголовок в шапке `validate_render.py`
(provenance + указатель на LICENSE-файл) и запись в `plugins/gramax/CHANGELOG.md` с атрибуцией
(NFR-006: «CHANGELOG плагина получает запись с указанием атрибуции источника»).

**Почему `LICENSE.upstream.md`, а не только заголовок в файле:** единственный существующий в
репозитории прецедент атрибуции — именно такой файл (mermaid-скилл); он несёт полный текст
лицензии + список изменений и находится статично, без чтения кода. Заголовок в файле — короткий
указатель, не дубликат полного текста.

**Последствия:** NFR-006 закрыт; каждый портированный файл имеет прослеживаемый provenance; список
изменений служит входом для ревью при будущих багфиксах линтера (что наше, что upstream).

## Решение 8 — severity/exit-код модель: ERROR → 1, WARN → 0, usage → 2

**Решение:** `validate_render.py` реализует exit-контракт NFR-001 точно: exit 0 — ERROR нет (WARN
могут быть), exit 1 — есть хотя бы один ERROR, exit 2 — некорректное использование (нет валидного
целевого файла/каталога). WARN сами по себе exit не меняют. В `check.sh` exit 1 и exit 2 оба →
`FAILED=1` (гейт красный); различие сохраняется в собственном выводе/stderr линтера для диагностики.

**Severity присуща классу правила (FR-113, BR-001), флага строгости нет.** Киллеры
(FR-104…FR-109) — ERROR безусловно, независимо от флагов и без понижения до WARNING; стиль/YAML
(FR-111, FR-112) — WARN. `--strict`, как у `validate_structure.py`, не вводится: у контент-линтера
нет оси «ужесточить» — класс киллера не должен понижаться (BR-001), а стиль по замыслу advisory.

**Почему не эскалация WARN→ERROR через флаг:** создала бы второй путь к красному гейту на
конструкциях, не являющихся киллерами, и размыла бы BR-001. Уровень определён эмпирическим
инцидентом, не строгостью запуска.

**Детерминизм (NFR-002):** обход файлов отсортирован, находки внутри файла упорядочены по номеру
строки; повторный прогон идентичен. `N/A` для токен-бюджета/латентности: локальный регэксп-скрипт,
без сети и модели (NFR-005, NFR-008).

**Последствия:** AC-013 (exit-коды) закрыт; красный гейт ровно на киллерах рендера; WARN-шум
(десятки H1 в собственном `content/`) принят как неблокирующий (BA Открытый вопрос 3 — ремедиация
вне периметра, за PM).

## Решение 9 — версия плагина 4.4.0 (Minor) и разрешение на правку `marketplace.json`

**Разрешение:** этот ADR — разрешающий документ (прецедент ADR-0012 Решение 7, ADR-0011 Решение 6)
на `metadata.version` → `"4.4.0"` в `.claude-plugin/marketplace.json` и текстовую (не структурную)
правку `description` записи `gramax`, если Tech-writer сочтёт нужным упомянуть линтер
рендер-киллеров. `name`, `owner`, состав `plugins`, `source` неприкосновенны.

**Semver (ADR-0006): Minor.** Решения 1–8 аддитивны (новый скрипт, новый контракт, новый
LICENSE-файл, новый suite, `--fast`-шаг) плюс два ослабления существующих проверок
`validate_structure.py` — `_KNOWN_TAGS` расширяется (W034 реже флагает: `<th>`/`<colgroup>`/`<col>`)
и баланс-набор `check_tags` сужается до `{html, comment}` — оба только ослабляют исход, ничего не
покрасят там, где было зелёно (классификация «нестрогая/ослабление», ADR-0012 Решение 1). Под
критерии Major (переименование, удаление skill, несовместимый `mcpServers`, смена структуры
`marketplace.json`) не подпадает. `plugins/gramax/.claude-plugin/plugin.json`: `4.3.0` → `4.4.0`
(не требует отдельного ADR). Правку выполняет Dev/Tech-writer отдельным коммитом после реализации.

## Consequences

**Положительные:**
- Класс киллеров рендера (HTTP 500 на GES) ловится на уровне ERROR с номером строки и подсказкой,
  до публикации — FR-104…FR-109, BR-001 закрыты структурно.
- «Одна находка на дефект» (BR-004) — структурная (ownership), не post-hoc-дедуп: `<th>` и
  пересечение баланс-чеков не дают дубля между двумя валидаторами.
- Двойное маскирование (fenced+inline) — общий примитив `lib/md_code_mask.py`: собственный
  `content/` не краснеет на ложных срабатываниях (11 ложных ERROR исходника устранены).
- Реестр киллеров/allowlist — машиночитаемый контракт: BR-002 и BR-003 исполняются, а не
  декларируются; будущий киллер добавляется строкой + CHANGELOG, демаркация с W034 обновляется сама.
- Pre-commit-гейт блокирует киллеры рендера на коммите (FR-119 User Journey 1), догфудинг встроен
  (AC-018), не разовая уборка.
- Атрибуция MIT по репозиторному прецеденту — NFR-006 закрыт без новых форм.

**Отрицательные / trade-offs:**
- Standalone `validate_structure.py` теряет репорт баланса `note/tabs/tab/color/highlight`
  (ownership уехал в рендер-линтер) и сужает W034 на `<th>`/`<colgroup>`/`<col>` — компромисс,
  смягчённый ADR-0012 G1 (нет известных потребителей) + обновлением README/hook-шаблона на
  двух-инструментальный гейт.
- Второй вызываемый валидатор у потребителя и третий JSON-контракт плагина — новая площадь API и
  новая зависимость от валидности контракта (явный error при повреждении, ADR-0012 паттерн).
- `validate_structure.py` получает механическую экстракцию `_mask_code` в `lib/` сверх демаркаций —
  семантически инвариантную, но это правка файла вне буквы NFR-007 (в духе — внутри: семантика
  проверок не меняется).
- `--fast` и `--full` дорожают на один офлайн-прогон; `--full` растёт до 13 шагов.
- H1-WARN-шум по собственному `content/` (десятки строк) принят как неблокирующий до отдельной
  ремедиации (за PM).

**Mitigations:**
- README плагина + hook-шаблон `pre-commit.sh` обновляются на два вызова — контракт гейта описан
  явно, а не подразумевается.
- CHANGELOG-маркер `Contract:` для `gramax-render-rules.json` — grep-детектируемый дрейф контракта
  (прецедент ADR-0012 FR-041).
- Демаркации локализованы в контракте: новый киллер = одна строка `killerTags`, без правки
  `validate_structure.py`.

## Alternatives Considered

- Расширение `validate_structure.py` портом (Решение 1, альтернатива a) — отклонено: разные
  severity-модели, размытая граница атрибуции MIT, больший объём правок против NFR-007.
- Все правила hardcoded в скрипте (Решение 2, альтернатива a) — отклонено: второй источник правды
  для реестра киллеров/allowlist, BR-002/BR-003 неисполнимы структурно.
- Дедуп `<th>` на уровне `check.sh` (Решение 3, альтернатива б) — отклонено: кросс-инструментальная
  сверка выводов хрупка и маскирует exit-коды; BR-004 требует ownership. Литеральное расширение
  `_KNOWN_TAGS` (альтернатива в) — отклонено: дрейф с контрактом при исключении киллера.
- Подключение только в `--full` (Решение 4) — отклонено: не даёт pre-commit-перехвата (FR-119,
  AC-019). Только `--fast` без suite — отклонено: теряется полный регрессионный контракт AC-001…
  AC-021.
- Копия `_mask_code` в `validate_render.py` (Решение 5) — отклонено: дрейф критичного
  анти-ложносрабатывающего примитива; импорт из `validate_structure.py` — отклонено: тянет
  `pyyaml`/link-парсеры.
- Рендер-линтер балансит только `table/tr/td/th`, `check_tags` владеет пересечением (Решение 6,
  вариант B спеки) — отклонено: противоречит FR-109/AC-006.
- Флаг эскалации WARN→ERROR (`--strict`) (Решение 8) — отклонено: размывает BR-001, второй путь к
  красному гейту на не-киллерах.
