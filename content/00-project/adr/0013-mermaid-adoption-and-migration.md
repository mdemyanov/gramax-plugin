# ADR-0013: Принятие file-based mermaid потребителями — граница юрисдикции, обнаружение и миграция

**Status:** Accepted
**Date:** 2026-08-11
**Plugin:** gramax

## Context

Требование `content/30-requirements/2026-08-11-mermaid-file-based-adoption.md` (FR-050…FR-064,
NFR-050…NFR-054). ADR-0010 (Accepted) установил file-based mermaid v4.0.0 —
`<mermaid path="…" width="…" height="…"/>`, ground-truth `blocks.md:176-182`. Разведка
`2026-08-11-plugin-consumers-gaps.md` (G4, G5) — решение не долетело до части потребителей.

**Вердикт BA проверен по файлам.** `smb-sales/scripts/validate-content.py:26-32`:
`ALLOWED_SUFFIXES = {".md"}`, комментарий разработчика — «любой не-`.md` файл … это дыра, а не
разрешение». Запрет (`CLAUDE.md:222-225`, «отдельный `.mermaid` не рендерится») опирается на
неверную посылку: причина отказа — слепота гейта на суффиксы, не поведение рендера. ADR-0010 не
пересматривается; пересмотра требуют два его пробела — граница юрисдикции (никогда не
формулировалась) и отложенная пакетная миграция (Решение 3 — «Phase 2 при реальном запросе»,
запрос состоялся: `moex`, `mango-cti-rest`, `naumen-smp-mcp`).

**ADR-0012** «Контракт валидации Gramax-каталога» (Draft, тот же день) формализует
`validate_structure.py` как публичную точку валидации — `gramax-tags.json`/
`gramax-catalog-rules.json` (Решение 3), обнаружимость (Решение 4), периметр плагин/проект
(Решение 6), semver 4.2.0 (Решение 7). Решения 2 и 3 ниже явно зависят от него, не дублируя.

---

## Решение 1 — Граница юрисдикции

**Решение:** контракт действует внутри поддерева, чей ближайший предок — `.doc-root.yaml`
(BR-001). Вне границы (`docs/`, планы, README, `CLAUDE.md`) инлайн-mermaid не нарушение.

**Носитель (FR-051):** короткая формулировка прямо в `skills/mermaid/SKILL.md` («Gramax-
интеграция», грузится при каждом вызове); развёрнутое обоснование, примеры, материал Решений 2 и
5 — один on-demand `skills/mermaid/references/jurisdiction-and-validation.md` (NFR-054, экономия
по прецеденту ADR-0010 NFR-004); одна ссылочная строка в `README.md` (покрывает оба grep-таргета
AC-001/AC-009).

**Валидация:** инструмент Решения 3 реализует ту же границу программно — ближайший предок
`.doc-root.yaml` на файл; без предка в пределах скана — пропуск молча (FR-055, «Альтернативный
путь» User Journey). Вложенные `.doc-root.yaml` (`moex`, G13) не требуют спецкейса — каждый узел
ищет своего ближайшего предка.

**Отвергнуто:** граница только в тексте ADR-0010 — не обнаружима в момент вызова (FR-051).

## Решение 2 — Конфликт «невидимый файл» (главный блокер)

**Выбран (b) как основной, усилен (a) как пример; (c) не общий ответ — зарезервирован Решением 5.**

**(b):** документируется предикат «валидный `.mermaid`»: расширение `.mermaid`; лежит рядом со
страницей-источником; имя `<page-slug>-<diagram-slug>.mermaid` (ADR-0010 Решение 2); первая
строка — один из 8 поддерживаемых типов; без Gramax-разметки внутри. Язык-независим — потребитель
реализует на своём стеке.

**(a):** `jurisdiction-and-validation.md` даёт буквальный пример патча для python-гейта на
allowlist суффиксов — `ALLOWED_SUFFIXES = {".md", ".mermaid"}`, маркирован как пример, не как
артефакт, который плагин ставит в чужой репозиторий (FR-063). Актуально для всех 8 репозиториев
линии `smb-sales`-валидатора (G4).

**Почему не «слепое доверие» (FR-053):** одно расширение allowlist само по себе — ровно то, что
FR-053 запрещает. Закрывает Решение 3: тот же инструмент проверяет, что конкретный `.mermaid`
реально соответствует предикату (a) — исполняемый способ убедиться, не только обещание.

**Зависимость от ADR-0012 (объявлена явно):** `gramax-catalog-rules.json` (Решение 3 ADR-0012)
сегодня не несёт поля для non-md content-классов (только `docRootRequiredFields`/
`frontmatterRequiredFields`/`indexPolicy`/`garbageFiles`). Запрос вперёд: добавить
`nonMdContentFiles`-класс для `.mermaid` (naming convention ADR-0010 Решение 2) — превратит (b) из
прозы в машиночитаемый контракт; до тех пор `jurisdiction-and-validation.md` — интерим-ответ.

**Чем платит:** добровольное принятие (FR-063, плагин не патчит чужие репозитории) — закрытие 7
латентных конфликтов не верифицируемо изнутри `gramax-marketplace`; вне известного кластера
потребитель получает только (b) и переводит его сам.

**Отвергнуто:** чистый (a) как общий готовый артефакт — переоценивает форму вне контроля плагина.
Чистый (c) как общий ответ — легитимирует отказ вместо пути к принятию (подменяет FR-052).

## Решение 3 — Обнаружение устаревшего формата

**Решение:** standalone-скрипт `plugins/gramax/scripts/migrate_mermaid.py` (PEP 723, только
stdlib — NFR-052), режим по умолчанию — отчёт, без мутаций и интерактива (NFR-053). Обход
заданного пути (по факту — репозиторий целиком, не только `content/`: AC-003 требует различать
in/out-of-jurisdiction файлы в одном прогоне); для каждого `*.md` — ближайший предок
`.doc-root.yaml` (Решение 1), без предка — пропуск молча. Внутри юрисдикции — два паттерна,
уже названных в SKILL.md § Backward compatibility: `<mermaid>…</mermaid>` (парный тег без
`path=`) и fenced ` ```mermaid…``` `. Самозакрывающийся `<mermaid path="…"/>` не совпадает ни с
одним по построению — уже корректные вхождения не задеваются на любом масштабе (BR-003, NFR-051,
см. 156 тегов `naumen-smp-mcp` в Решении 4). Отчёт — файл:строка (FR-056).

**Не skill:** пакетный regex-поиск через prompt-based skill дорог по токенам и недетерминирован;
ограничение ADR-0010 NFR-003 (только Write/Edit/Read) относилось к интерактивному skill'у одной
диаграммы за раз, не к отдельному инструменту — ответ на открытый вопрос 5 требования.

**Зависимость от ADR-0012 (объявлена явно):** легаси-паттерны — кандидат в `legacy[]`
`gramax-tags.json` (Решение 3 ADR-0012, сегодня там только drawio-тег); когда файл появится, Dev
добавляет запись `mermaid`, скрипт читает паттерны оттуда — не раньше реализации ADR-0012.
Проверка универсальна для любого каталога — проходит периметр ADR-0012 Решение 6 («belongs in
plugin»), но не встроена прямо в `validate_structure.py`: его `check_doc_root`
(`validate_structure.py:32-42`) требует `.doc-root.yaml` строго в корне аргумента и абортирует
иначе — не обслуживает repo-wide boundary-crossing скан, который требует AC-003. Если ADR-0012
расширит инвокацию до multi-root — Dev сводит проверку внутрь, скрипт устаревает; не блокер,
ADR-0013 не ждёт принятия ADR-0012. Скрипт получает строку в новой секции README «## Валидация
каталога» (ADR-0012 Решение 4) — отдельного механизма обнаружимости не заводится.

## Решение 4 — Миграционная процедура

**Решение:** тот же скрипт, флаг `--fix --yes` (тот же паттерн, что `validate_structure.py`) —
мутация; без флагов — только отчёт (FR-058). DSL — побайтово (BR-002); тег с дефолтами ADR-0010
Решение 5 (`width="800px" height="450px"` — инлайны сегодня без атрибутов размера).

**Именование (FR-060, без второй конвенции):** переиспользуется fallback-слаг `existing` из
ADR-0010 Решение 3 (`<page-slug>-existing.mermaid`) — у batch-прогона нет пользовательской темы.
Коллизия нескольких блоков в одном файле (`moex`, `008-…-log.md:159,243` — два блока) — тот же
алгоритм коллизии ADR-0010 Решение 2, детерминированно: следующий свободный номер
(`-existing-2.mermaid`, …), никогда не перезаписывает.

**Идемпотентность (NFR-050/AC-007) — структурная:** после миграции инлайн-блок физически не
существует — повторный прогон даёт ноль совпадений по построению regex, не по флагу состояния.

**Сводка (FR-064/AC-010):** мигрировано / вне юрисдикции / уже соответствует формату. Semver —
Minor (ADR-0006, additive); точный номер (`4.2.0` или `4.3.0`, ADR-0012 Решение 7 уже резервирует
`4.2.0`) решает PM/Dev порядком слияния, не фиксируется здесь литералом.

**Отвергнуто:** вторая naming-конвенция для batch-случая — FR-060 запрещает.

## Решение 5 — Разошедшиеся потребители

**Решение:** локальный оверрайд легитимен (FR-061) — потребитель вправе закрепить инлайн как
правило своего репозитория; не дефект, принуждения к консистентности за пределами юрисдикции нет
(BR-004). `jurisdiction-and-validation.md` называет класс конфликта («allowlist-валидатор не
видит файлы вне `*.md`») и контракт рендера (`blocks.md`) как факт, без императива и без имён
сторонних репозиториев в самом потребительском тексте (FR-062; `smb-sales` и проч. — только в
этом ADR/требовании). Периметр (FR-063): решения 1–4 не правят ничего вне `gramax-marketplace`.

**Отвергнуто:** предписание конкретному репозиторию — плагин не имеет полномочий над чужим
`CLAUDE.md`.

## Решение 6 — Амендмент к ADR-0010

**Что закрывается:** (1) граница юрисдикции — Решение 1. (2) Пакетная миграция, отложенная как
«Phase 2 при реальном запросе» — Решения 3–4, запрос состоялся.

**Форма:** оба пробела закрываются целиком внутри ADR-0013, без физической правки ADR-0010 —
тело/статус/frontmatter не трогаются. Это прямое следование прецеденту репозитория: когда
ADR-0010 частично superseded ADR-0009, ADR-0009 не редактировался — правило зафиксировано в самом
ADR-0009 (строка 248): «старые ADR не редактируются… смена статусов — отдельная задача PM».
Делегировать Dev правку тела ADR-0010 нарушило бы этот же прецедент. Forward-указатель в
ADR-0010 — отдельная, явно PM-санкционированная задача, не часть этого ADR.

**Почему не отмена:** ядро ADR-0010 (формат, ground-truth, naming convention, height-дефолт)
остаётся верным (Context выше). Оба пробела — про область действия и график, не про содержание;
полная замена заставила бы пересматривать уже корректные части без причины.

## Consequences

**Positive:** единый предикат закрывает 7 латентных конфликтов путём, который потребитель выбирает
сам; инструмент закрывает дрейф в трёх найденных репозиториях без риска для 156 тегов
`naumen-smp-mcp` (regex-классы структурно не пересекаются); граница юрисдикции убирает шум из
подсчёта нарушений; ноль новых зависимостей (NFR-052).

**Negative:** Решение 2 добровольно — плагин не верифицирует применение снаружи; общий
`jurisdiction-and-validation.md` (Решения 1/2/5) рискует разрастись без явного порога разделения;
standalone-скрипт временно дублирует обход дерева, который в будущем может взять на себя
расширенный `validate_structure.py`; номер версии 4.2.0 оспаривается ADR-0012 — фиксируется только
семантика (Minor).

**Mitigations:** обе кросс-ADR зависимости (Решения 2, 3) объявлены явно — fold-in не потеряется;
структурная дизъюнктность regex-классов снимает риск NFR-051; semver Minor сигнализирует «чисто
аддитивно».
