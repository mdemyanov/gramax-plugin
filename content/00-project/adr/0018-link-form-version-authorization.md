# ADR-0018: Резервирование версии 4.3.0 волны link-form-contract и разрешение на синхронную правку marketplace.json

**Status:** Accepted
**Date:** 2026-08-12
**Plugin:** gramax / marketplace

## Context

`content/00-project/adr/0016-link-form-contract.md` (Accepted, слит в main) закрывает контракт
формы ссылки на артефакт — резолвер `_collect_links` (Решение 1) и миграцию 103 навигационных
код-спанов (Решение 5). Его раздел «Consequences» уже классифицирует semver-эффект как **Minor**
(лестница ADR-0006): «Решение 1 чисто ослабляет существующую error-проверку… Точный номер версии —
решает PM/Dev порядком слияния (прецедент ADR-0013)» (`0016-link-form-contract.md:253-256`).

Это не явное разрешение. Фраза констатирует, кто решает точный номер, но не резервирует литерал и
не авторизует правку `.claude-plugin/marketplace.json` — красная линия CLAUDE.md («НЕ менять
`.claude-plugin/marketplace.json`… без ADR») формально не снята для этой волны.

Прецедент, на который ссылается ADR-0016, при ближайшем рассмотрении содержит именно тот
недостающий элемент. [Принятие file-based mermaid потребителями и пакетная миграция](0013-mermaid-adoption-and-migration.md) Решение 4
тоже отдаёт точный литерал версии «PM/Dev порядком слияния» — но не голословно: тот же абзац прямо
указывает, что число уже зарезервировано отдельным документом: «`4.2.0` или `4.3.0`, ADR-0012
Решение 7 уже резервирует `4.2.0`». Разрешение на саму правку `marketplace.json` для этого числа
выдало ADR-0012 Решение 7 — отдельный явный разрешающий документ, не побочная фраза внутри
Consequences другого ADR. У ADR-0016 такого эквивалента нет. Этот пробел — единственная незакрытая
архитектурная зависимость перед стартом Dev-фазы волны «контракт формы ссылки»: без явного
резервирования Tech-writer, выполняя bump в рамках release-flow этой волны, упрётся в красную
линию CLAUDE.md.

Текущее состояние обоих версионных полей — `"4.2.1"` (последний bump выполнен по
`content/00-project/adr/0017-cross-catalog-retraction.md` Решение 3, ретракция cross-каталожного
рецепта `code:`). Разрешение на синхронную правку `marketplace.json` в этом репозитории уже
применялось четыре раза: [Удаление внутренних drawio-skills и делегирование внешнему плагину](0008-drop-internal-drawio-skills.md) Решение 7,
`content/00-project/adr/0011-test-harness-taxonomy.md` Решение 6,
`content/00-project/adr/0012-catalog-validation-contract.md` Решение 7 и
`content/00-project/adr/0017-cross-catalog-retraction.md` Решение 3. Этот ADR закрывает пробел тем
же паттерном.

---

## Решение 1 — Версионирование: Minor 4.2.1 → 4.3.0, синхронный bump `marketplace.json` разрешён этим ADR

**Решение:**

1. `plugins/gramax/.claude-plugin/plugin.json`: `"version"` `"4.2.1"` → `"4.3.0"`. Классификация по
   лестнице ADR-0006: **Minor**. ADR-0016 Consequences уже установил эту классификацию для обоих
   практических компонентов волны — резолвер `_collect_links` чисто ослабляет существующую
   error-проверку (не может покрасить ранее зелёный каталог) и миграция 103 навигационных
   код-спанов — контентная правка формы ссылки, не меняющая структуру `.doc-root.yaml`-каталога
   или JSON-контракт. Этот пункт не пересматривает классификацию — только резервирует конкретный
   литерал номера.
2. Этот ADR — разрешающий документ (прецедент ADR-0008 Решение 7, ADR-0011 Решение 6, ADR-0012
   Решение 7, ADR-0017 Решение 3 — уже четырежды применённый в этом репозитории паттерн; этот ADR
   становится пятым звеном) на синхронную правку `.claude-plugin/marketplace.json`:
   `metadata.version` `"4.2.1"` → `"4.3.0"`. `name`, `owner`, состав `plugins`, `source` — не
   трогаются. Правка `description` записи `gramax` — на усмотрение Tech-writer, не обязательна:
   вслед за прецедентом ADR-0017 Решение 3, чисто ослабляющая/контентная правка не обязана
   упоминаться в публичном описании плагина.
3. PM sign-off не требуется — то же основание, что ADR-0006 и ADR-0017 Решение 3 применили к
   собственному случаю: ни новых entry, ни структурных изменений `marketplace.json`, только
   синхронная версия.
4. Bump выполняет Tech-writer как часть release-flow, после Dev + QA-runner (прецедент ADR-0006,
   ADR-0012 Решение 7, ADR-0017 Решение 3) — не часть Dev-фазы контентной/скриптовой правки волны
   «контракт формы ссылки».

**Обоснование выбора «зарезервировать сейчас», не «решать явочным порядком в момент релиза»:**
пробел, который закрывает этот ADR, не гипотетический. Без явного резервирования Tech-writer на
старте release-flow этой волны обязан либо остановиться перед красной линией CLAUDE.md без
разрешающего документа, либо интерпретировать констатирующую фразу Consequences ADR-0016 как
разрешение — второе создаёт прецедент нелитерального чтения ADR, подрывающий саму практику явного
резервирования, уже применённую в репозитории четыре раза подряд. Стоимость отдельного ADR
минимальна (тот же формат, что уже применялся), выгода — снятие неоднозначности до, а не во время
релиза.

**Отклонено:** пересмотр классификации Minor — не рассматривается. Этот ADR не переоценивает вывод
ADR-0016 Consequences, только резервирует номер и авторизует bump.

## Consequences

**Positive:**
- Пробел версионирования волны link-form-contract закрыт явно, до того как Tech-writer столкнётся
  с красной линией CLAUDE.md на релизе — не в момент, когда откладывать уже поздно.
- Версии `plugin.json` и `marketplace.json` остаются синхронными по конвенции, уже применённой в
  четырёх предыдущих bump'ах — не создаётся необъяснённого расхождения.
- Не потребовалась правка уже принятого и слитого в main ADR-0016 — амендмент оформлен новым
  документом, тот же паттерн, что [Drawio-stub skill и удаление submodule claude-mermaid](0009-drawio-stub-and-claude-mermaid-removal.md)
  (строка 248) закрепил как конвенцию репозитория.

**Negative / trade-offs:**
- Ещё один короткий ADR в реестре, узкий по объёму (одно решение) — цена явности вместо расширения
  тела ADR-0016 задним числом.
- Резервирование числа `4.3.0` до фактического релиза несёт риск: если порядок слияния волн в
  main изменится и перед link-form-contract попадёт другая Minor-фича, число `4.3.0` может быть
  занято раньше — тогда потребуется либо новый короткий амендмент, либо PM/Dev решает вопрос
  порядком слияния (тот же механизм, на который уже ссылается ADR-0016 Consequences и ADR-0013
  Решение 4).

**Mitigations:**
- Если порядок слияния сдвинет номер — исправление ограничивается корректировкой литерала в этом
  документе или новым коротким амендментом по тому же паттерну, не пересмотром классификации
  Minor и не правкой ADR-0016.
- `pm-review` checklist (уже используемый механизм, RISK-004 ADR-0008/ADR-0012) остаётся точкой
  контроля синхронности версий `plugin.json`/`marketplace.json` в одном коммите.

## Alternatives Considered

- Править ADR-0016 на месте, добавив явную формулировку резервирования в Consequences —
  отклонено: ADR-0016 уже `Accepted` и слит в main; конвенция репозитория
  (`content/00-project/adr/0009-drawio-stub-and-claude-mermaid-removal.md`, строка 248,
  подтверждена `content/00-project/adr/0015-root-index-inert.md` Решение 3 и
  `content/00-project/adr/0017-cross-catalog-retraction.md` Решение 1) — амендмент к принятому ADR
  оформляется новым документом, не правкой тела/статуса/frontmatter существующего.
- Не резервировать номер вообще, решать явочным порядком в момент релиза — отклонено: оставляет
  Tech-writer перед красной линией CLAUDE.md без разрешающего документа именно в момент, когда
  откладывать решение уже нельзя (релиз волны). Прецедент ADR-0013 → ADR-0012 Решение 7 показывает,
  что в этом репозитории явное резервирование отдельным документом уже практиковалось для такого же
  класса неопределённости («какой конкретно номер») — расхождение с этой практикой без причины не
  оправдано.
