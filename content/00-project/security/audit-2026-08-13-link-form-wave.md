# Security Audit — secrets sweep волны link-form перед публикацией

Фиксирует «Тип контента: Тест-отчёт» за неимением отдельного enum-значения для security-аудита
в `content/.doc-root.yaml` (тот же приём, что `2026-08-13-cross-catalog-retraction-dev-notes.md`
применил для «Урок»): по форме этот документ — набор проверок с вердиктом pass/fail, ближе к
тест-отчёту, чем к остальным пяти значениям enum.

**Секретов, ключей, токенов, credentials не найдено.** Первая строка отчёта по контракту
DevSecOps-роли зарезервирована под такую находку — резервировать нечего, блокирующего секрета
нет.

**Этот документ сам обезличен перед публикацией.** Репозиторий публичный, а отчёт документирует
утечку приватных имён и абсолютного пути — ради полноты фиксации он изначально цитировал их
дословно, что в опубликованном виде отменяло бы обезличивание, проведённое по остальной волне.
Приватные имена организаций/репозиториев, абсолютный локальный путь контрибьютора и корпоративный
e-mail заменены на обобщённые формулировки; severity, категории, точные адреса `файл:строка` и
факт находки сохранены без изменений — сами по себе они ничего не раскрывают. Список конкретных
приватных фрагментов, использованных при поиске (раздел «Метод», пункт 3), ведётся отдельно, вне
публичного корпуса.

## Scope

Всё, что волна добавляет или меняет в диапазоне `1264a16..HEAD` (5 коммитов, 41 файл) плюс
несакоммиченные правки Tech-writer поверх этого диапазона (обезличивание 16 вхождений в четырёх
файлах, `git diff --cached`). Полный список файлов — вывод `git diff --name-only 1264a16..HEAD`
(приведён в разделе «Метод» для воспроизводимости). Артефакты прошлых волн (файлы, датированные
`2026-08-11` и раньше, ADR-0012…0015 и т. д.) — вне периметра по прямому указанию: серьёзное,
что найдено там при попутной проверке, вынесено в отдельный раздел «Вне периметра волны», не
смешано с находками волны и не правится.

Ветка/дерево: `worktree-epic-link-form`, `HEAD` = рабочее дерево с застейдженными правками
Tech-writer поверх `d395ca2`. `git status --porcelain` вне `content/00-project/security/**` —
пусто на момент записи отчёта (единственные staged изменения — четыре файла обезличивания,
уже учтённые в периметре).

## Метод (воспроизводимо)

Все команды — из корня рабочего дерева этой волны (worktree `epic-link-form`).

```bash
git diff --name-only 1264a16..HEAD > /tmp/wave-files.txt   # 41 файл, список — в этом отчёте
FILES=$(cat /tmp/wave-files.txt)

# 1. Абсолютные пути контрибьютора
grep -n -E '/Users/[A-Za-z0-9_.-]+|/home/[A-Za-z0-9_.-]+|C:\\Users\\' $FILES

# 2. E-mail
grep -n -E '[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}' $FILES

# 3. Приватные/сторонние организации, репозитории, внутренние хосты/трекеры, персональные
#    идентификаторы контрибьютора (OS-логин, ник) — конкретный список фрагментов паттерна не
#    публикуется в этом документе, см. оговорку сразу под блоком команд
grep -n -i -E '<приватный-список-организаций-и-репозиториев>' $FILES
grep -n -i -E '<приватный-список-персональных-идентификаторов>' $FILES

# 4. Токены/ключи/credentials
grep -n -i -E 'BEGIN (RSA|OPENSSH|PGP|CERTIFICATE)|api[_-]?key|secret[_-]?key|password\s*[:=]|token\s*[:=]|AKIA[0-9A-Z]{16}|ghp_[0-9A-Za-z]{20,}|sk-[0-9A-Za-z]{20,}|xox[baprs]-' $FILES
grep -n -E '[A-Za-z0-9+/]{40,}={0,2}' $FILES   # base64-подобные строки, ручная проверка каждой

# 5. URL и домены
grep -n -o -E 'https?://[A-Za-z0-9./_%-]+' $FILES | sort -u
grep -n -o -E '[A-Za-z0-9.-]+\.(ru|com|net|io|dev|local|corp|internal|lan)\b' $FILES | sort -u

# 6. IP/localhost/tmp-пути/служебные хосты
grep -n -i -E '/tmp/|/private/tmp|scratchpad|localhost|127\.0\.0\.1|192\.168\.|10\.[0-9]+\.[0-9]+\.[0-9]+' $FILES
grep -n -i -E 'jira|confluence|slack|atlassian|bitbucket|teamcity|jenkins' $FILES
grep -n -i -E 'bearer |authorization:|connection string|jdbc:|mongodb://|postgres://|mysql://|redis://' $FILES

# 7. Git-метаданные (не только содержимое файлов — секреты живут и в коммитах)
git log --format='%h %an <%ae>' 1264a16..HEAD
git remote -v
git branch -r --contains 1264a16
```

**Оговорка о воспроизводимости (внесена при обезличивании этого документа).** Пункты 1, 2, 4, 5,
6, 7 воспроизводимы по этому тексту дословно. Пункт 3 — нет: паттерн здесь намеренно заменён
плейсхолдером, потому что буквальный список фрагментов имени — ровно то, что аудит обязан скрыть
от публичного читателя; воспроизведение списка в открытом документе отменяло бы саму находку,
которую он описывает. Класс цели (приватные организации/репозитории/внутренние хосты — отдельно от
персональных идентификаторов контрибьютора) и структура команды воспроизводимы; конкретный список
фрагментов ведётся вне этого документа и доступен PM/DevSecOps по запросу.

Дополнительно — точечная проверка каждой находки предыдущих проходов (PM, research-аудит) на
актуальность через `grep -n` по точному литералу, плюс полное прочтение новых крупных
документов (оба ADR, architecture-design, dev-notes, at-design, QA-report, README тестовых
suite) — там, где паттерн-грепы не покрывают семантику (например, историческую цитату внутри
текста ретракции).

## Явный ответ на вопрос «можно ли публиковать»

**Волну можно публиковать.** Все 5 находок раздела «Findings — периметр волны» (1 High + 4
Medium, все в одном файле, `content/10-domain/research/2026-08-13-link-form-corpus-audit.md`)
исправлены точечной текстовой заменой без нового research (см. таблицу выше и «Постпроверка»);
находки были документационными, без кода продукта и без исполняемого пути, и ни одна не требовала
отзыва секрета (секретов не найдено).

**Ничего в периметре волны, что нельзя было бы опубликовать в принципе, не найдено.** Единственный
класс риска серьёзнее «поправить формулировку» — уже материализованная утечка прошлых волн
(раздел «Вне периметра волны») — не создаётся и не усугубляется текущей волной, уже присутствует
в опубликованной истории `origin/main` независимо от решения по этому PR, и по прямому указанию
разбирается отдельно.

**Рекомендация:**
- [ ] merge with follow-up
- [ ] block merge
- [x] merge — clean (после исправления 5 находок ниже; вне-периметровая утечка прошлых волн —
      отдельная, уже открытая задача, не блокирует эту волну)

**Обоснование:** находки — точная текстовая утечка приватных имён и одного абсолютного пути в
одном research-документе волны, не секреты и не код; все 5 исправлены точечными заменами без
нового поиска, правки внесены до `git push` (см. «Findings» и «Постпроверка»). Блокировать merge
не требовалось ни архитектурно, ни фактически.
