# Правила писателя, изобретённые потребителями — диспозиция по шести темам

## Контекст

Разрешающий design-документ, не ADR. Закрывает FR-065…FR-076 из
`content/30-requirements/2026-08-11-writer-consumer-rules.md`, на основе research
[RES-002: Где потребителям не хватило инструкций плагина](../10-domain/research/2026-08-11-plugin-consumers-gaps.md) (G3, G6, G13). Enforcement и

решением по mermaid-миграции).

## A. Cross-каталожные ссылки

**FR-065 → в плагин, `references/doc-root-schema.md`.** Раздел «Корневые ключи» называет
назначение `code`, но не показывает сквозной пример. Добавить подраздел с реальным значением:

```yaml
# content/.doc-root.yaml (этот репозиторий)
code: GRAMAX-PLUGIN
```
`` `GRAMAX-PLUGIN/40-architecture/2026-08-11-writer-rules-disposition.md` `` — ссылка из статьи другого каталога.

Объявляющая сторона — реальное значение; принимающая иллюстративна (подтверждённого внешнего
двухкаталожного сетапа нет, открытый вопрос BA №4) — публиковать как «проверенный» пример
только после теста на живом сетапе, до тех пор — с пометкой «не проверено».

**FR-066 → в документацию, `SKILL.md` рядом со строками 204–208** (тот же ❌/✅-блок), 1–2
строки: чужой regex-валидатор не отличает код-спан `` `[X](Y)` `` от markdown-ссылки `[X](Y)`
— пример-иллюстрация может дать ложное срабатывание. Вне контекста ловушки бесполезно.

Enforcement — не эта тема, см. ADR-0012.

## B. Вложенные `.doc-root.yaml` и overlay-расширение `properties`

**Решение: у потребителя (вариант «в» FR-067/FR-068)** — вне периметра, с явной пометкой в
`references/doc-root-schema.md`, не молчанием. Один случай (`knowlage/moex`) — по BR-001
недостаточный сигнал, чтобы утверждать поведение `writer`/`validate_structure.py` для
вложенных каталогов (конфликты property, приоритет второго `.doc-root.yaml`) — нетривиальная
поверхность, не фиксируется по одному случаю.

Overlay-расширение `properties` технически не запрещено (YAML не проверяется полной схемой), но
не валидируется плагином. Рекомендованная необязывающая конвенция провенанса — комментарий
`# добавлено overlay'ем <имя>` рядом с property, по образцу `knowlage/moex`. Усилится сигнал
(≥2–3 независимых случая) — кандидат отдельного ADR, ориентировочно **ADR-0014**.

## C. Проекция статусов ADR ↔ каталог

**Решение: в плагин, `references/doc-root-schema.md`**, новый подраздел «Content type ADR —
`Статус`»:

- Для **новых** каталогов — enum с `Proposed` наравне с уже принятыми значениями (`Accepted`,
  `Superseded`, `Historical`...) — 1:1 с телом ADR, без слоя трансляции.
- Для **существующих** каталогов, где enum разошёлся сильнее одного значения (пример —
  `mango-cti-rest`: `Accepted→Approved`, `Proposed→Review`) — обязательная явная таблица
  соответствия (`Тело ADR` / `Frontmatter`) в реестре ADR каталога.
- **FR-070:** тело статьи — источник истины; frontmatter — проекция, обновляется тем же
  изменением. Расхождение носителей — дефект.

**Не решено здесь:** enum `Статус` в `content/.doc-root.yaml` этого репозитория не содержит
`Proposed` — структурная правка `properties`, требует отдельного SA-разбора перед внесением.
Follow-up для PM/Dev, не ADR-кандидат — правка данных, не архитектура.

## D. XML-блоки как признак структуры

**Решение: в документацию, `references/structure.md`**, раздел «XML-блоки, засчитываемые как
структура»: `<note>`, `<tabs>`, `<view>`, `<snippet>`, `<mermaid>`, `<drawio>`, `<image>`,
`<openapi>` (FR-071). Prose-перечень; машиночитаемая форма для внешних эвристик — расширение
ADR-0012, не дублируется заранее.

## E. Утечка абсолютных путей

**FR-072 → в документацию, `SKILL.md` → `## Guardrails`**, одна строка: риск двойной — утечка
идентификационных данных контрибьютора **и** битая ссылка, называть оба, не только техническое.

**FR-073 → остаётся ручной проверкой.** Единственный случай (`sd-ai-assistant`, ручной `grep`)
— сигнал недостаточен для кода в `validate_structure.py` сейчас (BR-001). Класс риска (privacy
leak) весомее числа повторов, поэтому предупреждение обязательно уже сейчас (BR-003: docs не
заменяют автопроверку, но их отсутствие — не оправдание). Автоматизация при усилении сигнала —
расширение контракта уже спроектированного ADR-0012, отдельный ADR-0014 под это не заводится.

## F. Дрейф знания в локальные скилл-дубли

**Решение: в плагин.**

- **FR-074 → `SKILL.md`**, 2–3 строки в `Core Principles`: `writer` — единственный
  authoritative источник Gramax-соглашений. Легитимно: локальный скилл с конвенциями
  конкретного каталога (нейминг раздела, property одного домена). Нелегитимно: локальный
  скилл, переизлагающий общее Gramax-правило и объявляющий себя приоритетным «при
  расхождении» — сигнал устаревания/неполноты `writer`, подлежит разбору, не архитектура.
- **FR-075 → новый `references/authoritative-source.md`** (~15–20 строк): grep-конвенция —
  `grep -rliE 'дополняет.{0,15}gramax:writer|при расхожден.{0,20}(побежда|приоритет)' **/skills/*/SKILL.md`
  — пункт чек-листа онбординга потребителя и периодического аудита сопровождающего плагина.
  Из `SKILL.md` — одна ссылочная строка.

## NFR Mapping

- **NFR-001.** `SKILL.md` (317 строк) получает 4 точечные вставки по 1–3 строки (backtick-
  ловушка, guardrail путей, authoritative-декларация+ссылка) — итог ≈ +8–10 строк, без новых
  разделов; основной объём в `references/`. `description` фронтматтера не меняется.
- **NFR-002.** Ни одно решение не переименовывает skill-имена и не меняет подтверждённый
  синтаксис (`<drawio path=.../>`, inline-code ссылка, object-нотация); тема B декларирует
  «не поддерживается», не альтернативный синтаксис.
- **NFR-003.** Добавления на русском, тем же регистром: короткие абзацы, таблицы, рабочие
  примеры вместо плейсхолдеров (FR-065 — реальный `code: GRAMAX-PLUGIN`).

## Открытые вопросы / кандидат ADR-0014

1. Формальная поддержка вложенных `.doc-root.yaml` и overlay-`properties` как first-class
   механизм (тема B) — decline по слабому сигналу; при усилении — отдельный ADR, ориентировочно
   **0014**.
2. Верификация примера FR-065 на реальном двухкаталожном сетапе — блокирует публикацию
   «проверенного» примера, не блокирует объявляющую половину.
3. Приведение `content/.doc-root.yaml` этого репозитория к рекомендации темы C (`Proposed`) —
   follow-up для PM/Dev, не ADR-кандидат.

## Контракт с QA-author

**AC:** AC-001…AC-013 — грепы по строкам/паттернам в `plugins/gramax/skills/writer/**` плюс
композитный `check.sh --fast` (AC-013). Архитектурный контекст: изменения только текстовые
(`SKILL.md`, `references/*.md` + новый `authoritative-source.md`); код `validate_structure.py`
не меняется (enforcement — ADR-0012); trust boundary отсутствует — нет исполняемого пути.

**Edge cases:**
- AC-002: `code:`, «cross-каталож» и паттерн `` `A/b` `` должны совпасть **в одном файле** —
  разнесение примера по двум файлам ломает цепочку `grep | xargs grep | xargs grep`.
- AC-006: grep с `-A5` порядково-чувствителен — «статус» обязано идти в пределах 5 строк
  **после** упоминания ADR. AC-001/AC-012 — регрессия: вставки FR-066 и FR-072 физически
  соседствуют с уже застрахованными grep'ами строками («inline code», «не резолвит», drawio-тег).
- Вопрос 2 (верификация FR-065): AC-002 пройдёт по синтаксису даже без проверки на живом
  сетапе — семантика не покрыта ни одним AC; проверять вручную, вне регрессионного набора.

**Test-pyramid:** AC-001…AC-010, AC-012 и AC-011 (ссылка ADR→требование) — unit, статический
grep, нет исполняемого кода; AC-013 (`check.sh --fast`) — integration, схема `.doc-root.yaml` +
frontmatter + весь `content/` вместе.
