# Контракт формы ссылки на артефакт — резолвер, миграция, интеграция с nauta

## Контекст

Реализация решений [ADR-0016](../00-project/adr/0016-link-form-contract.md) для требования
`content/30-requirements/2026-08-13-link-form-contract.md` (FR-077…FR-092). ADR фиксирует пять
решений: единая точка инференса расширения в резолвере (`_collect_links`), временный `.md`-
протокол при расхождении с `scripts/validate-content.py` (nauta), отказ от нового гейта для
классификации NAV/SELF/SUBJECT, отказ от автоматизации проверки цитирования и forward/back-
linking, стратегию миграции 103 навигационных код-спанов. Этот документ несёт то, что ADR
намеренно не несёт: компоненты, интеграционные точки, бриф для Dev/DevOps, контракт с
QA-author.

## Компоненты

| Компонент | Ответственность | Входы | Выходы | Зависимости |
|-----------|-----------------|-------|--------|-------------|
| `_collect_links` (`validate_structure.py:286-313`) | Единая точка сбора и **резолва** markdown-ссылок каталога — инференс расширения (ADR-0016 Решение 1) | `.md`-файлы каталога (после `_mask_code`) | `list[LinkRef]` (`source`, `raw_target`, `resolved`, `in_scope`) | `_mask_code`, `_MD_LINK_RE`, `_EXTERNAL_RE` |
| `check_broken_links` | Error, если `ref.in_scope and not ref.resolved.exists()` — без изменений в собственном коде, наследует фикс через `ref.resolved` | `list[LinkRef]` от `_collect_links` | `list[Issue]` (error) | `_collect_links` |
| `check_orphans` | Warning/error (`--strict`), если статья не в `_index.md` не получает ни одной входящей `ref.resolved` — без изменений в собственном коде | `list[LinkRef]`, список `.md`-файлов | `list[Issue]` (warning/error) | `_collect_links` |
| `migrate_nav_codespans.py` (new) | Пересканирует корпус (маскирование + классификация NAV/SELF/SUBJECT), конвертирует NAV-код-спаны в markdown-ссылки с `.md`-суффиксом (ADR-0016 Решение 2, 5) | `content/`, флаги `--fix --yes`, `--expect-count=N` | Отчёт (мигрировано/SELF/SUBJECT/спорное) + мутация файлов | `_mask_code`-эквивалент (копия, не импорт — прецедент RES-005 «побайтовая копия») |
| `/nauta:pm-review` чек-лист | Процессная проверка: голая отсылка `FR-NNN` (FR-086), RECORD/POINTER-пометка (FR-088), forward+back linking (FR-089), финальная классификация NAV/SELF/SUBJECT (FR-077…079) | PR-диф | Вердикт pass/block | Человек-ревьюер |

## Границы

- Резолвер (`_collect_links`) не проверяет код-спаны — они вырезаны `_mask_code` до сканирования;
  проверка пути внутри код-спана вне периметра этого ADR (ADR-0016 Решение 3).
- Ни одна проверка не выходит за пределы текущего `.doc-root.yaml`-каталога (унаследовано от
  ADR-0012 FR-047/FR-048, не меняется) — путь вне каталога не гейтится ни в каком виде (FR-084).
- Миграционный скрипт не переписывает SELF- и SUBJECT-код-спаны — только NAV, по классификации
  теста FR-077 (наследует все три подтеста: directionality — вручную закреплено в таблице-входе,
  existence/scope — механически на момент прогона).
- `scripts/validate-content.py` (nauta) не редактируется в этом репозитории ни при каких
  обстоятельствах — эскалация только через апстрим-issue.
- Классификация NAV/SELF/SUBJECT и цитирование `FR-NNN`/`путь:строка` не получают нового кода —
  граница явно проведена в ADR-0016 Решениях 3–4.

## Поток данных

```
Автор пишет NAV-код-спан → миграционный скрипт (пересканирует corpus) → классифицирует
  (existence+scope механически, directionality — из входной таблицы RES-005 либо ручной
   разметки) → конвертирует NAV → markdown-ссылка с .md-суффиксом (временный протокол,
   ADR-0016 Решение 2) → `_collect_links` резолвит литерально (уже сегодня работает,
   NFR-001) → check_broken_links / check_orphans проверяют как обычно
```

```
Автор пишет НОВУЮ ссылку без .md (канонический синтаксис SKILL.md:210) → _collect_links
  инферит .md/_index.md (ADR-0016 Решение 1) → check_broken_links находит файл → OK для
  plugins/gramax/scripts/validate_structure.py, НО check.sh --fast (validate-content.py,
  nauta) без инференса даёт error → блокировано до апстрим-фикса — поэтому временный
  протокол (Решение 2) предписывает .md-суффикс для собственного корпуса до этого момента
```

## Интеграционные точки

| Точка | Протокол | Контракт | Auth | Rate limit | Error handling |
|-------|----------|----------|------|------------|----------------|
| `_collect_links` → `check_broken_links` | внутренний вызов Python | `LinkRef.resolved.exists()` → error, если `in_scope` | N/A (офлайн-скрипт) | N/A | Error-сообщение включает `raw_target` и вычисленный `resolved`-путь |
| `_collect_links` → `check_orphans` | внутренний вызов Python | `LinkRef.resolved` как ключ `incoming`-словаря | N/A | N/A | Файл без входящих `resolved`-совпадений → warning (`--strict` → error) |
| `validate_structure.py` ↔ `check.sh --full` | subprocess, код возврата | ненулевой exit при `error`-уровне issue | N/A | Одноразовый запуск на коммит/CI | `check.sh --full` печатает `FAIL` и прерывает pipeline |
| `validate-content.py` (nauta) ↔ `check.sh --fast` | subprocess, код возврата | error на буквальный `.exists()`, без инференса (расхождение, ADR-0016 Решение 2) | N/A | Каждый коммит (pre-commit hook) | Красный `--fast` до временного `.md`-протокола или апстрим-фикса |

| SA/Dev → `tools-ai/nauta` (апстрим) | GitLab issue (доска `doc-hub.gitlab.yandexcloud.net/tools-ai/nauta`) | Текстовое описание дефекта + предложенный алгоритм (см. «Бриф для DevOps») | Доступ к внутреннему GitLab | N/A | Issue отслеживается вручную, релиз/пересинк — событие для снятия временного протокола |

## Открытые вопросы

1. Advisory-гейт на existence+scope-кандидатов NAV-код-спанов (без directionality) — оставлен
   опциональным улучшением (ADR-0016 Решение 3), не мандатом. Решает PM/Dev по стоимости.
2. Числовой порог NFR-002 на кратно большем каталоге — не измерено, отдельный замер при
   необходимости SLA.
3. Момент снятия временного `.md`-протокола (Решение 2) — событие «релиз nauta с фиксом +
   `/nauta:sync-scripts`», не календарная дата; отслеживает PM.
4. Реестр владения номерами `FR-/AC-/NFR-/BR-NNN` (сделал бы FR-086 дёшево автоматизируемым) —
   тот же класс, что открытый вопрос BA №3 про `RES-NNN`; не создаётся здесь.

## Контракт с QA-author

**AC (полный список из требования):**
- AC-001…AC-004 — классификация (NAV, SELF-приоритет, спорный случай #83, scope-граница SUBJECT).
- AC-005…AC-007 — целевая форма (построчное сравнение результата миграции, антипаттерн
  задокументирован в `SKILL.md`, regression guard — кросс-каталожное не мигрируется).
- AC-008…AC-012 — резолвер (позитив без расширения, позитив на раздел, антипаттерн остаётся
  ошибкой, генуинно битая ссылка, граница — путь вне каталога не проверяется).
- AC-013…AC-016 — цитирование и связность (голая отсылка — процессная проверка, `ADR-NNNN` —
  regression guard исключения, RECORD/POINTER — документальная проверка, forward+back linking —
  процессная проверка).
- AC-017…AC-018 — миграция (протухший путь исправлен, дрейф `путь:строка` устранён).
- AC-019 — композитный `bash scripts/check.sh --fast && echo PASS`, по коду возврата.

**Архитектурный контекст для тестов:**
- Компоненты: `_collect_links` (общая точка резолва), `check_broken_links`, `check_orphans`,
  новый `migrate_nav_codespans.py`.
- Интеграции: файловая система (fixtures), `check.sh --fast`/`--full` (composite exit code),
  `tools-ai/nauta` (внешняя, не тестируется в этом репозитории).
- Trust boundary: нет сетевых вызовов, нет auth — весь периметр офлайн, файловый I/O в пределах
  `.doc-root.yaml`-каталога либо явно вне него (граница FR-084).

**Edge cases / boundary conditions:**
- Цель уже оканчивается на `.md`, но файла нет (генуинно битая `.md`-ссылка) — инференс не должен
  пытаться добавить второе `.md` (AC-011 не должен внезапно "починиться").
- Цель — раздел без явного `_index` в тексте ссылки (`[X](section)`, не `[X](section/_index)`) —
  третий шаг инференса (`section/_index.md`) описан FR-082 текстуально, но не был отдельно
  прогнан исполняемым probe (RES-004 подтвердила код-путь чтением, не исполнением этой конкретной
  формы) — стоит покрыть отдельным тестом, если Dev реализует эту ветку.
- Пересечение с антипатерном FR-081: путь, начинающийся с имени doc-root-папки, но БЕЗ `.md` —
  не тестировался явно ни в требовании, ни в RES-004 (там форма 8 — только с `.md`); поведение
  резолвера на `content/section/doc` (без расширения) — не specified фактом, кандидат для теста
  Dev/QA, если возникнет в реальном корпусе.
- Миграционный скрипт: гонка между re-scan и `--expect-count` — если корпус меняется между
  запуском без флагов (отчёт) и повторным запуском с `--fix` (кто-то успел закоммитить правку) —
  guard должен сработать на новом прогоне, не на кэшированном отчёте.
- `check.sh --fast` (nauta) на ссылке без `.md`, написанной по ошибке до снятия временного
  протокола — ожидаемый false positive на переходный период, не дефект резолвера плагина.
