## Находка: AC-006 уже удовлетворён по несвязанной причине

По прецеденту `content/60-implementation/acceptance/2026-08-11-mermaid-adoption-at-design.md`

  | grep -qi 'антипаттерн\|не работает\|не резолв'; echo $?

Возвращает `0` (PASS) уже сегодня — но единственное совпадение (`SKILL.md:181`, «Полный

## Находка: AC-004 — самый архитектурно сложный AC этого трека

ADR-0016 Решение 3 констатирует: «существование+scope уже механичны... directionality —
эвристика по маркерным фразам... не различает NAV от SUBJECT без неё». Буквально это верно для
_markdown-ссылок_ (`_collect_links`, где `in_scope` — чистая проверка «резолвится ли путь внутри
`root`»). Но код-спан AC-004 — качественно другой случай: путь `content/_index.md` **физически
существует** внутри фикстурного `.doc-root.yaml`-каталога (файл `_index.md` в корне) — то есть
и existence, и НАИВНЫЙ scope-тест («резолвится ли путь внутри текущего каталога») механически
дают TRUE. Единственный сигнал, отличающий этот случай от настоящего NAV — то, что абзац
явно называет target принадлежащим другому репозиторию («в РЕПОЗИТОРИИ `acme-widgets`, не в
этом»). Это семантика уровня directionality, применённая не к «есть ли маркер направления»
(маркер «см.» присутствует буквально), а к «маркер направления указывает КУДА» — на файл в
этом каталоге или на одноимённый файл в другом. Как именно Dev технически распознает эту
разницу (лексический список маркеров «в другом репозитории»/«чужой проект»/эквивалент, ручной
allowlist по прецеденту FR-079/#83, что-то ещё) — решение реализации, не диктуется этим
документом; `ac-004` проверяет только НАБЛЮДАЕМЫЙ результат (код-спан не превращён в ссылку),
не внутренний механизм.

## «Вакуумная истина»: негативные ассерты нуждаются в позитивной гарантии (AC-002, AC-004, AC-007)

Тот же паттерн, что в `tests/gramax/mermaid-adoption/README.md` («Вакуумная истина», урок
`content/lessons-learned.md`). AC-002, AC-004, AC-007 формулируются как ОТСУТСТВИЕ эффекта
(«файл не должен измениться»). Пока `migrate_nav_codespans.py` не существует, `--fix --yes` не
мутирует НИЧЕГО — голая негативная проверка была бы тривиально верна без единой строчки кода
Dev. Все три скрипта сначала требуют позитивную гарантию — что тот же прогон `--fix --yes`
реально смигрировал ИЗВЕСТНЫЙ NAV-кейс (`nav-source.md`→`nav-target.md`) — и только затем
проверяют негативное условие для своего конкретного файла. Если позитивная гарантия не
выполнена, тест красный по этой причине (сегодня — именно так); если выполнена, но негативное
условие нарушено — красный по содержательной причине AC. Ни в одном случае тест не может
оказаться зелёным просто потому, что ничего не произошло.

Тот же приём применён к AC-001 отдельно для проверки ДЕТЕРМИНИЗМА: если бы инструмент вообще не
запускался, оба прогона report-mode дали бы ОДИНАКОВУЮ ошибку `uv run` — `diff` двух прогонов
был бы пуст тривиально, маскируя отсутствие инструмента под «детерминизм». `ac-001` проверяет
детерминизм только ПОСЛЕ того, как первый прогон подтверждённо нашёл `nav-source.md`
кандидатом.

## Интерпретация для Dev (контракты, не зафиксированные ADR буквально)

ADR-0016/companion-архитектура оставляют открытым точный формат вывода report-mode
`migrate_nav_codespans.py`. QA-author фиксирует минимальный рабочий контракт для стабов —
предложение, не требование ADR (по прецеденту `tests/gramax/mermaid-adoption/README.md`,
раздел «Интерпретация для Dev»):

1. **Формат находки (report-mode, `ac-001`):** `<путь>:<номер строки>` где-то в stdout для
   каждого NAV-кандидата, плюс регистронезависимое слово "nav" где-то в том же выводе
   (класс-метка). Если реальный формат Dev расходится — поправьте regex вместе с обоснованием
   прямо в `ac-001-nav-classification-deterministic.sh`, не убирайте ассерт молча (прецедент
   «Интерпретация AC-014», `content/60-implementation/acceptance/
   2026-08-11-validation-contract-at-design.md`).
2. **`--expect-count=N` — явный флаг, не позиционный аргумент**, по образцу `--fix`/`--yes`.
   Дефолт при отсутствии флага — 103 (число реального корпуса, ADR-0016 Решение 5); на
   фикстуре этого suite'а всегда передаётся явно (`--expect-count=2`).
3. **Форма результата (`ac-005`):** `[title-цели](относительный-путь.md)` — текст ссылки
   механически берётся из `title` frontmatter цели (не из заголовка `#` статьи и не из имени
   файла), href — относительный путь `os.path.relpath`-стиля С ЯВНЫМ `.md`-суффиксом
   (временный протокол ADR-0016 Решение 2, НЕ канонический FR-080 «без расширения» — это
   различие специфично ЭТОМУ репозиторию, см. заголовок задачи).
4. **`path`-аргумент — сам `.doc-root.yaml`-каталог**, по конвенции `validate_structure.py`
   (`uv run migrate_nav_codespans.py content`), не произвольный scan-root с поиском вложенных
   доc-root'ов (в отличие от `migrate_mermaid.py`, где это было нужно для проверки границы
   юрисдикции). Все `ac-*.sh` этого suite'а вызывают инструмент с `"$WORKDIR/content"`, не
   `"$WORKDIR"`. Если Dev выберет модель произвольного scan-root — поправьте инвокацию во всех
   7 `ac-*.sh` synchронно, с обоснованием.

Если реализация Dev расходится с любым из четырёх пунктов — поправьте regex/инвокацию вместе с
обоснованием прямо в соответствующем `ac-*.sh`, не убирайте ассерт молча.

## Boundary cases

- **AC-005 не проверяет случай, когда `nav-target.md` и `nav-source.md` лежат в разных
  подкаталогах** (относительный путь с `../`) — фикстура держит оба файла в одном каталоге для
  простоты; вычисление `os.path.relpath` с непустым `../`-префиксом не покрыто этим suite'ом.
  Явно вне периметра — не назван отдельным AC требования; при необходимости — follow-up тест,
  не блокирующий Dev.
- **AC-003 не проверяет саму цель `future-checklist.md`** (не-NAV код-спан на несуществующий
  файл внутри того же абзаца) — фикстура намеренно НЕ создаёт этот файл (мимикрирует «ещё не
  создан» из прецедента #83), но ни один `ac-*.sh` не ассертит её итоговую классификацию
  явно — не входит в формулировку AC-003 буквально.
- **`--expect-count` guard сам по себе не тестируется этим suite'ом** — ни один `ac-*.sh` не
  проверяет, что `--fix --yes` БЕЗ `--expect-count` (или с заведомо неверным значением)
  прерывается без мутаций. ADR-0016 Решение 5 специфицирует это поведение достаточно однозначно
  (hard guard), но ни один AC требования (AC-001…007) не называет это явно проверяемым условием
  — вне периметра этого трека; кандидат для отдельного regression-теста, если понадобится.

## Error cases

- **Отсутствующий инструмент (`uv run` на несуществующий файл):** `error: Failed to spawn`,
  ненулевой exit — ни один `ac-*.sh` не падает с bash-ошибкой (unbound variable, unhandled
  pipefail); только с явным `FAIL`-сообщением через `assert.sh`. Проверено прогоном
  `run.sh` (см. «Запуск» ниже) — все 7 тестов красные по содержательной причине, не по
  синтаксической ошибке suite'а.
- **Мутирующие сценарии (`ac-002`…`ac-005`, `ac-007`) работают ИСКЛЮЧИТЕЛЬНО на `mktemp`-копии**
  композитной фикстуры — ни один не пишет напрямую в `fixtures/composite/`, что git-tracked.
  Защита от каскадного искажения между тестами в одном прогоне `run.sh`.

### AC-018 — дрейф `путь:строка`

```bash
# Шаг 1: извлечь номер строки, процитированный в writer-consumer-rules.md:74
CITED=$(grep -oE 'adr/_index\.md:[0-9]+' content/30-requirements/2026-08-11-writer-consumer-rules.md \
  | head -1 | grep -oE '[0-9]+$')

# Шаг 2: если цитата явно помечена как RECORD (зафиксированный HEAD) — ревалидация не нужна
RECORD_MARK=$(grep -c 'RECORD' content/30-requirements/2026-08-11-writer-consumer-rules.md)

# Шаг 3: иначе (POINTER, по умолчанию) — сверить с фактической текущей строкой цитируемого
# текста (`adr/_index.md` объявляет словарь статусов ADR)
ACTUAL=$(grep -n 'Статусы:.*Proposed.*Accepted.*Superseded by ADR-MMMM' content/00-project/adr/_index.md \
  | head -1 | cut -d: -f1)

echo "cited=$CITED actual=$ACTUAL record_marker_count=$RECORD_MARK"
```

Ожидание ПОСЛЕ правки: либо `record_marker_count > 0` (явная пометка RECORD с зафиксированным
HEAD — ревалидация не требуется, FR-088), либо `cited == actual` (POINTER верен на момент
проверки).

**Наблюдаемое сейчас (2026-08-13, до правки):** `cited=11 actual=10 record_marker_count=0` —
ни RECORD-пометки нет, ни номера не совпадают: дрейф подтверждён, AC-018 не выполнен. Тот же
дрейф установлен независимо `RES-005` (`content/10-domain/research/
2026-08-13-link-form-corpus-audit.md`, находка 7) — эта команда его переоткрывает механически,
не полагаясь на снимок исследования.

**Осторожность для QA-runner:** `content/00-project/adr/_index.md` активно редактируется
параллельными задачами этой волны (ADR-0016/0017/0018 регистрируются в реестре) — Шаг 3 ищет
целевой текст ПО СОДЕРЖИМОМУ (`grep` по фразе «Статусы: Proposed | Accepted | Superseded by
ADR-MMMM»), не по жёстко зафиксированному номеру строки, поэтому устойчив к дальнейшему росту
таблицы реестра ADR ниже цитируемой строки.
