# AT-design: Резолвер гейта — инференс расширения `.md`/`_index.md` (link-form-contract)

**Роль:** QA-author (тест-дизайн до реализации Dev — этот документ и failing-тесты
предшествуют коду резолвера, не следуют за ним).
**Требование:** `content/30-requirements/2026-08-13-link-form-contract.md` (трек резолвера —
AC-008…AC-012; остальные AC требования — AC-001…007, AC-013…018 — параллельный QA-author-трек
классификации код-спанов и скрипта миграции, не этот документ).
**ADR:** `content/00-project/adr/0016-link-form-contract.md`, Решение 1.
**Архитектура:** `content/40-architecture/2026-08-13-link-form-contract-design.md`, «Бриф для
Dev» пп.1–2, «Контракт с QA-author».
**Артефакты этой задачи:**
- `tests/gramax/link-form-resolver/` — bash AC-suite (`ac-NNN-*.sh` + `run.sh` + независимая
  копия `lib/assert.sh`), прецедент `tests/gramax/catalog-validator/` (ADR-0012 Решение 5).
- `tests/gramax/link-form-resolver/fixtures/` — 8 фикстур, по одной на каждый `ac-*.sh`.

Документ фиксирует «Тип контента: Тест-отчёт» за неимением отдельного enum-значения
`AT-design` в `content/.doc-root.yaml` — тот же приём, что и в
`2026-08-11-validation-contract-at-design.md`.

## Почему один уровень (bash-suite), не pytest тоже

Бриф задачи допускал оба уровня (`plugins/gramax/scripts/tests/fixtures/link-resolution/` +
pytest, ИЛИ `tests/gramax/link-form-resolver/` + bash) и явно оставлял выбор QA-author.
Design-документ (`2026-08-13-link-form-contract-design.md`, «Контракт с QA-author» →
«Test-pyramid рекомендация») классифицирует AC-008…012 как **integration** с обоснованием
«уже принятый паттерн репозитория (`tests/gramax/catalog-validator/`, ADR-0012 Решение 5)» —
прямое указание на bash-suite, не на pytest. Решение: один уровень, не дублирование — та же
матрица AC дважды означала бы два README, два места искать «что осталось красным» без
выигрыша в покрытии (тот же аргумент, что «Одно требование — один suite» в
`tests/gramax/catalog-validator/README.md`). Если после реализации `_resolve_link_target` как
отдельно тестируемой функции понадобится unit-уровень — дешёвая добавка поверх уже зелёных
интеграционных тестов, не блокирующая эту задачу.

## Отклонение от буквального прочтения задачи («все тесты AC-008…012 падают red»)

Бриф задачи формулирует критерий приёмки как «все новые тесты для AC-008…012 запускаются и
падают (red) на текущем коде». Эмпирическая проверка (`uv run` на каждой фикстуре, до
написания финальных assert’ов) показала, что это невыполнимо для AC-010, AC-011, AC-012 без
искажения смысла самих AC — и это ожидаемо, не дефект тест-дизайна:

- **AC-010** тестирует цель, уже оканчивающуюся на `.md` (`content/section/doc.md`) — по
  Брифу для Dev п.1 («если target не оканчивается на `.md` — попробовать инференс; ИНАЧЕ —
  вернуть литеральный `resolve()`, как сегодня»), инференс к такой цели вообще не
  применяется. Резолв идентичен сегодняшнему и до, и после FR-082 — тест физически не может
  быть red, потому что тестируемое им поведение не меняется этой задачей вовсе.
- **AC-011** (target без `.md`, `missing-target`) промахивается на всех трёх шагах
  одновременно и сегодня (буквальный resolve тоже не находит файл), и после FR-082
  (инференс тоже не находит файл, потому что файла нет физически) — это ПРЯМАЯ проверка
  инварианта NFR-001 («резолвер не может превратить генуинно битую ссылку в ок»), инвариант
  по определению обязан выполняться в обеих точках времени, иначе NFR-001 нарушен уже сегодня.
- **AC-012** тестирует код-спан (backtick), не markdown-ссылку — `_mask_code` вырезает его до
  сканирования `_MD_LINK_RE` независимо от того, реализован ли инференс расширения. Граница
  FR-084 архитектурно уже удовлетворена (design-документ, «FR/NFR Mapping»: «FR-084 — уже
  удовлетворена архитектурой, без нового кода»).

Форсировать эти три пункта в красное состояние потребовало бы либо тестировать не то
поведение, которое реально описывает AC (например, требовать incorrectly, чтобы антипаттерн
ВРЕМЕННО чинился), либо временно ломать сегодняшний корректный резолв — оба пути хуже
честной фиксации фактического состояния. Только AC-008 и AC-009 действительно демонстрируют
отсутствующий код (второй шаг инференса `target + ".md"`) — они и есть настоящий red→green
цикл этой задачи; AC-010…012 — safeguards, защищающие от РЕГРЕССИИ при написании этого кода.
Подробная таблица с обоснованием по каждому пункту —
`tests/gramax/link-form-resolver/README.md`, раздел «Стартовое состояние».

## Находка для Dev/SA: `Path.exists()` не различает файл и директорию

`ac-009b-section-implicit-index-resolves.sh` (`[X](section)`, без явного `_index` в тексте)
зелёный уже сегодня — но ПОБОЧНО: `(md.parent / "section").resolve()` указывает на реально
существующую директорию, а `Path.exists()` истинен для директорий так же, как для файлов;
сегодняшний буквальный резолвер никогда не проверял, что цель — именно файл, а не каталог.
FR-082 говорит «не находит существующий **файл**» — более строгое прочтение (`is_file()` на
каждом шаге вместо `exists()`) заставило бы шаг 1 отклонять голые ссылки на директорию и
переходить к шагу 3 (`target/_index.md`) — семантически более точно, но с побочным эффектом:
директория БЕЗ `_index.md` внутри перестала бы резолвиться (сегодня резолвится случайно) —
новая ошибка там, где сегодня `OK`, формально пересекается с NFR-001. `ac-009b` сознательно
не тестирует эту ветку (директория есть, `_index.md` внутри нет) — требование не фиксирует
это поведение явно, домысливание тестом навязало бы Dev трактовку, которую BA не принял
решение по. Полный текст находки — `tests/gramax/link-form-resolver/README.md`.

## Boundary cases

- **Двойное расширение `.md`** (`ac-011b`) — прямое покрытие edge case из design-документа:
  инференс обязан ПРОБОВАТЬ добавление `.md` только к целям, ещё НЕ оканчивающимся на `.md` —
  проверено явным негативным ассертом (`grep -q 'missing.md.md'` обязан НЕ находить).
- **Антипаттерн × инференс без расширения** (`ac-010b`) — пересечение двух правил (FR-081 +
  FR-082), не specified требованием буквально ни в одном AC. Тест фиксирует единственный
  исход, механически выводимый из формулировки 3-шагового алгоритма (все три попытки строятся
  от одного и того же несуществующего префикса `content/`), не интерпретацию QA-author.
- **Третий шаг инференса без явного `_index`** (`ac-009b`) — упомянут design-документом как
  «не был отдельно прогнан исполняемым probe»; фикстура закрывает этот пробел, но с явной
  оговоркой (см. «Находка» выше) о том, что зелёный результат сегодня не эквивалентен
  фактическому исполнению шага 3 — только наблюдаемому исходу.

## Error cases

- **AC-011** — сообщение об ошибке обязано называть саму ссылку (`missing-target`), не только
  сигнализировать `exit≠0` — иначе тест не отличил бы «правильную» ошибку от любой другой
  случайной находки валидатора (например, unrelated frontmatter-ошибки).
- **AC-010** — то же требование к сообщению, применённое к антипаттерну
  (`content/section/doc.md`), чтобы отличить «ссылка осталась битой по правильной причине» от
  «фикстура сломана по случайной причине» (опечатка в frontmatter и т.п.).

## Не покрываем (вне scope)

- **AC-001…007, AC-013…018** требования — параллельный QA-author-трек (классификация
  код-спанов NAV/SELF/SUBJECT, `migrate_nav_codespans.py`, процессные пункты `pm-review`).
  Не дублируется здесь по прямому указанию задачи («не трогай... другой трек»).
- **Собственно алгоритм `_resolve_link_target`** — реализует Dev; этот документ и suite
  проверяют только наблюдаемое поведение (`exit`-код, текст сообщения), не внутреннюю
  структуру функции.
- **Ветка «директория существует, `_index.md` внутри нет»** (см. «Находка» выше) — поведение
  не specified требованием; сознательно не тестируется, чтобы не навязать трактовку.
- **Апстрим-расхождение с `scripts/validate-content.py`** (FR-083, NFR-004 CHANGELOG-запись) —
  за периметром теста резолвера, задача Dev/DevOps по брифу.

## Передача Dev

6 зелёных regression guards) + Бриф для Dev в
`content/40-architecture/2026-08-13-link-form-contract-design.md` (пп.1–2: точная сигнатура

зелёных должны ОСТАТЬСЯ зелёными после правки (safeguards NFR-001), не требуют отдельного
кода. Строка подключения suite'а к `scripts/check.sh` не входит в эту задачу — решение
Dev/PM по прецеденту `tests/gramax/catalog-validator` (DEV-002 там же, не подключён по
умолчанию).
