# Dev notes: ретракция кросс-каталожного `code:`-рецепта (ADR-0017)

Фиксирует «Тип контента: Урок» за неимением отдельного enum-значения для заметок реализации —
тот же приём, что `2026-08-11-validation-contract-dev-notes.md`.

**Требование:** `content/30-requirements/2026-08-13-cross-catalog-retraction.md` (FR-093…FR-099)
**ADR:** `content/00-project/adr/0017-cross-catalog-retraction.md`, Решение 2 (тексты замены),
Решение 4 (буллет `SKILL.md:213`)
**Тест-дизайн:** `content/60-implementation/acceptance/
2026-08-13-cross-catalog-retraction-at-design.md`

**Периметр этой поставки Dev:** пункты 1–3 и 7 «Брифа для Dev» ADR-0017 —
`doc-root-schema.md`, `SKILL.md` блок «## Ссылки», аннотация `content/40-architecture/_index.md`,
`scripts/check.sh --fast`. Пункты 4–6 (CHANGELOG, `plugin.json`, `marketplace.json`) — territория
Tech-writer (FR-102), сознательно не тронуты.

## Что было сделано

1. `plugins/gramax/skills/writer/references/doc-root-schema.md` — строка 15 таблицы «Корневые
   ключи» и раздел «## Cross-каталожные ссылки через `code`» заменены дословным текстом Решения 2

4. `bash scripts/check.sh --fast` — зелёный (exit=0).

## Что было неочевидно

### 1. Регресс-барьер `writer-consumer-rules/ac-001` не сломан, хотя категоричная фраза убрана

`writer-consumer-rules/ac-001-cross-catalog-markdown-ban-preserved.sh` — regression guard
другого suite'а, проверяющий `grep -qiE 'не резолвит'` в SKILL.md. Замена Решения 2 убирает
буквальную фразу «Gramax не резолвит markdown-ссылки между разными `.doc-root.yaml`-каталогами»
(FR-095 требует именно это — категоричное утверждение опровергнуто probe), но новый текст
сохраняет «резолвится» с отрицанием рядом («не резолвится» на строке про ❌-пример) — regex без
анкоринга матчит «не резолвит» как подстроку «не резолвится» (не резолвит+ся). Проверено явно
(`grep -qiE 'не резолвит' SKILL.md` → match) до коммита — совпадение не случайное, само слово
осталось в тексте по требованию ADR (объяснение через `../`-префикс тоже использует глагол
«резолвится»/«не резолвит**ся**»), но advisable проверять такие regression guard'ы других suite'ов
явным прогоном, а не полагаться на то, что «слово похоже, значит совпадёт».

### 2. Ретировка `writer-consumer-rules/ac-002` — отдельная задача PM, не часть ADR-0017

ADR-0017 не описывает эту правку — задача пришла отдельным поручением PM в этом же сообщении.
`tests/gramax/writer-consumer-rules/ac-002-cross-catalog-code-workflow-example.sh` проверял
co-occurrence сигналов `code:` + `cross-каталож` + паттерн `` `A/b` `` в одном файле как признак
«рабочий пример задокументирован» (FR-065 предыдущего требования). Измерено эмпирически: после
правки по ADR-0017 все три сигнала продолжают совпадать в одном файле — не потому что рецепт
рабочий, а потому что честное историческое объяснение ретракции («Прежде этот раздел показывал
двухшаговый рецепт... построенный на `code:`... inline code `` `CODE/путь.md` ``») неизбежно несёт
тот же словарный набор. Тест был бы случайно зелёным по неверной причине — то же семейство
дефекта, что «зелёный по грепу — не зелёный» (`content/lessons-learned.md`, 2026-08-10), только на
уровне семантики, не пустого ввода.

**Действие:** файл ретирован (`git rm`) из живого suite'а `writer-consumer-rules` по процедуре
`content/00-project/adr/0011-test-harness-taxonomy.md` Решение 2 (обязательное измерение,
документирование в README suite'а, а не молчаливое удаление). Полное обоснование, воспроизводимое
измерение и текст решения — `tests/gramax/writer-consumer-rules/README.md` → «Ретировка AC-002».
Файл НЕ перемещён в `tests/gramax/archive/` — тот каталог держит целые suite, замороженные на
версию релиза (ADR-0011 Решение 1), а не отдельные ретированные AC внутри всё ещё живого suite;
git history (`git log --follow`) сохраняет прежний текст без необходимости физического переноса.
Требование-источник (`2026-08-11-writer-consumer-rules.md`, FR-065) не редактировано — тот же
принцип BR-001, что и остальная часть этой поставки: Accepted/Done-артефакты не правятся в теле
задним числом, факт пересмотра фиксируется отдельно.

### 3. `bash scripts/check.sh --full` был красным ДО начала этой Dev-задачи — не регрессия этой правки

Проверено явно: `git stash` → откат к `HEAD` (`4a6f8d0`, коммит QA-author с failing stubs) →
`bash scripts/check.sh --full` → `exit=1`, тот же `shellcheck`-дефект (`SC2016`/`SC2034`) в трёх
файлах `tests/gramax/cross-catalog-retraction/**`, которые эта задача не трогает (не входят в
периметр Dev по ADR-0017 «Бриф для Dev»). `git stash pop` вернул рабочее дерево, `diff` между
прогоном `--full` до и после правок Dev показал ровно одно отличие — счётчик
`writer-consumer-rules` (12→11 из-за ретировки AC-002 выше), сам `shellcheck`-блок и его причина
идентичны. Задача не описывала владение этими тремя файлами (`ac-001`, `ac-002` suite'а
`cross-catalog-retraction`, `lib/baseline-commit.sh`) — они принадлежат QA-author; фикс
shellcheck-замечаний там (если понадобится) — не входит в периметр Dev этой задачи. Зафиксировано
здесь, чтобы следующий читатель `--full`-лога не решил, что эта Dev-поставка внесла регресс.

**Уточнение PM (добавлено после прогона QA-runner).** Абзац выше верен на момент, когда Dev его
писал, но к содержимому коммита `bba5d80` уже не относится: PM свёл в этот коммит и правку Dev, и
параллельно выполненный QA-author фикс тех самых трёх файлов (три точечных
`shellcheck disable=SC2016/SC2034` с построчным обоснованием). Поэтому `bash scripts/check.sh
--full` на `bba5d80` даёт `exit=0`, а не `exit=1` — проверяемо прогоном shellcheck на версиях
`4a6f8d0` (`exit=1`) против текущих (`exit=0`). Расхождение внесено батчингом коммита на стороне
PM, не ошибкой Dev; исходный абзац сохранён как запись того, что было верно на своём шаге.

## Ручная проверка AC-002(в) (cross-catalog-retraction), выполненная Dev

Чек-лист `tests/gramax/cross-catalog-retraction/README.md` → «Ручная проверка (AC-002в)» пройден
после финальной правки `SKILL.md`:
1. Блок «## Ссылки» прочитан целиком.
2. Единственный пример вида `[X](Y)` в блоке, относящийся к кросс-каталожным ссылкам, —
   ❌-иллюстрация `` `[Документ](other-catalog/path/to/file.md)` `` в обратных кавычках,
   помеченная явным ❌; остальные `[X](Y)`-примеры блока (буллеты «Внутренние», «На раздел») —
   про ссылки внутри одного каталога, не про кросс-каталожный случай, вне предмета AC-002(в).
3. Прозы вида «используйте `[Название](путь)` для кросс-каталожных документов» вне контекста
   ❌-иллюстрации в блоке нет.

Это не заменяет финальный QA/BA sign-off (семантическая проверка по контракту явно не
grep-детектируема целиком) — фиксируется как первичная self-check Dev перед сдачей.
