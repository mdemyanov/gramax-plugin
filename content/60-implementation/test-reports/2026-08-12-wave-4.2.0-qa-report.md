## Функциональная проверка мигратора (`migrate_mermaid.py`)

Проверка выполнена вручную во временном scratch-каталоге вне репозитория
(`migrator-func-test/`, вне `content/`), не через сам suite `mermaid-adoption` (тот прогнан
отдельно, см. таблицу выше) — независимая ручная сборка сценария поверх фикстур qa-author.

**Собранный каталог:**
```
migrator-func-test/
├── catalog/                       ← .doc-root.yaml здесь → юрисдикция
│   ├── .doc-root.yaml
│   ├── legacy-fenced.md           ← ```mermaid fenced-блок
│   ├── legacy-paired.md           ← <mermaid>...</mermaid> парный тег без path=
│   └── already-correct.md         ← уже корректный <mermaid path="..." width="800px" height="450px"/>
└── outside/                       ← нет .doc-root.yaml до корня прогона → вне юрисдикции
    └── no-jurisdiction.md         ← ```mermaid fenced-блок (та же легаси-форма, что и в catalog/)
```

### Шаг 1 — режим отчёта (без `--fix`)

```
$ uv run plugins/gramax/scripts/migrate_mermaid.py migrator-func-test
catalog/legacy-fenced.md:10
catalog/legacy-paired.md:10
To-migrate: 2
Out-of-jurisdiction: 1
Already-compliant: 1
exit=1
```

Sha256-снимок всего дерева до и после прогона — побайтово идентичен (0 расхождений в `diff`):
режим отчёта подтверждённо **ничего не изменил**. Метка первого счётчика — `To-migrate` (не
`Migrated`), как и предписывает контракт FR-064 для report-режима.

### Шаг 2 — независимый оракул DSL (до миграции)

DSL двух легаси-блоков извлечён `awk`-скриптом, не тем способом, которым это делает сам
`migrate_mermaid.py` (тот использует Python `re.DOTALL`-регексы `PAIRED_RE`/`FENCED_RE`, `awk`
работает построчно по маркерам `` ```mermaid ``/`` ``` `` и `<mermaid>`/`</mermaid>`):

```
oracle-fenced.mermaid:              oracle-paired.mermaid:
graph TD                            sequenceDiagram
  A[Start] --> B{Decision}            participant Alice
  B -->|Yes| C[End]                   participant Bob
  B -->|No| A                         Alice->>Bob: Hello Bob
                                       Bob-->>Alice: Hi Alice
```

### Шаг 3 — `--fix --yes`

```
$ uv run plugins/gramax/scripts/migrate_mermaid.py migrator-func-test --fix --yes
catalog/legacy-fenced.md:10
catalog/legacy-paired.md:10
Migrated: 2
Out-of-jurisdiction: 1
Already-compliant: 1
exit=0
```

Результат:
- `catalog/legacy-fenced-existing.mermaid` создан, `diff` с `oracle-fenced.mermaid` — пусто
  (побайтовое совпадение).
- `catalog/legacy-paired-existing.mermaid` создан, `diff` с `oracle-paired.mermaid` — пусто
  (побайтовое совпадение).
- Оба `.md`-файла теперь несут самозакрывающийся тег `mermaid` с атрибутами `path`, `width="800px"` и `height="450px"` на месте легаси-блока — конвенция именования (ADR-0010 Решение 2/3) и
  дефолты размера (ADR-0010 Решение 5) соблюдены. Точное значение `path` — относительный путь к
  свежесозданному `.mermaid`-файлу рядом со статьёй (см. фактические имена файлов выше).
- `catalog/already-correct.md` — sha256 не изменился, уже корректный тег не тронут (BR-003
  ADR-0013).
- `outside/no-jurisdiction.md` — sha256 не изменился, файл вне юрисдикции не мигрирован, несмотря
  на то что содержит ту же легаси-форму, что и `catalog/legacy-fenced.md`.
