## Неочевидное — эвристика directionality (FR-077 тест 1)

BA-формулировка называет маркеры («см.», «зафиксировано в», «обоснование в», «дополняет»,
«supersedes», «применяет») буквально, но реальный корпус использует их в ФОРМАХ, не покрытых
буквальным списком:

- **Голая шапка без двоеточия/жирного:** `Spec \`content/…\`` (не `**Spec:**`) — частый паттерн
  в ранних ADR (0001–0013), секция «## Context». Добавлена альтернатива `\b(?:ADR|Spec|
  Требование|…)\s*\(?\s*$` (bare-word в конце окна, опционально перед открывающей скобкой).
- **Структурный маркер пункта списка:** `- spec: \`path\`` / `N. **Label** — \`path\`` в разделе
  «## Связанные артефакты» — оказался ГОРАЗДО чаще buквального списка маркеров (37 вхождений
  `^- label: \`content/` только в реальном корпусе). Реализовано отдельным правилом
  (`_has_bullet_label_marker`/`_BULLET_LABEL_PREFIX_RE`), не перечислением слов-меток —
  надёжнее калибровки по каждому конкретному слову.
- **Comma-separated перечисление целей ОДНОГО пункта** (`- метка: \`a\`, \`b\`, \`c\``) —
  маркер у метки применяется ко ВСЕМ элементам перечисления, не только первому (окно
  вычисляется от начала ТЕКУЩЕГО пункта списка, не от предыдущего кандидата).

Калибровка велась итеративно против собственной таблицы RES-005
(`2026-08-13-link-form-corpus-audit.md`, 136 строк) — не для точного совпадения (задача прямо
разрешает расхождение с буквальным `103`), а чтобы отловить явные ложные срабатывания
(конвертация код-спана на путь из ДРУГОГО репозитория) и явные ложные пропуски (структурно
идентичные случаи, отличающиеся только словом-меткой). Финал: 145 NAV, 16 SELF, 290 SUBJECT.
Часть расхождений с RES-005 (~30 строк) — консервативный недомигрированный остаток
(inline-перечисления без «- »-маркера, вида «применялось четыре раза: A, B, C и D» — только
первый элемент распознан) и единичные семантически спорные случаи (RES-005 сама признаёт один
случай «СПОРНО»); ни один не приводит к ЛОЖНОЙ ссылке — только к оставленному код-спану,
безопасное направление ошибки.

## Неочевидное — граница scope и гомоним чужого репозитория (FR-077 тест 3, AC-004)

Наивный тест «путь физически существует внутри `.doc-root.yaml`-каталога» ложно-положителен на
гомониме — `content/_index.md`, упомянутый как файл ДРУГОГО репозитория с такой же структурой
каталогов (RES-005 3.4, реальный случай — вендорский корпус `gramax-user-docs`). Дополнительный
лексический маркер (`_CROSS_REPO_RE` — «не в этом», «другом/чужом репозитории»;
`_CROSS_REPO_NAMED_RE` — «репозиторий \`name\`») снимает ложный NAV. Область поиска маркера —
ТЕКУЩИЙ пункт списка (`_current_bullet_bounds`), не весь blank-line-абзац: первая версия искала
по всему абзацу и глушила NAV-кандидатов в СОСЕДНИХ, содержательно не связанных пунктах
numbered-list, где упоминание чужого репозитория относилось только к ОДНОМУ из нескольких
пунктов общего абзаца.

## Неочевидное — идемпотентность после мутации

После первого `--fix --yes` повторный report-mode прогон на уже смигрированном `content/`
находил 10 ложных NAV-кандидатов: код-спан, СЛЕДУЮЩИЙ за только что смигрированным в том же
предложении/перечислении, терял границу окна поиска маркера, потому что предыдущий код-спан
браузался `_INLINE_CODE_RE`, а его markdown-ссылка-замена — уже нет; маркер из-за только что
созданной ссылки «протекал» на следующий элемент. Фикс — markdown-ссылки учитываются как ТАКАЯ
ЖЕ граница окна, что и код-спаны-кандидаты (`_closest_link_end_before`). После фикса повторный
прогон на смигрированном корпусе стабильно даёт `To-migrate: 0`.

## Edge case'ы, покрытые тестами

- SELF-приоритет над NAV-звучащим маркером вокруг (AC-002).
- Классификация по СОБСТВЕННОЙ цели код-спана, не по предмету абзаца — прецедент #83 (AC-003).
- Scope-граница: гомоним пути из другого репозитория, несмотря на NAV-маркер и существующую
  цель (AC-004).
- Кросс-каталожный код-спан (путь вне текущего `.doc-root.yaml`) — не кандидат вовсе, регексп
  требования префикса `<root.name>/` естественно его исключает (AC-007).
- Детерминизм: два независимых прогона report-mode на одной и той же фикстуре дают идентичный
  вывод (AC-001).

## Не покрыто / известные ограничения

- Inline-перечисление без структурного «- »-маркера (`применялось четыре раза: A, B, C и D` —
  прямо в тексте абзаца, не список) — распознаётся только первый элемент. Безопасное
  направление (недомиграция, не ложная ссылка); кандидат для follow-up, если понадобится.
- Текст ссылки `[title]` — механический дефолт из `title` frontmatter цели без ручной правки
  (кроме двух случаев `content/_index.md` → «Gramax Marketplace», которые звучат чуть
  неестественно инлайн, но резолвятся корректно — ADR-0016 Решение 5 разрешает точечную
  коррекцию «экономно»; не правил вручную ни одного случая — все дефолты приемлемы).
