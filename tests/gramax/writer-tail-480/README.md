## Ловушки и границы (для Dev и ревьюера)

1. **AC-098 — ловушка регистра.** Формула AC грепает строчное `чего нет`
   (case-sensitive), а заголовок дизайна — «Чего нет в синтаксисе» с заглавной
   (начало предложения): один только заголовок формулу НЕ удовлетворяет. Stub
   держит букву формулы; Dev обязан дать хотя бы одно строчное «чего нет»
   mid-sentence — естественное место: вводная строка раздела («перечень того,
   чего нет в синтаксисе, — ровно четыре формы»). Прецедент ловушки —
   ac-087 волны writer-sync-470 (backtick).
2. **AC-100 (`expanded`) — цель только SKILL.md.** В `references/blocks.md`
   `expanded` — атрибут `<cut>` и остаётся (факт 9): ассерты ac-100 привязаны
   к файлу SKILL.md и blocks.md не трогают. Дизамбигуация «expanded
   `_index.md` ≠ атрибут `<cut expanded>`» — ревью-пункт (грепом не дёшево,
   edge case дизайна).
3. **AC-099 (`data:`) — подстрока.** Dev обязан употребить data:-форму минимум
   однажды; `data-theme` не сматчится на `data:` (нет двоеточия). Ревью-пункт:
   `data-theme` должен стоять именно в селекторе тёмной темы
   `html[data-theme="dark"]`, не в прозе о данных.
4. **Ревью-пункты вне дешёвого грепа** (по контракту дизайна): поля
   `description`/`hidden` FR-186 (слова слишком общие — уже в тексте навыка);
   двусторонняя дизамбигуация HTML-комментариев с ревью-комментариями
   `<comment id>`/`[comment:]` FR-183 (два предложения: в новом разделе и
   встречная строка в «Комментариях»); пометки источников
   «(docs-пометка, RES-007 §3/§4)» на каждом новом утверждении (NFR-075).
5. **ac-098 — маркер близости одной строкой.** Regex
   `(ждёт|очеред).*разв[её]ртк|разв[её]ртк.*(ждёт|очеред)` (без учёта
   регистра, толерантен к ё/е) требует маркер «ждёт/очередь» в ОДНОЙ строке
   markdown с «развёртками таблиц» — дешёвый греп не видит через перенос
   строки. Проза об отложенных развёртках — БЕЗ литеральных ключей
   (`aggregation` и под. запрещены байтовым негативом ac-102): дизайн называет
   их только «развёртки таблиц».
6. **ac-102 — граница набора ключей.** Негативы — только однозначные литералы
   развёрток: `aggregation`, `colspan`, `rowspan`, `countDistinct`,
   `header="column"`, `header="both"`, `header="none"`. НЕ включены: `sort`,
   `align` (риск столкновения с будущим легитимным контентом, напр.
   text-align в примерах HTML-компонента FR-185), `width`/`{width`
   (легитимны: аннотации размеров картинок SKILL.md:266 и под.), `row`/`column`
   (легитимна `header="row"` — единственная документированная форма,
   SKILL.md:357 и под.). Формула AC (`aggregation`, `colspan`) — подмножество.
   Вступление ключей после вердикта П2 — правка warden'а тем же изменением,
   что и вердикт (BR-020).
7. **ac-097 — свертка двухсторонняя.** Заголовок «Спецсимволы» обязан
   исчезнуть (`^#+ Спецсимволы` — негатив), а форма `5\.1` — пережить переезд
   дословно (позитив-регрессия, зелёная с рождения): удаление раздела без
   переноса форм — тоже красный.
8. **Позитивный grep негативного употребления** (прецедент AC-082 cover):
   `===` в ac-098 и `<!--` в ac-097 не различают «документируем отсутствие» и
   «используем»; примеры отсутствующих форм — только в ограждённых
   код-блоках, смысловой контроль — ревьюер.

```bash
rc=0; for f in tests/gramax/writer-tail-480/ac-*.sh; do bash "$f" || rc=1; done; echo "suite exit=$rc"
```

Автономен из любого рабочего каталога (`git rev-parse --show-toplevel`,
`$(dirname "${BASH_SOURCE[0]}")`); каждый скрипт запускается и отдельно:
`bash tests/gramax/writer-tail-480/ac-0NN-*.sh`. Каждый скрипт самодостаточен
(без `lib/`); запускать явно через `bash` (shebang `#!/usr/bin/env bash`;
bash 3.2-совместим). Зависимостей, кроме bash/grep/git, нет; цикл корректен и
в zsh (glob раскрывается шеллом, `"$f"` — в кавычках).
