# tests/gramax/render-quality/ — прибор рендер-проб Playwright: фикстуры, офлайн-стабы, швы прибора

Suite тест-дизайна (QA-author, **до** реализации Dev) для требования
`docs/30-requirements/2026-11-21-playwright-render-quality-requirement.md`
(AC-104…AC-119). Контракт стабов задан дизайном
`docs/40-architecture/2026-11-21-playwright-render-quality-design.md` (раздел
«Контракт с QA-author (красные стабы)»); фактическая база фикстур —
`docs/10-domain/research/2026-11-21-upstream-render-calibration-facts.md` (RES-009).
Нарезка: один файл `ac-NNN-*.sh` = один AC требования, 1:1; запись at-design —
`docs/60-implementation/acceptance/2026-11-21-playwright-render-quality-at-design.md`.

**Suite не подключён ни к одному гейту** — не к `scripts/check.sh` (`--fast`/`--full`),
не к `scripts/check-gramax.sh`. Регистрация шагом 18 в `--full`-блоке
`scripts/check-gramax.sh` — задача Dev тем же коммитом позеленения (FR-194, AC-113);
до этого сюита существует как красные стабы и гейтом не исполняется. `--fast` прибора
не касается никогда (NFR-078, варден `ac-118`).

## Инструмент, который закрывает Dev

Цель стабов — каркас `scripts/render-quality/` по Решению 5 дизайна (Dev создаёт, QA-author
НЕ создаёт): `probe.sh` (bash-вход, обёртка uv по прецеденту ADR-159), `warm.sh` (прогрев),
`probe.py`, `config.py`, `tier0_http.py`, `tier1_dom.py`, `tier2_shots.py`, `report.py`,
`render-target.example.json`. Швы, через которые стабы вызывают прибор (зафиксированы
дизайном, «Контракт с QA-author»):

- `--config <путь>` — конфиг цели (вместо дефолтного `render-target.local.json`);
- `--fixtures <каталог>` — мини-набор фикстур стаба (вместо `fixtures/` сюиты);
- `--report <путь>` — путь отчёта; каталог отчёта = каталог результатов
  (`screenshots/<slug>.png` рядом с отчётом — дом-раскладка `results/`);
- `--check-env` — только проверки окружения (цель → импорт playwright → браузер), без тиров;
- rc-семантика: `0` — расхождений нет; `1` — есть расхождения (отчёт написан);
  `2` — именованный отказ окружения, баннер `REFUSAL <КОД>: <подсказка>`.

## Карта «файл ↔ строка ERROR-таблицы» (AC-104)

Дефект-фикстуры — по 8 строкам ERROR-таблицы RES-009 §2 (дизайн, Решение 5); каждая несёт
**ровно одну** дефектную конструкцию — иначе вердикт тира не локализуется до причины (FR-187).

| Файл (`fixtures/<имя>.md`) | `tableRow` | Конструкция | Ожидание `tier0` |
|---|---|---|---|
| `th-in-table.md` | `ERROR-1` | `<th>` в таблицах | `kill` |
| `note-inline.md` | `ERROR-2` | инлайновый `<note>…</note>` в одну строку | `kill` |
| `invalid-utf8.md` | `ERROR-3` | невалидный UTF-8 (байтовая фикстура) | `either` |
| `multiple-images.md` | `ERROR-4` | несколько `![](…)` в одной строке | `kill` |
| `unbalanced-pair-tags.md` | `ERROR-5` | несбалансированные парные теги (`<tabs>`/`<tab>` без закрытия) | `kill` |
| `colgroup-multiline.md` | `ERROR-6` | многострочный `<colgroup>` (каждый `<col/>` на своей строке) | `kill` |
| `xml-in-html-comment.md` | `ERROR-7` | XML-тег внутри HTML-комментария | `kill` |
| `tag-fragment-tail.md` | `ERROR-8` | обрывок тега с хвостом вида `splay="List"/>` | `kill` |
| `note-in-cell.md` | `WARN-note-in-cell` | `<note>` внутри `<td>` (спорная severity — локально ERROR, апстрим-замер: HTTP 200) | `ok` |
| `note-in-note.md` | `WARN-note-in-note` | `<note>` внутри `<note>` (спорная severity) | `ok` |
| `control-table.md` | `control` | легальная таблица `<td>` + `header="row"` | `ok` |
| `control-colgroup-single-line.md` | `control` | легальный однострочный `<colgroup>` | `ok` |
| `control-note-block.md` | `control` | блочная заметка с пустыми строками вокруг | `ok` |
| `control-images.md` | `control` | изображения по одному на строку | `ok` |
| `control-balanced-tags.md` | `control` | сбалансированные `<tabs>`/`<tab>` | `ok` |
| `control-html-comment-text.md` | `control` | HTML-комментарий с plain-текстом без тегов | `ok` |
| `control-utf8.md` | `control` | валидный UTF-8 (кириллица) | `ok` |

Каждому `.md` отвечает пара `<имя>.expect.json` (дизайн, Решение 5):

```json
{
  "tableRow": "ERROR-1",
  "expect": { "tier0": "kill", "tier1": "any", "asserts": [] }
}
```

Примитив tier-1-ассерта один: `{"name", "selector", "count"}` (присутствие = `count: 1`).

## Антифабрикация: селекторы tier-1 — гипотезы до живого замера (R2 дизайна)

Офлайн-стабы проверяют **механизм** ассертов на HTML стаб-портала; живой словарь DOM-фактов
GES (какой селектор у отрисованного admonition, таблицы, вкладок) не установлен ни одним
источником. Значения `selector` в `expect.json` контрольных и спорных фикстур — посылки,
подтверждаемые при первом живом прогоне на цели; подтверждение фиксируется записью замера
(Решение 8). Пока замера нет, живой прогон вправе валить эти ассерты — это не дефект
прибора, а расхождение гипотезы с фактом, разбираемое по протоколу FR-196, а не молчаливая
правка селектора.

## `invalid-utf8.md` — байтовая фикстура

Файл намеренно не декодируется как UTF-8 (хвост, обрезанный посреди двухбайтового символа,
— семантика апстрима v1.2.0+, RES-009 §3.4). Две особенности:

- из прогона валидатора `validate_render.py` по протоколу FR-196 фикстура **исключается**:
  локальный порт падает на таком файле необработанным исключением и прекращает обход
  (факт 4 RES-009), а защита чтения без детектора в эпик не входит (FR-198, D7);
- при коммите возможен шум `git diff --check` (whitespace-гейт на staged-файлах) —
  контингенция дизайна (R1): строка `.gitattributes`
  `tests/gramax/render-quality/fixtures/invalid-utf8.md -text`; если и это спорно — Dev
  поднимает вопрос PM до коммита.

## Прогрев и порядок работы

1. **Офлайн-стабы** (`ac-*.sh`) детерминированы и требуют только python3 (стаб-портал) и,
   после посадки каркаса, uv-кэша playwright: живых обращений к сети нет — стаб-портал
   слушает только `127.0.0.1` (lib/stub_portal.py), конфиг стаба — временный файл через
   шов `--config`.
2. **Живой прогон** — `bash scripts/render-quality/probe.sh` с дефолтными путями; требует
   прогрева: `bash scripts/render-quality/warm.sh` (uv `--with playwright`, затем
   `playwright install chromium`). На непрогретой машине — именованный отказ
   (`REFUSAL PLAYWRIGHT_NO_BROWSER` и родня) — D8-поведение, не дефект сюиты.
3. **Пуш фикстур на цель** — стандартная git-рутина руками сопровождающего (D4:
   sync/push-навыки не строятся): выделенный каталог на цели (`catalog` конфига, например
   `render-probes`), слаг страницы = имя файла фикстуры без `.md`. Дрейф «фикстура в репо,
   страницы на цели нет» виден как `NOT_FOUND` с нотой (Решение 6).
4. Окно переиндексации gram.ax **не установлено** — число-константа не кодируется
   (NFR-080); устойчивый 5xx сразу после пуша — именованный кандидат с нотой, гейт вправе
   честно краснеть, перезапуск после переиндексации — операционная норма (R3 дизайна).
