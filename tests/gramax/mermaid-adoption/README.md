## Находка: буквальный AC уже удовлетворён по несвязанной причине (AC-001, AC-009)

Перед коммитом каждого stub'а буквальный grep из текста AC был прогнан на текущем состоянии
репозитория — не только чтобы убедиться «тест может стать зелёным при корректной работе»
(урок `content/lessons-learned.md`, запись 2026-08-11), но и чтобы исключить обратную
ситуацию: тест уже зелёный СЕЙЧАС по причине, не имеющей отношения к содержанию AC.

- **AC-001:** `grep -rliE '\.doc-root\.yaml' plugins/gramax/skills/mermaid/
  plugins/gramax/README.md` уже проходит — `SKILL.md` упоминает `.doc-root.yaml` в секциях
  «Синтаксис каталога» и «Backward compatibility» для определения XML/Markdown-синтаксиса,
  не для границы юрисдикции file-based mermaid. Голый буквальный grep был бы pre-passing по
  неправильной причине.
- **AC-009:** аналогично, голая проверка «`blocks.md` упоминается где-то в
  `skills/mermaid/`» уже ложно проходит (`SKILL.md:97` цитирует `blocks.md` как источник
  дефолтов `width`/`height`, причина не связана с конфликтом валидатора).

**Исправление:** оба скрипта сохраняют буквальный BA-grep как assert 1 (трассируемость), но
добавляют семантическое усиление (assert 2) — ключевое слово «юрисдикц» для AC-001,
co-occurrence «валидатор»+«blocks.md» **в одном файле** для AC-009. Оба усиления сегодня
красные (проверено вручную — см. `2026-08-11-mermaid-adoption-at-design.md`, раздел
«Находка»), поэтому итоговый цвет обоих тестов — красный, несмотря на то, что assert 1
проходит уже сейчас.

## Вакуумная истина: негативные ассерты нуждаются в позитивной гарантии (AC-003, AC-006, AC-007)

AC-003, AC-006, AC-007 формулируются как отсутствие эффекта («файл не появляется в отчёте»,
«фикстура не меняется», «второй прогон ничего не меняет»). Пока `migrate_mermaid.py` не
существует, инструмент не запускается вообще — отсутствие эффекта тривиально истинно без
всякой заслуги реализации. Все три скрипта сначала требуют позитивное подтверждение, что
инструмент реально что-то сделал (нашёл оба легаси-вхождения / реально смигрировал), и только
затем проверяют негативное условие. Подробности и код — `ac-003`/`ac-006`/`ac-007`, разделы
заголовков; обоснование — `2026-08-11-mermaid-adoption-at-design.md`.

## Композитная фикстура

`fixtures/composite/`:

```
fixtures/composite/
  content/
    .doc-root.yaml
    legacy-fenced.md            — ```mermaid fenced-блок (легаси-паттерн 1)
    legacy-paired.md            — <mermaid>…</mermaid> paired-тег (легаси-паттерн 2)
    already-migrated.md         — уже корректный <mermaid path="…"/> (не трогать, BR-003)
    already-migrated-diagram.mermaid
  outside/
    no-doc-root.md              — вне юрисдикции: нет .doc-root.yaml-предка (FR-050/FR-055)
```

Состав фикстуры (2 легаси + 1 вне юрисдикции + 1 уже корректный) буквально совпадает с
примером AC-010 из текста требования («2 подлежащих миграции + 1 вне юрисдикции + 1 уже
соответствующий формату») — один и тот же фикстурный каталог используется для AC-002,
AC-003, AC-005…AC-008 и AC-010, без дублирования.

**Изоляция:** ac-скрипты, которые мутируют состояние (`--fix --yes`) или иным образом рискуют
записать в отсканированное дерево, работают ИСКЛЮЧИТЕЛЬНО на копии в `mktemp`
(`lib/fixtures.sh::copy_composite_fixture`), никогда напрямую на git-tracked
`fixtures/composite/`. Проверено: `git status --porcelain` после полного прогона `run.sh` не
показывает изменений внутри `fixtures/composite/` — suite не оставляет мусора в рабочем
дереве.

## Фикстура масштаба (AC-004) — генерируется, не коммитится

AC-004 требует фикстуру «смоделированную по образцу 156 корректных тегов» (NFR-051, образец —
`naumen-smp-mcp`). Committing 156 пар `.md`+`.mermaid` (312 почти идентичных файлов) раздуло
бы репозиторий без содержательного выигрыша. Вместо статичных файлов —
`lib/fixtures.sh::generate_at_scale_fixture()`: строит фикстуру на лету в `mktemp` при каждом
прогоне `ac-004`, удаляет после (`trap … EXIT`). Генератор сам по себе — committed,
ревьюируемый, детерминированный артефакт; число файлов параметризовано (`count=156` по
умолчанию).

## Интерпретация для Dev (контракты, не зафиксированные ADR буквально)

ADR-0013 оставляет открытыми точные форматы вывода `migrate_mermaid.py`. QA-author фиксирует
минимальный рабочий контракт для стабов — предложение, не требование ADR:

1. **Формат находки (FR-056):** `<путь>:<номер строки>` — grep/rg-подобный, где-то в stdout.
   Используется в `ac-002`, `ac-003`, `ac-004`, `ac-006`.
2. **Формат сводки (FR-064, `ac-010`) — метка первого счётчика зависит от режима:**
   ```
   (режим отчёта, без --fix) To-migrate: <N>
   (--fix --yes)             Migrated: <N>
   Out-of-jurisdiction: <M>
   Already-compliant: <K>
   ```
   **Правлено PM-приёмкой после первой реализации DEV-003** (не найдено QA-author'ом на
   этапе тест-дизайна): исходная версия `ac-010` ассертила буквальный `Migrated: <N>` даже
   в режиме отчёта, где ни один файл не изменён. Первый вызов инструмента потребителем —
   всегда report-режимный (это дизайн: report before fix, FR-058/NFR-053) — читал бы
   «мигрировано N» и делал бы ложный вывод, что файлы уже изменены. `ac-010` теперь
   проверяет оба режима на одной композитной фикстуре: report-режим печатает
   `To-migrate: 2` и не мутирует ничего, `--fix --yes` на свежей копии той же фикстуры —
   `Migrated: 2` и реально мигрирует. Два других счётчика не изменились — верны и
   одинаково подписаны в обоих режимах.
3. **Exit-код чистого скана (`ac-004`):** `0` при отсутствии находок — по прецеденту
   `validate_structure.py`. Exit-код при НАЛИЧИИ находок нигде в этом suite'е численно не
   проверяется (ADR не фиксирует конкретное значение), но сам факт — «report-режим
   завершается ненулевым кодом, если есть находки» — задокументирован потребителю явно в
   `--help` инструмента и в `README.md` плагина (PM-приёмка, п. 4): поведение полезно для
   CI, но должно быть известно заранее, не по факту красной сборки.

Если реализация Dev расходится с любым из трёх пунктов — поправьте регулярку/фикстуру вместе
с обоснованием прямо в соответствующем `ac-*.sh`, не убирайте ассерт молча (прецедент —
«Интерпретация AC-014» в `content/60-implementation/acceptance/
2026-08-11-validation-contract-at-design.md`).

## AC-005 — DSL-оракул независим от парсера Dev

`ac-005-migration-preserves-dsl-and-defaults.sh` не хардкодит ожидаемый DSL как строковый
литерал (риск дрейфа между фикстурой и тестом при будущем редактировании одного без другого).
Вместо этого — извлечение блока из ПРИСТИНОЙ mktemp-копии фикстуры собственным `sed`/`awk`
QA-author'а, ДО вызова `migrate_mermaid.py`:

```bash
awk '/^```mermaid$/{flag=1;next}/^```$/{if(flag){flag=0};next}flag{print}' legacy-fenced.md
sed -n '/<mermaid>/,/<\/mermaid>/p' legacy-paired.md | sed '1d;$d'
```

Оракул независим от того, как Dev реализует парсинг легаси-блока — сравнение через `diff`
после миграции проверяет именно наблюдаемый результат (AC-005 «побайтово совпадает»), не
внутренний алгоритм извлечения.

## Запуск

```bash
bash tests/gramax/mermaid-adoption/run.sh; echo "exit=$?"
```

Автономен из любого рабочего каталога (использует `git rev-parse --show-toplevel` и
`$(dirname "${BASH_SOURCE[0]}")` — не полагается на текущий `cwd` вызывающего). Подключён к
`scripts/check.sh --full` (DEV-003, после того как все 10 AC позеленели) — `--fast` его не
запускает, суточный pre-commit gate им не удлиняется.

Первый прогон: `exit=1`, 10 из 10 тестов красные — ожидаемое стартовое состояние TDD-цикла,
не поломка suite'а.
