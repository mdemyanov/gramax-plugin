# AT-design: Инверсия раскладки документации — `content/` → `docs/`

## Исходный запрос

[Инверсия раскладки документации — `content/` → `docs/` с зачисткой исторических
артефактов](../../content/30-requirements/2026-11-17-docs-layout-inversion.md)
(JTBD «…хочу одного корня документации `docs/`…», FR-124…FR-130, AC-001…AC-012,
NFR-001…005). Механика исполнения —
[ADR-0021](../../content/00-project/adr/0021-docs-layout-inversion.md), цепочка
коммитов A → B → C → D1 → D2 → D3. Оба указателя разрешаются (проверено на 8b2db0b).

## Проверки задачи

Решение по АТ: надо — уровень integration (проверки состояния дерева и гейтов репозитория:
наличие/отсутствие файлов, git-история, содержимое конфигов, запуск `check.sh --fast` —
e2e-гейт для AC-012). Список проверок задачи не подан — каждый AC требования сам именует
свою проверку; они приняты как есть, кроме четырёх отклонений (см. «Допущения верхних ролей»).

## Boundary cases

- AC-002: ровно 2 — если переименование не распознано, `--follow` даёт 0; если распознан
  только сам переезд без предыстории — 1; граница проходит по «предыстория видна».
- AC-007: «ровно одна строка» — ноль корней и два корня оба красные; форма maxdepth 2
  отделяет настоящие корни (глубина 2) от 37 фикстурных `.doc-root.yaml` (глубина ≥ 5).
- AC-008: неполнота списка — отсутствие даже одного из 19 удалений красное; лишнее
  удаление ловит AC-010 (D вне одобренных).
- AC-010: граница статусов — `A` запрещён всегда; `D` сверяется построчно с закрытым
  списком 21 пути; `M` разрешён только на стороне `docs/` (см. отклонение); прочие
  статусы (C/T/…) — находка.

## Error cases

- malformed/mistyped input: N/A — требование оперирует состоянием репозитория, у него
  нет пользовательского ввода; класс не применим ни к одному сценарию.
- masked failure (именовано явно, по классам):
  - AC-010: пустой дифф при зелёных ассертах — pre-guard «миграция не исполнена» + guard
    «дифф пуст — переезд не отразился»; плюс guard `git cat-file` на существование BASE.
  - AC-004/AC-005/AC-006: исчезнувшая область скана делает grep пустым и проверку
    «зелёной по пустоте» — guard'ы на существование `docs/ plugins/ tests/ scripts/`,
    `.nauta-gates.yaml`, `AGENTS.md`.
  - AC-003: слишком широкие исключения маскируют забытые указатели — поэтому исключения
    строчные (антипаттерн/канон/голый токен), а не файловые, где возможно; в
    AGENTS.md/CLAUDE.md вне управляемых блоков запрещено ЛЮБОЕ упоминание (включая
    «голый» токен — FR-127 переписывает их в D3); самопомеха снята точечно
    (`tests/gramax/docs-migration/`), а не исключением `tests/` целиком.
  - AC-004: RECORD-исключение ограничено пятью выжившими отчётами живой эпохи по
    построчной маске; `_index.md` разделов не исключён (навигация обязана быть очищена).

## Красное состояние на 8b2db0b (замерено, не предполагается)

База замера: `git rev-parse HEAD` = `8b2db0bdb41643551163d7dcbdbe5c5c5c171c53`,
дерево чистое. Итог `bash run.sh`: `Passed: 1` (ac-012, warden), `Failed: 11`, rc 1.

## Rehearsal — физическое доказательство достижимости зелёного

Симуляция цепочки A→B→C→D1→D2→D3 на снимке `git archive HEAD` в scratch-каталоге
(рабочее дерево не тронуто) с обязательными по AC смягчениями (title==H1 по C22,
снятие указателей на удалённое — FR-125) дала: ac-001…004, 006…011 — PASS;
ac-005, ac-012 — FAIL по единственной причине: валидатор после переезда предъявляет
к объединённому каталогу требования, которые раньше предъявлял только в других профилях
(≈13 ошибок «тип "Требование" без `**Capability:**`» на статях 30-requirements,
регистрации в индексах). Это не дефект stub'ов — это ровно то, что AC-005 (валидатор
rc 0) и AC-012 (--fast зелёный) требуют от Dev: цепочка обязана довести объединённый
каталог до зелёного валидатора. Симуляция этих продуктовых решений (openspec-пары для
наследных требований) — работа Dev, не QA-author.

Попутно rehearsal поймал и исправил два дефекта моих же stub'ов до сдачи (mutation
honesty): awk-стриппер managed-блоков в ac-003 не включался — маркер begin содержит в
своём тексте литерал `nauta:managed:end` (правило «begin поглощает строку»); ac-010
разрешал M только трём файлам коммита A, тогда как честное переписывание указателей
FR-125 в переезжающих статьях законно правит и другие docs/-файлы (правило сужено до
стороны diff'а: M на content/ запрещён, M на docs/ разрешён).

## Оценка риска

Ключевой риск задачи — не «забыть переименовать», а тихая расползание: указатель на
удаляемое «переписан на новый путь», которого не существует (запрещено FR-125), RECORD
переписан задним числом (NFR-003), гейт временно отключён ради зелёного коммита
(NFR-004). Пакет закрывает каждый класс отдельным stub'ом: AC-004 запрещает литерал
удаляемых имён, AC-011 пинит RECORD-якорь дословно, AC-012 держит быстрый гейт на
каждом коммите. Остаточный риск после ретирмента doc-paths (ADR-0021 Решение 4) —
«забытый POINTER» — ловится однократно AC-003/AC-004; глубина ручного теста при приёмке
может быть минимальной, если оба зелёные и AC-010 показывает дифф без посторонних строк.

## Допущения

- Номер и послемиграционный путь ADR инверсии (`docs/00-project/adr/0021-docs-layout-inversion.md`)
  взяты из самого ADR-0021 (разделы «Решение 4» и «Связанные артефакты»); AC-009 не
  называет путь, assumption закреплён в шапке ac-009.
- BASE для AC-010 = HEAD на момент старта работ (8b2db0b), уже содержащий требование и
  ADR-0021 — прямо сказано в ADR-0021 (Решение 7, последний абзац).
- Канон-путь спек плагина nauta механически опознаётся формой
  `content/40-architecture/ADR-<N>…` (ADR-0021 Решение 3 приводит этот пример).
- «Голый» токен-конвенция (упоминание `content/` без продолжения-пути) в файлах вне
  AGENTS.md/CLAUDE.md отнесён к кл. 6 ECOSYSTEM и не требует переписывания; исключение —
  ручные зоны AGENTS/CLAUDE, где FR-127 требует переписать все упоминания.
- Симуляция цепочки в rehearsal — механическая аппроксимация решений Dev (например,
  reformulation provenance-шапок как замена литерала); она доказывает достижимость
  зелёного ассертами, а не является эталоном правок.

## Допущения верхних ролей (остановы веток и находки — обе стороны дословно)

1. **AC-007 vs реальность фикстур (останов ветки, обе стороны зафиксированы).**
   AC-007: «`find . -name ".doc-root.yaml" -not -path "./.git/*"` → ровно одна строка,
   `docs/.doc-root.yaml`». Измерение на 8b2db0b: `git ls-files | grep -c '\.doc-root\.yaml$'`
   → 39 отслеживаемых файлов; 37 — фикстуры suite'ов и payload плагина (кл. 6 ECOSYSTEM
   Решения 3 ADR-0021 — модели чужих каталогов потребителей; они не мигрируют и остаются).
   Буквальная проверка неисполнима после миграции. Рабочая форма в stub'е: `-maxdepth 2`
   (настоящие корни лежат на глубине 2). Правку формулировки AC оставляю PM.
2. **AC-010 vs цепочка ADR-0021 (отклонение, обе стороны зафиксированы).** AC-010:
   «остальные строки — `R`/`R100`». Цепочка Решения 7 неизбежно даёт `M` на стороне
   docs/: коммит A правит `docs/.doc-root.yaml`, `docs/_index.md`, `docs/onboarding-nauta.md`;
   переписывание указателей FR-125 правит переезжающие статьи после C. Буквальный запрет M
   неисполним одновременно с FR-125/FR-128. В stub'е: M разрешён на стороне docs/,
   запрещён на стороне content/; A запрещены; D — только 21 одобренный путь.
3. **AC-012 vs бриф «каждый stub красный сейчас» (останов ветки).** AC-012 (NFR-004):
   «`bash scripts/check.sh --fast` → exit 0» — на 8b2db0b замерено rc 0; NFR-004 требует
   зелёный на каждом коммите, включая текущий. Честного красного состояния не существует;
   принудительно красить запрещено методологией (green-born = warden, never forced red).
   Stub оставлен warden'ом: он краснеет в момент, когда чей-то коммит цепочки сломает
   быстрый гейт, — это его функция.
4. **AC-004 vs NFR-003 (отклонение, обе стороны зафиксированы).** AC-004 фильтрует
   только `grep -v "adr/"`, но NFR-003 защищает RECORD и в выживших отчётах: строка 258
   `2026-08-12-wave-4.2.0-qa-report.md` цитирует удалённый
   `2026-08-10-test-harness-taxonomy-qa-report.md`; буквальный конвейер сделал бы AC-004
   неисполнимым. В stub'е — построчные RECORD-исключения пяти выживших отчётов живой
   эпохи; `_index.md` разделов не исключён (навигация очищается по FR-125). Без
   исключений кл. 1 (само требование инверсии цитирует FR-129 дословно) AC-004 также
   был бы вечным.
5. **ADR-0021: неразрешённые остатки для ac-003 (находка Dev/SA, не останов).** Три
   файла с указателями на content/ не названы ни в Решении 5, ни в исключениях:
   `.nauta-ids.yaml` — функциональные home-globs (`home: ["content/00-project/adr/ADR-*.md"]`,
   `graveyard: …`, research/30-requirements — id-аллокатор сломается после переезда,
   если не переписать; файл ведёт провенианс от `bin/init.sh` — правка требует сверки с
   протоколом); `scripts/_apply_yaml_patch.py:16` — docstring с путём
   `content/.doc-root.yaml`; `tests/gramax/cross-catalog-retraction/lib/baseline-commit.sh:15–17`
   — цитаты `git show`/`git log` (RECORD, класс 2 — расширить исключение или переписать).
   Статьи content/ с путеподобными кодспанами (≈120 строк: требования link-form,(writer)
   — ADR-0021 утверждает «реальных markdown-ссылок с литералом content/ в теле статей
   нет»; markdown-ссылок действительно нет, но босоножные кодспан-указатели есть, и
   FR-125 требует их переписать — в таблице коммитов это не расписано).
6. **Пост-C поверхность валидатора (находка из rehearsal, для Dev/SA).** После переезда
   дефолтный корень валидации (docs/) предъявляет к переезжающим статьям требования,
   которых на content/-этапе не предъявлял: ≈13×«тип „Требование“ без строки
   `**Capability:**`» (30-requirements, включая само требование инверсии), регистрации
   в индексах, «регистрация пересказывает статью», C22 title≠H1 на ~20 ADR. AC-005
   (валидатор rc 0) и AC-012 (fast зелёный) вынуждают Dev решить это в цепочке —
   коммиты ADR-0021 в текущей редакции этого не расписывают.
