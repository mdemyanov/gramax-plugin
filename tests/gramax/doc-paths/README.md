# tests/gramax/doc-paths

Гейт против нерабочих `docs/`-указателей внутри `content/`, оставшихся после миграции
документов из `docs/` в `content/`.

## Область

Только `content/`. Каталоги `plugins/`, `tests/` и корневые документы (`CLAUDE.md`,
`AGENTS.md`, `README.md`) покрывает `tests/gramax/nauta-integration/ac-007-no-stale-doc-paths.sh`.
Области намеренно не пересекаются (ADR-0011, BR-003) — новое правило про `docs/`-пути вне
`content/` кладите в `ac-007`, не сюда.

## Критерий: роль предложения, не каталог (ADR-0011 Решение 4)

Одно и то же упоминание `docs/…` в тексте бывает:

- **Указатель** — trace-шапка (`**Spec:**`, `**ADR:**`), футер «Ссылки», проза «Spec `…`
  описывает фичу». Читателя приглашают перейти, а переход упирается в пустоту. Это находка
  гейта — путь нужно починить (заменить на актуальный `content/`-путь).
- **Запись** — процитированная выполненная команда, строка таблицы найденных hits с
  вердиктом, список исключений на дату решения. Замена пути переписала бы историческую
  запись задним числом. Такие строки сохраняются дословно и перечисляются в `allowlist.txt`.

## `allowlist.txt` — две формы записи

```
path/to/file.md:123 — причина     точечная: конкретная строка есть историческая запись
path/to/file.md — причина         whole-file: весь документ посвящён самой миграции
```

Whole-file форма — не дыра в гейте: документ, целиком посвящённый переезду путей (сама спека
этой работы, ADR, обосновывающий политику), по определению не содержит указателей «перейди
сюда» — он содержит таблицу соответствия старого и нового пути. Такому документу точечная
защита каждой строки не нужна и была бы шумом.

## Гейт также проверяет allowlist на протухание (FR-027)

Каждая точечная запись обязана указывать на строку, которая **сейчас** ещё содержит
`docs/`-путь. Если строку отредактировали (или сдвинули номер, или убрали путь), а запись
allowlist осталась — это молчаливая дыра: запись прикрывает уже не ту строку. Гейт в этом
случае падает с диагностикой `allowlist устарел`, а не проходит по старому номеру строки.

Поведение на протухании проверяется на фикстуре `fixtures/stale-allowlist/`, а не мутацией
`content/`: пре-коммит/CI не вправе никого редактировать.

## Как чинить падение гейта

1. **`FAIL: нерабочий указатель на docs/`** — это указатель, не запись. Замените путь на
   актуальный `content/`-эквивалент прямо в тексте статьи.
2. **`FAIL: allowlist устарел`** — либо строка действительно перестала быть записью (тогда
   удалите устаревшую запись из `allowlist.txt`), либо номер строки просто сдвинулся (тогда
   поправьте номер на актуальный — команда для проверки описана в комментарии вверху
   `allowlist.txt`).
3. Если находка — новая историческая запись (не указатель), добавьте точечную строку в
   `allowlist.txt` с причиной, почему замена пути исказила бы историю.

## Устройство

Ядро вынесено в `lib/scan.sh` (`scan_doc_paths <content-root> <allowlist-path>`), чтобы одна
и та же логика гоняла и по живому `content/` (`ac-001`), и по фикстуре рассинхрона (`ac-002`)
без мутации рабочего дерева.

- `ac-001-no-stale-pointers.sh` — на живом `content/`: непокрытых указателей быть не должно.
- `ac-002-stale-allowlist-detected.sh` — на `fixtures/stale-allowlist/`: гейт обязан заметить
  протухшую запись и не заметить свежую.

Гейт **не подключён** к `scripts/check.sh` в этой задаче — подключается отдельной задачей
после того, как указатели, найденные `ac-001`, починены.
