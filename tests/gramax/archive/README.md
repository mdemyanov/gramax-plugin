# tests/gramax/archive/ — замороженные свидетельства приёмки

Этот каталог держит test suite, которые больше не запускаются. Каждый — не действующий
контракт, а зафиксированное на момент своего релиза свидетельство того, что было верно
именно тогда. Обоснование и критерий отнесения suite сюда — ADR:
`content/00-project/adr/0011-test-harness-taxonomy.md` (Решение 1).

## Правило archive/: не редактировать, не запускать, не считать в отчётах

- **Не редактировать.** После коммита, которым suite переехал сюда, ни один файл внутри
  `archive/<suite>/` не меняется — включая обновление версионных пинов (`2.0.0`, `3.0.0`,
  `4.0.0`) до текущей версии плагина. Пины — исторический факт, а не проверка «текущая версия
  не меньше N»; перевод в `>=` уничтожил бы именно то, что делает архив архивом (см. ADR-0011,
  обоснование к Решению 1).
- **Не запускать.** Ни один suite под `archive/` не вызывается никаким агрегатором:
  ни `scripts/check.sh` в любом режиме, ни `run.sh`/`run-all.sh` другого suite. Единственное
  исключение из «не запускать» — `mermaid-file-based/verify.sh`, см. ниже.
- **Не считать в отчётах.** Ни один количественный отчёт вида «N passed / M failed» не включает
  suite из `archive/`. Красный/зелёный счёт архивного suite не отражает состояние текущего
  плагина — только состояние на момент версии, приёмку которой suite удостоверяет.

Единственная защита этого правила — дисциплина и данный README, не технический барьер:
git history уже защищает архив от потери, но не от правки; барьер от правки — сознательный
выбор в пользу простоты (ADR-0011, Trade-offs Решения 1).

## Суть трёх suite

| Suite | Исходный путь | Версия релиза, чью приёмку suite удостоверяет |
|---|---|---|
| `remove-diagram-skills/` | `tests/gramax/remove-diagram-skills/` | 2.0.0 |
| `routing-mermaid-drawio/` | `tests/gramax/routing-mermaid-drawio/` | 3.0.0 |
| `mermaid-file-based/` | `tests/gramax/mermaid-file-based/` | 4.0.0 |

Каждый suite переехал сюда `git mv` без единого изменённого байта — история переезда видна в
`git log --follow` по любому файлу внутри. Ассерты внутри (версионные пины, ожидания
устаревшего на момент приёмки синтаксиса) остаются буквально такими, какими были написаны для
своего релиза: `2.0.0`, `3.0.0`, `4.0.0` — не `4.1.0`, текущая версия плагина на момент этого
коммита.

## `mermaid-file-based/verify.sh` — единственное исполняемое исключение

`archive/mermaid-file-based/verify.sh` появится задачей 5 (реализует QA-author, в этом же
коммите переезда не создаётся). Это параметризованный скрипт, принимающий путь к каталогу с
артефактами ручного вызова `gramax:mermaid` (`verify.sh <output-dir>`) — единственный файл во
всём архиве, который допустимо запускать вручную. Он не входит ни в один режим
`bash scripts/check.sh` (требует живого вызова skill'а, не автоматизируется в pre-commit/CI) и
не наращивает какой-либо количественный отчёт. После своего появления `verify.sh`, как и весь
остальной архив, дальше не редактируется.

## Ретировка AC о поле `skills` в `plugin.json`

`routing-mermaid-drawio/ac-014` требовал присутствия top-level поля `skills` в `plugin.json`.
Этот AC ретирован — не смягчён, а убран целиком — из состава живого `plugin-contract/`
(ADR-0011, Решение 2; FR-012 требования).

**Почему ретировка, а не «пока не реализовано».** AC опирался на посылку, что Claude Code
читает список skills из декларативного поля манифеста. Посылка ложна: skills обнаруживаются
автоматически по каталогу `skills/` внутри плагина, поле манифеста рантаймом не читается.
Значит AC не «ещё не позеленел», а не мог позеленеть никогда — предмет проверки не существует
ни в одной версии системы, на которую опирается требование.

**Измерение (SA, 2026-08-09), по всем установленным плагинам в `~/.claude/plugins/cache`:**

```
find ~/.claude/plugins/cache -name plugin.json -path '*.claude-plugin*' | wc -l   → 53 файла
… уникальных имён плагинов (marketplace/name)                                    → 22
… файлов с top-level полем "skills"                                              → 0
```

Ни один из 53 файлов `plugin.json` (22 разных плагина, включая сам `gramax` 4.1.0) поля
`skills` не несёт. Направление результата воспроизводимо: любой читатель может перепрогнать
команду выше и получить тот же ноль. (Отдельный, более ранний замер PM в тот же день дал
похожую, но не идентичную цифру — «20» плагинов вместо «22»; расхождение объясняется тем, что
кэш плагинов растёт со временем между двумя замерами, направление результата — «поле нигде не
встречается» — то же самое.)

Живой `tests/gramax/plugin-contract/` эту проверку не содержит и не должен — воспроизводить
её означало бы кодировать невыполнимое условие как будто оно когда-нибудь может выполниться.
