# tests/gramax/docs-migration

Suite приёмки инверсии раскладки документации `content/` → `docs/` — 12 красных stub'ов
по AC-001…AC-012 требования
[Инверсия раскладки документации](../../content/30-requirements/2026-11-17-docs-layout-inversion.md)
(механика исполнения — [ADR-0021](../../content/00-project/adr/0021-docs-layout-inversion.md),
цепочка коммитов A → B → C → D1 → D2 → D3).

## Режим работы

До миграции все stub'ы, кроме `ac-012` (warden — быстрый гейт зелёный по рождению,
см. его шапку), красные: они ассертят конечное состояние дерева, которого ещё нет.
Зелёнеет каждый по мере исполнения цепочки ADR-0021 — какой коммит делает какой stub
зелёным, см. таблицу ниже и `at-design.md`. Suite НЕ подключён к `scripts/check.sh` —
проводку выполняет Dev в своей цепочке (подключение красного suite сломало бы быстрый гейт).

Запуск: `bash tests/gramax/docs-migration/run.sh` либо индивидуально
`bash tests/gramax/docs-migration/ac-00X-*.sh`.

## Отклонения от буквальных команд AC (обе стороны зафиксированы в at-design.md)

- **AC-004**: к `grep -v "adr/"` добавлено исключение строк выживших отчётов живой эпохи —
  RECORD по NFR-003 / Решению 3 ADR-0021 (якорь — строка 258 отчёта wave-4.2.0);
  `_index.md` разделов НЕ исключён — навигация обязана быть очищена.
- **AC-006**: первая проверка — по правой стороне пары (`grep -n "→ content/00-project"`),
  редакция PM после останова ветки SA.
- **AC-007**: `find` с `maxdepth 2` — буквальная команда без ограничения глубины ловит 37
  фикстурных `.doc-root.yaml` (кл. 6 ECOSYSTEM), «ровно одна строка» недостижима.
- **AC-010**: `M` разрешён на стороне `docs/` (коммит A правит три файла, а переписывание
  указателей FR-125 правит переезжающие статьи после C), запрещён на стороне `content/`;
  `A` запрещены всегда, `D` — только 21 одобренный путь. Буквальный запрет `M` конфликтует
  с FR-125/FR-128 и цепочкой ADR-0021 (Решение 7).

## Устройство

Без `lib/` и `fixtures/`: каждый скрипт самодостаточен, минимальные ассерты скопированы
инлайн у соседних suite'ов (`doc-paths/lib/assert.sh` — сам scheduled к ретирменту в D2,
копировать его в новый suite нельзя). ROOT резолвится через `git rev-parse` — все проверки
идут от корня дерева. Красное состояние каждого stub'а на 8b2db0b записано в `at-design.md`.
