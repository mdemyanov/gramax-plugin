# tests/gramax/cross-catalog-retraction/ — ретракция нерабочего `code:`-рецепта (hotfix 4.2.1)

Suite тест-дизайна (QA-author, до реализации Dev/Tech-writer) для требования
`content/30-requirements/2026-08-13-cross-catalog-retraction.md` (AC-001…AC-009) и решения
`content/00-project/adr/0017-cross-catalog-retraction.md`. Покрывает все 9 AC требования —
молчаливых пропусков нет: 9 AC — исполняемым скриптом (одно, AC-002(в), — частично
автоматически + обязательная ручная проверка, честно зафиксировано, не имитируется).

Полный тест-дизайн с обоснованиями — `content/60-implementation/acceptance/
2026-08-13-cross-catalog-retraction-at-design.md`.

Весь контракт этой волны статический (grep по тексту, `jq` по JSON, `git diff` по диапазону
коммитов) — исполняемого пути через движок Gramax нет (см. ADR-0017 → «Контракт с QA-author» →
«Trust boundary: отсутствует»).

## Ручная проверка (AC-002в)

`ac-002-skill-md-links-block-consistent.sh` частично автоматизирует AC-002(в): проверяет, что
буллет `SKILL.md:213` («Кросс-каталожные: ...») не содержит паттерн markdown-ссылки `[X](Y)`
(или отсутствует целиком — тоже допустимо по FR-096). Эта часть — надёжный, узко нацеленный
grep (изолирует ровно нужную строку через Кириллическое написание «Кросс-каталож», отличное от
нового Латинского заголовка «Cross-каталожные ссылки:» — проверено эмпирически, единственное
совпадение и до, и после правки).

**Что НЕ покрывает автоматика** (честно, не имитируется): что нигде ДАЛЬШЕ в тексте не
появляется НОВОЕ отдельное утверждение о рабочей markdown-форме для кросс-каталожных ссылок.
Причина — сам исправленный текст (ADR-0017 Решение 2) содержит легитимный ❌-пример
`` `[Документ](other-catalog/path/to/file.md)` `` в обратных кавычках, внешне неотличимый от
markdown-ссылки для наивного regex («Ловушка чужих валидаторов» — предупреждение, вписанное в
сам исправленный текст). Отличить «утверждение» от «иллюстрации» — задача для человека, не для
grep.

**Чек-лист перед финальным QA sign-off:**
1. Прочитать блок «## Ссылки» SKILL.md целиком после правки Dev.
2. Убедиться, что единственные примеры вида `[X](Y)` в этом блоке — легитимные ❌-иллюстрации
   («вот так делать не надо»), обёрнутые в обратные кавычки, а не рекомендованный синтаксис.
3. Убедиться, что нигде в блоке нет прозы вида «используйте ссылку `[Название](путь)` для
   кросс-каталожных документов» вне контекста ❌-иллюстрации.

## Известное ограничение негативной проверки AC-006 (FR-101)

«Отсутствие явного упоминания стороннего репозитория-потребителя» в общем виде не
grep-детектируемо — нельзя перечислить регуляркой все возможные будущие имена репозиториев.
`ac-006-changelog-migration-guide.sh` автоматизирует только два конкретных, уже известных
случая утечки (`content/lessons-learned.md`, 2026-08-11: `knowlage/moex`, `mango-cti-rest`) плюс
прокси-проверку на повторное введение отклонённой ADR-0017 «рабочей» формы `../../`. Полная
гарантия периметра FR-101 — ручной обзор Tech-writer/QA-runner перед публикацией
CHANGELOG-записи, тот же класс ограничения, что и AC-002(в) выше.

## Находка: ручной перенос строк ломает построчный grep на многословных фразах (ac-006, ac-001, ac-002)

При написании `ac-006-changelog-migration-guide.sh` на синтетической фикстуре обнаружено:
`CHANGELOG.md` (как и весь `content/*.md` этого репозитория) пишется с ручным переносом строк на
~90 столбце. Точный текст Решения 3 ADR-0017 переносит фразу «не изменилась» ровно на границе
строк («... не\nизменилась и не требует действий ...»). Построчный `grep -qiE 'не измени'`
против сырого текста секции дал бы **ложный FAIL** на буквально корректном, дословно
скопированном из ADR тексте — «красный TDD-stub, который нельзя погасить корректной работой»
(`content/lessons-learned.md`, 2026-08-11) — зеркальный случай по отношению к более известному
классу «зелёный по грепу — не зелёный»: здесь ложно КРАСНЕЕТ корректная реализация, а не ложно
зеленеет некорректная.

**Исправление:** все многословные проверки в `ac-006`, `ac-001` и `ac-002((a)/(b), не
bullet-isolation (в))` идут по «FLAT»-версии файла/секции — переводы строк схлопнуты в пробел
(`tr '\n' ' '`) — перед grep. Проверено на синтетической CHANGELOG-фикстуре с точным текстом
ADR-0017 Решения 3: без нормализации — ложный `FAIL` на элементе (в); с нормализацией — корректный
`PASS`. `plugins/gramax/skills/writer/**` (цель `ac-001`/`ac-002`) на практике не переносит
строки на ~90 столбце (проверено — макс. длина строки 262/528 символов соответственно), поэтому
риск там ниже, но нормализация применена одинаково для консистентности и на случай, если Dev
скопирует ADR-текст с сохранением его переносов.

## Подключение к `scripts/check.sh`

**Решение: НЕ подключать сейчас — ни к `--fast`, ни к `--full`.** `scripts/check.sh` не
правится этой задачей.

**Обоснование:**
- ADR-0017 не предписывает новую test-инфраструктуру для этой ретракции — наоборот, явно
  выбирает облегчённый guard (предупреждение редакторам, встроенное в исправленный текст
  `doc-root-schema.md`) вместо отдельного test harness («без затрат на отдельную
  test-инфраструктуру», Решение 2). Правка `scripts/check.sh` не следует из ADR прямо — по
  инструкции задачи она правится «только если это прямо следует из ADR».
- Прецедент: `tests/gramax/writer-consumer-rules/` и `tests/gramax/catalog-validator/`
  создавались QA-author'ом красными и НЕ подключёнными к `check.sh`; подключение к `--full`
  происходило отдельным шагом Dev/PM после того, как все живые AC становились зелёными
  (`writer-consumer-rules/README.md`: «Suite подключён к `scripts/check.sh --full` (DEV-004,
  после того как все 12 живых AC стали зелёными)»; `catalog-validator/ac-001…`: «QA-author НЕ
  подключает suite к check.sh сам»). Этот suite следует тому же порядку.
- AC-001(в) и AC-009 этого требования уже независимо проверяют `bash scripts/check.sh --fast`
  композитно (по коду возврата) — сам факт наличия/цвета этого suite'а не входит в критерии
  `--fast`, и не должен: `--fast` — pre-commit-скорость (whitespace/JSON/`validate-content.py`),
  этот suite — секундная, но не мгновенная проверка (запускает `check.sh --fast` дважды внутри
  себя, `jq`, несколько `grep` по всему `content/`/`plugins/`).

**Когда подключать:** когда все 6 сегодня красных скриптов (AC-001, AC-002, AC-005, AC-006,
AC-007, AC-008) станут зелёными — по прецеденту, это решение Dev/Tech-writer/PM на выходе из
их фазы, не работа этой задачи QA-author.

## Диапазон коммитов для `git diff` (AC-003, AC-008 ветка а)

Зафиксирован в `lib/baseline-commit.sh`: `BASELINE_COMMIT="ce4228d"` — единственный коммит,

при создании suite'а, до начала правок Dev/Tech-writer.

## Находка вне периметра этой задачи: `writer-consumer-rules/ac-002` останется зелёным и после ретракции

`tests/gramax/writer-consumer-rules/ac-002-cross-catalog-code-workflow-example.sh` (другой
suite, другое требование — `2026-08-11-writer-consumer-rules.md`) проверяет co-occurrence трёх
сигналов (`code:`, `cross-каталож`, паттерн `` `A/b` ``) в одном файле как признак «рабочий
пример через `code` задокументирован». Точный текст замены ADR-0017 Решение 2 (историческое
объяснение: «Прежде этот раздел показывал двухшаговый рецепт ... построенный на `` `code:` ``
... inline code `` `CODE/путь.md` `` ...») **тоже** несёт все три сигнала в одном файле — просто
в прошедшем времени, как описание РЕТИРОВАННОГО рецепта, а не как рекомендация. Этот suite не
правит `writer-consumer-rules/ac-002` (вне периметра этой задачи — другой suite, другое
требование) и не считает его indicator'ом корректности ретракции. Задокументировано также в
`content/lessons-learned.md` (запись 2026-08-13) как урок для команды: co-occurrence-грep,
рассчитанный на «рецепт документирован как рабочий», не отличает эту рекомендацию от «рецепт
задокументирован как история/предостережение» — то же сочетание слов, противоположный смысл.
